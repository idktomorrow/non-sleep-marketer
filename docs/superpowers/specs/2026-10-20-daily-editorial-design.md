# 관심 분야별 최신 이슈와 사진 중심 게시물 추천 설계

상태: 사용자 검토용 제안. 제품 코드 구현 없이 Claude에게 전달하는 설계다.

## 목적과 요청

사용자가 치이카와·롤·연예인·패션 같은 관심 분야 하나를 정하면 매일 최신 소재를 찾아 게시물을 추천한다. 원본 사진·상품 이미지·공식 포스터·게임 이미지가 중심이고, 글과 장식은 이를 설명한다. 마음에 드는 게시물은 게시하고 나머지는 임시 저장해 나중에 활용한다. 제공된 인스타그램 화면은 시각적 방향의 참고이며 그대로 복제하지 않는다.

사용자 요청은 관심 분야 설정, 최신 유행 소재, 약 3개 추천, 사진 중심 편집, 임시 저장, Claude가 구현할 계획이다. 아래 세부 수치와 운영 기본값은 작성자의 제안이며 사용자 확정값이 아니다. 첨부 이미지의 반응 수치만으로 사진 사용이 성과의 원인이라고 단정하지 않는다.

## 현재 코드에서 확인한 동작

| 영역 | 현재 구현 | 이번 변경 |
|---|---|---|
| 관심 분야 | `Persona.topics` 문자열 목록을 검색어와 분류 라벨로 함께 사용 | 검색할 대상·별칭과 콘텐츠 유형을 분리 |
| 수집 | 네이버 뉴스·블로그 최근 1주 검색, 한국 전체 Google Trends RSS, 업로드, 선택적 커뮤니티 | 분야별 검색어·공식 출처, 작성일·행사일·이미지·반응 신호 수집 |
| 관련성 | `collect.relevance_instruction`: 정보성 자료인지 판정. 기본 기준 0.8. 후기·일기·홍보 등을 제외 | 공식 신제품 발표와 판매 안내를 무조건 광고로 버리지 않도록 자료 역할 분리 |
| 주제 | 관심 주제 중 가장 가까운 하나 선택 | 분야 → 대상 → 사건 → 콘텐츠 유형으로 분리 |
| 분류기 | Gemini 우선, Claude, 키워드 규칙으로 대체. 30분 후 우선 분류기 재시도 | 기존 대체 체계 활용, 규칙 분류만으로 사실·이미지 확인 완료 판정 금지 |
| 소재 선정 | `_pick_material`: 가장 오래 쓰지 않은 주제에서 관련성 높은 미사용 자료 최대 3개 | 동일 사건을 묶고 최신성·관심 신호·근거·이미지 확보 상태로 순위 선정 |
| 생성 수 | 게시 플랫폼별 하루 쿼터의 최댓값 기준 | 추천 수 기본 3개와 게시 수 별도 관리 |
| 디자인 | info/list/compare 템플릿과 전역 clean/photo/illust 스타일 | 원고별·슬라이드별 사진 편집 구성 |
| photo | 사진이 없으면 코드로 그린 도형·그라디언트. 배경 직접 업로드 가능 | 기사·공식 자료의 정확한 이미지 확보 후 배치 |
| 보관 | 검토 대기 원고는 이미 DB에 남지만 추천·보관함 개념 없음 | 추천함, 보관함, 게시 대기 구분 |

관련성 점수는 분류기의 신뢰도에서 계산한 선별 지표다. 사실 정확도나 인기도의 검증된 확률이 아니다. `SourceItem.published_at` 필드는 있지만 네이버 수집 구현은 채우지 않는다. Google Trends는 분야별 상승률을 저장하지 않고 전체 급상승 항목의 검색량 문자열을 본문에 넣는다.

## 사용자 경험

1. 설정에서 관심 분야 하나와 대상을 정한다. 예: 치이카와 / 한국 독자 / 한국·일본 자료. 넓은 분야인 연예인·패션은 처음에는 넓게 시작할 수 있고 좋아하는 인물·브랜드로 좁힐 수 있다.
2. 프로그램이 활동 시간 안에서 자료 수집 → 이슈 묶기 → 이미지 확인 → 추천 선정 → 원고·카드 렌더링을 순서대로 실행한다.
3. 오늘 화면에 서로 다른 이슈의 완성된 게시물 최대 3개가 표시된다. 각 항목은 표지, 제목, 추천 이유, 근거 링크, 자료 날짜, 이미지 확인 상태, 모든 장 보기, 캡션을 제공한다.
4. 버튼은 `게시 대기`, `보관`, `수정`, `관심 없음`. 게시 대기는 기존 시간·쿼터를 지키며, 바로 게시 기능이 필요하면 기존 수동 게시 동작과 같은 제한을 사용한다.
5. 보관함에서는 분야·날짜·콘텐츠 유형으로 찾아 다시 편집하거나 게시 대기로 보낸다. 기존 원고를 그대로 게시하는 것과 새 원고로 복제하는 것을 구분한다.
6. 이미 게시된 원고는 상태를 되돌리지 않는다. `새 초안으로 만들기`로 복제하고 원본 ID를 연결한다. 같은 사건의 반복 게시는 경고하고 자동 게시하지 않는다.

추천 3개는 하나의 소재를 3가지 디자인으로 만든다는 의미가 아니다. 하루에 게시물 3개를 반드시 게시한다는 의미도 아니다. 적절한 소재나 사진이 1개뿐이면 1개만 제공하고 부족한 이유를 표시한다. 완성된 원고 3개를 생성하는 기본안이지만, 비용 때문에 선택 후 제작으로 변경할 수 있도록 선정과 생성은 분리한다.

## 분류 체계와 분야 설정

| 축 | 치이카와 예시 | 역할 |
|---|---|---|
| 분야 | 캐릭터 | 수집 설정의 기본 묶음 |
| 대상 | 치이카와, 하치와레, 우사기 | 정확한 검색·사진 일치 확인 |
| 별칭 | ちいかわ, Chiikawa | 다국어 검색 확장 |
| 사건 | 특정 항공사와 특정 날짜의 협업 발표 | 기사 중복 묶기·추천 중복 방지 |
| 유형 | 신상품, 협업, 행사, 구매 안내, 해설 | 편집 순서와 레이아웃 결정 |
| 시의성 | 새 소식, 현재 관심 증가, 상시 정보 | 추천 이유와 유효기간 |

`editorial_profile`은 설정에 추가하고 기존 `Persona` 계약은 유지한다. 초기 프리셋은 치이카와·롤·연예인·패션이며 검색어·언어·선호 출처·제외어를 사용자가 바꿀 수 있다. 롤은 게임명 별칭을 명시해 동음이의어를 제외한다. 각 프리셋의 실제 출처 연결은 구현 시 공식 페이지를 조사하고 수집 샘플로 검증한다. 확인하지 않은 엔드포인트를 계획에서 동작한다고 가정하지 않는다.

## 최신성과 유행 판정

- 새 소식 기본 창은 작성 시각 기준 최근 72시간. 부족하면 최근 7일까지 확장하고 날짜를 표시한다. 수집 시각을 작성 시각으로 대체하지 않는다.
- 작성일 미상인 자료는 탐색 후보로만 두고 단독 근거로 자동 추천·게시하지 않는다. 미래 행사의 공식 안내는 행사 종료 전까지 별도 이벤트 후보로 유지할 수 있다.
- 기사 URL이 달라도 같은 사건이면 한 묶음이다. 대상 ID, 사건 유형, 제품·행사 식별자, 날짜를 추출해 후보를 만든 뒤 근거 문장으로 병합 여부를 확인한다. 단순히 같은 키워드라고 합치지 않는다.
- 인기도는 관측 데이터로만 판단한다. 출처별 게시물 반응, 검색 신호, 독립적인 보도 증가 등을 관측 시각과 함께 저장한다. 서로 다른 플랫폼의 조회 수를 그대로 비교하지 않는다.
- 제안 점수: 관련성 25, 최신성 25, 관측 관심도 20, 근거 신뢰성 15, 이미지 준비도 15. 각 항목은 0~1로 정규화한다. 인기도 데이터가 없으면 해당 항목은 0이며 `새 소식`으로 표시한다. `급상승`은 동일 지표의 시간차 관측 등 비교 근거가 있을 때만 표시한다.
- 게시된 동일 사건은 14일간 제외하되 신제품 추가·일정 변경처럼 새 사실이 있으면 새 버전으로 검토 가능하다. 추천함·보관함에 이미 있는 사건은 새로 생성하지 않고 기존 항목과 연결한다.
- 서로 다른 사건 상위 3개를 선택하며 동일 유형은 기본 최대 2개로 제한한다. 부족하면 수를 줄이고 억지로 채우지 않는다.

## 이미지 확보와 편집

이미지는 주제와 실제로 일치하는 원본 시각 자료다. 실물 사진뿐 아니라 공식 캐릭터 그림, 게임 화면, 제품 렌더, 포스터도 포함한다. 생성형 이미지로 신제품·실존 인물·공식 행사 모습을 꾸며 사실처럼 대체하지 않는다. 일러스트를 쓸 때도 실제 대상 이미지와 함께 배치하는 것을 기본으로 한다.

이미지마다 원문 URL, 이미지 URL, 출처, 수집 시각, 파일 해시, 크기, 대상·제품·사건 연결, 사용 근거와 검토 상태를 기록한다. 출처의 공식성, 대상 일치, 이미지 사용 가능 여부는 서로 다른 판정이다. 공식 페이지라고 사용 가능으로 자동 표시하지 않는다. 첫 버전은 사용자 소유·허용된 출처의 자료를 자동 편집 대상으로 사용하고 나머지는 확인 대기로 남긴다. 다른 계정의 완성된 카드뉴스나 워터마크가 있는 편집물을 원본 사진으로 선택하지 않는다.

동일 대상·행사·제품 버전인지 원문과 이미지의 표기/OCR/시각 검사로 확인한다. 모델 판단이 애매하면 `이미지 확인 필요`로 남긴다. 이미지 없는 후보는 별도 후보 목록에 보존하되 완성 추천 3개에 넣지 않는다. 여러 장이 필요하면 원본 1장을 무의미하게 반복하지 않고 장수를 줄인다.

기본 1080×1350, 4~8장. 내용이 적으면 3장까지 허용하고 10장 계약 한도를 지킨다. 참고 화면 중 13장 구성은 이번 범위에서 재현하지 않는다.

| 장 역할 | 편집 규칙 |
|---|---|
| 표지 | 원본 이미지 70% 이상, 짧은 제목 최대 2줄, 필요한 영역에만 어두운 그라디언트, 작은 분류명·브랜드 |
| 개요 | 큰 이미지와 2~3줄 요약. 무엇이 새로 나왔는지 먼저 설명 |
| 상품·비교 | 2~4개 이미지와 개별 제품명·가격·기준일 연결. 사진 전체를 배경으로 깔아 해결하지 않음 |
| 일정·방법 | 날짜·장소·판매처 등 확인 가능한 정보. 양이 많으면 슬라이드 분리 |
| 마무리 | 저장·팔로우 제안, 출처. 기존 필수 표기 유지 |

사진 크롭의 초점과 텍스트 위치를 저장하고 검토 화면에서 조정 가능하게 한다. 얼굴·상품·로고를 가리는 경우 재배치한다. 표지는 270×338 미리보기에서도 읽혀야 한다. 실패하면 게시 차단 사유를 표시한다. 글자는 HTML/CSS로 렌더해 수정할 수 있게 한다.

기존 덱 JSON과 `nsm/ports`는 유지한다. 별도 `VisualManifest`가 원고 ID와 revision별 슬라이드 레이아웃·asset ID·크롭·제품 라벨을 저장한다. 새 렌더 진입점이 기존 `CardDeck`과 manifest를 함께 받는다. 기존 덱만 있는 원고는 기존 렌더러로 처리한다. 상품 그리드의 이름·가격도 manifest에 출처와 함께 저장하고 품질 검사 대상에 포함한다.

## 상태와 게시 동작

기존 콘텐츠 상태와 분리한 추천 상태: `candidate → preparing → ready → saved | queued | dismissed`. `preparing → failed` 재시도 가능. 실제 게시 여부는 기존 publications가 원본이며 추천 상태와 중복 관리하지 않는다.

- `ready`와 `saved`는 기존 콘텐츠의 `pending_review`에 대응한다. 보관은 승인이나 게시 예약이 아니다.
- 새 추천 생성은 기존 자동 게시 토글이 켜져 있어도 기본적으로 승인하지 않는다. 처음에는 선택 게시가 기본이다.
- 선택 사항 `추천 자동 게시`: 기존 자동 게시 토글과 보호 모드, 비용, 근거·이미지·신선도 검사를 모두 통과한 경우만 허용한다. 추천 수와 별개로 하루 자동 선택 수 기본 1개, 이후 기존 플랫폼 쿼터가 적용된다.
- 마지막 사실 확인에서 24시간이 지났거나 날짜·가격이 있는 원고는 게시 직전에 원문을 다시 확인한다. 원문 접근 실패, 변경·품절·종료가 있으면 검토로 돌린다. 내용 수정은 새 revision이며 기존 승인을 무효화한다.
- 보관은 기본 만료 없이 유지한다. 오래된 뉴스는 상태 배지를 달고 재검증 후 사용한다. 원본 자료·이미지는 보관 중 삭제하지 않는다.
- 추천 작업은 일자+프로필+사건 버전 키로 멱등 처리한다. 실패한 실행을 재시도해도 이미 완성된 원고를 다시 생성하지 않는다.

## 구조와 운영 제약

기존 Python/FastAPI/Jinja/HTMX/DuckDB/APScheduler를 유지한다. 신규 엔진·저장소·라우트는 파일을 나눠 추가한다. 기존 게시·댓글·쿼터·계정 확인·표기·CSRF·재시작 복구를 재사용한다.

수집 완료를 기다리지 않는 고정 시간 간격 예약을 추가하지 않는다. `daily_editorial` 작업이 수집부터 생성까지 순서를 보장하고 각 단계는 저장된 체크포인트에서 재개한다. 실행 중 변경되는 설정은 작업 시작 때 스냅샷을 잡고 다음 실행부터 적용한다. 기존 생성 모드와 추천 모드는 하나만 일일 예약한다. 수동 키워드 생성은 유지한다.

기존 `count_contents_between`, `used_in_content_id`, 플랫폼 배정은 추천용 생성과 분리해야 한다. 추천은 게시 쿼터를 소모하지 않으며 게시 대상으로 고를 때 플랫폼에 배정한다. 추천 원고의 출처 연결은 별도 다대다 관계로 저장해 기존 댓글의 근거 조회까지 이어 준다.

추천 실행의 유료 호출 전체(분류·비전·본문 생성·재시도)를 비용 기록·상한에 포함한다. 기본 한도는 기존 `daily_cost_cap_usd`를 공유한다. 각 단계 호출 전에 검사하고 중단 이유를 표시한다. 마지막 호출로 상한을 소폭 넘을 수 있다는 기존 특성은 유지하되 무제한 재시도하지 않는다. 관측 없는 임의 비용 예측값을 UI에 표시하지 않는다.

원격 이미지 다운로드는 http(s), 공개 주소만 허용하고 리다이렉트도 검사한다. 크기·시간·픽셀 수를 제한하며 실제 파일 형식을 확인한다. 실패 시 해당 후보만 제외한다. 파일은 로컬에 보관해 미리보기·게시 시 핫링크에 의존하지 않는다. DB 백업과 이미지·manifest 복구를 함께 검증한다.

## 구현 순서와 완료 기준

1. 분야 설정·출처 메타데이터·이슈 묶기·추천 순위.
2. 실제 이미지 수집·검증·저장.
3. 사진 중심 렌더링·원고별 편집.
4. 완성 추천 3개·보관·게시 연결·재검증.
5. 전체 실행·복구·운영 문서·실계정 없는 검증.

첫 운영 검증은 치이카와로 진행하지만 네 프리셋 설정과 회귀 픽스처를 제공한다. 모든 분야에서 같은 수집 품질을 보장한다고 표시하지 않는다. 분야별 최소 1개 실제 출처 샘플을 확인하고 수집 불가능한 출처는 설정에서 비활성화한다.

완료 시 동일 사건 중복 없이 3개 완성 원고를 만들고, 저장한 원고가 재시작 후 남으며, 자료·사진이 부족하면 수가 줄어들고 이유가 보인다. 이미 게시된 항목을 다시 자동 게시하지 않고, 오래된 보관 글은 재검증한다. 모바일 표지와 실제 PNG를 시각 검증하고 기존 테스트를 통과한다. 추천 품질은 노출을 통제한 운영 비교가 있어야 평가 가능하며 스크린샷 반응 수치를 성공 기준으로 쓰지 않는다.


## 구현 검토에서 정한 기본안

추천 자동 게시도 이번 구현에 포함한다. 선택 사항이라는 표현은 사용자가 켜는 운영 옵션이라는 뜻이다. 기본은 manual이며 새 설정에서 auto로 바꾸고 기존 자동 게시 조건까지 만족해야 한다.

이미지 출처의 초기 사용 상태는 unknown이다. 사용 가능 근거를 확인한 출처만 allowed로 등록한다. 설정의 이미지 출처 화면에서 경로·자산 범위, 근거 URL 또는 사용자 메모, 확인 시각을 관리한다. 개별 후보에서도 해당 이미지의 사용 근거와 대상 일치를 확인하거나 사용할 수 있는 사진으로 교체할 수 있다. 사용자 확인 자체가 사용 허가를 만들어내는 것은 아니다. blocked 자료는 근거 갱신이 필요하다. 허용 이미지가 없어도 앱은 시작되고 후보를 보여주지만 완성 추천은 0개일 수 있다.

통합 검증은 사용 가능한 테스트 이미지로 진행한다. 실제 운영 샘플은 적합한 이미지 확보 여부를 별도 결과로 기록하며 확보되지 않으면 실데이터 검증 완료로 보고하지 않는다. 실제 출처 조사와 이미지 확보는 Task 2~3의 초기 검증 항목이다.

후보는 처음에는 이미지 준비도를 0으로 두고 상위 최대 10개를 탐색한다. 이미지 검증 후 실제 준비도로 다시 순위를 매겨 서로 다른 사건 최대 3개를 확정한다. 날짜·근거 등 필수 조건을 이미지 점수로 상쇄하지 않는다.
