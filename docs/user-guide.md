## 1. 시작 전에

### 무엇을 하는 도구인가

내 PC에서 계속 켜 두는 프로그램입니다. 내가 정한 "AI 가상 인플루언서" 페르소나가 자료를 모으고, 카드뉴스와 글을 만들어 인스타그램·스레드에 올리고, 내 게시물의 댓글에 답하고, 성과를 대시보드로 보여줍니다. 민감한 것(출처가 불확실한 글, 불만·환불·법적 댓글)은 자동 처리하지 않고 나에게 넘깁니다.

### 요구 사항

- Windows 11 PC. 프로그램이 도는 동안 PC가 켜져 있어야 합니다(절전 해제 권장).
- 계정: 인스타그램(**프로 계정**이어야 인사이트를 읽습니다), 스레드. 처음에는 계정 없이 드라이런으로 써볼 수 있습니다.
- API 키: Claude API(글 생성·답글, 필수), Gemini API(자료·댓글 분류, 무료 구간이면 0원. 없으면 Claude로 분류), 이미지 생성 API(선택, 끄면 브랜드 색 배경).
- 브라우저: Aside 브라우저(기본) 또는 프로그램이 띄우는 Chromium 창에 직접 로그인.

### 위험 고지 (첫 실행 때 동의 화면이 나옵니다)

- 인스타그램·스레드·네이버·커뮤니티 약관은 자동화 도구 사용을 제한합니다. 계정이 제한되거나 정지될 수 있습니다. 이 도구는 빈도를 낮추고 무작위 간격을 두지만 위험을 없애지는 못합니다.
- 메인 계정 대신 **테스트 계정으로 먼저** 써 보고, 수집에는 수집 전용 계정을 쓰길 권합니다.
- 생성된 글은 AI가 쓴 것입니다. 설치 직후에는 **보호 모드**가 켜져 있어 첫 20건(`protect_count`)을 모두 내가 검토합니다. 품질을 확인한 뒤 대시보드에서 자동 게시를 켜세요.

### 법적 표기

이 도구는 모든 게시물에 다음을 자동으로 넣습니다. 끌 수 없습니다.
- 글 첫 줄: "인공지능(AI)을 기반으로 생성된 가상인물이 포함된 게시물입니다" (공정위 심사지침 예시 문구 그대로)
- 카드 이미지: 표지와 마지막 장의 페르소나 이름 바로 옆에 "가상인물" 배지(중간 장은 이름도 배지도 없음), AI 배경을 쓴 경우 "AI 생성 이미지"
- 협찬 게시물로 설정하면: "#광고"와 "광고" 배지

페르소나가 "직접 써 봤다"는 식의 체험 후기를 쓰는 것은 공정위 지침상 부당 광고가 될 수 있어 기본 금칙 패턴으로 막혀 있습니다. 실제 고객 후기는 자료로 올리면 출처와 함께 인용됩니다.

## 2. 설치와 첫 설정

### 설치

PowerShell에서 한 번만 실행합니다.

```powershell
winget install astral-sh.uv
uv python install 3.12
git clone https://github.com/idktomorrow/non-sleep-marketer.git
cd non-sleep-marketer
uv sync
uv run playwright install chromium
```

### 설정 마법사

```powershell
uv run nsm init
```

마법사는 다음 순서로 묻습니다. 다시 실행하면 기존 값이 기본값으로 나와서 엔터만 누르면 유지됩니다.

1. **위험 고지 동의**: 동의하지 않으면 설정이 저장되지 않습니다.
2. **브랜드**: 이름, 업종, 대표 제품, 핵심 메시지, 브랜드 색(카드뉴스 색이 됩니다).
3. **페르소나**: 활동 시간(예: `09:00-12:00, 18:00-23:00`, 자정을 넘는 `22:00-02:00`도 됩니다), 이름, 핸들, 인물상, 말투, 관심 주제, 금칙어, 협찬 표기 여부, 바로 켤지 여부. 체험 후기처럼 보이는 표현("써봤는데" 등)은 기본으로 막혀 있습니다.
4. **API 키**: Claude 키는 필수, Gemini(분류, 무료)와 OpenAI(배경 이미지)는 선택입니다. 키는 파일이 아니라 Windows 자격 증명 관리자에 저장됩니다. 입력할 때 화면에 보이지 않습니다.
5. **플랫폼**: 처음에는 "드라이런으로 시작"을 권합니다. 실제로 올리지 않고 미리보기 폴더에 결과만 저장합니다.

### 어디에 무엇이 저장되나

| 위치 | 내용 |
|---|---|
| `%USERPROFILE%\.nsm\config.yaml` | 브랜드·페르소나·운영 설정 (직접 고쳐도 됩니다) |
| `%USERPROFILE%\.nsm\data.duckdb` | 수집 자료, 콘텐츠, 댓글, 지표, 비용, 로그 |
| `%USERPROFILE%\.nsm\backups\` | 데이터 자동 백업(매일 새벽 4시 반, `data-날짜.duckdb`, 다른 프리셋은 `data-프리셋-날짜.duckdb`, 프리셋마다 최근 7개). 되살리는 법은 7절 |
| `%USERPROFILE%\.nsm\presets\이름\` | 프리셋(페르소나·브랜드 `preset.yaml`, 캐릭터 그림 복사본, 그 프리셋의 `data.duckdb`). 기본 프리셋은 위 `data.duckdb`를 그대로 씀 |
| `%USERPROFILE%\.nsm\uploads\` | 내가 직접 올리는 자료(제품 정보, 보도자료, 엑셀, 고객 후기, 공지 캡처·포스터 이미지) |
| `%USERPROFILE%\.nsm\upload-text\` | 올린 이미지에서 옮긴 글(같은 이미지를 두 번 읽지 않게 남겨 둠, 지워도 됨) |
| `%USERPROFILE%\.nsm\preview\` | 드라이런 결과물 |
| Windows 자격 증명 관리자 `non-sleep-marketer` | API 키 |

다른 위치를 쓰려면 환경 변수 `NSM_HOME`을 지정합니다.

### 점검

```powershell
uv run nsm doctor
```

`FAIL`이 없으면 시작할 수 있습니다. `WARN`은 선택 기능이 꺼져 있다는 뜻입니다.

대부분은 대시보드 "설정" 화면에서 바꿀 수 있습니다. 아래는 파일에 저장되는 이름입니다.

| 키 | 기본값 | 뜻 |
|---|---|---|
| `dry_run` | `true` | 실제 게시 대신 미리보기 저장 |
| `quotas` | 인스타 1, 스레드 2 | 플랫폼별 하루 최대 게시 수 |
| `daily_cost_cap_usd` | `3.0` | 하루 API 비용 상한(달러). 넘으면 생성을 멈추고 알림 |
| `min_source_chars` | `800` | 본문이 이보다 짧은 자료(검색 요약문만 남은 것)는 원고 재료로 쓰지 않음(C31) |
| `min_facts` | `2` | 원고에 든 구체 사실(날짜·수량·가격·장소·이름) 수가 이보다 적으면 자동 승인하지 않고 검토로 |
| `topic_weekly_limit` | `2` | 관심 주제(소재 묶음)마다 최근 7일 원고 수 상한. 넘으면 다른 주제 먼저. `0`이면 없음 |
| `max_bodies_per_run` | `24` | 자료 모으기 한 번에 원문을 읽는 자료 수(전엔 6이라 요약문만 남는 자료가 많았음) |
| `protect_count` | `20` | 보호 모드: 사람이 승인해야 하는 첫 콘텐츠 수 |
| `collect.google_news` | `true` | 구글 뉴스 RSS로 관심 주제의 최신 기사를 모음(0원). 네이버가 안 잡는 매체를 보완. 마음에 안 들면 `false`(ADR 0050) |
| `classifier` | `auto` | Gemini 키가 있으면 Gemini(무료 구간), 없으면 Claude, 둘 다 없으면 낱말 규칙. `gemini`·`claude`·`keyword`로 고정 가능. 고른 것이 실패하면 다음으로 넘어가며 알림(ADR 0048) |
| `models.gemini` | `gemini-3.5-flash-lite` | 분류에 쓰는 Gemini 모델 |
| `image_generation` | `off` | AI 배경 이미지(유료). `off`: 만들지 않고 코드로 그린 배경만(사진은 검토 화면에서 직접 올림). `auto`: OpenAI 키가 있으면 만듦. `on`: 항상 만듦(키가 없으면 경고 후 코드 배경). `nsm init`에서 OpenAI 키를 새로 넣으면 켤지 물어봄 (ADR 0036) |
| `brand.character` | `none` | 일러스트형 카드 표지·마지막 장 캐릭터(설정 화면 "일러스트형 캐릭터"). `none` 없음(기본), `custom` 직접 올린 그림(`brand.character_cover`·`brand.character_outro`), `drawn` 도형 캐릭터 (ADR 0046) |
| `brand.character_ai_made` | `false` | 캐릭터가 있는 장에 "AI 생성 이미지" 표기. AI로 만든 그림이라도 실제처럼 보이지 않는 만화 캐릭터면 표기하지 않음. 사진처럼 실제 같은 그림을 AI로 만들어 올렸다면 켜세요 (ADR 0046) |
| `brand.card_style` | `clean` | 카드 디자인 스타일(설정 화면 "카드 스타일"). `clean` 깔끔, `photo` 사진형, `illust` 일러스트형. 아래 "카드 스타일" 참고 |

## 3. 드라이런으로 결과 미리 보기

처음에는 실제 계정 없이 드라이런으로 돌려 봅니다(`config.yaml`의 `settings.dry_run: true`, 마법사 기본값).

```powershell
uv run nsm run
```

- 창에 `대시보드: http://127.0.0.1:8765`가 뜨면 브라우저로 엽니다. 이 주소는 내 PC에서만 열립니다.
- 프로그램은 정해진 시각에 알아서 움직입니다: 상태 점검 30분마다, 수집은 활동 시간 창마다 시작 20분 뒤(창이 하나면 하루 1회), 생성은 첫 활동 시간 창 시작 50분 뒤, 게시는 30분마다(게시 시간·쿼터·간격 안에서), 댓글 확인 5분마다(`reply_interval_minutes`, 인스타그램은 30분마다 `instagram_comment_interval_minutes`), 지표는 새벽 3시. 모든 시각에는 몇 분씩 무작위 지연이 섞입니다.
- 기다리지 않고 바로 보고 싶으면 대시보드 "오늘" 화면의 **지금 실행**에서 자료 모으기 → 원고 만들기 → 게시하기 순으로 누릅니다. 누른 화면 오른쪽 아래에 진행 상황이 뜨고, 끝나면 결과 요약과 Windows 알림이 옵니다. **원고 만들기**는 오늘 목표와 상관없이 누를 때마다 1건을 더 만듭니다(비용 상한·쓸 자료가 있어야 함). 더 만든 원고도 게시는 하루 게시 수와 간격을 지키므로, 바로 더 올리려면 설정에서 하루 게시 수를 늘리세요.
- 드라이런 게시물은 `%USERPROFILE%\.nsm\preview\날짜\콘텐츠ID\플랫폼\`에 카드 PNG(1080×1350, 브랜드 색과 Pretendard 글꼴)와 원고로 저장되고, 20분 간격으로 가짜 댓글이 달려 대댓글 흐름까지 확인할 수 있습니다.
- 끄려면 창에서 `Ctrl+C`.

한 번만 돌려 보고 싶을 때(디버그):

```powershell
uv run nsm run --once --job collect
uv run nsm run --once --job generate
uv run nsm run --once --job publish
```

카드 디자인만 확인하고 싶으면 덱 JSON 하나를 바로 그려 볼 수 있습니다(예시 덱: `tests/fixtures/decks/`).

```powershell
uv run nsm render-preview tests/fixtures/decks/info.json --out preview-cards
uv run nsm render-preview tests/fixtures/decks/info.json --out preview-cards --style illust
```

`--style`을 빼면 설정의 카드 스타일(`brand.card_style`)로 그립니다.

### 카드 스타일

설정 화면 → 브랜드 → **카드 스타일**에서 고릅니다. 스타일마다 지금 브랜드 색과 페르소나 이름으로 그린 견본(표지·본문 장)이 작게 보이고, 색을 바꾸면 저장하기 전에도 견본이 그 색으로 바뀝니다. 견본을 누르면 그 스타일이 선택됩니다. 저장하면 다시 켜지 않아도 다음에 그리는 카드부터 바뀝니다. 아직 올리지 않은 원고(게시 대기 포함)는 게시할 때 새 스타일로 다시 그립니다. 새 스타일에서 글이 카드에 다 들어가지 않으면 올리지 않고 검토로 돌려보내며 알림을 띄웁니다. 검토 상세의 "미리보기 렌더"로 먼저 확인하세요. 샘플은 `docs/samples/styles/`에 있습니다.

### 캐릭터와 로고

일러스트형 카드는 표지 왼쪽 아래와 마지막 장 오른쪽 아래에 페르소나 캐릭터를 넣을 수 있습니다. 기본은 캐릭터 없음이고, 넣고 싶으면 그림을 올리세요. 가상인물 배지가 있는 장에만 들어가고, 중간 장에는 없습니다.

- **고르기**: 설정 → 브랜드 → **일러스트형 캐릭터**에서 없음(기본), 직접 올린 그림, 도형 캐릭터 중에 고르고 저장하세요. 일러스트형 견본이 그 캐릭터로 바뀝니다.
- **직접 올리기**: 설정 맨 아래 **캐릭터·로고 그림**에서 표지 캐릭터, 마지막 장 캐릭터(비우면 표지 그림), 로고를 올립니다(PNG·JPEG·WebP, 10MB 이하).
  - 캐릭터는 흰 종이 같은 바탕을 자동으로 지우고 그림만 남깁니다. 윤곽선 안의 흰 부분은 남습니다. 바탕이 사진이거나 여러 색이면 덜 지워질 수 있으니, 그때는 "바탕 자동으로 지우기"를 끄고 투명 PNG를 올리세요.
  - 캐릭터를 올리면 바로 "직접 올린 그림"으로 바뀝니다. 다 지우면 "없음"으로 돌아갑니다.
  - 로고는 세 스타일 모두 표지·마지막 장의 이름 앞에 작게 들어갑니다. 로고는 새로 만드는 원고부터 들어가고, 이미 만든 원고는 예전 로고 그대로입니다.
- **직접 만든 그림만** 올리세요. 다른 회사·작가의 캐릭터(예: 치이카와, 산리오)를 올리면 그대로 카드에 실려 게시되어 저작권 문제가 생깁니다.
- **AI 표기**: 기본은 꺼져 있습니다. AI로 만든 그림이라도 실제 사람이나 사진처럼 보이지 않는 만화 캐릭터면 꺼 두셔도 됩니다. 사진처럼 실제 같은 그림을 AI로 만들어 올렸다면 "캐릭터가 있는 장에 'AI 생성 이미지' 표기하기"를 켜세요. "가상인물" 배지는 이것과 상관없이 늘 붙습니다.
- 저장하면 다시 켜지 않아도 다음에 그리는 카드부터 바뀌고, 게시 대기 중인 일러스트형 원고도 올릴 때 새 캐릭터로 다시 그립니다. 샘플은 `docs/samples/characters/`에 있습니다.

| 스타일 | 모양 | 어울리는 글 |
|---|---|---|
| `clean`(기본) | 표지·마무리는 브랜드 색 면, 본문은 밝은 바탕에 카드 | 무난한 정보 정리 |
| `photo` 사진형 | 장마다 꽉 찬 어두운 배경(고리·사선 무늬), 제목은 줄마다 강조색 상자, 부제·문단·마무리 문구는 흰 말풍선 | 소식·이슈. 검토 화면에서 배경 사진을 올리면 그 사진 위에 같은 모양으로 올라감 |
| `illust` 일러스트형 | 파스텔 점 무늬 바탕, 페르소나 캐릭터(표지에 서 있고 마무리에서 손을 흔듦), 흰 스티커 번호 카드, 테두리 말풍선 | 팁·순서·목록 |

- 세 스타일 모두 배경을 코드로 그려 **추가 비용이 없습니다.** 글자는 이미지에 굽지 않아 깨지지 않고, 가상인물·광고 표기와 표지 글자 크기(스레드 썸네일 기준)도 똑같이 지킵니다.
- 코드로 그린 배경에는 "AI 생성 이미지" 표기가 붙지 않습니다. AI 배경을 켠 경우 그 배경이 들어간 장에만 붙습니다.
- 캐릭터는 이 도구가 자체로 그린 도형 캐릭터이고, 몸 색은 브랜드 주 색을 따릅니다.
- 지금은 모든 원고에 같은 스타일이 적용됩니다. 원고마다 다르게 고르는 기능은 아직 없습니다(ADR 0037).

`nsm run`이 켜져 있는 동안에는 `--once`를 쓸 수 없습니다(데이터 파일을 한 프로세스만 열 수 있음). 대시보드의 **지금 실행**을 쓰세요.

## 4. 대시보드 사용법

대시보드 주소는 `uv run nsm run`을 실행한 뒤 http://127.0.0.1:8765 입니다(내 PC에서만 열림). 휴대폰 폭에서도 볼 수 있습니다.

### 간단 모드와 고급 모드

오른쪽 위 **간단 | 고급** 스위치로 바꿉니다. 처음에는 간단 모드이고, 고른 모드는 다시 켜도 그대로입니다. 두 모드는 보이는 것만 다르고 할 수 있는 일은 같습니다.

| | 간단 모드(매일 쓰는 사람) | 고급 모드(설정을 다듬거나 문제를 찾는 사람) |
|---|---|---|
| 메뉴 | 오늘, 검토, 게시 대기, 댓글, 성과, 주간 리포트, 설정 | 위 메뉴에 자료, 실행 기록 추가 |
| 오늘 | 할 일, 오늘 게시·대기(승인된 원고가 있으면 플랫폼별 **다음 게시 시각**)·비용, 페르소나·자동 게시 스위치, 지금 실행(자료 모으기·원고 만들기·댓글 확인), **자료 올리기** | 위에 쓸 수 있는 자료 수, 모든 작업의 지금 실행, 최근 실행 표 추가 |
| 설정 | 페르소나, 브랜드·카드 스타일, 게시 시간, 하루 게시 수, 비용 상한, "광고" 표기, 알림 | 위에 활동 시간, 게시 간격, 자료 검색 기간, 댓글 확인 간격, 금칙 패턴 추가 |

- 간단 모드에서 설정을 저장해도 숨은 세부 값은 바뀌지 않습니다.
- 숨긴 화면도 알림을 누르거나 주소(`/materials`, `/logs`)로 들어가면 열립니다.

### 화면별로 할 수 있는 일

| 게시 대기 | 승인돼 올라가기를 기다리는 원고(올라갈 순서대로)와 플랫폼별 상태, 최근 7일 게시 목록. 고치려면 **검토로 되돌리기**(되돌리는 즉시 게시가 멈춤), 필요 없으면 **폐기** |
| 검토 상세 | 카드(왼쪽)와 원고(오른쪽)를 나란히. 위쪽 막대에 저장·미리보기 렌더·승인·폐기. 카드 장마다 문구 고치기, 배경 사진 올리기·지우기, 캡션·스레드 글 고치기, 사실 주장과 출처, 금칙어 경고, 플랫폼별 게시 상태 |
| 댓글 | 사람이 확인할 댓글(불만, 가격·환불, 법적 문제, 스팸 추정, 분류 불확실, 답글 초안에 금칙어, 보냈지만 확인 못 한 답글). 직접 답글 보내기 또는 처리 완료 |
| 성과 | 게시물별 조회·도달·좋아요·댓글·저장·공유, 팔로워, 댓글 처리 현황(평균 자동 응답 시간), 최근 14일 비용 |

"정상"이면 볼 것 없음, "오래 안 돌았음"이면 PC가 꺼졌거나 프로그램이 멈췄는지 확인. 아래: 변화가 있던 실행만(아무 일 없던 성공은 숨기고 같은 결과가 이어지면 "N번"으로 묶음, "전체 보기"를 누르면 모든 줄). 줄마다 무엇을 했는지 한 줄 요약(예: "새 댓글 없음 · 인스타그램 요청 제한으로 쉬는 중(02:56 이후 다시)", "1건 올림 · 안 올린 곳: 스레드 3시간 간격 대기(14:00 이후)"). 오류가 있으면 첫 오류 내용이 뒤에 붙음 |
| (모든 화면) 종 모양 | 알림함. 안 읽은 수가 뜨고, 누르면 최근 알림이 펼쳐짐. 하나를 누르면 읽음이 되고 관련 화면으로 이동, **전체 읽음**으로 한 번에 정리. 데스크톱 알림을 꺼도 여기에는 남음 |
| (모든 화면) 오른쪽 아래 | "지금 실행"으로 누른 작업의 진행 상황("실행 중… n초")과 끝난 뒤 결과 요약. ×로 닫거나 3분 뒤 사라짐 |
| 설정 | 페르소나(이름·인물상·말투·관심 주제·금칙어·금칙 패턴), 브랜드(이름·업종·제품·핵심 메시지·색·카드 스타일·일러스트형 캐릭터), 캐릭터·로고 그림 올리기, 운영(활동 시간·게시 시간·하루 게시 수·비용 상한·게시 간격·댓글 확인 간격·인스타그램 댓글 확인 간격·"광고" 표기), 알림 켜기/끄기와 테스트 알림. 저장하면 다음 작업부터 바로 반영(다시 켤 필요 없음, 활동 시간을 바꾸면 수집·원고 시각도 다시 잡음). 계정·드라이런·API 키는 안전을 위해 `uv run nsm init`에서만 |

자주 하는 일:

1. **매일 아침**: "오늘" 화면의 할 일 목록을 위에서부터 누르세요. 검토할 원고는 가장 오래 기다린 것부터 열립니다.
2. **원하는 이야기로 원고 만들기**: "오늘"의 **키워드로 원고 만들기**에 키워드(예: "치이카와 굿즈 신상")를 넣고 누르세요.
   - 네이버 블로그·뉴스에서 그 키워드의 최근 글을 바로 찾아, 쓸 만한 자료 최대 3건으로 원고 1건을 만듭니다. 1~2분 걸리고 진행은 오른쪽 아래에 보입니다.
   - 쓸 만한 자료가 없으면 만들지 않고 알려 줍니다(비용 없음). 키워드를 조금 넓히거나 바꿔 보세요.
   - 만든 원고는 평소 원고와 같은 규칙으로 검토 대기나 게시 대기로 갑니다. 관심 주제 목록은 바뀌지 않습니다.
   - 자동 수집이 한쪽 이야기로 쏠리면(예: 극장판만) 설정의 **수집 제외어**에 그 낱말을 넣으세요. 그 낱말이 든 글은 모으지도, 원고에 쓰지도 않습니다.
3. **이미지 공지로 원고 만들기**: 굿즈 예약판매 공지, 팝업 포스터, 가격표처럼 글자가 든 이미지(png·jpg·webp, 5MB 이하)를 "오늘"이나 "자료"의 **자료 올리기**로 올리세요.
   - Claude가 이미지에 보이는 글자와 사실(상품명·날짜·장소·가격·구매처·디자인 수)을 글로 옮겨 자료로 씁니다. 예: CGV 팝콘통 공지 → "CGV 먼작귀 팝콘통 예약판매 오픈 / 구매처: 네이버에서 [CGV 스토어] 검색"
   - 올리자마자 옮긴 글 앞부분이 안내에 보입니다. 틀린 곳이 있으면 그 파일을 지우고 더 선명한 이미지로 다시 올리세요.
   - 글자가 없는 사진(예: 인형만 찍은 사진)은 자료로 쓸 수 없어 올리지 않습니다. 이미지는 카드에 들어가지 않습니다(캐릭터 저작권).
   - 한 장에 1센트 미만이 들고, 같은 이미지는 한 번만 읽습니다.
4. **처음 N건 검토하기**: 보호 모드(`protect_count`, 기본 20건) 동안은 모든 원고가 검토 대기열로 옵니다. 하나씩 열어 출처와 문구를 확인하고 승인하세요. N건을 승인한 뒤 "오늘" 화면에서 **자동 게시**를 켜면, 기준을 통과한 콘텐츠는 그때부터 자동으로 올라갑니다(자동 게시가 꺼져 있으면 N건이 지나도 계속 검토로 옵니다).
5. **실패했던 게시 다시 시도**: 게시가 4번 실패하거나 중간에 끊긴 콘텐츠는 검토 대기열로 돌아옵니다. 플랫폼에서 실제로 안 올라간 것을 확인한 뒤 승인하면 처음부터 다시 시도합니다.
6. **댓글 처리**: 알림이 오면 댓글 화면에서 직접 답하거나, 답할 필요가 없으면 처리 완료를 누릅니다.
   - "답글을 보냈지만 플랫폼에서 확인하지 못함"으로 넘어온 댓글은, 프로그램이 "게시"까지 눌렀는데 화면에서 답글을 찾지 못한 경우입니다. 두 번 달리지 않게 다시 보내지 않으니, 플랫폼에서 실제로 달렸는지 보고 없으면 보여 주는 문장을 그대로 직접 답글로 보내세요. 달려 있으면 처리 완료를 누르세요.
   - 자동 답글은 게시물 본문과 그 원고를 만들 때 쓴 기사(최대 3개)를 보고 씁니다. 거기에 답이 있으면 날짜·장소를 구체적으로 알려 줍니다. 오늘 날짜를 기준으로 말하고, 링크는 넣지 않습니다.
   - 답이 없는 질문(예: 일본 행사 글에 "한국에는 안 열리나요?")에는 지어내지 않고, 아는 만큼 말한 뒤 "아직 발표된 소식은 없는 것 같아요"처럼 답합니다. 댓글마다 새로 검색하지는 않으므로, 원고를 만든 뒤 나온 새 소식은 모릅니다.
   - 답글 1개에 약 $0.003(4~5원)이 듭니다.
7. **카드 다듬기**: 검토 상세 화면 "고치기"에서 장마다 제목·본문·목록(한 줄에 하나)을 고치고 저장합니다. "미리보기 렌더"를 누르면 지금 원고로 카드를 그려 보여 주고, 글이 넘치는 장이 있으면 알려 줍니다. 배경 사진은 장마다 PNG·JPEG·WebP(10MB 이하)를 올릴 수 있습니다. 직접 올린 사진에는 "AI 생성 이미지" 표기가 붙지 않습니다(AI가 만든 배경이 한 장이라도 남아 있으면 사진 장에도 붙습니다). 마무리 장의 출처도 한 줄에 하나씩(웹 주소 또는 "브랜드 제공 자료" 같은 이름, 1~5개) 고칠 수 있고, 고친 출처는 카드와 SNS 글 끝 "출처:" 줄에 그대로 나갑니다. 사실 주장의 근거 자료는 바뀌지 않으니 근거를 지우지 않았는지 확인하세요. 검토 대기 중인 콘텐츠만 고칠 수 있고, 고치면 이미 그린 카드는 지워지고 게시 때 다시 그립니다.


### 프리셋 (페르소나 갈아끼우기)

설정 화면 맨 위 "프리셋" 칸에서 페르소나·브랜드를 이름 붙여 저장하고 전환합니다. 프리셋은 설정 묶음이 아니라 **작업 공간**입니다: 자료·원고·댓글·성과·알림함이 프리셋마다 따로 쌓입니다(관련 자료 판정이 관심 주제 기준이라 섞이면 다른 프리셋이 자료를 못 받습니다).

- **지금 설정을 저장**: 이름을 넣고 저장. 같은 이름이면 덮어쓰고, 새 이름이면 새 프리셋이 됩니다(그 프리셋의 자료·원고는 전환할 때 비어 있는 상태로 시작).
- **전환**: 목록에서 "전환". 지금 설정은 현재 이름으로 자동 저장되고, 진행 중인 작업이 있으면 끝난 뒤 바뀝니다(오른쪽 아래 "프리셋 전환" 표시). 다음 수집부터 새 주제로, 다음 답글부터 새 말투로 돕니다.
- **지우기**: 프리셋과 그 자료·원고·성과를 모두 지웁니다. 지금 쓰는 프리셋과 "기본"은 못 지웁니다.
- 공통으로 쓰는 것: 계정(핸들)·브라우저 로그인·API 키·운영 설정(간격·상한·알림)·`uploads` 폴더. 계정은 실제 로그인과 맞아야 해서 프리셋이 바꾸지 않습니다.
- 상단 바에 "기본"이 아닌 프리셋 이름이 배지로 보입니다.
- 알아 둘 것: 하루 비용 상한은 프리셋마다 따로 셉니다(전환한 날은 "오늘 비용"을 한 번 보세요). 되돌리려면 "기본"으로 전환하면 원래 데이터가 그대로입니다.

## 5. 실제 계정 연결

실제 게시·답글·댓글 숨기기는 **Aside 브라우저**가 대신 합니다. 이 프로그램은 Aside에게 정해진 순서의 브라우저 동작을 시키고, 비밀번호는 다루지 않습니다.

### 준비

1. [Aside](https://docs.aside.com/help/developers)를 설치하고, Aside 브라우저에서 게시할 스레드·인스타그램 계정으로 로그인합니다. 인스타그램은 **프로페셔널 계정**(크리에이터 권장)이어야 조회수 같은 인사이트를 읽습니다.
2. Aside CLI를 설치합니다(위 문서의 Windows 설치 명령). `uv run nsm doctor`에서 `Aside CLI`가 OK면 됩니다.
3. `%USERPROFILE%\.nsm\config.yaml`의 `settings`를 고칩니다.

```yaml
settings:
  dry_run: false
  browser_driver: aside
  accounts:
    threads: "@내_스레드_핸들"
    instagram: "@내_인스타그램_핸들"
```

`accounts`에 적은 핸들과 Aside 브라우저에 로그인된 계정이 **다르면 게시하지 않습니다**. 다른 계정에 잘못 올라가는 것을 막는 장치입니다.

### 무엇이 일어나나

| 하는 일 | 걸리는 시간(실측) | 비고 |
|---|---|---|
| 글 + 카드 이미지 게시 | 약 20초 | 게시 전에 로그인 계정 확인, 게시 후 글 주소 저장 |
| 새 댓글 읽기 | 글 하나당 약 10초 | 글 화면 첫 페이지에 보이는 답글까지 |
| 자동 답글 | 약 45초 | |
| 스팸 댓글 숨기기 | 약 10초 | 스레드의 "모두에게 숨기기" |
| 지표 읽기 | 약 10초 | 조회수, 조회한 사람, 좋아요, 답글, 리포스트, 팔로워 |
| 인스타그램 카드 게시 | 약 70초 | 자르기를 **4:5**로 골라 표기 배지가 잘리지 않게 하고, "Threads에 공유"는 끔(스레드는 따로 올림) |
| 인스타그램 댓글 읽기·답글 | 약 10초씩 | 숨기기는 인스타그램 웹에 없어 스팸은 검토 대기열로 넘어감 |
| 인스타그램 지표 | 약 10초 | 조회수, 좋아요, 댓글, 저장, 공유(인사이트), 팔로워 |

작업할 때 Aside 브라우저에 탭이 잠깐 열렸다 닫힙니다. 그동안 Aside 브라우저를 같이 써도 되지만, 그 탭은 건드리지 마세요.

### 연결 점검 (계약 테스트, 개발자용)

어댑터가 약속(게시 → 주소, 댓글 읽기, 답글, 숨기기 지원 여부, 지표, 로그인 확인)을 지키는지 확인하는 테스트가 있습니다.

- `uv run pytest`에는 드라이런 어댑터 점검이 포함됩니다. 실계정에는 접속하지 않습니다.
- `uv run pytest -m contract tests/contracts/test_platform_contract.py`는 실계정을 **읽기만** 합니다(로그인 계정, 팔로워 수). 이미 올라간 글 코드를 `NSM_CONTRACT_THREADS_POST`·`NSM_CONTRACT_INSTAGRAM_POST`에 넣으면 그 글의 지표·댓글도 읽습니다. 글을 올리지 않습니다.
- `test_threads_live.py`·`test_instagram_live.py`는 실제로 **글을 올렸다가 지웁니다**. 운영 계정에 잠깐 보이므로 사람이 있을 때만 돌리세요.

### 로그인이 풀리면

30분마다 로그인 상태를 확인합니다. 풀려 있거나 다른 계정이면 그 플랫폼의 자동 게시·답글을 멈추고 알림을 보냅니다. Aside 브라우저에서 다시 로그인하면 다음 확인 때 자동으로 다시 시작합니다.

### 요청 제한(HTTP 429)에 걸리면

플랫폼이 "요청이 너무 많다"며 페이지를 막는 경우입니다. 로그인이 풀린 것이 아니므로 다시 로그인할 필요가 없습니다(ADR 0038).

- "인스타그램 요청 제한" 알림이 한 번 뜹니다. 알림에 언제까지 쉬는지 나옵니다.
- 그동안 그 플랫폼의 게시·댓글 확인·지표를 쉬고, 브라우저로 그 사이트를 열지 않습니다. 처음은 2시간이고, 쉰 뒤 바로 또 막히면 4시간, 8시간까지 늘어납니다.
- 쉬는 동안 "게시하기"를 직접 눌러도 그 플랫폼은 건너뜁니다. 결과에 "요청 제한으로 쉬는 중(HH:MM 이후 다시)"이 나옵니다.
- 쉬는 시간이 끝나면 저절로 다시 시도합니다. `nsm run`을 다시 켜면 한 번은 바로 다시 시도합니다.
- 자주 걸리면 설정 화면의 "인스타그램 댓글 확인 간격"을 늘립니다.

### 자동 시작 등록

PC를 켤 때 자동으로 실행되게 하려면 `uv run nsm install-autostart` (해제: `uv run nsm uninstall-autostart`).

## 6. 성과와 주간 리포트 읽는 법

### 성과 화면

- **게시물별 지표**: 조회·도달·노출·좋아요·댓글·저장·공유. 플랫폼마다 제공하는 지표가 다릅니다(인스타 도달·노출은 프로 계정 필요). 없으면 `-`.
- **팔로워**: 하루 한 번(새벽) 기록합니다.
- **댓글 처리**: 자동 답글·숨김·사람 확인 건수와 평균 자동 응답 시간.
- **비용**: 최근 14일, 종류별(글 생성 llm, 이미지 image, 분류 classifier).

### 주간 리포트

매주 월요일 오전 8시에 지난주(어제까지 7일, 현지 날짜 기준) 결산이 `%USERPROFILE%\.nsm\reports\weekly-날짜.md`로 만들어지고 알림이 옵니다. 대시보드 **주간 리포트** 화면에서도 볼 수 있고, "오늘" 화면의 지금 실행에서 **주간 리포트**를 눌러 바로 만들 수도 있습니다.

| 절 | 내용 |
|---|---|
| 요약 | 플랫폼별 게시 수, 평균 참여율, 댓글 처리, 비용 합계 |
| 팔로워 | 플랫폼별 주초 → 주말 변화 |
| 가장 잘된 콘텐츠 | 참여율 상위 3개와 이유(평균 대비 배수, 형식, 게시 시간대, 주제, 저장이 많은지) |
| 다음 주 추천 주제 | 내 관심 주제 중 참여율이 높았고 쓸 자료가 남은 순서, 관련 급상승 검색어 |
| 협찬(광고) 게시물 | 광고 표기 게시물만 따로(미디어킷용) |

**참여율** = (좋아요 + 댓글 + 저장 + 공유) ÷ 조회. 아직 성과 기록이 없는 주제는 평균보다 조금 낮게 쳐서, 검증된 주제가 먼저 추천됩니다. 리포트는 정해진 계산 규칙으로 만들어서 API 비용이 들지 않고, 같은 데이터면 늘 같은 결과가 나옵니다.

## 7. 문제 해결

| 증상 | 확인할 것 |
|---|---|
| 무엇이든 이상할 때 | `uv run nsm doctor`로 Python, 데이터, 설정, API 키, 브라우저, 폰트, Aside CLI를 점검 |
| "스레드 게시 계정이 설정에 없습니다" | `settings.accounts`에 `threads: "@핸들"`을 적기. 비어 있으면 실계정 동작을 하지 않음 |
| "로그인 계정 @A ≠ 설정 @B" | Aside 브라우저에 로그인된 계정이 설정과 다름. 맞는 계정으로 로그인하거나 설정을 고치기 |
| 게시는 됐는데 댓글·지표가 안 모임 | 올린 뒤 글 주소를 확인하지 못한 경우(로그에 "글 주소를 찾지 못함"). 중복 게시를 막으려고 성공으로 기록하고 프로필 주소만 남김. 그 글의 댓글은 스레드에서 직접 확인 |
| Aside가 카드 이미지를 못 올림 | 이 프로그램이 이미지를 직접 넘기므로 Aside 파일 권한 설정은 필요 없음. `nsm doctor`로 Aside CLI를 확인하고, 방화벽이 127.0.0.1(내 PC 안) 연결을 막는지 확인 |
| API 키가 진짜 되는지 | `uv run nsm doctor --live`: Claude·Gemini를 한 번씩 실제로 호출(비용 1원 미만, 오늘 비용에 기록됨. `nsm run`이 켜져 있으면 기록은 건너뜀). `--with-image`를 붙이면 OpenAI 이미지도 1장(약 70원) |
| 생성이 안 됨 | 실행 로그에 "Claude API 키가 없어" → `nsm init`으로 키 입력. "비용 상한" → 오늘 비용이 상한에 닿음(다음 날 재개, 또는 `daily_cost_cap_usd` 조정). "쓸 자료 없음" → 관련 자료가 모일 때까지 기다리거나 `uploads` 폴더에 자료 추가 |
| 게시가 안 됨 | 페르소나가 꺼져 있거나 활동 시간 밖, 오늘 쿼터를 채움, 같은 플랫폼 직전 게시 후 3시간이 안 됨("게시하기"를 직접 누르면 간격은 무시), 콘텐츠가 승인되지 않음 중 하나. 게시하기 결과 알림에 플랫폼별 이유가 나옵니다 |
| "로그인 필요" 알림 | 그 플랫폼의 자동 게시·답글이 멈춘 상태. 브라우저에서 다시 로그인하면 다음 상태 점검(30분 이내)에 자동으로 다시 시작 |
| "계속 0건" 알림·오늘 할 일 | 자료 모으기가 며칠째 관련 자료 0개이거나, 승인된 원고가 있는데 며칠째 못 올린 상태. 실행 기록에서 그 작업의 요약(안 올린 이유 등)을 보고, 며칠째 0이면 수집하는 사이트 화면이 바뀌었을 수 있음([known-gaps.md](known-gaps.md) 2절) |
| 데이터를 되살리고 싶음 | `nsm run`을 끄고, `%USERPROFILE%\.nsm\backups\`의 원하는 날짜 파일을 `%USERPROFILE%\.nsm\data.duckdb`로 복사(덮어쓰기)합니다(기본이 아닌 프리셋은 `data-프리셋-날짜.duckdb`를 `presets\프리셋\data.duckdb`로). 같은 폴더에 `data.duckdb.wal`이 있으면 지웁니다. 다시 켜면 그날 새벽 상태로 돌아갑니다. 지금 바로 백업하려면 대시보드 "지금 실행"의 "백업·정리" |
| "인스타그램 요청 제한" 알림 | 로그인 문제가 아님. 요청이 많아 인스타그램이 잠시 막은 것으로, 알림에 적힌 시각까지 쉬었다가 자동으로 다시 시작(5절 "요청 제한에 걸리면") |
| 원고가 한 이야기로만 나옴(예: 극장판만) | 설정의 **수집 제외어**에 그 낱말을 넣고, 원하는 이야기는 "오늘"의 **키워드로 원고 만들기**로 바로 만드세요. 자동 수집은 관심 주제마다 몇 건씩만 모으고 주제를 돌아가며 써서, 기사가 많은 쪽으로 쏠릴 수 있음 |
| "키워드 원고: 쓸 만한 자료가 없어 만들지 않음" | 그 키워드로 최근(설정의 자료 검색 기간) 정보 글이 없거나, 후기·일기·제외어 글뿐이었음. 키워드를 넓히거나(예: "치이카와 굿즈") 자료 검색 기간을 늘려 보세요 |
| 이미지를 올렸더니 "읽을 정보를 찾지 못해 올리지 않았습니다" | 글자나 정보가 없는 사진입니다. 공지 캡처나 포스터처럼 글자가 보이는 이미지를 올리세요. 글자가 너무 작으면 그 부분을 크게 캡처해서 올리세요 |
| 이미지를 올렸더니 "Claude API 키가 필요합니다" | 이미지는 Claude가 읽습니다. 별도 PowerShell에서 `uv run nsm init`을 실행해 Claude API 키를 넣고, `nsm run`을 껐다 켜세요 |
| 이미지를 올렸더니 "Claude 호출 실패" | 키가 만료됐거나 인터넷이 끊겼습니다. 연결을 확인하고 다시 올리세요. 키를 바꿨다면 `nsm run`을 껐다 켜세요 |
| 인스타그램 게시 실패 "자르기 단계가 나오지 않음" | 인스타그램이 업로드 창 앞에 "알림 설정" 같은 안내 창을 띄운 경우. 2026-10-18 버전(C21)부터 자동으로 닫음. 이 메시지가 계속 나오면 프로그램을 최신으로 받고 `nsm run`을 다시 켜세요. 그래도 나오면 Aside 브라우저에서 인스타그램을 열어 새 안내 창이 떴는지 보고 알려 주세요(화면이 바뀐 것) |
| 고친 게 적용이 안 된 것 같음 | 화면 맨 아래 버전 번호(예: v0.4.3)를 보세요. 머지된 버전보다 낮으면 아직 예전 코드로 켜져 있는 것이니 `nsm run`을 껐다 켜세요 |
| 알림 "분류기 대체" | 고른 분류기(보통 Gemini)가 실패해 다음 분류기로 넘어갔다는 뜻. 30분 뒤 Gemini를 다시 시도하고, 알림은 6시간에 한 번만 옵니다. 계속 오면 Gemini 무료 한도(하루 약 1,500회)나 키 문제를 확인하세요. 낱말 규칙까지 내려갔으면 자료 판정이 거칠어지니 키를 점검하세요 |
| 자료 모으기가 계속 "관련 자료 0개" | 관심 주제가 너무 넓거나 좁은지, 브랜드 이름·업종이 주제와 맞는지(설정 화면) 확인. 그래도 며칠째 0이면 수집하는 사이트 화면이 바뀌었을 수 있음([known-gaps.md](known-gaps.md) 2절) |
| `--once`가 "파일을 열 수 없음"으로 실패 | `nsm run`이 이미 켜져 있음. 대시보드의 지금 실행을 쓰기 |
| Windows 알림이 안 뜸 | 설정 화면의 "Windows 알림 받기"가 켜져 있는지, "테스트 알림 보내기"를 눌러 확인. 그래도 안 뜨면 Windows 설정 → 시스템 → 알림에서 알림과 "방해 금지"를 확인하고, 알림 목록에 "논슬립 마케터"가 꺼져 있지 않은지 확인. 실패하면 로그(`%USERPROFILE%\.nsm\logs\nsm.log`)에 "데스크톱 알림 실패"가 남음 |
| PC를 켤 때 자동으로 실행되게 | `uv run nsm install-autostart` (해제: `nsm uninstall-autostart`). 로그는 `%USERPROFILE%\.nsm\logs\` |

## 8. 표기 의무와 콘텐츠 정책

### 자동으로 붙는 표기 (끌 수 없음)

| 어디에 | 무엇이 |
|---|---|
| 인스타그램 캡션·스레드 글의 첫 줄 | `인공지능(AI)을 기반으로 생성된 가상인물이 포함된 게시물입니다` |
| 카드 이미지 표지와 마지막 장 | 페르소나 이름 바로 옆 "가상인물" 배지. 중간 장에는 이름(인물)도 배지도 넣지 않음(가상인물이 나오는 장에만 표시, ADR 0043) |
| AI 배경을 쓴 카드 | "AI 생성 이미지" 작은 캡션 |
| 협찬 표기를 켠 경우 | 첫 줄 맨 앞에 `#광고`, 표지 카드에 "광고" 배지 |

협찬 여부는 대시보드 **설정**의 "모든 게시물에 광고 표기", 설정 마법사의 "협찬(광고) 게시물로 표기할까요?", 또는 config.yaml의 `persona.ad_label`로 정합니다.

### 원고 품질 규칙 (자동 검사)

사람이 눈으로 볼 항목(말투, 출처, 표기 위치, 한글 깨짐, 스레드 썸네일)은 [품질 체크리스트](quality-checklist.md)에 대시보드 어디서 보는지와 함께 적어 두었습니다. 릴리스 전 회귀 테스트 명령도 그 문서 끝에 있습니다.


- 네이버 블로그·뉴스는 **최신순으로 최근 1주**(설정 화면 "자료 검색 기간")만 찾습니다. 몇 주 전 "출시 예정" 글로 이미 지난 일을 앞으로의 일처럼 쓰지 않게 하기 위해서입니다.
- 관련 자료로 판정된 글은 원문 본문(최대 3,000자)까지 읽고 씁니다. 방문 후기·여행기·일기는 자료로 쓰지 않습니다.
- 원고를 쓸 때 오늘 날짜와 자료를 모은 날짜를 함께 알려 줍니다. 그 사이 지났을 수 있는 "예정·아직 공지 전" 내용과 소문·추측·예상 가격은 쓰지 않습니다. 글에 "소문", "이야기가 돌아요", "예상 가격" 같은 말이 있으면 한 번 다시 만들고, 그래도 있으면 검토로 보냅니다(사유: "확인되지 않은 내용").
- 인스타그램 캡션과 스레드 글 끝에 `출처: 네이버 블로그`처럼 출처 줄이 붙습니다.
- 말투 설정에 "이모지는 한 개까지"처럼 적으면 그 개수를 셉니다. 넘거나 "자료에 따르면" 같은 딱딱한 표현이 있으면 한 번 다시 만들고, 그래도 어기면 검토 대기열로 보냅니다(사유: "페르소나 규칙 위반").
- 카드 목록 앞의 번호·기호는 자동으로 뗍니다(카드가 점을 붙입니다).
- **재료가 빈약하면 쓰지 않습니다**(C31): 본문이 800자 미만인 자료, 분류기가 "구체 사실 없음"으로 판정한 자료는 원고 재료에서 뺍니다. 2026-10-22 "달력 어디서 살까요? → 검색해 보세요" 원고가 247자 요약문 하나로 쓰였던 일에서.
- **이미 올린 소식은 다시 쓰지 않습니다**: 최근 14일 게시물의 제목·사실 주장과 같은 사건으로 보이는 자료(제목 낱말 겹침, 그다음 분류기에게 "같은 소식인가" 확인)는 제외합니다. 같은 주제라도 새 사실(새 행사·새 날짜)이면 씁니다.
- **한 소재에 쏠리지 않게**: 관심 주제마다 최근 7일 원고가 2건이면 다른 주제를 먼저 씁니다. 관심 주제를 소재 종류(극장판·굿즈·팝업·콜라보·캐릭터)로 나눠 두면 이 규칙이 제대로 돕니다.
- **비교형은 자료가 둘 이상일 때만** 만듭니다. 하나뿐이면 정보형으로.
- 원고에 구체 사실(날짜·수량·가격·장소·이름)이 2개 미만이면 자동 승인하지 않고 검토로 보냅니다(이유: "구체 사실 부족"). "검색해 보세요", "판매자마다 달라요" 같은 일반론 문구가 있으면 한 번 다시 만들고, 그래도 있으면 검토로.

### 무엇이 자동 게시되고 무엇이 검토로 가나

아래 중 하나라도 해당하면 자동으로 올리지 않고 대시보드의 검토 대기열로 갑니다. 대기열에서는 사유가 함께 보입니다.

1. **자동 게시가 꺼져 있음**: 설치 직후 기본값입니다.
2. **보호 모드**: 자동 게시를 켜도 내가 직접 승인한 콘텐츠가 `protect_count`(기본 20건)가 될 때까지는 모두 검토합니다.
3. **출처가 확인되지 않는 주장**: 글의 사실 주장마다 근거 자료가 연결돼야 합니다. 이번에 쓴 자료가 아닌 것을 근거로 대면 검토로 갑니다.
4. **관련성 부족**: 실제로 인용한 자료의 관련성이 0.8 미만.
5. **금칙어·금칙 패턴**: 내가 정한 금칙어, 그리고 "써봤는데", "내돈내산" 같은 가상인물의 체험 표현.

### 게시 규칙

- 활동 시간 안, 그리고 게시 시간(`posting_hours`, 정했을 때만) 안에서만, 플랫폼별 하루 쿼터(기본 인스타 1, 스레드 2) 안에서만 올립니다.
- 같은 플랫폼에 연달아 올리지 않도록 최소 3시간 간격을 둡니다(`min_hours_between_posts`). 대시보드에서 "게시하기"를 직접 누르면 이 간격은 무시하고 바로 올립니다. 하루 게시 수와 게시 시간은 그대로 지킵니다.
- 게시에 실패하면 15분, 1시간, 4시간 뒤 다시 시도하고, 그래도 실패하면 알림을 보내고 검토 대기열로 돌립니다.
- 답글을 보내는 도중 프로그램이 죽어도 같습니다. 다시 켜면 그 댓글이 "답글을 보내는 중 프로그램이 중단됨"으로 댓글 화면에 오니, 플랫폼에서 달렸는지 보고 직접 답글 또는 처리 완료를 누르세요.
- 게시 도중 PC가 꺼지거나 프로그램이 죽으면, 실제로 올라갔는지 알 수 없으므로 자동으로 다시 올리지 않습니다. 검토 대기열에 "중단됨, 플랫폼 확인 필요"로 표시되니 플랫폼에서 확인한 뒤 다시 승인하세요.

### 드라이런 결과 보기

드라이런에서는 `%USERPROFILE%\.nsm\preview\날짜\콘텐츠ID\플랫폼\`에 카드 PNG와 원고(`post.txt`, 블로그는 `post.md`)가 저장됩니다. 가짜 댓글·답글·숨김 기록은 `preview\actions.log`에 남습니다.
