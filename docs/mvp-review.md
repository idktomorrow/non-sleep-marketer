# 논슬립 마케터 MVP 냉정 평가 (2026-10-11)

> 대상: [PRD](PRD.md), [기획 결정 기록](planning-decisions.md) · 이 문서의 결론은 PRD와 [contracts.md](contracts.md), [issues.md](issues.md)에 이미 반영했습니다.
> 결정 4건(DB·대시보드 구조, 게시 기본 구현, 후기형 처리, 이슈 등록)은 2026-10-11 사용자가 확정했습니다.

## 한 줄 총평

문제 정의와 범위 설정(드라이런 먼저, 세 플랫폼, 사람 검토 대기열)은 좋습니다. 그러나 **그대로 구현하면 돌아가지 않는 결함 1개**(DuckDB 다중 프로세스), **법적 위험 1개**(후기형 카드뉴스), **운영 설계 공백 여러 개**(사이클 구조, 쿼터·비용 상한, 중복, 멱등성, 재부팅)가 있었습니다. 또 2명이 동시에 작업하려면 "계약"이 먼저 있어야 하는데 PRD에는 인터페이스 정의가 없었습니다. 모두 고쳤습니다.

## 평가 결과 (심각도순)

| # | 심각도 | 발견 | 조치 |
|---|---|---|---|
| 1 | 치명 | **DuckDB는 한 프로세스만 읽기/쓰기로 열 수 있음.** 엔진 프로세스가 열어둔 동안 별도 Streamlit 프로세스는 읽지도 못함. 지금 구조는 실행 즉시 막힘. | 엔진·스케줄러·대시보드 웹서버를 **단일 프로세스**로 합치고 대시보드를 **FastAPI + Jinja2/HTMX**로 변경. DuckDB는 유지(무료, 로컬). Streamlit 제거. UI/UX 디자인 자유도도 함께 확보. |
| 2 | 법적 | **후기형 카드뉴스.** 공정위 개정 심사지침(2026-06-01 시행, 계도기간 없음)은 가상인물 표시를 해도 "실제 사용 경험에 기반한 추천처럼 표현"하면 부당 광고로 봄. AI 페르소나가 직접 후기를 쓰는 형태가 정확히 이에 해당. | 후기형 삭제, **비교형**으로 대체(정보형·리스트형·비교형). 페르소나의 1인칭 체험 표현("써봤는데", "제가 먹어보니")은 금칙 패턴으로 차단. |
| 3 | 높음 | **표기 문구가 불명확.** "AI 가상인물"이라는 단일 표기만 있었음. 지침은 문자 매체(블로그 등)는 제목/첫 부분에 "AI를 기반으로 생성된 가상인물이 포함된 게시물입니다" 또는 "가상인물 포함", 사진은 인물 인근에 "가상인물" 표시를 예시로 제시. AI 기본법 31조의 생성물 표시는 별개 의무. | 표기 규칙을 **문자(캡션/본문 첫 줄)·이미지(슬라이드 배지)·광고** 세 층으로 명문화. 템플릿에 표기 슬롯을 필수 계약으로 넣음. 시행령·지침 원문은 1차 검수 전에 재확인(이슈 M2). |
| 4 | 높음 | **"1사이클"이 단일 루프.** 댓글은 몇 분마다, 수집은 하루 1~2회, 게시는 하루 1~2회가 적정한데 한 사이클에 모두 묶여 있어 과수집·과생성·비용 폭증 또는 댓글 지연 중 하나가 발생. | 엔진을 **주기가 다른 6개 잡**(collect / generate / publish / reply / metrics / health, 주 1회 weekly_report)으로 분리. 테스트 경계는 "잡 1회 실행"으로 유지. |
| 5 | 높음 | **쿼터·비용 상한 없음.** 하루 게시 수, LLM·이미지 비용 상한이 없어 버그 하나로 계정 도배나 과금 가능. | 플랫폼별 일일 게시 쿼터(기본 IG 1, Threads 2, 블로그 1), 일일 비용 상한(기본 $3) 초과 시 생성 중단 + 알림. |
| 6 | 높음 | **자동 게시 기준이 뒤섞임.** "신뢰도 0.8"은 jev의 *관련성 분류* 신뢰도이지 내용의 사실성이 아님. 또 "모든 문장에 출처"는 의견·연결 문장까지 출처를 요구해 자동 게시가 사실상 불가능하거나 LLM이 가짜 출처를 붙이게 유도. | 생성기가 **구조화 출력**(claims[] 각각 source_item_id)을 내고, 정책은 "사실 주장(claim)마다 DB에 존재하는 출처가 연결됨"을 검사. 관련성 신뢰도 0.8은 *자료 선별* 기준으로 명확화. **보호 모드** 추가: 설치 후 첫 20건은 무조건 검토 대기열, 사용자가 대시보드에서 자동 게시를 켜야 해제. |
| 7 | 중간 | **멱등성·재시도 미정의.** 게시 중 크래시하면 재시작 후 같은 글이 두 번 올라갈 수 있음. 재시도 횟수·간격도 없음. | 상태 `publishing`을 어댑터 호출 전에 기록. 재시작 시 `publishing` 상태 콘텐츠는 자동 재시도하지 않고 "확인 필요"로 검토 대기열 이동. 실패 재시도 3회(15분·1시간·4시간), 이후 `abandoned`. |
| 8 | 중간 | **중복 방지 없음.** 같은 URL을 매번 재수집하고, 지난주 다룬 주제를 또 생성. | 자료는 URL 정규화 해시로 중복 제거, 주제는 최근 14일 게시 주제와 겹치면 제외. |
| 9 | 중간 | **Aside 무인 동작 근거 약함.** YC 소개·도움말에 "게시·결제·메시지는 승인 대기"가 명시. Allow 규칙으로 우회 가능할 수도 있으나 문서상 미확인. 윈도우판은 2026-09-14 출시 확인. | 결정: **계획대로 Aside 기본, 1일차 검증 실패 시 Playwright 저장 프로필**. 어댑터를 "플랫폼 로직"과 "브라우저 드라이버(Aside/Playwright)"로 한 번 더 분리해 교체 비용 최소화. 1일차 검증 절차를 구체화(이슈 M2). |
| 10 | 중간 | **jev 권한 가정이 틀림.** jev는 "초대"가 아니라 MotherDuck 계정으로 씀. 현재 가격표 기준 Lite 플랜 $0, AI 함수 포함(하루 10 AI Unit 소프트 한도), EU 리전 제외, 프리뷰 상태. TypeSafe 직접 가입은 2026-09-22부터 중단. | 1일차 검증을 "MotherDuck Lite 가입 → `prompt_jev` 1회 호출"로 교체. Claude 분류기는 대안이 아니라 **동등한 1급 구현**(같은 포트)으로 둠. |
| 11 | 중간 | **댓글 숨김 기능이 플랫폼 웹에 있다는 보장 없음.** 인스타그램·스레드 웹의 "숨기기" 메뉴는 조사에서 확인 못 함(앱은 있음). 네이버 블로그는 삭제·비공개만. | 어댑터에 **capability 선언** 추가. `hide_comment` 미지원 플랫폼은 스팸 댓글을 "스팸 추정"으로 사람에게 넘김. 1일차에 수동 확인. |
| 12 | 중간 | **지표 가용성 미확인.** 인스타그램 인사이트(도달·노출·저장·공유)는 **프로 계정**에서만 보임. 플랫폼마다 제공 지표가 다름. | 플랫폼별 지표 매트릭스를 계약에 명시. 설정 마법사에서 인스타그램 프로 계정 전환 안내. |
| 13 | 중간 | **재부팅·시크릿·알림 구현 방식 미정.** | Windows 작업 스케줄러 등록 명령(`nsm install-autostart`), `keyring`(Windows 자격 증명 관리자), `winotify` 알림으로 확정. |
| 14 | 낮음 | **PC 재부팅 후 로그인 만료 감지** 조건이 없었음. | health 잡이 30분마다 각 어댑터 `health()` 호출, 로그아웃 감지 시 알림 + 해당 플랫폼 게시·답글 중단. |
| 15 | 낮음 | **병렬 작업 계약 부재.** 역할만 "A/B"로 나뉘고 인터페이스·데이터 계약·디렉터리 소유권이 없어 2명이 동시에 못 움직임. 테스트·템플릿 담당 팀원이 1일차에 할 일이 없음. | [contracts.md](contracts.md)에 포트 시그니처, 도메인 모델, DB 테이블, 카드 덱 JSON 계약, 픽스처 규격, 디렉터리 소유권을 명시. 팀원은 1일차부터 템플릿·테스트 기반 착수 가능. |

## 유지한 결정 (재론하지 않음)

- 공식 API 대신 브라우저 자동화(Aside, 대안 Playwright). 계정 제재 위험은 사용자가 인지·감수.
- 인스타그램·스레드·네이버 블로그 세 플랫폼 MVP 포함.
- 드라이런 MVP 1주 → 실계정 2주차.
- 사용자별 로컬 설치, 서버 없음.

## 남은 위험 (해결 아님, 인지 필요)

- **네이버 블로그 글쓰기 자동화**가 세 어댑터 중 가장 어렵습니다(스마트에디터 ONE, 이미지 업로드). 2주차 어댑터 순서를 스레드 → 인스타그램 → 네이버로 잡았습니다.
- **Aside 크레딧**: 무료 월 500크레딧이고 작업당 소모량이 일정하지 않습니다. 하루 수십 번 브라우저 작업을 하면 유료 전환이 필요할 수 있습니다. Playwright 대안은 크레딧이 없습니다.
- **법규 원문 미확인**: 공정위 지침·AI 기본법 시행령은 언론 보도와 로펌 뉴스레터로만 확인했습니다. 첫 실제 게시 전 원문 대조가 필요합니다(이슈 M2에 포함).
- **2주 일정**: 메인 담당 범위가 15개 이슈입니다. 2주차 실계정 어댑터 3종이 가장 큰 변수이며, 네이버는 3주차로 밀릴 수 있습니다.
