# 0060. 로그인 안 됨을 세부 상태로 나누되, 확인 창은 자동으로 풀지 않는다

- 상태: 제안
- 날짜: 2026-11-03
- 결정한 사람: 선웅제(배치 E5 요청), 세부 기본값은 Claude가 배치 중 골랐다
- 관련: incidents/0010, ADR 0054(오류 종류 표)·개정 1(멈춤 이유), ADR 0038(요청 제한)

## 배경

health와 댓글 확인·게시 전 확인은 내 프로필 링크가 안 보이면 "로그인돼 있지 않음" 한 가지로만 보고했다.

- 2026-10-29~11-01 인스타그램은 로그아웃이 아니라 본인 확인(captcha)과 문자 인증을 요구했다(incidents/0010). 사람은 화면과 알림만 보고 로그아웃인 줄 알았다.
- 2026-11-02 스레드는 글 페이지가 하얗게 덜 열린 것을 로그인 풀림으로 보고했다.

상태마다 사람이 할 일이 다르다(다시 로그인 / 확인 창 끝내기 / 코드 넣기 / 앱에서 계정 확인).

## 선택지

1. **문구로 나눠 알리기만**: 화면을 보고 상태를 나눠 알리고, 푸는 것은 사람이 한다.
2. **확인 창을 자동으로 넘기기**: "계속"을 누르거나 문자 코드를 읽어 넣는다. 빨리 풀릴 수 있다. 하지만 보안 확인은 자동화를 막으려는 장치라, 자동으로 넘기면 계정 정지 위험이 커지고 플랫폼 약관에도 어긋난다. 문자 코드는 사람의 휴대폰에 온다.
3. **주소만으로 나누기**: 간단하다. 하지만 인스타그램은 본인 확인과 문자 인증도 `/accounts/suspended/` 주소로 띄워, 주소만 보면 "계정 정지"로 잘못 말한다(증거 3건).

## 결정

1을 고른다. 가장 중요한 이유: 보안 확인은 사람이 하라고 만든 것이고, 자동으로 넘기면 계정 자체를 잃을 수 있다.

**상태 목록**(`nsm/adapters/platforms/auth_state.py`):

| 상태 | 뜻 | 사람이 할 일 | 자동 재개 |
|---|---|---|---|
| `logged_out` | 로그인 폼 | Aside 브라우저에서 다시 로그인 | 다음 점검(30분 이내) |
| `challenge` | 본인 확인·captcha("사람임을 확인하세요") | Aside 브라우저에서 직접 확인 | 확인 끝나면 다음 점검 |
| `verify` | 문자·이메일 코드("휴대폰 번호를 입력 / 코드 보내기") | 인증 마치기 | 다음 점검 |
| `two_factor` | 두 단계 인증 코드 | 코드 넣기 | 다음 점검 |
| `restricted` | 계정 제한·정지 안내 문구 | 플랫폼 앱에서 계정 상태 확인 | 풀리면 다음 점검 |
| `unknown` | 로그인 안 됨, 원인을 화면으로 모름 | 화면을 보고 판단 | 다음 점검 |

- **판정 순서**: 화면 글·라벨 → 주소 → 로그인 폼 문구 → unknown. 문구를 먼저 보는 이유는 위 3의 주소 함정이다. `restricted`는 정지·비활성화 안내 문구가 있을 때만 쓴다.
- **빈 화면은 로그인 문제가 아니다.** 셋을 모두 만족할 때만 일시적 실패(`transient`)로 본다: 로그인·확인 주소가 아니고, 보이는 글이 없고, 라벨도 없다. 로그인 폼은 글이 있으므로 진짜 로그아웃을 삼키지 않는다.
- **패턴은 한 곳(`data/auth_states.json`)에 모은다.** 플랫폼은 문구를 자주 바꾸고, 바뀌면 unknown으로 보인다. 그때 증거 폴더의 화면 글을 보고 JSON만 고치면 된다. 코드·테스트를 뒤지지 않게 한다.
- **포트는 그대로 둔다.** `HealthStatus`는 동결이다. 상태는 어댑터의 `auth_state` 속성(health)과 `LoginRequiredError.auth_state`(댓글·게시)에 두고, 엔진은 `getattr`으로 읽는다(E1의 `kind`, ADR 0038의 `retry_at`과 같은 방식). 상태를 detail 문자열 앞에 붙이지 않는다.
- **멈춤 정보**(`paused_platforms_info`)에 `auth_state`와 `notified_at`을 더한다.
  - 멈춘 플랫폼도 점검은 한다. 실패 횟수와 실패 기록은 다시 쌓지 않는다.
  - 상태가 바뀌면(예: challenge → verify) 멈춤 정보를 고치고 바로 알린다.
  - 같은 상태면 `notified_at`부터 24시간마다 한 번 "(계속)" 알림을 보낸다.
  - 멈춘 플랫폼의 일시적 실패는 멈춤 이유를 바꾸지 않는다.
- **증거**: 보안 확인·두 단계 인증·제한이면 health가 예외 없이도 화면을 남긴다(E1 쿨다운 1시간 그대로). 그냥 로그아웃은 남기지 않는다.
- **계정을 더 건드리지 않는다.** health 스크립트는 홈 하나만 열고, 로그인 페이지를 새로 열거나 무엇을 누르지 않는다(테스트로 고정). 지표 잡은 멈춘 플랫폼을 건너뛴다.

## 결과

- 쉬워진 것:
  - 알림만 보고 할 일을 안다.
  - 멈춘 동안 상태가 바뀌어도 따라간다.
  - 증거가 health에서도 남는다.
- 어려워진 것: 문구 패턴은 플랫폼이 바꾸면 낡는다. unknown이 늘면 JSON을 고친다.
- 다시 볼 조건:
  - unknown이 자주 보이면 패턴을 늘린다.
  - 보안 확인이 풀린 뒤 며칠 안에 되풀이되면, 자동화 감지를 줄이도록 인스타그램 활동 간격을 다시 본다(incidents/0010).
