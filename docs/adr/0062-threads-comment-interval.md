# 0062. 스레드 댓글은 15분마다 최근 7일 글만 보고, 글이 안 열리면 빈 결과가 아니라 오류로 다룬다

- 상태: 제안
- 날짜: 2026-11-04
- 결정한 사람: 선웅제(배치 C37 요청), 세부 기본값은 Claude가 배치 중 골랐다
- 관련: incidents/0011, ADR 0038(인스타그램 댓글 간격), ADR 0054(오류 종류 표), ADR 0060(빈 화면)
- 번호: 배치 요청은 0061이었으나 0061은 C36(미래 일정 시제)이 먼저 써서 0062로 했다.

## 배경

2026-11-04 06:42부터 스레드 글 페이지가 본문 없이 열렸다("문제가 발생했습니다" + "다시 시도"). 댓글 확인은 글마다 20초를 기다린 뒤 빈 목록을 성공으로 돌려줬다. 13시간 동안 댓글을 못 읽었는데 화면은 "정상"이었다(incidents/0011).

그때 스레드는 잡이 돌 때마다(5분) 최근 14일 글을 모두 열었다. 11-03 기준으로 하루 260회 × 36개, 약 9,360번이다. 인스타그램은 2026-10-14 요청 제한 뒤로 30분마다 최근 3일만 본다(ADR 0038).

## 선택지

1. **간격·일수는 그대로, 오류만 드러내기**: 장애는 보이지만, 하루 9천 번 넘게 여는 것은 그대로다. 플랫폼이 자동화로 의심할 여지도 그대로다.
2. **스레드 간격 15분·최근 7일 + 오류 드러내기 + 연속 실패 시 30분 쉬기**: 덜 열고, 안 열리면 알고, 계속 안 열리면 덜 두드린다.
3. **스레드도 인스타그램처럼 30분·3일**: 가장 덜 연다. 하지만 스레드 답글이 최대 30분 늦어진다. 스레드는 요청 제한을 받은 적이 없어 지금은 과하다.

## 결정

2를 고른다. 가장 중요한 이유: 댓글 확인 한 번에 여는 글 수가 확인 간격보다 부담을 더 키운다. 7일 넘은 글의 새 댓글은 드물고, 답이 15분 늦는 것은 받아들일 만하다.

**하루 글 페이지 열기 횟수**

| | 간격 | 볼 글 | 하루 확인(최대) | 하루 페이지 열기 |
|---|---|---|---|---|
| 전(스레드) | 5분(잡마다) | 최근 14일, 36개 | 288회(11-03 실제 260회) | 약 9,360번(실제 260 × 36) |
| 후(스레드) | 15분 | 최근 7일, 10개 | 96회 | 최대 960번(96 × 10) |
| 인스타그램(그대로) | 30분 | 최근 3일, 6개 | 48회 | 최대 288번 |

글 수는 11-04 새벽 백업 복사본의 게시 기록으로 셌다. 글이 늘면 함께 는다.

**바뀐 설정**
- `threads_comment_interval_minutes`: 새로 둔다. 기본 15, 5~180.
- `comment_lookback_days`: 기본을 14에서 7로 낮추고 범위를 1~30으로 둔다.
- 둘 다 설정 화면 "고급"에 보인다. 기존 설정 파일에 이 값이 없으면 새 기본값이 적용된다(pydantic 기본값). 값이 적혀 있으면 그대로다.
- **주의**: 설정 화면에서 저장하면 기본값까지 모두 파일에 쓰여서, 그런 사용자는 파일에 `comment_lookback_days: 14`가 남아 있다(운영 설정 파일도 그렇다). 사람이 일부러 고른 14와 구분할 수 없어 자동으로 바꾸지 않는다. 설명서와 배치 보고에 "설정 화면에서 7로"를 적었다.

**오류로 다루기**
- 플랫폼 오류 화면(안내문과 "다시 시도" 버튼이 **같은 칸**에)은 일시적 `page` 오류다. 페이지 다른 곳의 문구와 버튼을 엮지 않는다.
- 반드시 있어야 하는 요소를 기다린 결과가 비면 `nsmEnsure`로 던진다. 글 본문이 그 예다.
- 오류 화면 감지는 로그인 확인보다 먼저 본다. 그래서 E5의 빈 화면 판정보다 앞선다.

**연속 실패 시 쉬기**
- 글 하나가 안 열리면 그 글만 건너뛴다(지운 글 하나가 조회 전체를 7일 막지 않게). 묶음의 모든 글이 안 열릴 때만 실패다.
- 같은 플랫폼 댓글 조회가 **글이 안 열려서**(오류 코드 `page`) 연속 2번 실패하면 그 플랫폼 댓글 확인만 30분 쉰다. Aside 꺼짐 같은 다른 일시적 실패는 세지 않고, 끼면 연속이 끊긴다. 장애 화면 기록의 조치도 "댓글 확인 30분 쉬기(연속 실패)"로 남는다.
- 횟수는 설정 키 `comment_fetch_failures` 하나에 두고, 성공하면 지운다.
- 알림은 연속 구간에 한 번이다. 게시는 멈추지 않는다(게시는 다른 페이지를 열고, 글이 안 올라가면 게시 잡이 따로 재시도한다).

**소요 시간 경고**
- 댓글 확인이 잡 간격의 2배를 넘게 걸리면 실행 기록과 장애 화면 실패 목록에 남긴다.
- 알림은 보내지 않는다. 느린 것만으로 사람을 깨울 일은 아니다.

## 결과

- 쉬워진 것: 글이 안 열리면 첫 확인부터 오류로 보인다. 계속 안 열리면 30분씩 쉬며 덜 두드린다. 평소에 여는 페이지가 약 10분의 1이 된다.
- 어려워진 것: 스레드 답글이 최대 15분 늦다. 7일 넘은 글의 새 댓글은 놓친다(필요하면 설정에서 늘린다).
- 다시 볼 조건:
  - 스레드도 요청 제한을 받으면 간격을 더 늘린다.
  - 오류 안내문 문구가 바뀌면 `nsmCheckPage`의 문구를 고친다(그 사이에도 본문 시간 초과로 오류는 난다).
