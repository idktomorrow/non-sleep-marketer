# 0037. 원고별 카드 스타일은 덱 JSON에 `style` 필드를 더하는 계약 변경으로 2차에 한다

- 상태: 제안 (2차 작업 전 두 사람 합의 필요)
- 날짜: 2026-10-14
- 결정한 사람: 배치 S8 기본값(초안). 계약 변경은 메인·서브 합의 PR로
- 관련: 이슈 #34, [ADR 0036](0036-code-drawn-card-styles.md), [ADR 0024](0024-card-editor-scope.md), [contracts.md](../contracts.md) 5절(카드 덱 JSON 동결)

## 배경

S8 1차는 설정 `brand.card_style` 하나로 모든 원고의 스타일을 정한다. 원고마다 다른 스타일을 쓰고 싶을 수 있다. 예를 들어 소식은 photo, 정리 글은 illust로 나눌 수 있다. ADR 0024도 카드 편집 화면의 스타일 선택 칸을 S8 뒤로 미뤘다.

원고별 스타일은 원고(덱)에 값이 있어야 한다. 그런데 카드 덱 JSON은 동결 계약이다. 생성기·저장소·렌더러·편집 화면·테스트 픽스처가 모두 이 모양을 쓴다.

## 선택지

1. **덱 JSON에 `style: "clean" | "photo" | "illust" | null` 추가**: 원고와 스타일이 함께 저장되고 렌더 캐시 지문에도 자연히 들어간다 / 동결 계약 변경이라 두 사람 합의 PR에서 모델·생성기·편집 화면·픽스처를 함께 고쳐야 한다.
2. **덱 밖 별도 테이블(content_id → style)**: 계약을 안 바꾼다 / 같은 원고 정보가 두 곳에 나뉘고, 렌더 캐시 지문·미리보기·게시가 모두 따로 조회해야 한다.
3. **하지 않음(전역 하나만)**: 단순하다 / 원고 성격에 맞춘 스타일을 못 고른다.

## 결정 (초안)

1번을 2차로 제안한다. 이번 S8에서는 계약을 바꾸지 않는다.

- 값이 `null`이거나 없으면 `brand.card_style`(전역)을 쓴다. 지금 저장된 원고는 그대로 읽힌다.
- 생성기(Claude)는 스타일을 고르지 않는다. 사람이 검토 화면에서 고른다. 생성 비용과 프롬프트를 늘리지 않기 위해서다.
- 카드 편집 화면(ADR 0024)에 스타일 선택 칸을 한 줄 더한다. 바꾸면 미리보기 렌더로 바로 확인한다.
- 렌더러는 `deck.style or brand.card_style`로 고른다. 포트 `render(deck, out_dir)`는 그대로 둔다.

## 결과

- 합의되면 PR 하나에서 함께 고친다.
  - `nsm/domain/models.py`의 `CardDeck`
  - 덱 JSON 계약 문서(contracts.md 5절)와 `tests/fixtures/decks/`
  - 생성기 출력 검사
  - 편집 화면과 라우트 테스트
  - 렌더러의 스타일 선택과 테스트
- 다시 볼 조건: 운영하면서 전역 스타일 하나로 부족하다는 요구가 실제로 생기면 진행한다. 그 전에는 1차(전역)로 충분하다.
