# 0054. 오류 종류 표 하나로 실패를 다루고, 실패 순간 증거를 남긴다. 코드가 스스로 고치지는 않는다

- 상태: 제안 (배치 E1. 선웅제 요청: 흩어진 오류 처리를 표로 묶고 증거를 자동 저장, 기존 동작은 바꾸지 않되 화면 변경은 재시도하지 않음)
- 날짜: 2026-10-27
- 관련: [ADR 0038](0038-instagram-rate-limit-rest.md)(요청 제한 쉬기), [ADR 0048](0048-gemini-classifier-replaces-jev.md)(분류기 대체), devlog C23(확인 못 한 답글은 사람에게)·C24(중단 복구)·C27·C33

## 배경

실패 처리가 여러 곳에 if문으로 흩어져 있었다: 게시는 `retry_at`이면 쉬고 아니면 15·60·240분 재시도 뒤 포기, 답글은 요청 제한이면 'new'로 되돌리고 아니면 사람에게, health는 요청 제한이면 쉬고 아니면 멈춤. 실패 원인도 오류 문구로만 알 수 있어서, "게시 버튼 없음"(인스타그램 화면이 바뀜) 같은 실패를 15분·60분·240분 세 번 더 시도한 뒤에야 사람에게 왔다. 다시 해도 같은 결과인데 네 시간 반을 쓴 셈이다. 그리고 실패한 순간의 화면이 남지 않아, 무엇이 바뀌었는지는 사람이 다시 재현해 봐야 알았다(C21 알림 대화상자, C22·C25 답글 대상).

## 선택지

1. 그대로 두고 문구로 판단 → 새 실패마다 if문이 늘고, 같은 오류를 곳마다 다르게 처리할 수 있다.
2. **오류 종류 5개와 종류별 정책을 한 표로(채택)**. 엔진은 `policy_for(e)`만 읽는다.
3. 표에 더해 "자가 치유"(화면이 바뀌면 다른 버튼을 찾아 눌러 보기, 셀렉터를 스스로 고치기) → 기각(아래).

## 결정

- `nsm/domain/errors.py`: `ErrorKind` 5종과 `ErrorPolicy` 표. 엔진(게시·답글·health)은 이 표를 읽는다.
- 포트는 동결이라 `AdapterError`는 그대로 두고, 어댑터가 던지는 하위 클래스 `PlatformError`(`aside_common.py`)에 `kind` 속성을 붙인다. 엔진은 클래스를 가져오지 않고 속성으로 읽는다(ADR 0038의 `retry_at`과 같은 방식). 종류가 없는 예외는 외부 실패면 `transient`, 그 밖의 파이썬 예외는 `config_or_bug`로 본다.
- Aside 스크립트 오류 코드 → 종류: 스크립트가 직접 던진 "버튼·메뉴·대화상자를 못 찾음"은 `ui` 코드(인스타그램·스레드 스크립트의 25곳) → `ui_changed`. 라벨 없는 예외(`script`: 탭이 닫힘, 실행 맥락 사라짐, net::ERR_…, 대기 시간 초과)와 `page`·`timeout`·`cli`·`interrupted` → `transient`(지금처럼 재시도). `login`·`mismatch` → `auth`, `ratelimit` → `rate_limited`. 파이썬 쪽 검사 실패(계정 미설정, 파일 경로, 댓글 ID) → `config_or_bug`.
- 표(지금 코드가 하던 대로, 화면 변경만 바뀜):

| 종류 | 예 | 재시도 | 플랫폼 멈춤 | 알림 | 사람에게 | 증거 |
|---|---|---|---|---|---|---|
| `transient` 일시적 | 네트워크 끊김, 페이지 안 열림, Aside 응답 시간 초과, 화면 대기 시간 초과, 탭이 닫힘 등 라벨 없는 브라우저 예외 | 설정 간격(15·60·240분) 뒤 다시, 다 쓰면 포기 | health 점검이 실패하면 멈춤 | 포기할 때 | 재시도를 다 쓰면 원고를 검토로. 답글은 그 댓글을 사람 확인으로 | 남김 |
| `rate_limited` 요청 제한 | HTTP 429 | 플랫폼이 정한 시각까지 쉬었다 다시(횟수 안 씀, ADR 0038) | 멈추지 않음(쉬기만) | 쉬는 구간마다 한 번 | 넘기지 않음 | 안 남김 |
| `auth` 로그인·권한 | 로그인 풀림, 로그인 계정 ≠ 설정 계정 | 설정 간격대로(게시는 지금과 같음) | health 점검이 멈춤("로그인 필요") | health가 멈출 때 | 바로: 다시 로그인. 로그인되면 health가 다시 켬 | 남김 |
| `ui_changed` 외부 화면 변경 | "게시 버튼 없음", "자르기 단계가 나오지 않음", "답글 달기 없음" | **다시 하지 않음**(해도 같다) | health 점검이 실패하면 멈춤 | **바로**(플랫폼마다 6시간에 한 번) | **바로**: 원고를 검토로 되돌리고 증거 폴더를 알림에 붙임 | 남김 |
| `config_or_bug` 설정 누락·프로그램 오류 | 게시 계정 미설정, 올릴 수 없는 파일, 댓글 ID 형식 오류, 카드 렌더 예외 | 설정 간격대로 | health 점검이 실패하면 멈춤 | 포기할 때 | 재시도를 다 쓰면 원고를 검토로 | 남김 |

- 증거: 어댑터가 실패를 던지는 순간 `<NSM_HOME>/logs/shots/<플랫폼>-<YYYYMMDD-HHMMSS>/`에 `screenshot.png`, `dialogs.json`(role=dialog 수, 보이는 글, svg title·aria-label, 주소), `log-tail.txt`(로그 마지막 50줄). 스크린샷은 Aside 스크립트가 탭을 닫기 전에 `catch` 안에서 찍는다. 쿠키·저장소는 읽지 않고, 글·주소·로그의 토큰·키·세션 값은 지운다. 오류 문구 끝에는 폴더 **이름**만 `(증거: threads-20261027-101500)`으로 붙는다(집 폴더 경로가 대시보드·알림에 드러나지 않게, 잘림 한도도 덜 먹게). 전체 경로는 `evidence_dir` 속성에 있고 "화면 변경" 알림에 함께 적는다. 같은 플랫폼·같은 종류의 증거는 한 시간에 한 번만 남긴다(30분마다 도는 health·댓글 묶음 반복으로 폴더가 쌓이지 않게). 증거 수집은 스크립트 안에서 시간 제한(글 읽기 3초, 화면 5초, 남은 시간이 6초 아래면 건너뜀)을 둬, 멈춘 페이지 때문에 원래 오류 코드(요청 제한·로그인)를 잃지 않게 한다. 결과 줄이 잘려 해석하지 못하면 형식 오류가 아니라 Aside 오류(`cli`)로 다룬다. 저장이 실패하면 경고만 남기고 원래 오류를 그대로 던진다. 요청 제한(쉬는 동안 매번 던짐)과 Ctrl+C 중단에는 남기지 않는다. `evidence_keep_days`(14일) 넘은 폴더는 새벽 정리 잡이 지운다.

## 자동으로 하는 것과 하지 않는 것

| 자동으로 함 | 하지 않음 |
|---|---|
| 정해진 간격으로 재시도 | 실패한 화면을 보고 다른 버튼을 찾아 눌러 보기 |
| 요청 제한이면 쉬었다 다시 | 셀렉터·문구를 스스로 바꿔 고치기 |
| 분류기가 실패하면 다음 분류기로 대체(C27) | 확인하지 못한 게시·답글을 다시 보내기 |
| 로그인이 풀리면 그 플랫폼 멈춤, 되면 다시 켬 | 화면 변경 뒤 계속 재시도하기 |
| 사람에게 넘기기(검토 대기열·사람 확인 댓글) + 증거 | |

경계를 여기 두는 이유: 게시와 답글은 되돌릴 수 없다. 화면이 바뀐 상태에서 코드가 스스로 "비슷한 버튼"을 누르면, 이미 올라간 글을 한 번 더 올리거나 엉뚱한 곳에 답글을 달 수 있다(C22·C25에서 실제로 답글이 새 댓글로 달렸다). **두 번 올리는 것보다 한 번 빠지는 쪽**(C23·C24)이 이 프로젝트의 원칙이라, 화면이 바뀌면 멈추고 사람에게 증거와 함께 넘긴다. 고치는 일은 사람이 증거를 보고 배치로 한다.

## 결과

- 화면 변경은 네 시간 반 재시도 대신 즉시 검토로 오고, 알림에 증거 폴더가 붙는다. 대기열의 원고가 차례로 실패해도 "화면 변경" 알림은 플랫폼마다 6시간에 한 번이다(게시 잡은 한 번에 플랫폼마다 한 건만 시도하므로 원고는 30분에 하나씩 검토로 돌아온다).
- 그 밖의 동작(재시도 간격, 429 쉬기, 로그인 멈춤, 답글을 사람에게)은 그대로다.
- 어려워진 것: 스크립트가 직접 "못 찾음"을 던진 경우만 화면 변경이다. 실제로는 화면 변경인데 대기 시간 초과로 드러나면 예전처럼 재시도 뒤 포기한다. 증거는 그때도 남는다.
- 증거 폴더는 한 번에 수백 KB(스크린샷). 14일 보관이면 실패가 잦아도 수십 MB.
