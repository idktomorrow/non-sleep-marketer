# 0074. 백업은 클라우드 API 대신 사용자가 고른 폴더(동기화 폴더)에 한 부 더 복사하고, 실패는 경고만 한다

- 상태: 채택
- 날짜: 2026-11-18
- 결정한 사람: 선웅제(배치 C49 요청), 세부는 Claude
- 관련: devlog [2026-10-16-batch-C12](../devlog/2026-10-16-batch-C12.md)(하루 한 번 백업), [2026-11-18-batch-C49](../devlog/2026-11-18-batch-C49.md), `docs/known-gaps.md` 4절

## 배경

maintenance는 하루 한 번 `<NSM_HOME>/backups/`에 DB 백업을 만들고 최근 `backup_keep`개만 남긴다. 백업이 같은 PC 디스크에만
있어서, 디스크가 고장 나면 데이터와 백업이 함께 사라진다(known-gaps 4절).

## 선택지

1. **구글 드라이브·OneDrive API로 직접 올리기**: PC 밖 보관이 확실하다. 하지만 서비스마다 OAuth 앱 등록, 토큰 보관(keyring),
   만료 처리가 필요하고, 사용자가 쓰는 서비스마다 코드를 늘려야 한다.
2. **사용자가 고른 폴더에 복사**: 동기화 앱(구글 드라이브 데스크톱·OneDrive)이 그 폴더를 클라우드로 올린다. USB·NAS 폴더도 된다.
   토큰이 없고 코드가 작다. 다만 동기화 앱이 꺼져 있으면 PC 안의 다른 폴더일 뿐이다.
3. 아무것도 안 하고 문서로 "가끔 직접 복사"만 안내(지금 상태).

## 결정

2번. 키·토큰을 늘리지 않고(시크릿은 keyring에만이라는 가드레일 그대로), 어떤 동기화 서비스든 같은 코드로 된다.

- 본 백업이 성공한 뒤 같은 이름으로 복사(임시 이름 → `os.replace`). 복사 폴더도 본 백업과 같은 규칙으로 같은 접두어만 정리.
- 복사 실패(폴더 없음·쓰기 실패·백업 폴더 안)는 본 백업을 실패로 만들지 않는다. WARNING 한 줄, 알림 "백업 복사 실패" 한 번,
  실행 기록에 "복사 실패: 이유". 데이터를 지키는 본 백업이 부가 기능 때문에 실패로 보이면 안 된다.
- 설정 화면은 저장 때 검사(절대 경로·폴더 있음·쓰기 가능)하되 막지 않고 안내만 한다. 폴더를 나중에 만들 수 있게.

## 결과

- 사용자가 폴더 하나만 고르면 PC 밖 백업이 생긴다. 기본은 끔이라 지금 사용자는 바뀌는 것이 없다.
- 동기화 앱이 올렸는지는 이 프로그램이 모른다. 앱이 오래 꺼져 있으면 복사본도 PC 안에만 있다(사용설명서·known-gaps에 적음).
- DB 백업 하나를 매일 동기화 폴더에 올린다(실행 기록의 "데이터 백업 …(N MB)"가 그 크기). 수백 MB가 되면 압축이나 주 1회 복사를 다시 본다.
