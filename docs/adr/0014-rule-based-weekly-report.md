# 0014. 주간 리포트는 LLM 없이 규칙으로 계산하고, 기간은 현지 날짜 기준 지난 7일 전체로 고정한다

- 상태: 제안 (배치 H) · 날짜: 2026-10-11 · 관련: 이슈 #15, PRD 사용자 스토리 54·55

## 배경

주간 리포트는 "가장 잘된 콘텐츠와 그 이유, 다음 주 추천 주제"를 보여줘야 한다. LLM에게 지표를 주고 분석을 쓰게 할 수도 있고, 정해진 계산 규칙으로 만들 수도 있다. 또 "지난 7일"을 실행 시각 기준으로 잡으면, 스케줄러 지터(±10분)나 수동 실행 때문에 매주 리포트 기간이 겹치거나 빈다.

## 선택지

1. **LLM 서술형 분석**: 자연스러운 설명 / 비용, 결과가 매번 다름, 숫자를 지어낼 위험, 테스트 어려움
2. **규칙 계산**: 무료, 같은 데이터면 같은 결과, 테스트 가능 / 설명이 정형적

## 결정

2번.
- 참여율 = (좋아요 + 댓글 + 저장 + 공유) ÷ 조회. 상위 3개의 이유는 평균 대비 배수, 형식, 게시 시간대, 주제, 저장 비율.
- 추천 주제: 주제별 평균 참여율 순. 성과 기록이 없는 주제는 평균 × 0.8로 본다(검증된 주제를 앞세우되 새 주제도 시도할 여지). 동점이면 남은 자료가 많은 순.
- 기간: 현지 날짜 기준 오늘 0시 전까지의 7일 전체 `[오늘-7일 0시, 오늘 0시)`. 같은 날 언제 만들어도 같은 기간이다.

## 결과

- 리포트 파일 이름의 날짜는 기간이 끝나는 다음 날(= 만든 날)이다.
- 서술형 분석이 필요해지면 생성기 포트에 메서드를 추가하고, 규칙 계산 결과를 입력으로 주는 방식으로 확장한다(숫자는 규칙이, 문장은 LLM이).
