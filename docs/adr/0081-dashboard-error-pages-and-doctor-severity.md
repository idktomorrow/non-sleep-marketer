# 0081. 대시보드 오류는 요청 종류에 따라 화면·조각·JSON으로, doctor는 핵심 기능이 안 도는 것을 dry_run에 따라 FAIL로

- 상태: 채택
- 날짜: 2026-11-28
- 결정한 사람: 선웅제(배치 C61 지시: 오류 화면 HTML/HTMX 조각/JSON 분기, doctor FAIL 기준을 dry_run에 따라). 배치 C61 기본값: Accept가 없거나 `*/*`면 JSON, 설정 파일 없음도 FAIL, 게시 시간 창은 60분 규칙 없이 정렬·길이 0 거절만
- 관련: [ADR 0006](0006-single-process-duckdb-fastapi.md)(한 프로세스 대시보드), [ADR 0017](0017-aside-default-driver-after-day1.md)(Aside 드라이버), [ADR 0028](0028-dashboard-settings.md) 개정 1(계정·드라이런·보호 모드는 설정 화면에서 바꾸지 않음), 외부 정적 코드 검토(2026-11-27) 1-11·1-17·2-21, devlog [2026-11-28-batch-C61](../devlog/2026-11-28-batch-C61.md)

## 배경

1. **오류가 JSON으로 뜸(1-11, 2-21).** 대시보드에 예외 처리기가 없었다. 그래서 폼을 보내다 `HTTPException`이 나면 브라우저에 `{"detail": "…"}` JSON이 그대로 떴다. 승인·되돌리기·폐기 409, 편집·자료 삭제 400, 미리보기 504/500, 답글 502·400이 그랬다. 쿼리 문자열 오타(`/settings?saved=x`, `/logs?all=x`)에는 FastAPI 기본 422 JSON이 영어로 떴다. 자료 화면(C46)은 "숫자가 아니면 기본값"으로 이미 고쳐 두었다.
2. **doctor 판정과 문서가 다름(1-17).** README와 사용설명서는 "FAIL이 없으면 준비 끝, WARN은 선택 기능"이라고 한다. 그런데 doctor는 Claude 키 없음과 Aside CLI 없음을 WARN으로 두었다. 실제로는 Claude 키가 없으면 원고가 하나도 안 만들어지고, `dry_run: false`에서 Aside가 없으면 게시가 하나도 안 된다. doctor가 설정을 읽지 않아 "실계정인데 `accounts`가 비었다"도 못 잡았다.

## 선택지

오류 응답:

1. **항상 HTML 오류 화면**: 브라우저에는 좋다. 그러나 `fetch`로 부르는 설정 화면 폴더 고르기와 기존 테스트 67곳이 `r.json()["detail"]`·상태 코드를 본다.
2. **요청 종류로 나눔**(고름)
   - `HX-Request` 헤더면 detail 문구만 든 배너 조각
   - Accept에 `application/json`이면 JSON
   - Accept에 `text/html`이면 오류 화면
   - 그 밖(Accept 없음·`*/*`)은 JSON

doctor:

1. **문서를 고침**("WARN도 확인하세요"): 문서는 고치기 쉽다. 그러나 사람이 WARN 사이에서 치명적인 것을 골라야 한다.
2. **판정을 고침**(고름): 핵심 기능이 안 도는 것만 FAIL로 올린다. 드라이런이면 Aside·계정은 지금 필요 없으니 WARN으로 둔다.

## 결정

- **오류 응답(`nsm/app/errors.py`)**
  - `install_error_handlers`가 Starlette `HTTPException`(FastAPI 것과 없는 주소 404 포함)을 받는다. 판단 순서는 HTMX → JSON → HTML이다. 상태 코드와 응답 헤더는 바꾸지 않는다.
  - 오류 화면(`error.html`)은 `base.html` 레이아웃을 쓴다. 사람 말 제목(409 "지금은 할 수 없습니다" 등), detail 문구, "뒤로" 링크가 있다. "뒤로"는 같은 대시보드(host가 같은) Referer일 때만 그 주소이고, 아니면 `/`다.
  - detail이 없는 예외의 영어 기본 문구("Not Found")는 한국어로 바꾼다.
  - 화면 틀을 그리다 실패하면(DB 오류 등) 문구만 든 최소 HTML을 돌려준다.
  - `*/*`를 JSON으로 두는 까닭: 브라우저 폼과 주소창은 늘 `text/html`을 보낸다. `*/*`는 스크립트·테스트 클라이언트·`fetch` 기본값이다. 이렇게 하면 지금 동작을 기대하는 쪽이 깨지지 않는다.
  - HTMX 조각: 이 대시보드의 HTMX 요청은 알림 배지·작업 상태 폴링과 닫기 버튼뿐이다. htmx 2.0.4는 4xx·5xx 응답을 기본으로 화면에 넣지 않는다. 그래서 조각은 지금 화면을 덮지 않는다(폴링 자리가 오류 문구로 바뀌지 않음). 오류를 보일 자리(`hx-target-error` 등)를 붙이는 HTMX 화면이 생기면 그때 그대로 쓴다.
  - 편집 폼 400: 브라우저 폼 요청이면 검토 화면을 보낸 값 그대로 다시 그리고 오류 문구를 위에 보인다. 설정 폼이 이미 이렇게 한다. 다른 요청이면 지금처럼 400 JSON이다.
  - 쿼리 켬/끔(`saved`, `all`)은 문자열로 받는다. `1·true·yes·on`이 아니면 끔이다.
- **doctor 판정(`nsm/doctor.py`)**
  - FAIL:
    - 설정 파일이 없을 때. `nsm run`이 바로 멈추기 때문이다. 예전에는 WARN이었다.
    - Claude 키가 없을 때.
    - 실계정(`dry_run: false`)인데 Aside CLI가 없거나 `settings.accounts`가 비었을 때.
  - WARN:
    - 드라이런이거나 설정 파일이 아직 없을 때의 Aside·계정. 문구는 "드라이런이라 지금은 필요 없음"이다. `doctor._aside()`를 인자 없이 부르면 예전처럼 WARN이다.
    - 켠 플랫폼 중 일부만 계정이 없을 때. 그 플랫폼만 게시하지 않는다.
  - 문서 문구 "FAIL이 없으면 준비 끝"은 그대로 둔다. 이제 그 말이 참이다.

## 결과

- 쉬워진 것
  - 폼에서 거절돼도 브라우저에 사람 말 화면이 뜨고 "뒤로"로 돌아간다.
  - 카드 문구를 길게 고치다 400이 나도 입력이 남는다.
  - `nsm doctor`에 FAIL이 없으면 정말로 원고 만들기와 (실계정이면) 게시까지 도는 상태다.
- 어려워진 것
  - 같은 오류가 세 모양이 되어, 새 화면을 만들 때 어느 쪽으로 가는지 알아야 한다(위 판단 순서).
  - 키 없이 doctor를 돌리면 이제 종료 코드가 1이다(CI처럼 키 없는 곳에서 `nsm doctor`를 성공 조건으로 쓰면 안 됨).
- 남는 것
  - 422(폼 칸 빠짐 등 `RequestValidationError`)는 처리기를 달지 않았다. 브라우저 폼은 칸을 늘 보내서 겪을 일이 드물다. 쿼리 오타 두 곳만 기본값으로 고쳤다.
  - 활동 시간 창 하한 60분(같은 배치, `schema.check_windows`)은 경계에 걸린다. 원고 시각은 창 시작 +50분에 APScheduler 지터 0~600초가 붙고, 창 끝은 포함하지 않는다(`policy._in_window`). 그래서 딱 60분인 창은 작업 스레드가 다른 잡에 밀리면 창 밖이 될 수 있다. 오프셋 보정은 배치 지시로 하지 않았다.
  - 편집 폼 말고 다른 폼(배경 올리기·자료 삭제 등)의 400은 오류 화면을 띄우고 "뒤로"로 돌아간다. 입력을 다시 채우지는 않는다. 파일 입력은 브라우저가 다시 채울 수 없다.
- 다시 볼 조건
  - HTMX로 폼을 보내는 화면이 생기면 4xx를 화면에 넣을 자리를 정한다.
  - doctor가 실계정 로그인 상태까지 볼 수 있게 되면 FAIL 기준을 다시 본다.
