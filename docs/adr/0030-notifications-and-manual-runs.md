# 0030. 알림이 실제로 뜨게, "지금 실행"은 결과를 보여 주고 원고는 1건 더

- 상태: 채택 (선웅제 요청, 2026-10-13) · 날짜: 2026-10-13 · 관련: [0028](0028-dashboard-settings.md), [0008](0008-autopublish-guardrails.md)

## 배경

실계정 운영 첫날 선웅제가 세 가지를 짚었다.

1. **알림이 안 뜬다.** 로그에는 "검토 대기 콘텐츠" 알림을 보냈다고 남았지만 화면에는 없었다. winotify는 앱 이름("논슬립 마케터")을 그대로 Windows 알림 앱 ID로 쓰는데, Windows는 등록되지 않은 앱 ID로 온 알림을 오류 없이 버린다. winotify는 PowerShell 출력을 버려 실패도 알 수 없었다. 또 알림 문구를 PowerShell 큰따옴표 here-string에 그대로 넣어서, 문구에 `$(...)`가 있으면 그 부분이 PowerShell 코드로 실행될 수 있었다.
2. **"지금 실행"을 누르면 실행 기록 화면으로 넘어갈 뿐, 끝났는지 알 수 없다.**
3. **"원고 만들기"를 눌러도 "오늘 생성 목표 달성"으로 건너뛴다.** 사람이 더 만들고 싶을 때 막혔다.

## 결정

- **알림**: 앱 ID `NonSleepMarketer`를 HKCU\Software\Classes\AppUserModelId에 표시 이름 "논슬립 마케터"로 등록한다(관리자 권한 불필요, 처음 보낼 때). 알림 XML은 파이썬에서 이스케이프해 PowerShell 작은따옴표 문자열에만 넣고 `-EncodedCommand`로 넘긴다. 실패하면 오류를 로그에 남긴다. 작업 스레드를 막지 않게 별도 스레드에서 보낸다. winotify 의존성은 뺐다.
- **알림 켜기/끄기**: `settings.desktop_notifications`(기본 켜짐). 설정 화면에서 바꾸고 "테스트 알림 보내기"로 확인한다. 꺼도 대시보드 안의 할 일 목록·진행 표시와 로그는 그대로다.
- **지금 실행**: 누른 화면에 그대로 머물고, 오른쪽 아래에 "○○ 실행 중… n초"를 띄워 2초마다 갱신한다. 끝나면 "○○ 완료/실패"와 한국어 결과 요약(예: 새 자료 15건 · 관련 자료 5건)을 3분 동안 보여 주고, 데스크톱 알림도 보낸다. 다른 사이트에서 온 요청이면 원래 화면 대신 첫 화면으로 보낸다(열린 리다이렉트 방지).
- **원고 만들기(지금 실행)**: 하루 목표와 상관없이 누를 때마다 1건을 더 만든다. 비용 상한과 쓸 자료 조건은 그대로 지킨다. 하루 쿼터를 넘겨 만든 원고는 모든 게시 플랫폼에 배정해, 쿼터가 남는 날 차례로 올라간다. 자동 실행은 지금처럼 하루 목표까지만 만든다.

## 결과

- 더 만든 원고도 게시는 하루 게시 수(설정 화면)와 간격을 지킨다. 바로 더 올리고 싶으면 하루 게시 수를 늘린다.
- 알림 앱 ID 등록은 사용자 레지스트리 한 곳에만 남는다. 지우려면 `HKCU\Software\Classes\AppUserModelId\NonSleepMarketer`를 삭제한다.
