# 0031. 알림함(종 모양)과 게시 대기 화면

- 상태: 채택 (선웅제 요청, 2026-10-13) · 날짜: 2026-10-13 · 관련: [0030](0030-notifications-and-manual-runs.md), [0008](0008-autopublish-guardrails.md)

## 배경

- "지금 실행" 결과 표시는 3분 동안 화면 구석에 남아 거슬리는데, 닫을 방법이 없었다.
- 정작 중요한 알림(검토할 원고, 확인할 댓글, 로그인 필요)은 Windows 알림을 놓치면 다시 볼 곳이 없었다.
- 승인한 원고(게시 대기)를 볼 화면이 없었다. 수동 승인일 때는 물론이고, 자동 게시를 켠 뒤에도 "다음에 무엇이 올라가는지" 보고, 문제가 있으면 막을 수 있어야 한다.

## 결정

- **알림함**: 모든 알림을 DB `notifications` 테이블에 남긴다(스키마 v3). 데스크톱 알림을 꺼도 남는다. `RecordingNotifier`가 기존 Notifier 포트(제목, 내용, 수준)를 그대로 받아 기록하고 데스크톱 알림으로 넘긴다. 누르면 갈 화면은 알림 제목으로 정한다(`link_for`). 포트는 바꾸지 않는다.
- **종 모양**: 머리줄 오른쪽에 종과 안 읽은 수(30초마다 갱신)를 둔다. 누르면 최근 15개가 펼쳐진다. 하나를 누르면 읽음이 되고 관련 화면으로 간다. "전체 읽음"이 있고, "알림 모두 보기"에서 최근 200개를 본다. 오래된 알림은 지운다.
- **진행 표시 닫기**: 끝난 "지금 실행" 표시에 ×를 둔다(실행 중인 것은 닫히지 않음).
- **게시 대기 화면(`/queue`)**: 승인된 원고를 오래된 순(올라갈 순서)으로 보여 준다. 플랫폼별 상태(게시 대기, 실패·재시도 시각, 게시됨)를 함께 보여 주고, 최근 7일 게시 목록도 둔다. 할 수 있는 일은 세 가지다.
  - 열어 보기
  - **검토로 되돌리기**: 승인됨 → 검토 대기. 게시 작업은 승인된 원고만 올리므로 그 즉시 멈추고, 바로 고칠 수 있다.
  - **폐기**
- 지금 올리는 중(publishing)인 원고는 되돌리기·폐기를 막는다(409). 한쪽 플랫폼에만 올라간 원고를 폐기해도 올라간 글은 지워지지 않으므로 화면에 안내한다.

## 결과

- 자동 게시 후에도 게시 대기에서 언제든 막을 수 있다.
- 알림함 기록은 DB 쓰기가 하나 늘 뿐이다. 실패해도 작업은 계속된다(로그만).
