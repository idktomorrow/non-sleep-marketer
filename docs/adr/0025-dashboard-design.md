# 0025. 대시보드 디자인: "오늘 할 일" 중심의 밝은 관리 화면

- 상태: 제안 (배치 I, 취향에 따라 갈리는 선택 3가지는 선웅제가 PR 리뷰에서 고름) · 날짜: 2026-10-13 · 관련: 이슈 #16, [devlog](../devlog/2026-10-13-batch-I.md)

## 배경

배치 I 사용자 점검(devlog 1단계)에서 확인한 문제:

- 오늘 할 일을 바로 알 수 없었다. 같은 크기 카드 8개가 나란히 있었다.
- 원고 하나를 승인하는 데 클릭 4번과 긴 스크롤 2번이 들었다.
- 영어 내부 값(`pending_review`, `collect`)이 그대로 보였다.
- 휴대폰에서 댓글·성과 화면이 깨졌다.
- 처음 설치한 사람에게 다음 할 일을 알려 주지 않았다.

## 결정 (구현한 기본안)

- **구조:**
  - 개요는 "오늘 해야 할 일" 목록을 가장 크게 둔다. 항목은 검토할 원고, 사람이 답할 댓글, 게시 실패, 멈춘 플랫폼이고, 숫자를 누르면 바로 그 화면으로 간다. 원고는 가장 오래 기다린 것부터 연다.
  - 처음 설치한 사람에게는 4단계 시작 안내를 보인다.
  - 검토 상세는 카드(왼쪽)와 원고(오른쪽)를 나란히 두고, 저장·미리보기·승인·폐기를 위쪽 고정 막대에 둔다.
  - 댓글은 카드로 보이고, 답글 보내기를 주 동작으로 둔다.
- **표시:** 내부 값은 화면에서만 한국어로 바꾼다(`nsm/app/ko.py`). 잡 이름에는 하는 일 설명을 붙인다. DB·라우트·폼 이름은 그대로다.
- **모양:**
  - 밝은 바탕(#F5F6F8)과 흰 패널, Pretendard(카드 렌더러와 같은 파일을 `/fonts`로 제공)를 쓴다.
  - 강조색은 설정의 브랜드 주 색이다. 밝은 바탕에서 읽히도록 어둡게 맞춘 값(`palette().primary_ink`)을 쓴다.
- **안전:** 폐기와 "답하지 않고 처리 완료"는 확인 창을 띄운다. 저장하지 않은 수정이 있으면 승인 전에 알린다. 검토 목록에서 바로 승인하는 버튼은 뺐다(카드와 글을 확인한 뒤 승인).
- **휴대폰:** 표는 가로 스크롤 칸 안에 넣고, 메뉴는 한 줄 가로 스크롤로 바꿨다. 7개 화면 모두 390px 폭에서 페이지 가로 넘침이 없다(`scripts/dashboard_shots.py`로 측정).

## 취향에 따라 갈릴 수 있는 선택 3가지

| 선택 | A안 (지금 구현) | B안 |
|---|---|---|
| 1. 강조색 농도 | 브랜드 색은 버튼·링크·숫자·선택된 메뉴에만. 바탕은 흰색·연회색 | 위쪽 머리 막대 전체를 브랜드 색으로 칠하고 글자는 흰색. 브랜드 느낌이 강하지만 경고색(노랑·빨강)이 덜 눈에 띈다 |
| 2. 검토 화면 카드 크기 | 왼쪽 열에 카드 한 장씩 크게(폭 약 400px, 세로로 넘겨 봄). 글자를 읽으며 고칠 수 있다 | 작은 썸네일을 가로 한 줄로 두고, 누르면 크게 보기. 원고 칸이 넓어지지만 카드 글자를 읽으려면 한 번 더 눌러야 한다 |
| 3. 메뉴 위치 | 위쪽 가로 메뉴(휴대폰에서 가로 스크롤) | 왼쪽 세로 사이드바(휴대폰에서는 아래 탭 막대). 메뉴가 늘어도 자리가 넉넉하지만 넓은 화면에서 본문 폭이 줄어든다 |

B안으로 바꾸려면 `nsm/app/static/app.css`와 `base.html`만 고치면 된다. 라우트와 테스트는 그대로다.

## 결과

- 아침 과제 "원고 열어 한 줄 고쳐 승인"이 클릭 4번 + 긴 스크롤 2번에서 클릭 3번(오늘 → 검토하기, 저장, 승인)으로 줄었다. 스크롤은 필요 없다.
- 라우트 테스트(`tests/app`)를 그대로 두고 통과했다. 화면 동작 테스트(`tests/app/test_ui.py`)를 추가했다.
- 다크 모드는 넣지 않았다(밝은 관리 화면이 기본안). 필요하면 CSS 변수만 덮으면 된다.
