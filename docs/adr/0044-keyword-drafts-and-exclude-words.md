# 0044. 키워드로 원고 만들기, 수집 제외어

- 상태: 제안 (배치 C15. 선웅제가 정한 것: 둘 다 만든다, 키워드 원고도 평소 자동 게시 규칙대로, 쓸 만한 자료가 없으면 만들지 않고 알림)
- 날짜: 2026-10-16
- 결정한 사람: 선웅제(범위·게시 규칙·자료 없을 때), 배치 C15 기본값(검색 건수, 제외어 규칙 세부)
- 관련: [ADR 0022](0022-fetch-article-body-for-relevant-items.md)(원문 읽기), [ADR 0032](0032-fresh-sources-and-no-rumors.md)(최근 자료만), [ADR 0030](0030-notifications-and-manual-runs.md)(지금 실행 진행 표시)

## 배경

사용자는 "치이카와 굿즈"를 알고 싶은데, 만들어진 원고는 대부분 극장판 이야기였다. 관심 주제에 "치이카와 굿즈"가 있는데도 그랬다. 원인은 세 가지다.

1. 한 번 모을 때 30건을 주제 6개 × 블로그·뉴스로 나눠, 주제 하나에 2건 남짓만 모인다.
2. 요즘 기사가 극장판 위주라, "치이카와 굿즈"로 찾아도 "극장판 특전 굿즈"가 많이 나온다.
3. 원고 주제는 가장 오래 안 쓴 주제부터 돌아가며 고른다. 사람이 "이번엔 이걸로"를 고를 수 없다.

## 선택지

- 사람이 고르게 하는 방법
  1. 관심 주제를 하나만 남겼다가 되돌린다. 번거롭고, 바꾸는 동안 다른 주제 수집이 멈춘다.
  2. **키워드로 바로 찾아 원고 1건 (채택)**: 관심 주제와 따로, 한 번만 쓴다.
- 원하지 않는 이야기를 빼는 방법
  1. 금칙어를 쓴다. 금칙어는 "자동 게시만 막는" 용도이고, 원고는 그대로 만들어진다.
  2. **수집 제외어 (채택)**: 모을 때 버리고, 이미 모은 것도 원고에 쓰지 않는다.

## 결정

- **키워드 원고**(`nsm/engine/keyword.py`, 잡 이름 `keyword`)
  - 위치: 대시보드 "오늘"의 "키워드로 원고 만들기" 칸(두 모드 모두). `POST /keyword-draft`, CLI는 `nsm run --once --job keyword --keyword "…"`
  - 키워드는 2~40자, 공백을 정리한다.
  - 찾기: 검색어를 받는 소스만 쓴다. 네이버 블로그·뉴스와 켜 둔 커뮤니티이고, 구글 트렌드·올린 파일은 쓰지 않는다. 소스마다 12건이다. 이미 모아 둔 글이 다시 나오면 그것도 후보다.
  - 판정: 이번에 찾은 안 쓴 글만, 키워드를 관심 주제로 더한 지시로 판정한다. 이미 모아 둔 글도 다시 판정한다(예전 점수는 키워드를 몰랐다). 후기·일기·제외어 글은 판정 전에 뺀다.
  - 이 점수는 그 실행에서만 쓰고 DB에 남기지 않는다. 남기면 안 쓴 글이 나중에 자동 원고에 섞인다. 예전에 쌓인 미판정 자료도 키워드로 판정하지 않는다. 새로 찾은 글은 다음 자료 모으기가 평소 기준으로 판정한다.
  - 고르기: 이번에 찾은 글 중 키워드 기준 관련 자료만 쓴다. 관련성 높은 순으로 3건이다. 예전에 쌓인 다른 자료는 섞지 않는다. 고른 글은 원문을 읽고, 원문에 제외어가 있으면 뺀다.
  - 만들기: 평소 원고와 같은 경로(`_make_one`)다. 비용 상한, 페르소나 규칙, 출처 검증, 보호 모드, 자동 게시 스위치를 그대로 따른다. 원고의 주제(`persona_topic`)는 키워드다.
  - 쓸 만한 자료가 없으면 만들지 않는다. Claude 생성 비용도 들지 않는다. 진행 표시와 알림에 "찾은 최근 글 N개 중 쓸 만한 자료가 없음"이 나온다.
  - 페르소나가 꺼져 있거나 활동 시간 밖이면 검색도 하지 않는다. API 키가 없거나 비용 상한에 닿아도 하지 않는다.
  - 관심 주제 목록은 바꾸지 않는다. 이번에 찾았지만 안 쓴 자료는 평소처럼 주제 분류를 거쳐 자동 원고에 쓰일 수 있다.
  - 작업 스레드 하나에서 다른 작업과 차례로 돈다. 진행은 "지금 실행"과 같은 오른쪽 아래 표시로 본다. 같은 키워드가 아직 도는 중이면 다시 눌러도 한 번만 돈다.
- **수집 제외어**(`settings.collect.exclude_words`, 설정 화면 페르소나 칸, 두 모드 모두)
  - 제목·본문에 그 낱말이 든 글은 저장하지 않는다. 분류 비용도 들지 않는다.
  - 이미 모아 둔 자료라도 그 낱말이 들어 있으면 원고에 쓰지 않는다.
  - 대소문자는 가리지 않는다. 낱말이 들어 있기만 하면 뺀다.
  - 키워드 원고의 키워드 안에 든 제외어는 그 실행에서만 풀린다. 예를 들어 "극장판"을 빼 두었어도 "극장판 굿즈"로는 찾을 수 있다.

## 결과

- 사람이 원하는 이야기를 바로 원고로 만들 수 있다. 자동 수집에 기대지 않아도 된다.
- 제외어로 한쪽에 쏠린 소재를 걸러 낼 수 있다.
- 어려워진 것
  - 제외어가 짧으면(예: "영화") 원하는 글까지 빠질 수 있다. 낱말 단위 일치라 문맥은 보지 않는다.
  - 키워드 원고도 하루 게시 한도를 지킨다. 이미 한도를 채웠으면 다음 날 올라간다(사람이 만든 원고는 모든 플랫폼에 배정, ADR 0030).
  - 수집과 같은 브라우저를 쓰므로, 너무 자주 누르면 네이버 검색이 늘어난다. 한 번에 블로그·뉴스 2페이지다.
- 다시 볼 조건
  - 키워드 원고를 자주 쓰면 "이 키워드를 관심 주제에 더하기"나 "여러 건 만들기"를 검토한다.
  - 제외어 때문에 원하는 자료까지 빠진다는 피드백이 오면 "제목에만 적용"을 검토한다.
