# 0008. 자동 게시는 보호 모드·일일 쿼터·비용 상한·claim 단위 출처 검사를 모두 통과해야 한다

- 상태: 채택 · 날짜: 2026-10-11 · 결정: 선웅제 · 관련: [mvp-review](../mvp-review.md) #4~#8, [contracts 4절](../contracts.md)

## 배경

원래 기준은 "출처가 있고 jev 신뢰도 0.8 이상이면 자동 게시"였다. 문제가 셋 있었다.
- 0.8은 자료 **관련성** 신뢰도이지 글 내용의 사실성이 아니다.
- "모든 문장에 출처"는 의견·연결 문장까지 출처를 요구해 자동 게시가 불가능하거나 LLM이 가짜 출처를 붙이게 만든다.
- 하루 게시 수·비용에 상한이 없어 버그 하나로 계정 도배나 과금이 가능하다. 게시 중 크래시하면 이중 게시도 가능하다.

## 결정

- 생성기는 사실 주장(claim)마다 `source_item_id`를 낸다. 정책은 그 ID가 DB에 실제로 있는지 검사한다.
- 0.8은 자료 선별 기준으로 쓴다.
- 보호 모드: 첫 20건은 무조건 검토, 대시보드에서 자동 게시를 켜야 해제.
- 일일 쿼터(인스타 1, 스레드 2, 블로그 1)와 일일 비용 상한($3), 초과 시 중단 + 알림.
- 재시도 3회(15분·1시간·4시간) 후 abandoned. 재시작 시 `publishing` 잔여 건은 자동 재시도하지 않고 검토로(멱등성).

## 결과

- 모든 규칙이 `nsm/domain/policy.py` 순수 함수라 엔진 시나리오 테스트로 전부 검증한다.
- 기본값은 설정으로 바꿀 수 있다.

## 2026-10-13 변경: 보호 모드 20건 → 10건

선웅제 결정. 실계정 운영 첫날 기준으로, 보호 모드가 끝나도 금칙어·출처 없는 주장·관련성 미달·규칙 위반 원고는 계속 검토로 가고 자동 게시 스위치도 사람이 켜야 한다. 하루 최대 3건이면 20건은 일주일쯤 걸려서, 템플릿 3종을 각각 세 번쯤 볼 수 있는 10건으로 줄였다. 이 PC의 `config.yaml`에서 `settings.protect_count: 10`(저장소 밖). 코드 기본값(20)은 새 설치를 위해 그대로 둔다.
