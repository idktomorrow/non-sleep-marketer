# 0039. 작업 요약은 한 함수가 만드는 한국어 문장으로, 예전 형식 줄은 DB를 고치지 않고 보여 줄 때 바꾼다

- 상태: 제안 (배치 C10 기본값. PR 리뷰에서 선웅제 확인)
- 날짜: 2026-10-16
- 결정한 사람: 선웅제(요청: "요약 줄을 전체적으로 사람이 읽기 쉬운 문장으로"), 배치 C10 기본값
- 관련: [ADR 0030](0030-notifications-and-manual-runs.md)("지금 실행" 결과 알림), [ADR 0038](0038-instagram-rate-limit-rest.md)

## 배경

실행 기록 요약이 `reply: new=0, auto_replied=0, hidden=0, escalated=0, ignored=0, rate_limited=['…']`처럼 내부 값 그대로였다. 사용자가 이 줄의 뜻을 몰라 물었다.

- 요약은 실행이 끝날 때 문자열로 `run_logs.message`에 저장된다. 지금 DB에는 예전 형식 줄이 수백 개 있다.
- "지금 실행" 결과 알림(`ko.result_text`)은 같은 결과를 따로 짧게 만들어, 실행 기록과 표현이 달랐다.

## 선택지

1. **새 줄만 문장으로**: 가장 단순하다 / 실행 기록 화면에 예전 줄과 새 줄이 섞여 보인다(하루 수백 줄이라 며칠간).
2. **DB를 한 번 고침(마이그레이션)**: 저장된 줄을 새 문장으로 덮어쓴다. 예전 형식 해석기를 나중에 지울 수 있다 / 사용자 데이터를 되돌릴 수 없게 바꾼다. 해석이 틀리면 원래 줄이 사라진다.
3. **보여 줄 때 바꿈(채택)**: 화면 필터가 예전 형식을 알아보면 같은 문장으로 바꾼다. DB는 그대로다 / 해석기를 계속 두어야 한다. 화면을 그릴 때마다 최대 200줄을 해석한다.

## 결정

3번. 원래 기록을 지키는 쪽을 골랐다.

- `nsm/engine/summary.py`의 `describe(job, skipped, counts, errors)` 하나가 문장을 만든다.
  - 잡마다 문장이 있고 " · "로 잇는다.
  - 실행 기록(`JobResult.summary()`), "지금 실행" 알림(`ko.result_text`), 로그 파일이 모두 이 함수를 쓴다.
- 예전 줄은 `readable(job, message)`가 바꾼다.
  - 모르는 모양이면 손대지 않는다.
  - 목록 글자 안의 `, x=`나 따옴표 없는 값도 읽는다.
  - 실행 기록·개요 화면에서 필터 `run_text`로 쓴다.
- 새 잡을 더하면 `summary.py`에 문장 함수도 더한다. 테스트가 `runner.JOBS`의 모든 잡에 문장이 있는지 본다.

## 결과

- 실행 기록·개요·알림이 같은 문장을 보여 준다. 예: "새 댓글 없음 · 인스타그램 요청 제한으로 쉬는 중(02:56 이후 다시)"
- 실제 로그 531줄(5개 잡)을 모두 바꿔 봤다. 바뀌지 않은 줄은 0이었다.
- 어려워진 것
  - 예전 형식 해석기(`_LEGACY`, `_legacy_counts`)를 유지해야 한다.
  - 결과 값에 새 키를 더하면 문장 함수에도 더해야 요약에 나온다.
- 다시 볼 조건: 예전 형식 줄이 실행 기록 화면(최근 200줄)에서 모두 밀려나면 `readable`과 해석기를 지운다. 하루 수백 줄이 쌓이므로 머지 후 며칠이면 된다.
