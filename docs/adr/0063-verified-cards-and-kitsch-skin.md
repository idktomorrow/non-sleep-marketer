# 0063. 카드에는 확인된 정보만, 출처는 게시 글로, 모양은 구성과 장식(스킨)을 나눠 정한다

- 상태: 제안
- 날짜: 2026-10-23
- 결정한 사람: 서브(제안), 사용자 피드백 2026-10-23 반영, 메인 합의 전
- 관련: S18 PR(#108), ADR 0062(형식은 내용이 정한다)·0050(사진 우선형)·0007(글자는 HTML)

## 배경

S18 실호출 결과를 본 사용자 피드백(2026-10-23):

- 카드에 "구체적인 정보 확인 필요", "배송비와 특전 조건도 살펴봐요", "방문 전 판매 매장을 확인하세요" 같은 줄이 남았다. 보는 사람에게 확인을 떠넘기는 줄은 정보가 아니다. 카드는 **"정말 정보만 알찬 것"** 이어야 한다.
- 카드 아래 작은 출처 글씨는 읽히지 않고 자리만 차지한다. 출처는 지워서는 안 되지만, 실제 주소가 있는 게시 글 끝에 있는 편이 쓸모 있다.
- 사용자가 준 참고 카드(분홍 반짝이 바탕의 굿즈 사진 콜라주와 손글씨 이름표, 유튜브 썸네일처럼 굵은 외곽선 제목, 예능 자막)는 **같은 정보 구성**에 **다른 장식**을 얹은 것이다. 지금 구조에서 장식을 바꾸려면 새 템플릿을 만들어야 하는지가 문제였다.

## 선택지

1. **프롬프트만 고친다**("확인 필요라고 쓰지 마"): 비용이 없다. 하지만 모델은 가끔 어기고, 어겨도 아무도 모른다.
2. **프롬프트 + 생성 직후 정리기**: 규칙을 어긴 줄을 카드에서 걷어 캡션 "참고:" 줄로 옮긴다. 정보는 사라지지 않고 카드는 깨끗해진다. 정규식이 놓치는 표현은 남는다.
3. **장식마다 새 템플릿**(kitsch.html 등): 자유도는 크지만 장 종류 × 템플릿 수만큼 분기가 늘고, 소식형에서 고친 배치(사진 짝짓기·정보 줄 배치·넘침)를 따로 고쳐야 한다.
4. **구성은 소식형 하나, 장식은 스킨 CSS**: 같은 HTML(같은 표기 슬롯·같은 넘침 검사)에 `skin-kitsch` 클래스와 `kitsch.css`만 더한다. 장식 자유도는 CSS 범위로 줄어든다.

## 결정

**2와 4.** 이유: 내용 규칙은 코드가 검증해야 지켜지고, 장식은 구성과 따로 바뀌어야 둘 다 망가지지 않는다.

- **확인된 정보만**: 프롬프트에 "확인 필요·찾아보세요·살펴봐요·추후 공지"를 카드에 쓰지 말 것, 표지 부제는 핵심 사실 한 줄로 적었다. 생성 직후 `strip_viewer_checks`가 그런 정보 줄·요점·문장·마무리·부제를 걷어내고 캡션 끝 "참고:"로 옮긴다. 걷어내 덱 계약이 깨지면(2장 미만) 원래 덱을 두고 검토에서 사람이 고친다.
- **출처는 게시 글로**: 카드에는 출처를 그리지 않는다(사진 설명·덱 출처 줄·마무리 출처 목록·밈 참조 표기). 게시할 때 캡션 끝에 "출처" 블록으로 실제 주소를 붙인다(스레드는 글자 수 때문에 주소 하나). 원고 계약의 출처 필드는 그대로라 검토·계약 테스트는 같다.
- **키치형 스킨**: `brand.card_style: kitsch`는 렌더러 안에서 소식형 구성(`style=editorial`)에 `skin=kitsch`를 더한 것이다. 바뀌는 것은 다음과 같다.
  - 바탕: 파스텔 물방울과 반짝이(코드 장식, 사진 없는 장에서만)
  - 표지: 굵은 외곽선 제목(Black Han Sans), 노란 스티커 칩 부제(Jua)
  - 장 제목: 형광펜 밑줄
  - 사진: 흰 테두리 스티커
  - 상품: 진한 외곽선 카드, 손글씨 이름표(Gaegu)
  - 정보 줄: 티켓 모양
  - 폰트는 OFL이라 동봉한다(`nsm/templates/fonts/OFL-display-fonts.txt`). 그림은 여전히 실제 자료 사진뿐이다.
- **만드는 순서(프로세스)**: 아래 순서로 만든다. 각 단계는 앞 단계 결과만 받는다. 장식을 고쳐도 내용 검증을 다시 하지 않고, 내용을 고쳐도 CSS를 건드리지 않는다.
  1. 내용(확인된 사실만, 정리기)
  2. 구성(장마다 표현, ADR 0062 검증)
  3. 사진 배치(그림을 보는 모델 + 검증)
  4. 장식(스킨)
  5. 렌더 검사(넘침·대비·썸네일 크기)와 사람 확인

## 보충: 실호출 뒤 피드백(2026-10-23 오후)

"치이카와 최신 굿즈" 재실행 결과에 대한 사용자 피드백은 세 가지였다. 표지에 사진이 있어야 가장 좋다. 흐린 배경 위에 올린 사진은 싸 보인다. 썸네일의 파란 막대는 불필요하다. 사용자는 "멀리 보는 프로세스"로 고치라고 했다. 증상을 하나씩 막지 않고, 같은 원인을 단계에서 고쳤다.

- **원인 하나: 사진의 종류를 가리지 않았다.** 파란 막대, 겹친 제목("치이카와 ANA 굿즈"), "10.23 업데이트" 꼬리표, 매장 목록 캡처는 모두 같은 원인이다. 블로그·기사가 글자를 얹어 만든 이미지를 실물 사진과 똑같이 다뤘다.
  - 이제 사진을 고르는 모델이 사진마다 종류를 적는다: photo, official, designed, screenshot.
  - 코드는 photo(실물)와 official(공식 포스터·키 비주얼)만 배치한다.
- **표지가 먼저다.** 모델이 표지를 비워 두면 남은 쓸 수 있는 사진을 표지에 넣는다. 남은 게 없으면 본문 장의 사진을 표지로 옮긴다.
- **흐린 채움을 없앴다.** 사진은 칸을 꽉 채우고 가장자리를 조금 자른다. 아주 가로로 긴(1.3:1 초과) 표지 사진만 위에 원본 비율로 두고, 아래는 진한 색 면으로 둔다.
- **밈 만드는 방법(`make`)을 고르게 했다.** 사용자 피드백: "유명한 짤에 이 캐릭터만 합성".
  - `composite`: 유명 짤 원본을 바탕으로 두고, 인물·대상 하나만 캐릭터로 바꾸거나 끼워 넣는다. 원본 글자는 지우고 글은 HTML로 얹는다.
  - `restage`: 예전처럼 구조만 빌려 새로 그린다.
  - 합성은 원본 사진을 그대로 쓴다. 출처 표기는 사용 허락이 아니므로 검토 사유에 "원본 짤 합성: 원본 사진의 권리·실존 인물 확인 필요"를 남긴다. 자동 승인하지 않고 사람이 판단한다.

## 보충 2: 편집 밀도(2026-10-23 저녁)

사용자 피드백: 레퍼런스와 견주면 아직 단순하다. 장식을 더하거나 템플릿을 늘리라는 뜻이 아니다. 소재를 자세히 보고, 팬이 반응할 디테일과 맥락을 골라 이미지와 문장으로 보여 주는 편집이 부족하다.

- **진단**: 원고는 기사 글만 보고 먼저 쓰였고, 사진은 원고를 다 쓴 뒤에 모아 붙였다(`_fill_info_slot`: 원고 → 저장 → 사진). 원고를 쓰는 모델은 실제 사진에 무엇이 보이는지 몰랐다. 그래서 장이 안내문처럼 나뉘었고, 상품 장에 상품이 보이지 않아도 완성으로 쳤다.
- **결정: 관찰 → 관점 → 장 편집.**
  1. **관찰**: 사진 우선형이면 원고를 쓰기 전에 사진을 모은다. 그림을 보는 모델(포트 `PhotoObserver`)이 사진마다 종류, 보이는 것, 눈에 띄는 디테일 최대 3곳과 위치를 적는다. 보이는 것만 적고, 이름·설정·가격은 추측하지 않는다. 기록은 `candidates.json`에 남는다.
  2. **추가 확보**: 쓸 수 있는 사진(실물·공식)이 3장보다 적으면, 이미 수집한 자료 중 같은 소재의 다른 글에서 **사진만** 더 모은다. 사실은 원래 자료에서만 가져온다.
  3. **관점·장 편집**: 원고(`ContentBrief.photos`)가 중심 관점(`angle`)을 먼저 정한다. 장마다 다음 네 가지를 고른다.
     - 보여 줄 사진
     - 크게 볼 디테일(`focus`)
     - 디테일을 짚는 짧은 주석(`marks`)
     - 표지 사진
     
     정해진 순서는 없다.
  4. **코드 검증**: 원고 선택을 코드가 다시 확인한다.
     - 남의 썸네일·캡처는 쓰지 않는다.
     - 관찰에 없는 디테일은 쓰지 않는다. 확대한 디테일과 다른 특징을 말하는 글·주석이 붙으면 확대·주석을 버린다. 실호출에서 귀를 확대하고 "소매 장식"이라고 쓴 일이 있었다.
     - 표지와 같은 사진을 본문에 통째로 다시 쓰지 않는다.
     - 상품이 하나도 보이지 않는 상품 장은 정보 줄로 줄이고 "자료 부족"으로 남긴다.
     
     관점과 부족한 자료는 검토 사유에 편집 메모로 보인다(`GeneratedContent.editor_notes`). 카드와 글에는 나가지 않는다.
  5. **표현**: 디테일 확대(원본의 그 영역만 칸에 꽉)와 주석(점 + 짧은 글). 키치형은 사진을 구경하는 장에서 무늬·반짝이를 빼고, 정보 장에만 남긴다.
  6. **앱 흐름**:
     - 추천 작업이 이 순서로 원고를 만든다.
     - 추천 카드의 "사진 보고 다시 편집"은 같은 자료·같은 사진으로 다시 편집한다(`info_reedit` 작업).
     - 사진은 예전처럼 "이 사진 쓰기"로 사람이 확인한 뒤에 들어간다. 이때 확대·주석이 함께 적용된다.
- **밈**: 유명 밈 재해석 경로는 유지하고 세 가지를 바꿨다.
  - 소재 폭을 넓혔다. 반응짤, 방송 장면 패러디, 고르는 재미, 팬덤 딜레마를 모두 후보로 둔다. 필수 유형이나 할당량은 아니다. "다른 캐릭터로 바꿔도 성립한다"고 감점하지 않는다.
  - 재미의 핵심(`core`: 표정·시선·배치·동작·자막·대비)을 기획에 적고, 그림 지시에 "꼭 보이게"로 넘긴다.
  - 완성 그림 검토(포트 `MemeImageReviewer`)를 붙였다. 그림이 나오면 핵심이 실제로 보이는지 보고, 문제를 단계(구도·합성·글자·발상)로 나눠 검토 사유에 남긴다. 구도·합성 문제면 지적을 장면 지시에 붙여 **한 번만** 다시 만든다. 글자·발상 문제는 사람이 고친다.
- **절충**:
  - 관찰은 원고당 AI 호출 1번이 더 든다(그림 입력, 약 $0.03). 완성 밈 검토도 1번이 더 든다(약 $0.02).
  - 확대 좌표는 관찰 모델의 대략값이라, 작은 디테일은 조금 빗나갈 수 있다.
  - 자료 자체에 상품 사진이 없으면(예: 입장 안내 블로그) 구경할 장이 생기지 않는다. 같은 소재 글을 새로 **검색**해 사진을 찾는 단계는 다음 배치다.

## 결과

- 쉬워진 것:
  - 새 장식을 CSS 파일 하나로 더할 수 있다. 소식형의 배치 개선이 스킨에도 그대로 간다.
  - 카드에서 "확인하세요"류가 구조적으로 빠진다.
- 어려워진 것:
  - 스킨은 HTML 구조를 못 바꾼다. 장마다 다른 콜라주(사진을 겹쳐 흩뿌리기)나 번호 동그라미 주석은 구성 쪽 표현으로 따로 더해야 한다.
  - 기울인 카드·사진은 회전한 상자가 가로 넘침으로 잡혀 글자가 최소 크기까지 줄었다(실호출 확인). 그래서 회전은 넘침 검사 밖의 작은 칩(부제)에만 쓴다.
  - 정규식이 놓치는 떠넘기기 표현은 남는다.
- 다시 볼 조건:
  - 스킨이 셋 이상으로 늘면 구성 쪽에 "콜라주" 같은 표현을 계약으로 올릴지 메인과 합의한다.
  - 캡션 출처 블록이 플랫폼 글자 수를 자주 넘기면 주소 수를 줄인다.
