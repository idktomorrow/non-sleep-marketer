## 배경

만화 2컷과 보조 스티커는 유료 그림 호출이고, 한 원고에 여러 장이며, 사람이 장면·캐릭터를 바꾸거나 대사만 고칠 수 있다. 메모리 큐는 재시작에 사라지고, 콘텐츠 판 번호로만 유효성을 보면 1번째 컷이 적용되는 순간 2번째 컷이 "낡은 결과"가 되고 대사 수정도 그림을 버리게 만든다.

## 선택지

1. **요청 안에서 동기 호출** / 대시보드 요청이 1~2분 붙잡히고 작업 스레드(게시·답글)가 막힌다.
2. **메모리 큐 + 콘텐츠 판 번호로 유효성** / 재시작에 유실, 2컷이 서로를 무효화.
3. **DB 작업 표 + 슬롯별 spec 지문 (채택)** / 호출 전에 행이 있어 재시작·중복을 다룰 수 있고, 유효성은 그 자리의 그림 조건으로만 판단한다.

## 결정 (제안)

- **출연진(Cast)**: 주인공(만화)과 보조(정보 카드 스티커, 없음 가능)를 따로. `CharacterRef.kind ∈ account(계정 캐릭터)|content(이 콘텐츠의 캐릭터)|custom(직접 지정)`과 `use ∈ generate|real_only`는 **다른 축**이다. 콘텐츠 캐릭터도 참조가 있으면 생성 주인공이 된다. 참조 파일은 원고 폴더(`media/content/<id>/cast/`)로 **복사**하고 프로필 판 번호를 남긴다(프로필을 고쳐도 과거 원고는 그대로). 기본값은 작업 공간의 `hero_default`/`sidekick_default`, 없으면 설정의 캐릭터 그림.
- **캐릭터 프로필**: `<프리셋 폴더>/characters/<id>/profile.yaml + ref-*.png`(상품 사진과 분리). 설정에서 만들기·참조 올리기/지우기·외형 설명으로 참조 그림 만들기(유료, 작업 표 경유).
- **제작 슬롯**: 만화 컷마다 `s{i}.panel{j}`, 정보 카드의 첫 메모에 `s{i}.sticker`(보조가 있을 때). spec 지문 = 장면·캐릭터(kind·프로필 판·외형)·참조 파일 내용·크기·투명·품질. **라벨·말풍선은 넣지 않는다**(대사만 고쳐도 진행 중 그림은 적용).
- **2컷 의존**: 2번째 컷은 1번째 컷이 활성화된 뒤에 그 결과 파일을 참조에 더해 만든다("같은 캐릭터, 다른 장면"). 1번째가 실패하면 기다리던 2번째는 취소.
- **작업 표 `image_jobs`**: queued → claimed → sent → succeeded | succeeded_stale | failed | unknown | cancelled. 같은 대상·같은 spec이 진행 중이면 다시 만들지 않는다. 보내기 직전 spec을 다시 보고 바뀌었으면 비용 없이 취소. 결과 반영은 한 트랜잭션(그림 이력 추가 + 지금 spec과 같으면 덱 적용·활성화, 다르면 후보). 재시작: claimed → queued, sent → unknown.
- **오류**: 정책 차단은 사유와 함께 실패, 한도·과부하는 `next_attempt_at` 재예약(3회), 키·크레딧은 실패 + 알림, **응답 불명은 자동 재시도 없이 unknown**(사람이 "다시 요청" 또는 "과금 안 됨 확인"으로 원장 예약 해제). 키가 없으면 작업마다 이유를 남기고 도형 등으로 대체하지 않는다.
- **그림 이력 `content_images`**: 업로드·외부 원본·AI 모두 기록(active | candidate | archived). 이전 결과 재사용 = 활성 전환. 직접 올린 실제 자료는 `ai=false`라 AI 표기가 붙지 않는다.
- **실행**: `images` 잡(1분, 한 번에 3장)이 처리. 제작 모드 `full`이면 밈 대본 직후 작업을 넣고, `plan_first`(기본)면 사람이 "그림 없는 자리 모두 만들기"를 누른다. 추천 슬롯 단계는 작업 집합에서 파생(producing·failed_image·unknown_image·ready).

## 결과

- 정보 2 + 밈 1에서 밈 컷만 실패해도 그 컷만 다시 요청한다. 장면을 바꾸기 전에 도착한 그림은 후보로 남아 골라 쓸 수 있다.
- 어려워진 것: 상태가 작업 표·그림 이력·슬롯 단계로 나뉜다(역할이 다르다). 응답 불명은 사람이 정리한다(서버 조회 API 없음).
- 테스트: 도메인(지문은 대사 무관·장면/참조/품질에 반응, 2번째 컷 참조, 참조 없음·실제 자료만은 대체 없이 실패), 엔진(두 컷 활성화, 진행 중 대사 수정 적용, 장면 변경 시 후보·보내기 전 취소, 실패 컷만 재시도, 응답 불명 무재시도·재시작 복구, 비용 상한·중복 방지, 키 없음, 세 가지 출연진, 실제 자료 업로드, 프로필 복사본), 라우트·캐릭터 설정.
