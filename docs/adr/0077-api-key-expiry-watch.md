# 0077. API 키 만료는 사람이 적은 만료일 메모 + health의 하루 한 번 자동 확인 + 실행 중 401/403 즉시 알림으로 잡는다

- 상태: 채택
- 날짜: 2026-11-21
- 결정한 사람: 선웅제(배치 C53 요청), 대행 Claude
- 관련: [0028](0028-dashboard-settings.md)(설정 화면, 키는 keyring), [0054](0054-error-taxonomy-and-evidence.md), devlog [2026-11-21-batch-C53](../devlog/2026-11-21-batch-C53.md)

## 배경

운영 Claude 키는 30일 만료로 발급한다. 2026-11-12 00:56 키가 만료되자 generate가 401로 실패했는데, 로그 한 줄만 남고
알림이 없어 그날 게시가 0건이었다. 프로그램은 만료일을 API로 알 수 없다. Anthropic은 키 만료일을 조회하는 API가 없고,
Gemini 키는 만료가 없다. 설정 화면의 "확인"(모델 목록 조회, 비용 0)은 사람이 눌러야만 돈다.

## 선택지

1. **실행 중 401만 알린다**: 단순하다 / 알게 되는 순간이 이미 실패한 뒤다(새벽 생성이면 아침까지 모른다).
2. **공급자 콘솔에서 만료일을 읽는다**: 정확하다 / 그런 공개 API가 없다. 콘솔 화면을 읽으면 로그인·화면 변경에 약하다.
3. **사람이 적은 만료일 메모로 미리 알리고, 하루 한 번 자동 확인하고, 실행 중 401/403은 바로 알린다**: 미리 알 수 있고,
   메모를 잊어도 자동 확인이 하루 안에 잡고, 그 사이 실패는 즉시 알린다 / 메모는 사람이 적어야 하고 틀릴 수 있다.

## 결정

3번. 가장 큰 이유: 만료일을 아는 건 발급한 사람뿐이라 "적어 두면 미리, 안 적어도 하루 안에" 두 겹이 필요하다.

- **왜 메모 방식**: 만료일은 키 값이 아니라 날짜라 설정 저장소(`key_expiry`)에 둔다(keyring 아님). 새 키를 저장하면 옛 날짜는
  지운다(옛 키의 날짜로 엉뚱한 알림이 가지 않게). 키를 지우면 날짜·알림·자동 확인 상태도 지운다.
- **왜 자동 확인을 health에 붙였나**: health는 30분마다 돌고 이미 "로그인 상태 점검"이라 키 점검과 성격이 같다. 새 잡을 만들면
  예약·따라잡기·실행 기록 배지를 또 만들어야 한다. 24시간 간격은 `key_check`의 마지막 시각으로 지키고, 플랫폼 점검 결과와
  섞이지 않게 별도 try로 감싼다. 네트워크를 타니 끄는 중이면 건너뛴다. 결과: invalid는 하루 한 번 error, limit은 같은 상태가
  이어지는 동안 한 번 warn, network·unknown은 판단할 수 없으니 알리지 않는다. 저장·"확인" 결과도 바로 기록해, 새 키로 바꾸면
  첫 화면의 옛 오류 배너가 바로 사라진다. 판단 못 한 저장 결과(연결 실패)는 옛 결과만 지워 다음 점검에서 바로 확인한다.
- **알림 단계 7·3·1·0 이유**: 7일은 한 주 안에 새 키를 발급할 여유, 3일은 주말을 끼어도 한 번 더, 1일·0일은 마지막 경고다.
  매일 보내면 무시하게 되니 단계마다 한 번만 보내고, 지난 뒤에는 실제로 멈춘 상태라 하루 한 번. 꺼져 있다 켜져 그날을 놓치면
  다음 단계 전까지는 놓친 단계로 한 번 보낸다(5일 남은 날 켜면 "5일 전"). 메모 날짜가 바뀌면 단계를 처음부터 센다.
- **즉시 알림**: generate가 401/403(`status_code`)을 만나면 "Claude API 키 오류"를 하루 한 번. 분류기가 Gemini·Claude 키 거절
  (401/403·`API_KEY_INVALID`)로 다음 분류기로 넘어갈 때도 같은 규칙. 둘 다 `key_check`를 invalid로 적어 같은 날 health의 자동 확인과
  겹치지 않는다(24시간 안이라 다시 부르지 않고, 불러도 하루 한 번).

## 결과

- 만료 7일 전부터 데스크톱 알림·알림함·첫 화면 배너(간단 모드 포함)로 미리 안다. 메모를 안 적어도 하루 안에 자동 확인이 잡는다.
- 키마다 하루 한 번 모델 목록 조회가 늘어난다(비용 0, 요청 3개).
- 메모가 틀리면 알림도 틀린다. 공급자가 만료일 조회 API를 내면 메모 대신 그것을 쓴다.
