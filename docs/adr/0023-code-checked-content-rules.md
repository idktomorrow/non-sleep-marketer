# 0023. 코드로 검사할 수 있는 원고 규칙은 생성 후 검사하고, 출처 줄은 게시할 때 붙인다

- 상태: 제안 (배치 Q1) · 날짜: 2026-10-13 · 관련: [0008](0008-autopublish-guardrails.md), [0019](0019-label-wording-and-placement.md), 이슈 #42

## 배경

2026-10-12 드라이런에서 다음 문제가 나왔다.

- 프롬프트에 "이모지는 한 개까지"가 있었는데 캡션에 ✔ 두 개와 ☕가 들어갔다.
- 스레드 글이 "자료에 따르면"으로 딱딱했다.
- 카드 목록에 "1." 번호가 이중으로 붙었다.
- 인스타 캡션과 스레드 글에 출처가 없었다.

모델은 프롬프트 규칙을 확률적으로만 지킨다.

## 선택지

1. 프롬프트만 강화: 싸다 / 여전히 어길 수 있고, 어긴 것을 모른다
2. **코드로 검사·교정할 수 있는 규칙은 코드가 맡는다**: 확실하다 / 다시 만들 때 비용이 든다

## 결정

2번. `nsm/domain/quality.py`에 규칙을 두고 프롬프트에도 같은 내용을 적는다.

- **고칠 수 있는 것은 고친다:** 카드 목록의 번호·기호는 떼고, 출처 줄은 게시할 때 붙인다. 출처 줄은 카드 마무리 장의 출처에서 사이트 이름 1~2개를 뽑은 것이다(예: "출처: 네이버 블로그"). 글자 수 상한(스레드 500자)을 맞출 때 출처 줄과 표기 문구는 남기고 가운데 본문만 줄인다.
- **고칠 수 없는 것은 검사한다:** 대상은 이모지 개수(말투 설정에서 읽음, 예: "이모지는 한 개까지" → 1)와 딱딱한 표현 목록이다. 어기면 한 번 다시 만들고, 그래도 어기면 자동 게시하지 않고 검토 대기열로 보낸다. 사유에는 "페르소나 규칙 위반: …"을 적는다. 비용 상한에 닿았으면 다시 만들지 않고 바로 검토로 보낸다.
- **관련성:** 방문 후기·여행기·일기는 제목 규칙으로 분류기 전에 거른다(비용도 아낀다). 분류기 지시문에도 "정보성 글만 관련"을 명시한다(jev·Claude 공통).

## 결과

- 다시 만들면 생성 비용이 최대 두 배다(콘텐츠당 약 6센트 → 12센트). 하루 비용 상한이 함께 막는다.
- 출처 줄은 원고(DB)에는 없고 게시 형태에만 있다. 대시보드 수정 화면의 원고에는 보이지 않는다.
- 제목 규칙은 보수적으로 잡았다("여행용 드립 키트" 같은 정보성 제목은 통과). 놓친 후기는 분류기 지시문이 거른다.
