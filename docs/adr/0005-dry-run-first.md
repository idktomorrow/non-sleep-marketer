# 0005. 실제 게시 전에 드라이런 MVP를 먼저 완성한다

- 상태: 채택 · 날짜: 2026-10-11 · 결정: 선웅제 · 관련: [planning-decisions](../planning-decisions.md) Q21, 이슈 #10

## 배경

실계정 연결은 로그인·제재 위험·UI 변경 때문에 가장 불확실하다. 그 불확실성이 수집·생성·정책·대시보드 개발을 막으면 안 된다.

## 선택지

1. **플랫폼 하나를 끝까지(실계정) 먼저**: 실제 위험을 일찍 발견 / 나머지 개발이 어댑터에 묶임
2. **드라이런 어댑터로 전체 흐름 먼저, 실계정은 2주차**

## 결정

2번. 드라이런 어댑터는 같은 포트를 구현하므로 엔진·대시보드는 실계정 여부를 모른다.

## 결과

- 드라이런은 제품 기능이다(사용자가 계정 없이 체험). 게시물은 `preview/` 폴더에, 댓글·지표는 픽스처로 시뮬레이션.
- 실계정의 위험은 배치 B(1일차 검증)에서 미리 일부 확인해 둔다.
- 드라이런 어댑터도 어댑터 계약 테스트를 통과해야 한다.
