# 0064. 로그인 표지가 보이는데 계정 이름을 못 읽으면 `auth`가 아니라 `ui_changed`로 보고, 계정으로 행동하기 직전에는 핸들을 반드시 확인한다

- 상태: 제안
- 날짜: 2026-11-06
- 결정한 사람: 배치 C39(Claude), 사용자 검토 대기
- 관련: [incidents/0012](../incidents/0012-2026-11-05-threads-profile-icon-title.md), ADR 0063(스레드 프로필 아이콘 `<title>`), ADR 0060(로그인 세부 상태), ADR 0054(오류 종류 표)

## 배경

로그인 판정은 "내 계정 이름(핸들) 읽기" 하나에 걸려 있었다.
- `nsmAssertHandle`은 `readHandle`이 빈 값이면 `NsmError('login')`을 던진다.
- health는 핸들이 비면 화면을 `classify`로 나눈다. 로그인 폼·보안 확인 문구가 없으면 `unknown`이 되고, health 잡이 플랫폼을 멈춘다.

2026-11-05 스레드가 프로필 아이콘 이름 방식을 바꾸자, 로그인된 화면에서 핸들을 못 읽었다. 스레드는 약 1시간 39분 "로그인 필요(원인 모름)"으로 멈췄다(incidents/0012).

그때 증거(`threads-20261105-205557`)에는 로그인한 사람만 보는 것들이 있었다. "nonsleepmarketer님에게 답글 남기기...", 왼쪽 메뉴의 "새로운 스레드", 이름표 "새로운 스레드"·"알림"이다.

이 실패는 오류 종류 표로는 `ui_changed`(화면 변경, 코드 수정 필요)다. 하지만 `auth`(다시 로그인)로 보였고, 플랫폼 전체가 멈췄다.

## 선택지

1. **지금처럼 핸들만**: 단순하다. 화면이 조금 바뀔 때마다 멈추고 엉뚱한 안내("다시 로그인")를 한다.
2. **로그인 표지로 로그인을 인정하고 행동도 허용**: 멈추지 않는다. 하지만 계정이 맞는지 모른 채 게시·답글을 한다. process.md와 CLAUDE.md의 "로그인된 계정이 설정 핸들과 다르면 게시하지 않는다"를 어긴다.
3. **표지는 판정에만, 행동 직전에는 핸들 필수**(이것).
   - health는 표지가 있으면 성공으로 보고 멈추지 않는다. 대신 화면 변경으로 기록하고 알린다.
   - 게시·답글·댓글 읽기 직전의 `nsmAssertHandle`은 핸들을 못 읽으면 동작하지 않는다. 그때 표지가 있으면 `ui`(→ `ui_changed`), 없으면 지금처럼 `login`(→ `auth`)이다.

## 결정

3을 고른다. 가장 중요한 이유는 두 가지 안전장치를 동시에 지킬 수 있어서다. 하나는 "다른 계정에 올리지 않는다"는 가드레일이고, 다른 하나는 화면 변경을 로그인 문제로 오인하지 않는 것이다.

### 판정 규칙

`auth_state.looks_logged_in(page, platform)`은 셋을 모두 만족할 때만 참이다.
- 빈 화면(`is_blank`)이 아니다.
- `classify(page)`가 `unknown`이다. 즉 로그인 폼·본인 확인·인증·제한 문구와 로그인·확인 주소 어디에도 안 걸린다.
- 그 플랫폼의 `logged_in_markers`가 화면 글이나 이름표에 있다.

문구는 `nsm/adapters/platforms/data/auth_states.json` 한 곳에 둔다. 브라우저 쪽 `nsmAssertHandle`은 같은 정규식 원문을 `ARGS.nsm_auth`(`auth_state.js_auth_args`)로 받는다. 로그인 폼과 화면 글 규칙을 합친 `blockers`, 그리고 확인 주소 `check_urls`가 함께 간다.

| 플랫폼 | 표지(정규식, 대소문자 무시) | 근거 |
|---|---|---|
| 스레드 | `님에게 답글 남기기` | 글 페이지의 답글 입력칸. 0012 증거 text |
| | `새로운 소식을 공유해보세요` | 프로필의 글쓰기 버튼. `threads.py` `_PUBLISH`가 누르는 버튼 |
| | `Reply to <이름>...`, `What's new?` | 영어 화면 대응. 실제 증거로 확인하지 못함 |
| 인스타그램 | 줄 전체가 `새로운 게시물`·`New post`·`만들기`·`Create`·`알림`·`Notifications` | 왼쪽 메뉴. `instagram.py`가 누르는 "새로운 게시물" 아이콘 이름. 로그인된 인스타그램 증거는 아직 없다 |

메뉴 문구는 로그아웃 화면에도 보이므로 표지에서 제외하고, 글쓰기 칸 문구만 쓴다(스레드 "새로운 스레드"·"Start a thread"는 로그아웃 홈·글 페이지 왼쪽 메뉴에도 있음을 새 브라우저로 확인했다).

"줄 전체"는 `(^|\n)…(\n|$)`다. "알림 설정" 안내 창이나 "새 계정 만들기" 같은 문장 속 낱말은 표지가 아니다.

**확인한 것**:
- 기존 증거 15개(`~/.nsm/logs/shots/*/dialogs.json`)와 테스트 픽스처 5개에 표지를 대 봤다. 인스타그램 본인 확인·문자 인증 4건과 스레드 빈 화면 1건에서는 하나도 맞지 않았다.
- 처음 표지(메뉴 문구 포함)로는 로그인된 스레드 화면 4건에서만 맞았다. 0012 사례와, 10-30·11-04·11-05에 글이 안 열렸던 화면 3건이다(로그인은 돼 있었음). 메뉴 문구를 뺀 뒤에는 2건(0012 사례, 10-30)만 답글 입력칸으로 맞는다. 11-04·11-05의 2건은 메뉴 문구로만 맞았던 화면이라, 그런 화면은 핸들을 못 읽으면 지금처럼 `auth`가 된다(틀려도 멈추는 쪽).
- 로그아웃 스레드 화면(메뉴 문구 + "가입하기") 픽스처 `threads-logged-out-menu`: 그대로도, "가입하기"·"로그인"을 뺀 경우에도 표지가 맞지 않는다.
- 실계정 브라우저는 열지 않았다.

### health와 health 잡

- `_health`: 핸들이 비어도 `looks_logged_in`이면 다음처럼 처리한다.
  - `HealthStatus(logged_in=True, detail="… 로그인은 됐으나 계정 이름을 못 읽음(화면 변경)")`을 돌려준다.
  - 어댑터에 `ui_warning`(문구, 증거 폴더)을 남긴다.
  - 증거는 `ui_changed` 종류로 한 시간에 한 번 남긴다. 스크린샷은 `auth`나 `ui_changed` 증거 중 하나라도 남길 수 있을 때 찍는다.
  - 정상 로그인이나 로그인 실패면 `ui_warning`은 `None`이다.
- health 잡은 성공으로 보고 멈추지 않는다. 멈춰 있던 플랫폼이면 푼다.
- `ui_warning`이 있으면 플랫폼별로 6시간에 한 번 장애 기록(`ui_changed`, 증거 폴더 포함)을 남기고 알린다. 6시간 시계는 게시의 화면 변경 알림과 같은 키(`ui_changed_notified`)다. 30분마다 같은 기록이 쌓이지 않게, 알릴 차례일 때만 기록한다.

### 행동 직전 (원칙 2)

`nsmAssertHandle`이 표지를 보고 `ui`를 던지면 어댑터는 `PlatformError(kind="ui_changed")`를 낸다(기존 `_KIND_BY_CODE` 매핑). 엔진은 기존 표대로 처리한다.
- 게시: 재시도 없이 원고를 검토로 되돌리고 알린다(6시간에 한 번).
- 댓글 확인: 그 회차만 실패로 기록한다. 플랫폼을 멈추지 않고 연속 실패 쉬기에도 세지 않는다.
- 답글: 그 댓글을 사람 확인으로 넘긴다.

## 결과

- 화면이 조금 바뀌어도 플랫폼 전체가 멈추지 않는다. 사용자는 "다시 로그인"이 아니라 "화면 변경(코드 수정 필요)" 알림과 증거 폴더를 받는다.
- 그동안 게시·답글은 하지 않는다. 계정을 확인하지 못했기 때문이다.
  - 게시 잡이 돌 때마다 차례가 된 원고가 한 건씩 검토로 돌아간다(화면 변경은 재시도 없음). 알림은 6시간에 한 번이라, 오래 이어지면 승인 대기열이 조용히 비워진다. 고친 뒤 다시 승인해야 한다.
  - 미리 건너뛰는 방식(게시 잡이 `ui_warning`을 보고 시도하지 않음)은 다음 배치 후보로 남긴다.
  - 멈춰 있던 플랫폼을 풀 때 "다시 연결됨" 알림도 "다시 시작"이 아니라 "게시·답글은 계정 확인이 될 때까지 하지 않음"으로 알린다.
- **감수하는 위험: 로그아웃 화면에 같은 문구가 들어오는 경우**. 메타가 로그아웃 화면에 글쓰기 칸 문구를 보여 주고, 로그인 폼 문구도 우리 규칙과 다르게 바꾸면 이렇게 된다. 스레드 왼쪽 메뉴는 실제로 로그아웃 화면에도 있어서("가입하기"가 로그인 폼 규칙에 걸려야만 로그아웃으로 판정됐다) 표지에서 뺐다.
  - 로그아웃을 "화면 변경"으로 잘못 알린다. 사람이 해야 할 일(다시 로그인)을 늦게 알게 된다.
  - 감수하는 까닭: 이 경우에도 게시·답글은 핸들 확인을 못 해 하지 않는다. 즉 틀려도 안전한 쪽(행동 안 함)이고, 알림은 그대로 간다. 반대 방향(로그인됐는데 멈춤)은 0012에서 실제로 일어났다.
  - 표지는 로그인 폼·보안 확인 문구가 없을 때만 참이고, 줄 전체 일치로 좁혀 이 위험을 줄였다.
- 다시 볼 조건: 로그인된 인스타그램 증거가 생기면 표지를 실제 문구로 확인한다. 화면 변경 알림이 로그아웃으로 밝혀진 일이 생기면 그 화면 글을 픽스처로 넣고 규칙을 고친다.
- ADR 0063의 "대체 경로 사용 기록"은 이번에도 하지 않았다(남은 후보).
