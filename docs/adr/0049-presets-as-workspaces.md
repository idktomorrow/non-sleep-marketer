# 0049. 프리셋은 "설정 묶음"이 아니라 작업 공간이다: 프리셋마다 DB 파일을 따로 둔다

- 상태: 제안 (배치 C29. 선웅제 결정: 프리셋 도입, 자료·댓글·성과도 프리셋별로. 방식(DB 분리)은 배치 기본값. 결과물을 보고 되돌릴 수 있음)
- 날짜: 2026-10-21
- 관련: [ADR 0006](0006-single-process-duckdb.md)(단일 프로세스·DuckDB), [ADR 0046](0046-character-images.md)(캐릭터 그림)

## 배경

페르소나를 바꿔 가며 써 보고 싶다("치이카와 정보 계정"과 "카페 브랜드"를 번갈아). 설정 화면에서 페르소나·브랜드를 손으로 고쳐도 되지만, 돌아올 때 다시 쳐야 하고 그 사이 쌓인 자료·원고·성과가 섞인다.

섞이면 생기는 문제는 UI 불편이 아니라 **동작 오류**다.
- 자료의 "관련 있음/없음"은 페르소나의 관심 주제 기준으로 판정해 DB에 닫아 둔다. A일 때 "관련 없음"으로 닫힌 카페 기사는 B로 바꿔도 다시 보지 않는다 → B가 자료를 못 받는다.
- 원고는 특정 말투로 쓴 것이고 댓글은 그 원고에 달린 것이다. 성과 비교는 프리셋을 두는 이유 자체다.

## 선택지

1. **설정만 저장·전환**(DB 공유) → 위 문제 그대로. 반나절.
2. **한 DB에 `preset` 열을 달고 모든 조회에 필터** → 비교 화면은 쉽지만 조회가 40개 남짓이라 하나만 빠져도 다른 프리셋 자료가 섞여 보인다. 도메인 모델(동결)을 건드릴 수도 있다. 이틀.
3. **프리셋마다 DB 파일**(채택) → 쿼리 수정 0, 새는 곳 없음. `Database.switch()`로 연결만 갈아끼우면 Repository들은 그대로. 하루.

## 결정

- `<NSM_HOME>/presets/<이름>/` 에 `preset.yaml`(페르소나·브랜드), `brand/`(캐릭터 그림 복사본), `data.duckdb`. **기본 프리셋은 기존 `data.duckdb`를 그대로 쓴다**(옮기지 않음, 되돌리기 쉬움).
- 공유하는 것: 계정 핸들·브라우저 로그인(실계정과 묶여 있어 프리셋이 바꾸지 않는다), API 키, 운영 설정(`settings`), 업로드 폴더, 렌더 결과·리포트 폴더.
- 전환은 **작업 스레드에서**(`scheduler.submit`) 한다: 다른 잡과 겹치지 않고, `Database` lock 안에서 옛 연결을 닫고 새 파일을 연다. 순서: 지금 프리셋 자동 저장 → 대상 설정 입히기·저장·반영 → DB 교체(실패하면 설정 되돌림) → 새 DB의 중단 작업 복구(`recover_interrupted*`).
- 설정 화면 맨 위 "프리셋" 칸: 목록(이름·페르소나·브랜드·주제)·전환·지우기·"지금 설정을 저장". 상단 바에 기본이 아닌 프리셋 이름 표시.
- 지우기는 폴더째(DB 포함). 지금 쓰는 프리셋과 기본 프리셋은 못 지운다. 이름 비교는 폴더(slug) 기준("내 브랜드"와 "내-브랜드"는 같은 프리셋). 다른 기존 프리셋 위에 "지금 설정을 저장"은 거부한다(그 프리셋의 DB가 다른 페르소나 것이 되지 않게).
- 켤 때(`nsm run`·`nsm job`)는 설정의 `preset`이 가리키는 DB를 연다. 재시작해도 전환한 프리셋이 이어진다.
- 전환 순서는 설정 저장 → DB 교체. DB 교체가 실패하면(깨진 파일) 설정을 되돌려 둘이 어긋나지 않게 한다. `Database.switch`는 새 파일을 먼저 열어 스키마까지 확인한 뒤에야 바꾼다.
- 백업 파일 이름에 프리셋을 넣는다(`data-<프리셋>-날짜.duckdb`). 기본은 예전 그대로.

## 결과

- 프리셋별로 자료·원고·댓글·성과·알림함이 완전히 나뉜다. 되돌리려면 설정의 `preset`을 `기본`으로 두고 `presets/` 폴더를 지우면 끝(기본 DB는 손대지 않았다).
- 어려워진 것
  - **하루 비용 상한이 프리셋마다 따로** 센다(비용 기록이 DB 안에 있어서). 전환한 날에 한해 최대 두 배까지 쓸 수 있다. 공통 장부로 빼는 건 필요해지면.
  - 낱말 대체 분류기(키가 하나도 없을 때만)의 주제 목록은 켤 때 만든다. 전환 뒤엔 예전 주제로 남는다 → 다시 켜면 해결. Gemini·Claude 분류기는 매번 현재 설정을 읽어 영향 없다.
  - 성과 화면은 지금 프리셋 것만 보인다. 프리셋끼리 비교는 다음 배치(다른 프리셋 DB를 읽기 전용으로 붙여서).
  - 백업은 지금 열린 DB만 한다. 다른 프리셋 DB는 전환해서 쓸 때 백업된다.
- 다시 볼 조건: 프리셋을 둘 이상 실제로 운영하게 되면 비용 공통 장부와 비교 화면을 붙인다. 프리셋을 안 쓰게 되면 이 배치를 되돌린다.
