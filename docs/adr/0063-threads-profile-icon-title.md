# 0063. 스레드 내 핸들은 프로필 아이콘의 aria-label 또는 `<title>`로 읽고, 왼쪽 메뉴의 설정 핸들 링크를 마지막 대체로 둔다

- 상태: 제안
- 날짜: 2026-11-05
- 결정한 사람: 배치 C38(Claude), 사용자 검토 대기
- 관련: [incidents/0012](../incidents/0012-2026-11-05-threads-profile-icon-title.md), ADR 0054(오류 종류 표), ADR 0060(로그인 세부 상태), 배치 C37

## 배경

스레드 어댑터는 로그인 여부와 계정을 `readHandle`로 확인한다. 왼쪽 메뉴의 프로필 링크(`<a href="/@핸들">`)를 찾아 그 핸들을 읽는다. 핸들이 비면 `nsmAssertHandle`이 `NsmError('login', '로그인돼 있지 않음')`을 내고, 건강 점검은 그 플랫폼을 멈춘다.

2026-11-05에 스레드 화면이 바뀌었다(사용자 확인).

| | 전 | 후 |
|---|---|---|
| 링크 | `<a href="/@핸들">` | `<a href="/@nonsleepmarketer" role="link">` |
| 아이콘 이름 | `<svg aria-label="프로필">` | `<svg role="img"><title>프로필</title></svg>`, aria-label 없음 |

`readHandle`은 `svg[aria-label="프로필"]`만 찾았다. 그래서 로그인된 화면에서 빈 핸들을 돌려줬고, 20:56부터 스레드가 "로그인 필요"로 멈췄다. 증거 화면(`~/.nsm/logs/shots/threads-20261105-205557`)에는 "nonsleepmarketer님에게 답글 남기기..." 입력칸과 왼쪽 메뉴 "새로운 스레드·프로필·인사이트"가 보인다.

## 선택지

1. **이름 두 방식만**: svg의 `aria-label` 또는 svg 안 `<title>` 글이 "프로필"/"Profile"(앞뒤 공백 제거)인 링크의 핸들을 쓴다.
   - 장점: 링크에서 읽은 실제 핸들이라, 다른 계정으로 로그인돼 있으면 계정 불일치(`mismatch`)를 그대로 잡는다.
   - 단점: 아이콘 이름이 또 바뀌면(다른 단어, 이름 없음) 같은 오판이 반복된다.
2. **1 + 마지막 대체**: 둘 다 못 찾으면 `a[href="/@" + 설정 핸들]`(하위 주소 없는 정확한 주소) 중 왼쪽 메뉴에 있는 링크를 찾아 설정 핸들을 돌려준다. 왼쪽 메뉴는 `nav` 안이거나 아이콘(svg)을 가진 링크로 본다. 글 카드(`[data-pressable-container="true"]`)와 가운데 칼럼(`[aria-label="칼럼 본문"]`) 안 링크는 뺀다.
   - 장점: 아이콘 이름만 바뀌는 다음 변경에도 멈추지 않는다.
   - 단점: 설정 핸들로 찾으므로 이 경로로는 계정 불일치를 잡을 수 없다. 메뉴에 내 링크가 있으면 "내 계정"이라고 볼 뿐이다.
3. **대체를 `role="link"`까지 넓힘**: 스레드는 거의 모든 `<a>`에 `role="link"`를 붙인다. 글 작성자 링크와 구별되지 않아 기각한다.

## 결정

2를 고른다. 가장 중요한 이유는 다음과 같다. 화면 문구 변경은 사람이 고치기 전까지 재시도로 풀리지 않는다(incidents/0004). 그런데 지금은 "로그인 필요"로 보여 사용자가 엉뚱한 곳을 확인하게 된다. 대체 경로가 있으면 같은 종류의 변경에서 멈추지 않는다.

위험은 이렇게 줄였다.
- 대체는 이름 두 방식이 모두 실패했을 때만 쓴다. 정상 화면에서는 링크의 실제 핸들을 읽어 계정 불일치를 잡는다.
- 글 작성자 링크로 착각하지 않도록 글 카드와 가운데 칼럼 안은 뺀다. 내 글 페이지에서는 작성자 링크도 `/@설정핸들`이라 이 제외가 없으면 로그아웃된 상태도 로그인으로 보인다.
- 하위 주소가 있는 링크(`/@me/post/…`)는 대체 후보가 아니다. 아이콘도 메뉴도 아닌 맨 링크(본문 속 멘션 등)도 후보가 아니다.
- 로그아웃 화면에는 왼쪽 메뉴의 프로필 링크가 없다. 그래서 대체가 로그아웃을 로그인으로 볼 가능성은 낮다. 확실하지 않은 점: 실제 메뉴가 `<nav>` 안인지는 확인하지 못했다(실계정 브라우저를 열지 않음). 그래서 아이콘을 가진 링크도 메뉴로 본다.

## 결과

- 테스트(`tests/unit/test_page_errors.py`, 가짜 탭)는 다음을 확인한다.
  - aria-label 화면, `<title>` 화면(한·영, 공백), 대체 경로에서 모두 핸들을 읽는다.
  - `<title>` 방식에서 다른 계정이면 계정 불일치로 나온다.
  - 프로필 링크가 없거나 글 카드 안 작성자 링크·하위 주소·맨 링크뿐이면 여전히 로그인 필요다.
  - 건강 점검도 `<title>` 화면을 로그인으로 본다(멈춤이 풀린다).
- 대체 경로를 탔는지는 지금 기록하지 않는다. 다음에 화면이 또 바뀌어 대체로만 버티고 있어도 알기 어렵다.

### 다음 배치 후보(이번에 구현하지 않음)

- **로그인 판정을 핸들 하나에 걸지 않기**(C39에서 구현, [ADR 0064](0064-logged-in-markers.md)): 핸들을 못 읽어도 로그인된 화면의 표지가 보이면 `auth`가 아니라 `ui_changed`로 판정한다. 표지의 예는 답글 입력칸("…님에게 답글 남기기"), 왼쪽 메뉴 "새로운 스레드"·"인사이트"·"저장됨", "새로운 소식을 공유해보세요"다. 그러면 사용자는 "로그인 필요(원인 모름)" 대신 "화면이 바뀜(코드 수정 필요)"을 보고 알맞은 사람에게 넘긴다. 로그인 폼·본인 확인 화면이면 지금처럼 `auth`와 E5 세부 상태로 나눈다.
- **대체 경로 사용 기록**: readHandle이 대체로 읽었으면 결과에 표시를 붙인다. 건강 점검이 하루 한 번 "프로필 아이콘을 이름으로 못 찾음(화면 변경 의심)"을 실행 기록에 남긴다.
- 인스타그램 `readHandle`도 같은 방식(이름 하나에 의존)인지 점검한다.
