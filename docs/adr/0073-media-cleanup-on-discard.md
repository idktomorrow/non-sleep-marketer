# 0073. 폐기한 원고의 이미지는 폐기 즉시 지우고 새벽 정리가 한 번 더 쓴다. 게시된 원고의 카드는 영구

- 상태: 채택
- 날짜: 2026-11-17
- 결정한 사람: 선웅제(배치 C48 요청), 세부는 Claude
- 관련: devlog [2026-10-25-batch-C33](../devlog/2026-10-25-batch-C33.md)(정리는 백업 뒤), devlog [2026-11-17-batch-C48](../devlog/2026-11-17-batch-C48.md)

## 배경

`media/`에는 원고마다 카드(`cards/<id>/`, 게시 때 렌더), 미리보기(`previews/<id>/`, 카드 편집), 올린 배경
(`uploads/backgrounds/<id>/`)이 쌓인다. maintenance 잡은 DB 쪽만 정리하고 이미지는 지우지 않았다. 운영 PC 기준(사용자
측정): 게시 71건 카드 40.7MB, 게시 원고의 중복 미리보기 7.5MB, 폐기 원고 미리보기 2.5MB. 폐기는 끝 상태라(`discarded`
에서 나가는 전이 없음) 그 이미지는 다시 쓰이지 않는다. 게시된 원고의 카드는 검토 목록 썸네일과 글 상세에 쓰인다.

## 선택지

1. **폐기 즉시만**: 바로 비지만, 지우기에 실패하거나 C48 전에 폐기된 원고는 남는다.
2. **새벽 정리만**: 한곳에서 하지만 폐기한 뒤 다음 04:30까지 남는다.
3. **둘 다**(폐기 즉시 + 새벽 쓸기): 코드 경로가 둘이지만 같은 함수 하나(`remove_content_media`)를 쓴다.
4. 게시 카드도 오래되면 지우기: 디스크는 더 줄지만 화면의 썸네일·상세가 깨진다.

## 결정

3번. 폐기 라우트는 상태 전이가 성공한 뒤 지우고, 실패해도 폐기는 성공(WARNING 한 줄). 새벽 정리(백업 뒤)는 폐기 원고
폴더 전부와, 카드(`slide-01.png`)가 있는 게시 원고의 미리보기만 지운다. 게시 카드는 화면에 쓰여 영구로 둔다(4번 기각).
ULID 모양이 아닌 폴더(`_contract` 같은 계약 테스트 흔적)와 `style-previews`는 건드리지 않는다.

## 결과

- 폐기·중복 미리보기(약 10MB)는 다음 새벽 정리에서 빠지고, 이후로는 폐기 즉시 빠진다.
- 디스크는 게시 수에 비례해 계속 는다(게시 1건에 카드 약 0.6MB). 게시가 수천 건이 되거나 디스크가 문제 되면
  "오래된 게시 카드는 첫 장만 남기기"를 다시 본다.
