# 0072. 대시보드 화면 정리 2차: 주간 리포트 변환기를 직접 쓰고, 자료는 50건씩, 휴대폰 표는 카드로 쌓는다

- 상태: 제안
- 날짜: 2026-11-14
- 결정한 사람: 선웅제(배치 C45 요청), 세부는 Claude
- 관련: [ADR 0025](0025-dashboard-design.md)(대시보드 모양), [ADR 0070](0070-ask-page-for-reading.md)(문서 질문 화면 정리, 같은 "기존 토큰만" 원칙), devlog [2026-11-14-batch-C45](../devlog/2026-11-14-batch-C45.md)

## 배경

데스크톱 1280px·휴대폰 390px로 찍어 본 화면에서 아래 문제가 보였다.

- 주간 리포트가 `<pre>`에 통째로 들어가 `#`·`**`·`-`가 글자로 보였다. 마크다운 라이브러리는 의존성에 없다.
- 자료 탭은 모은 자료 150건을 한 번에 그려 데스크톱에서 9,700px가 넘었다.
- 성과 탭은 표 셋뿐이었고, 팔로워 표는 날짜×플랫폼마다 한 줄이라 60줄이 넘었다.
- 휴대폰에서 표 오른쪽이 잘렸고, 옆으로 밀 수 있다는 표시가 없었다. 상단 메뉴도 마찬가지였다.
- 사람 말이 아닌 문구가 셋 있었다: "사람 승인 11/10건", "PlatformError: threads: … (증거: …)", 영어 단계 이름.

## 선택지

### 주간 리포트 렌더링

1. **마크다운 라이브러리를 더한다**(markdown-it-py 등): 기능은 많지만 의존성이 하나 늘고, 리포트가 쓰지 않는 문법(HTML 통과, 링크, 표)까지 열린다. 그만큼 이스케이프를 따로 걱정해야 한다.
2. **리포트가 쓰는 문법만 다루는 작은 변환기를 직접 쓴다**(`nsm/app/md_lite.py`, 70줄 남짓): 제목·굵게·목록·하위 목록·빈 줄만 다룬다. 줄마다 먼저 이스케이프한다.

### 자료 목록 길이

1. 예전처럼 150건을 한 번에 그린다.
2. 50건씩 나누고 GET `?offset=`로 넘긴다(JS 없이).
3. 무한 스크롤: JS가 필요하고, 뒤로 가기를 하면 위치를 잃는다.

### 휴대폰 표

1. 모든 표를 가로 스크롤로 두고 표시만 더한다.
2. 줄이 긴 표(댓글·실행 기록·게시물별 성과)는 행을 카드처럼 세로로 쌓는다(`table.stack` + `td::before { content: attr(data-label) }`). 나머지는 가로 스크롤에 "더 있음" 표시를 단다.

## 결정

- **주간 리포트**: 변환기를 직접 쓴다(선택 2).
  - 리포트 생성기(`weekly_report.py`)가 쓰는 범위는 좁고, 같은 저장소에서 함께 바뀐다.
  - 모르는 줄은 문단으로 두니, 생성기가 새 문법을 써도 글은 보인다(모양만 덜 다듬어짐).
  - 태도는 `ask_format.answer_html`과 같다. 전부 이스케이프한 뒤 우리가 만든 태그만 넣는다.
  - `#`는 h2로 내린다. 페이지 제목 h1("주간 리포트")은 템플릿이 쓴다.
- **자료 목록은 50건씩**(선택 2). `Repository.list_source_items_view`에 `offset`을 더했다.
  - 50은 데스크톱 한두 화면 분량이고, 하루 수집량(대개 20~40건)이 한 쪽에 들어간다.
  - 다음 쪽이 있는지는 51건을 읽어 안다. 건수 쿼리를 따로 두지 않는다.
  - 전체 건수는 이미 있는 `source_counts`로 제목 옆에 보인다.
- **휴대폰 표**: 선택 2. 쌓는 기준 폭은 720px다(카드 스타일 고르기 등 기존 좁은 화면 기준과 같음).
  - "더 있음"은 오른쪽 끝을 마스크 그라데이션으로 옅게 보이는 방식이다. JS 몇 줄이 끝까지 밀면 `.has-more`를 뗀다. 휴대폰에서는 첫 넘치는 표 위에 "옆으로 밀어 보세요"를 한 번만 붙인다.
  - CSS만으로 하는 스크롤 그림자(`background-attachment: local`)는 표 머리줄 배경이 가려서 쓰지 않았다.
- **성과 요약 카드**는 아래 표가 이미 쓰는 값만 올린다(`nsm/app/perf_summary.py`).
  - 팔로워의 "7일 전"은 마지막 기록일에서 7일 전, 그날 기록이 없으면 그 전 가장 가까운 날과 비교한다. 그보다 오래된 기록이 없으면 변화를 뺀다.
  - "사람 처리"는 `resolved` 건수다.
  - 날짜별 팔로워·비용 표는 `<details>`로 접는다.
- **댓글 화면 필터는 만들지 않는다.** 30일 댓글이 11건이라 한 화면에 다 들어가고, 필터는 쓰일 일보다 칸만 늘린다. 댓글이 하루 수십 건으로 늘면 다시 본다.
- **문구**
  - 보호 모드: "보호 모드 끝(사람 승인 N건)" / "보호 모드: 사람 승인 N/M건(모두 검토로)".
  - 실패 요약: `summary.friendly_error`가 예외 클래스 접두어, 영어 플랫폼 접두어(한국어로 바꿔 앞에 둠), `(증거: …)` 꼬리를 뗀다. 증거 id는 장애 화면 "자세히"에 있다.
    - DB에 이미 문장 형식으로 남은 기록은 `readable`이 오류 꼬리만 고쳐 보여 준다. 옛 `job: k=v` 형식은 원래대로 `describe`를 거친다.
  - 장애 단계 이름: `ko_stage` 필터를 쓰고, 원래 값은 `title` 속성에 둔다.
- **오늘 화면**: 할 일 칸을 가로로 꽉 채운다. 숫자 카드는 한 줄(`auto-fit`이라 고급 4칸, 간단 3칸, 휴대폰 2칸)이고, 페르소나·자동 게시는 그 다음 한 판에 나란히 둔다.

## 결과

- 지난 리포트 파일도 같은 형식이라 다시 만들지 않아도 전부 읽는 문서로 보인다.
- 자료·성과 탭 높이가 줄었다(예시 데이터 기준 자료 5,825 → 2,952px, 성과 4,564 → 1,092px). 전후 스크린샷은 `docs/samples/ui/before|after/27~31-*.png`에 있다.
- 새 외부 CSS·JS·라이브러리는 없다. 새 색 없이 기존 토큰만 썼다.
- 라우트·DB 스키마·잡 로직은 그대로다. 예외는 자료 탭 `offset` 매개변수와 저장소 쿼리의 OFFSET이다.
