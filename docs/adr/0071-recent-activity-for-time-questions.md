# 0071. "가장 최근 댓글" 같은 시간 질문은 DB가 만든 "최근 활동" 조각으로 답하고, DB 조각은 경로로 가린다

- 상태: 제안
- 날짜: 2026-11-13
- 결정한 사람: 선웅제(배치 R7 요청), 세부는 Claude
- 관련: [ADR 0068](0068-post-metrics-at-answer-time.md)(성과 요약 조각, 같은 패턴), [ADR 0065](0065-collected-and-posts-sources.md)(우리 글 출처·작성자 이름 빼기), [ADR 0058](0058-rag-doc-chat.md)(답변·"모른다" 두 겹), [ADR 0070](0070-ask-page-for-reading.md)(요약 배지), devlog [2026-11-13-batch-R7](../devlog/2026-11-13-batch-R7.md)

## 배경

- "가장 최근에 달린 댓글이 뭔가요?"라고 물으면 "조각에 날짜가 없어 확인할 수 없다"는 답이 나왔다. 규칙대로 맞는 답이다.
  - 우리 글 문서(`PostsSource`)의 `## 댓글` 아래 줄이 `- 본문 → 답글: …`뿐이어서 날짜가 없었다.
  - 벡터 검색은 뜻이 비슷한 조각을 찾을 뿐이고, 시간순으로 줄 세우지는 못한다. 날짜를 넣어도 "가장 최근" 조각이 상위 다섯에 든다는 보장이 없다.
- 순위 질문에도 같은 문제가 있었다. R5(ADR 0068)는 DB가 만든 `posts/_summary` 조각을 검색 결과 뒤에 붙여 풀었다. 시간 질문에는 이런 처리가 없었다.
  - "가장 최근 댓글"은 `RANK_WORDS`의 "가장"에 걸려 성과 요약이 붙었다. 하지만 요약에는 댓글이 없어 도움이 되지 않았다.
- 요약 조각은 `h is summary`(객체 동일성)로 구분했다. DB 조각이 둘 붙으면 그중 하나만 "요약"으로 표시된다.
- 설명서에 "댓글 확인이 N분 걸림(간격 M분)"이라는 자리표시자 문장이 있었고, 모델이 이를 그대로 옮겨 답했다.

## 선택지

1. **댓글 줄에 날짜만 넣는다**: 색인만 바뀐다. "그 댓글 언제 달렸어"에는 답할 수 있다. 하지만 "가장 최근"은 검색 순위에 달려 있어 여전히 못 답한다.
2. **"최근 활동" 조각을 색인에 넣는다**: 내용이 매일(댓글이 달릴 때마다) 바뀌어 밤마다 다시 임베딩된다. 밤 8시 색인 뒤에 달린 댓글은 다음 날까지 보이지 않는다.
3. **답할 때 DB에서 "최근 활동" 조각을 만들어 붙인다(성과 요약과 같은 방식)**: 임베딩·`doc_chunks`가 없고, 물을 때의 최신 상태를 쓴다. 단점은 시간 낱말 목록에 기대야 한다는 점이다.

## 결정

1과 3을 함께 한다.

- **댓글 줄 날짜**는 `- YYYY-MM-DD 본문 → 답글: …` 형식이다.
  - 날짜는 설정 시간대의 현지 날짜이고, 게시 줄(`게시: YYYY-MM-DD`)과 같은 `_day`를 쓴다. 연도를 넣어 해가 바뀌어도 헷갈리지 않는다. 시각은 넣지 않는다. 날짜만으로 충분하고, 시각까지 넣으면 조각 글이 길어진다.
  - created_at이 없으면 날짜 없이 예전 형식으로 쓴다.
- **최근 활동 조각**의 경로는 `posts/_recent`이고 제목 경로는 "우리 글 > 최근 활동(MM-DD 기준)"이다. 내용은 두 절이다.
  - 최근 게시 글 10건: `- MM-DD HH:MM 게시 | 플랫폼 | 제목`.
  - 최근 댓글 10건, 최신이 맨 위: `- MM-DD HH:MM | 플랫폼 | 글 제목 | 댓글: 본문 120자 → 답글: 답글 120자 또는 "없음"`. 게시된 글에 달린 댓글만 싣고 숨김·스팸은 뺀다. 지운·실패한 글의 댓글이 10자리를 차지하지 않게 우리 글 문서와 같은 기준을 쓴다(리뷰).
  - 시각은 설정 시간대로 바꿔 쓴다. 줄은 짧게 MM-DD HH:MM으로 쓰고, 안내 줄에 연도가 든 기준 시각(`기준 시각 2026-11-12 12:00(Asia/Seoul)`)을 둔다. 해가 바뀔 때(01-02에 본 "12-30")와 "어제"를 이 시각으로 가린다(리뷰).
  - 작성자 이름은 `scrub_people`로 지우는 데만 쓰고 싣지 않는다(ADR 0065).
  - 답글은 실제로 나간 것만 싣는다. 판정은 `sources_db.reply_sent`로 빼서 우리 글 문서와 함께 쓴다.
  - 글도 댓글도 없으면 조각을 붙이지 않는다.
- **붙이는 조건**(`wants_recent`)은 출처가 `wants_summary`와 같고(전체·우리 글), 낱말 두 묶음이 함께 있어야 한다.
  - `TIME_WORDS`(최근·마지막·방금·어제·오늘·그제·이번 주·지난주·지난 주·새로 달린·새 댓글) 하나와, 글·댓글 활동을 묻는 `ACTIVITY_WORDS`(글·게시·올린·올렸·답한·답했·반응; "댓글"·"답글"은 "글"에 걸림) 하나가 함께 있을 때다.
  - 시간 낱말만으로 붙이면 "오늘 질문 수 상한", "최근 며칠 수집 자료"처럼 문서를 묻는 질문에도 조각이 붙는다. 그러면 근거 없음이라 0원이던 질문에 Claude가 불린다(리뷰). 요청서의 "시간 낱말이 있으면"보다 좁혔다.
  - "가장"은 `RANK_WORDS`에 그대로 둔다. 그래서 "가장 최근 댓글"에는 두 조각이 다 붙는다.
  - 붙었으면 검색이 근거 없음이어도 Claude를 부른다(ADR 0068과 같은 예외).
- **DB 조각 판정은 경로로 한다**: `h.path in DB_PATHS`(`posts/_summary`, `posts/_recent`).
  - 객체 동일성 대신 경로로 보면 두 조각이 같이 붙어도 둘 다 `score: null`·`summary: true`로 기록된다.
  - `ask.summary_ids`도 두 경로를 다 본다(`list_has_any`).
- **배지는 "요약"을 그대로 쓴다.** 화면 변경이 없고(ADR 0070의 템플릿 그대로), 근거 제목이 "최근 활동(…)"이라 구분된다. "최근" 배지를 새로 만들면 템플릿·CSS·테스트가 늘지만, 얻는 정보는 제목과 같다.
- 시스템 지시에 두 줄을 더한다.
  - "'최근'·'마지막' 같은 질문은 조각에 적힌 날짜·시각 순서로 답하고, 날짜가 없는 조각으로 순서를 추측하지 않는다."
  - "문서의 N·M 같은 자리표시자는 그대로 옮기지 말고 말로 풀어 쓴다."
  - 설명서의 자리표시자 문장(댓글 확인 시간, 조각 수, 다시 물을 시간, 보호 모드 건수, 실행 기록 묶음)은 예시 숫자로 바꾼다.

## 결과

- 얻는 것
  - "가장 최근에 달린 댓글", "어제 올린 글", "마지막으로 답한 댓글"에 물을 때의 DB 기준으로 답한다. 색인 시각에 묶이지 않는다.
  - 임베딩 비용이 없다.
  - 우리 글 문서의 댓글 줄에도 날짜가 생겨, 검색으로 찾은 댓글에 "언제"를 답할 수 있다.
- 감수하는 것
  - **댓글 줄이 바뀌어 다음 밤 색인 때 댓글 조각이 한 번 다시 임베딩된다**(sha256 증분, 조각 단위). 우리 글 조각은 237개(R4c 복사본)다. 이 중 댓글 절이 든 조각만 바뀌고, 전부 바뀌어도 한 회 900건·하루 1000건 안에서 한 번에 끝난다.
  - **낱말은 목록이다.** "요즘", "얼마 전"처럼 목록에 없는 표현은 놓친다. "누가 마지막에 말 걸었어"처럼 활동 낱말 없이 묻는 질문도 놓친다. "글"은 흔한 낱말이라 "최근 글쓰기 규칙"처럼 문서를 묻는 질문에는 여전히 붙는다(질문당 최대 20줄).
  - 최근 열 건만 담는다. "지난주 수요일 댓글"처럼 열 건보다 먼 것은 검색(댓글 줄 날짜)에 기댄다.
- 다시 볼 조건
  - 놓치는 질문이 잦으면 `ACTIVITY_WORDS`를 늘리고, 엉뚱하게 붙는 질문이 잦으면 "글"을 "올린 글"·"댓글"처럼 좁힌다.
  - 열 건이 모자라다는 질문이 나오면 `RECENT_TOP`을 늘리거나, 질문의 날짜("어제")로 기간을 거른다.

## 리뷰에서 그대로 둔 것

- "가장"을 `RANK_WORDS`에서 빼라: 요청서가 정한 대로 둔다. "가장 최근 댓글"에는 성과 요약도 붙는다. 다만 지표가 없으면 요약은 붙지 않고, 붙어도 Claude는 시간 순서 지시대로 답한다.
- 댓글 줄 날짜로 다음 색인 때 다시 임베딩된다: 위 "감수하는 것"에 적었다(우리 글 조각 237개 안, 하루 한도 안).
- 자리표시자 지시가 R7과 무관하다: 요청서의 3번 목표이고, 위 결정에 적었다.
