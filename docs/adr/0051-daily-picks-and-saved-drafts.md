# 0050. 오늘의 추천 3개와 보관함: 검토 대기 위에 `picks` 표를 얹고, 사진 후보는 사람이 확인한 뒤에만 카드에 넣는다

- 상태: 제안 (배치 S11, 서브 제안 PR. 메인 합의 전에는 머지하지 않는다)
- 날짜: 2026-10-20
- 결정한 사람: 서브(제안 초안). 추천 모드 기본값·사진 사용 범위는 메인이 정한다
- 관련: [0050](0050-editorial-style-verified-photos.md)(사진 우선형, 사진은 사람이 확인), [0045](0045-image-materials.md), [0044](0044-keyword-drafts-and-exclude-words.md)(키워드 원고), [0012](0012-daily-target-and-topic-rotation.md)(일일 목표·주제 순환), [0024](0024-card-editor-scope.md)(카드 편집), contracts.md 2절(콘텐츠 상태 동결)

## 배경

사용자는 관심 분야 하나(치이카와·롤·연예인·패션)를 정해 두면 **매일 최근 소식 중 서로 다른 소재 3개를 완성 원고로 받아 보고**, 마음에 드는 것은 게시하고 나머지는 보관했다가 다음에 올리길 원한다(2026-10-20 기획).

지금 흐름은 그와 다르다.
- 일일 원고(generate)는 "가장 오래 안 쓴 주제" 하나에서 자료 3건을 골라 하루 목표(플랫폼 쿼터 최대, 기본 2건)만큼 만든다(ADR 0012). 서로 다른 사건 3개를 고르는 단계가 없다.
- `SourceItem.published_at`은 어떤 소스도 채우지 않아 "최근"을 공개 시각으로 판단할 수 없었다.
- "보관"에 해당하는 상태가 없다. `ContentStatus`(draft·pending_review·approved·published·discarded)는 동결 계약이다.
- `count_contents_between`은 상태와 상관없이 오늘 만든 원고를 모두 세므로, 추천 원고를 따로 빼지 않으면 일일 목표를 잡아먹는다. `save_generated`는 항상 게시 레코드까지 만든다.
- 관심 주제(`persona.topics`)는 검색어이자 분류 라벨이다. 별칭(ちいかわ, Chiikawa)을 주제에 더하면 라벨도 갈라져 같은 사건이 다른 주제로 흩어진다.

## 선택지

1. **일일 원고 수를 3으로 늘리기**: 가장 쉽다 / 같은 주제에서 연달아 뽑히고, 전부 게시 쿼터·자동 승인에 섞인다. 보관 개념이 없다.
2. **추천 전용 테이블 7개 + 사건 추출 + 인기도 관측 + 이미지 사용권 레지스트리 + 체크포인트 재개 + 자동 게시**(다른 세션의 설계 초안): 가장 완전하다 / 메인 소유 코드 전반을 바꾸는 몇 주짜리 작업이라 "보고 가져가는" 제안 PR로는 평가하기 어렵다.
3. **`picks` 표 하나를 검토 대기 위에 얹는 작은 추천 모드 (채택)**: 콘텐츠 상태·동결 계약은 그대로, 추천·보관·사진 후보 상태만 옆 표에 둔다. 사건 묶기는 제목 토큰 기준, 최신성은 `published_at` 기준, 인기도 관측은 하지 않는다 / "유행 순위"는 아니다. 번역 없이 토큰 겹침으로만 묶는다.

## 결정

3번. 설정 `settings.picks.enabled`를 켜면 일일 `generate`는 쉬고 **`picks` 잡**이 대신 돈다.

- **흐름(한 잡 안에서 순서 보장)**: 수집(`run_collect`) → 아직 안 쓴 관련 자료를 **사건 단위로 묶기** → 순위 → 위에서부터 **서로 다른 사건 최대 N개**(기본 3)를 완성 원고로. 예약 시각 순서에 기대지 않는다.
- **사건 묶기**(`nsm/domain/picks_policy.py`, 순수 함수): 대표 주제가 같고 제목 토큰 Jaccard ≥ 0.4면 같은 사건. 단, 명시된 날짜(10월 23일 / 11월 1일)나 따옴표 고유명('마스코트 인형' / '아크릴 키링')이 서로 다르면 합치지 않는다. 별칭과 굿즈 소식에 흔한 일본어 낱말(コラボ→콜라보, グッズ→굿즈 …)은 대표 주제·한국어로 바꾼 뒤 비교한다. 한계: 번역기가 아니라서 공통 토큰이 없는 한·일 제목은 다른 사건으로 남을 수 있다.
- **최신성은 `published_at`**: 네이버 검색 결과의 날짜 표기("3시간 전", "2026.10.19.")를 읽어 채운다. 기본 72시간 안이면 "최근 소식", 더 오래됐으면 "오래된 자료", 모르면 **"날짜 확인 필요"**로 표시하고 순위를 뒤로 보낸다. 수집 시각으로 대신하지 않는다. 화면 문구는 "유행"이 아니라 **"최근 소식 추천"**이다(인기도 관측이 없으므로).
- **중복·제외**: 최근 14일에 만든 원고 제목, 최근 30일에 '관심 없음'으로 버린 사건의 지문과 같은 사건이면 추천하지 않는다('관심 없음'은 자료를 풀어 주지만 지문을 남긴다). 주제가 겹치지 않게 1라운드는 주제마다 하나씩 뽑는다.
- **저장**: 추천 원고는 **항상 `pending_review`**. `PicksStore.save()`가 contents + 자료 사용 표시 + `picks` 행을 **한 트랜잭션**으로 넣고 게시 레코드는 만들지 않는다. `count_contents_between`은 `picks`에 있는 원고를 세지 않는다(일일 목표 보존). 유료 AI 배경(`_add_background`)은 부르지 않는다.
- **`build_draft` 분리**: 일일 원고의 `_make_one`에서 "생성 → 규칙 검사 → 출처 검증 → 게시 판정"을 `build_draft()`로 떼어 추천과 같이 쓴다. 반환값 `Draft`에 규칙 위반 목록·판정이 그대로 들어 있어, 일일 원고의 자동 승인 차단은 바뀌지 않는다(회귀 테스트).
- **사진 후보**: 묶음의 대표 자료 원문에서 og:image를 받아 `media/picks/<id>/candidate.*`에 두고 `photo_status='candidate'`로 표시한다. **카드에는 안 들어간다.** 검토 상세에서 "이 사진 쓰기"를 눌러야 표지·마지막 장 `background`가 된다(ADR 0050). 안전: http(s)만, 원문·이미지·모든 리다이렉트 홉이 공개 IP로만 풀려야 하고(사설·루프백·링크로컬 거절), 리다이렉트 3번, HTML 2MB, 이미지 10MB, 2500만 픽셀, 짧은 변 600px, Pillow로 실제 형식 검사.
- **게시 준비 완료 vs 사진 확인 대기**: 사진을 정했고(쓰기·안 쓰기·없음) 미리보기 렌더에서 넘침이 없어야(`render_checked_at`) "게시 준비 완료"다. 사진을 바꾸면 렌더 확인은 다시 한다. 사진 없는 원고를 "사진 게시물 완성"으로 표시하지 않는다.
- **게시·보관·관심 없음**(`nsm/app/review_actions.py`, 추천이 아닌 원고에도 같은 함수): `게시` = 승인(사람) + 게시 레코드 + 포기한 게시 되살림 + `queued`를 한 트랜잭션으로("승인됐는데 안 올라가는" 상태 방지). 기존 `/review/{id}/approve`도 같은 길을 쓴다. `보관` = 상태는 그대로 `pending_review`, 추천은 `saved`. `관심 없음` = 폐기 + 자료 해제 + `dismissed`(지문 보존). 게시 대기에서 되돌리면 `saved`.
- **보관 글 재확인**: 만든 지 48시간이 지난 원고는 "다시 확인했어요"(날짜·가격·행사 종료)를 누른 뒤 24시간 안에만 게시로 보낼 수 있다. 자동 재검증은 후속.
- **관심 분야 묶음**(치이카와·롤·연예인·패션): 관심 주제·검색 별칭·제외어를 채우고 추천 모드를 켠다. 별칭은 **검색어 확장에만** 쓰고 분류 라벨은 대표 주제다.
- **기본값**: `picks.enabled=false`. 기존 사용자는 아무것도 바뀌지 않는다. "지금 실행: 오늘의 추천 만들기"는 모드가 꺼져 있어도 한 번 만들어 볼 수 있다.

## 결과

- 켜면 매일 "오늘" 화면 위에 최근 소식 추천 최대 3건이 뜨고, 게시·보관·관심 없음으로 처리한다. 보관함은 `/picks`.
- 지키는 것: 동결 계약·콘텐츠 상태 그대로, 일일 목표·게시 쿼터와 분리, 자동 승인 없음, AI 배경 없음, 사진은 사람이 확인한 뒤에만.
- 테스트: 순수 규칙(묶기·날짜·제외·다양성, 한·일 제목), 날짜 파싱, og:image 안전 규칙(사설 주소·크기·가짜 형식·리다이렉트), 저장소 트랜잭션, 잡(3건·검토 대기·게시 레코드 없음·목표 미소모·AI 배경 없음·멱등·비용 상한·관심 없음 재추천 방지), 화면(게시/보관/관심 없음/사진 쓰기/재확인 관문/프리셋), 일일 원고 회귀.
- 어려워진 것·후속: 인기도("유행") 측정 없음, 번역 기반 사건 병합 없음, 상품별 사진 자동 확보 없음(S12 계약 변경), 보관 글 자동 재검증 없음, 자동 게시 없음.
- 다시 볼 조건: 메인이 ADR 0045 사진 범위를 다르게 정하면 사진 후보 수집을 끄거나(`photo_candidates=false`) 출처 화이트리스트로 좁힌다. 운영에서 같은 사건이 두 번 추천되면 묶기 임계값(0.4)과 일본어 낱말표를 넓힌다.
