# 0038. 플랫폼 요청 제한(HTTP 429)은 로그인 문제와 구분해 정해진 시간 쉬고, 인스타그램 댓글은 더 드물게·최근 글만 본다

- 상태: 제안 (배치 C9 기본값. PR 리뷰에서 선웅제 확인)
- 날짜: 2026-10-16
- 결정한 사람: 선웅제(배치 지시: 429 감지와 댓글 확인 간격 수정), 배치 C9 기본값
- 관련: [ADR 0029](0029-reply-interval.md)(댓글 확인 간격 5분), [ADR 0018](0018-platform-capabilities-from-day1.md), [ADR 0008](0008-autopublish-guardrails.md)(자동 게시 안전장치)

## 배경

2026-10-14 20:24부터 하루 넘게 인스타그램 댓글 확인이 5분마다 "로그인 필요: 로그인돼 있지 않음"으로 실패했다. 같은 시간에 30분마다 도는 로그인 점검은 성공이었고, 그사이 인스타그램 게시도 두 번 성공했다.

- 원인을 직접 확인했다. 글 페이지(`instagram.com/p/…`) 8개를 열어 보니 모두 Chrome 오류 화면 "HTTP ERROR 429"(요청이 너무 많음)였다. 홈 화면은 정상이었다.
- 오류 화면에는 내 프로필 사진이 없다. 그래서 핸들 확인 코드가 "로그인 안 됨"으로 잘못 보고했다.
- 댓글 확인은 5분마다(ADR 0029) 최근 14일 글을 하나씩 연다. 시간당 글 페이지 100번 가까이다. 그날 계약 테스트·재시도로 짧은 시간에 여러 번 게시한 것도 겹쳤다.
- 막힌 뒤에도 5분마다 계속 열어 제한이 풀리지 않은 것으로 보인다.
- 첫 실패(게시 중 `net::ERR_HTTP_RESPONSE_CODE_FAILURE`)는 페이지 이동 자체가 막힌 경우다.

## 선택지

1. **감지만 고침(429를 "요청 제한"으로 표시)**: 원인은 보이지만 5분마다 계속 두드려 제한이 길어진다.
2. **감지 + 쉬기 + 인스타그램 확인을 드물게(채택)**: 막히면 정해진 시간 그 플랫폼에 브라우저 요청을 보내지 않고, 평소에도 인스타그램 글 페이지를 덜 연다 / 인스타그램 댓글 답이 최대 30분 늦어진다.
3. **댓글 확인 간격 전체를 늘림**: 단순하다 / 문제없는 스레드까지 느려진다.

## 결정

2번.

- **감지(어댑터).**
  - 핸들을 읽기 전에 페이지가 막혔는지 먼저 본다(`nsmCheckPage`).
    - 본문에 "HTTP ERROR 429"·"Too Many Requests"·"몇 분 후 다시 시도"가 있으면 요청 제한이다.
    - 그 밖의 Chrome 오류 화면은 "페이지를 열 수 없음"(일반 오류)이다. 둘 다 더는 "로그인 필요"가 아니다.
  - 오류 메시지의 `ERR_HTTP_RESPONSE_CODE_FAILURE`는 요청 제한으로 보지 않는다. 지운 글(404)이나 서버 오류(500)에도 나와서, 그때마다 몇 시간씩 쉬면 안 되기 때문이다(코드 리뷰 반영). 오류 메시지에 "HTTP ERROR 429"가 있을 때만 요청 제한이다.
  - 댓글을 읽을 때 핸들 확인은 첫 글에서만 하고, 페이지 검사는 글마다 한다. 둘째 글부터 막혀도 알아본다.
  - 로그인 점검(health)도 같은 감지를 거친다.
- **쉬기(어댑터).**
  - 요청 제한을 만나면 2시간 동안 그 플랫폼에 브라우저 요청을 보내지 않고 바로 `RateLimitedError(retry_at)`를 낸다.
  - 쉰 뒤 바로 또 막히면 4시간, 8시간(최대)으로 늘린다. 한 번 성공하면 처음(2시간)으로 돌아간다.
  - 로그인 점검의 성공은 처음으로 돌리지 않는다. 홈 화면은 글 페이지가 막혀도 열리기 때문이다.
  - 댓글을 여러 묶음으로 읽다가 한 묶음이라도 막히면 읽은 것까지 버리고 요청 제한을 올린다. 일부만 넘기면 "마지막 댓글 시각"이 앞당겨져, 못 읽은 글의 댓글을 영영 놓친다.
  - 쉬는 시각은 메모리에만 둔다. 다시 켜면 한 번은 다시 시도한다.
- **잡(엔진).**
  - 포트는 동결이라 어댑터 예외 클래스를 가져오지 않는다. 예외의 `retry_at`, 어댑터의 `blocked_until` 속성으로 알아본다(`nsm/engine/rate_limit.py`).
  - health: 플랫폼을 멈추지 않고 "로그인 필요"도 보내지 않는다.
  - reply·metrics: 실패가 아니라 "쉬는 중"으로 적는다(`rate_limited`).
    - 답글을 달다 막히면 남은 댓글을 사람에게 넘기지 않고 `new`로 둔다. 쉬고 나서 처리한다.
    - 지표는 막히기 전까지 넣은 수를 그대로 센다.
  - publish: 쉬는 동안 그 플랫폼을 건너뛰고 이유를 보여 준다. 사람이 누른 "게시하기"도 쉰다(계정 보호).
    - 게시하다 막히면 재시도 횟수를 쓰지 않는다(`refund_attempt`). 쉬는 끝 시각에 다시 올린다. 원고 탓이 아니므로 "게시 포기"·검토로 돌리지 않는다.
  - 알림: 쉬는 구간마다 한 번만 "인스타그램 요청 제한"(경고)을 보낸다. "언제까지 쉬고, 로그인은 풀리지 않았다"를 알려 준다.
- **인스타그램 댓글 확인을 가볍게.**
  - `instagram_comment_interval_minutes`(기본 30분, 10~180, 설정 화면): 댓글 확인 잡이 5분마다 돌아도 인스타그램은 이 간격보다 자주 보지 않는다. 지터를 생각해 2분 일찍 와도 본다.
  - `instagram_comment_lookback_days`(기본 3일, config.yaml): 최근 며칠 글만 연다(스레드는 그대로 14일).
  - 확인을 시도한 시각은 실패해도 적는다. 막힌 플랫폼을 몇 분마다 두드리지 않기 위해서다.
  - 대시보드 "지금 실행"(댓글 확인)은 간격을 무시하지만, 쉬는 중이면 그대로 쉰다.

## 결과

- 시간당 인스타그램 글 페이지 열기가 약 100번에서 많아야 10번 안팎으로 준다(최근 3일 글 × 30분마다).
- 429가 와도 "로그인 필요"로 잘못 알리거나 플랫폼을 멈추지 않는다. 몇 시간 쉬고 스스로 다시 시도한다.
- 어려워진 것
  - 인스타그램 댓글 자동 답이 최대 30분 늦어진다.
  - 3일보다 오래된 글의 새 댓글은 인스타그램에서 직접 확인해야 한다.
- 다시 볼 조건
  - 30분 간격에서도 429가 반복되면 간격을 늘리거나 확인할 글 수를 더 줄인다.
  - 인스타그램 알림 화면 하나로 새 댓글을 모아 보는 방식이 가능해지면 글 페이지를 하나씩 열지 않는다.
