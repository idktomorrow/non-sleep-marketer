# 0032. 최신 자료만 찾고, 지난 예정·소문은 쓰지 않는다

- 상태: 채택 (선웅제 지적, 2026-10-13) · 날짜: 2026-10-13 · 관련: [0022](0022-fetch-article-body-for-relevant-items.md), [0023](0023-code-checked-content-rules.md)

## 배경

10월 13일에 만든 원고가 "CGV 먼작귀 팝콘통 가격은 아직 소문 단계", "극장판은 9월 30일에 개봉해요"라고 썼다. 실제로는 이미 개봉했고, 팝콘통은 3차 판매까지 진행된 뒤였다. 근거 자료는 네이버 블로그 글 한 편이었다. 개봉 전에 쓴 "출시일·가격 총정리" 글이었다.

원인은 세 가지였다.
1. 네이버 검색 기본값이 정확도순이라 몇 주 전 글이 위에 왔다.
2. 원고를 쓰는 모델은 오늘 날짜도 자료 날짜도 몰랐다.
3. 확인되지 않은 소문을 옮기지 말라는 규칙이 없었다.

## 결정

- **수집**: 네이버 블로그·뉴스 검색에 최신순(`so:dd`)과 기간(`p:1w`)을 붙인다. 기간은 설정 `collect.recent_period`(1d/1w/1m/all, 기본 1w)이고 설정 화면 "자료 검색 기간"에서 고른다. 2026-10-13 실제 검색으로 옵션이 동작함을 확인했다. 검색 결과에는 작성일이 늘 보이지 않아, 날짜로 거르는 대신 검색 단계에서 기간을 건다.
- **원고 작성**: 프롬프트 맨 앞에 오늘 날짜를 넣고, 자료마다 수집일(`collected`)과 알면 작성일(`published`)을 붙인다. 시스템 규칙도 더한다.
  - 그 사이 지났거나 바뀌었을 수 있는 "예정·출시 전·아직 공지 전"은 쓰지 않는다.
  - 날짜가 있는 사실은 날짜를 밝혀 지난 일로 쓴다.
  - 소문·추측·예상 가격은 쓰지 않는다.
- **코드 검사**: SNS 글(캡션·스레드·카드)에 "소문, 루머, 카더라, 이야기가 돌, 예상 가격, 아직 공지, 아직 공개되지"가 있으면 규칙 위반이다. 한 번 다시 만들고, 그래도 있으면 검토로 보낸다(ADR 0023과 같은 흐름). "출시 예정"은 공식 발표된 일정에도 쓰는 말이라 코드 검사에서는 뺐다(프롬프트 규칙으로만).

## 결과

- 이미 모아 둔 자료 중에는 예전 방식(정확도순)으로 들어온 오래된 글이 남아 있을 수 있다. 새 프롬프트 규칙과 코드 검사가 걸러 주지만, 며칠은 검토에서 날짜에 민감한 내용을 한 번 더 본다.
- 기간을 짧게 잡을수록 자료 수가 줄어든다. 틈새 주제에서 자료가 모자라면 1m으로 늘린다.
