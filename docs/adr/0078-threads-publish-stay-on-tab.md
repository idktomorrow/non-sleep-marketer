# 0078. 스레드 게시 뒤 게시 탭을 떠나지 않고 확인은 다른 탭에서

- 상태: 채택
- 날짜: 2026-11-25
- 결정한 사람: 선웅제(배치 C58 요청), 대행 Claude
- 관련: [0020](0020-aside-repl-execution.md) 개정 1(게시 뒤 못 찾으면 확인 실패로 재시도, C43), [0054](0054-error-taxonomy-and-evidence.md)(증거), 장애 [0017](../incidents/0017-2026-11-13-threads-publish-aborted-by-navigation.md), devlog [2026-11-25-batch-C58](../devlog/2026-11-25-batch-C58.md)

## 배경

2026-11-13 ~ 11-24에 스레드 게시가 11번 "게시를 확인하지 못함(프로필에서 글을 못 찾음)"으로 실패했다. 매번 1·2차가 실패하고 3차에 성공했다. 실패한 시도는 실제로 서버에 올라가지 않았다. 재시도의 게시 전 멱등 확인이 한 번도 "이미 올라간 글"을 찾지 않았고, 중복 게시도 없었다.

스크립트는 미리보기(`blob:`)가 생기자마자 '게시'를 누르고, 창이 닫히자마자 같은 탭을 프로필 주소로 옮겨(`findMine(pg)`의 `pg.goto`) 글을 찾았다. 스레드 웹은 '게시'를 누르면 창을 먼저 닫고 이미지 업로드·게시를 뒤에서 마친다. 그래서 탭을 옮기면 진행 중인 요청이 끊긴다. 인스타그램은 같은 페이지에서 "공유되었습니다"를 기다린 뒤 옮겨서 이 문제가 없었다.

## 선택지

1. **창이 닫힌 뒤 같은 탭에서 몇 초 기다렸다 옮긴다**: 가장 작은 변경이다. 그러나 업로드가 언제 끝나는지 모르고, 기다림이 짧으면 같은 일이 생긴다.
2. **게시 탭은 끝까지 두고, 확인은 따로 연 탭에서 한다**: 게시 탭의 요청이 스크립트가 끝날 때까지 살아 있다. 대신 탭 하나를 더 열고, 증거를 찍을 탭을 골라야 한다.
3. **네트워크 요청 완료를 엿본다**: 가장 정확하다. 그러나 Aside repl에서 요청을 가로채는 건 화면 구조보다 더 자주 바뀌고, 테스트하기도 어렵다.

## 결정

2번을 고르고 1번의 짧은 대기를 더한다. 가장 큰 이유는 "끊기지 않게"를 시간 추측이 아니라 구조로 보장하기 때문이다.

- **게시 탭 `pg`는 '게시'를 누른 뒤 다른 주소로 옮기지 않는다.** 게시 전 멱등 확인(`before`)은 지금처럼 `pg`에서 한다(아직 게시 전).
- 창이 닫히면 게시 탭에서 5초를 기다린다. 그다음 `게시 중|Posting`이 보이면 사라질 때까지, `게시됨|게시되었|Posted`가 보이면 바로, 최대 15초를 더 기다린다. 문구가 전혀 안 보여도 실패로 보지 않는다. 스레드의 실제 문구는 기록이 없어서, 본 문구를 결과(`settle`)로 돌려주고 로그에 남긴다.
- 확인 탭은 한 번만 열고(`nsmOpen`) 회차마다 `findMine`의 `goto`로 다시 읽는다. 확인 중 오류는 '못 찾음'으로 본다. 게시를 누른 뒤에는 던지지 않는다(0020 개정 1).
- 이미지가 있으면 미리보기 뒤 1.5초를 두고, '게시'가 활성일 때 누른다(`nsmUntil(() => nsmClickText(dlg, '게시'), 15000, 500)`). 이를 위해 공통 `nsmClickText`가 `aria-disabled="true"`·`disabled` 버튼을 건너뛴다. 같은 함수를 쓰는 스레드·인스타 답글의 '게시'도 `nsmUntil(…, 5000, 300)`으로 감싼다.
- 글 찾기 예산은 `nsmLeft() - 25000`이다(인스타그램과 같은 여유). 끝까지 못 찾았을 때 `nsmEvidence({ page: pg })`가 게시 탭의 화면을 5초 예산으로 찍는다. 예전 17초 여유로는 마지막 회차 뒤 4~6초만 남았다. 그래서 스레드 증거에는 `screenshot.png`가 한 번도 없었다. `nsmEvidence`는 찍을 탭을 `opts.page`로 받는다(없으면 예전처럼 마지막에 연 탭).

## 결과

- 좋아지는 것: 확인 때문에 게시가 끊기지 않는다. 실패하면 게시 탭의 화면이 증거로 남는다. 답글은 잠깐 비활성인 버튼 때문에 "버튼 없음"이 되지 않는다.
- 나빠지는 것: 게시 한 번에 탭이 하나 더 열리고, 최소 5초가 늘어난다. 글 찾기 시간은 8초 줄어든다(105초 안).
- 0020 개정 1과의 관계: 개정 1은 "못 찾으면 확인 실패로 재시도, 재시도는 멱등 확인부터"이다. 이 결정은 그 확인이 게시를 끊지 않게 하는 것이고, 재시도·멱등 규칙은 그대로다.
- 다시 볼 때: 머지·재시작 뒤 며칠간 로그에서 `게시를 확인하지 못함`이 사라지는지 본다. 남는다면 증거의 `screenshot.png`와 `settle` 로그로 다음 원인을 본다.
