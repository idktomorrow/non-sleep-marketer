# 0020. 실계정 어댑터는 `aside repl` 고정 스크립트로 돌리고, 이미지는 일회용 로컬 서버로 넘긴다

- 상태: 채택(2026-10-13, 선웅제 확정) · 날짜: 2026-10-13 · 관련: [0017](0017-aside-default-driver-after-day1.md), 이슈 #14, [day1-verification](../day1-verification.md)

## 배경

0017에서 Aside를 기본 드라이버로 정했다. 실제로 만들어 보니 다음이 확인됐다(2026-10-13, Aside CLI 1.26).

- `aside repl "<js>"`는 부를 때마다 새 세션이고 120초 제한이 있다. JS 안에서는 `fs`가 **세션 폴더와 Aside 프로젝트 폴더 밖을 읽지 못한다**. 앱 설정의 Can view에 `~/.nsm`을 넣어도 repl에는 적용되지 않았다.
- repl 안의 `fetch()`는 `http://127.0.0.1`에 닿는다.
- 스레드 웹: 인라인 답글 칸에는 게시 버튼이 없고, 댓글 페이지의 답글 아이콘을 누르면 "답글" 창이 열린다. 아이콘 이름은 `aria-label` 대신 SVG `<title>`에 있는 경우가 많다.

## 선택지

1. 자연어 `aside "...올려줘"`: 구현이 쉽다 / 게시 문구가 에이전트 지시가 되는 프롬프트 인젝션, 매번 다른 동작, 1분 안팎
2. **고정 JS 템플릿 + 값은 base64 JSON 데이터로만 + 이미지는 127.0.0.1 일회용 HTTP 서버**
3. 사용자가 Aside 프로젝트 폴더에 이미지를 복사: 설정이 늘고, Aside가 볼 수 있는 범위가 넓어진다

## 결정

2번.

- **실행:** `subprocess.run([aside.exe, "repl", script])`. 셸을 쓰지 않는다. 결과는 `@@NSM@@{json}` 한 줄로 받는다. 오류 메시지는 ANSI와 쿠키·토큰처럼 보이는 값을 지우고 300자로 자른다.
- **이미지:** 넘길 PNG만 무작위 포트·무작위 경로로 내주는 서버를 호출 동안만 연다. JS가 받아 세션 폴더에 쓴 뒤 업로드한다. 올릴 수 있는 파일은 NSM `media` 폴더 아래 PNG로 제한한다.
- **계정 확인:** 모든 동작 전에 로그인된 핸들을 읽어 `settings.accounts`와 비교한다. 핸들이 비어 있으면 실계정 동작을 하지 않는다.
- **멱등 게시:** 게시 전에 프로필에서 같은 글(본문 고유 문구)을 찾아 있으면 다시 올리지 않는다. 게시 버튼을 누른 뒤에는 주소를 못 찾거나 시간이 다해도 오류로 돌리지 않는다(오류 → 재시도 → 확인이 빗나가면 중복 게시). 확인은 최근 6시간 글, 본문 앞 40자로만 하고 8자 미만이면 하지 않는다. **C43에서 바꿈**: 게시 뒤 주소를 못 찾으면 확인 실패로 재시도한다(아래 개정 1).
- **댓글 ID:** `작성자:코드`. 대시보드가 `플랫폼:ID`를 URL 경로에 넣으므로 `/`는 쓰지 않는다.

## 결과

- Aside 설정 Can view에 `~/.nsm`을 넣을 필요가 없다(1일차 검증 때 넣었다면 빼도 된다). Aside가 볼 수 있는 범위가 줄어든다.
- 동작마다 Aside 브라우저에 탭이 잠깐 열린다. 스크립트는 끝나면 자기가 연 탭을 닫는다.
- 화면 구조가 바뀌면 `nsm/adapters/platforms/threads.py`의 JS만 고친다. 계약 테스트(`-m contract`)가 실계정에서 바로 알려 준다.
- 시간 예산: repl 120초 제한 안에서 끝나도록 모든 대기를 105초 예산으로 자른다. 댓글은 글 4개씩 나눠 읽는다.
- 한계: 답글은 글 화면 첫 페이지에 보이는 것까지만 읽는다. 답글이 많은 글은 놓칠 수 있다.
- Aside 세션 폴더(`~/.aside/u/0/sessions`)에 업로드용 사본이 남는다. 정리는 Aside가 한다(확인 필요).

## G2(인스타그램)에서 덧붙임

- 게시 대화상자는 단계(자르기 → 편집 → 새 게시물 만들기)마다 숨은 이전 단계 버튼이 DOM에 남는다. DOM 검색으로 "다음"을 누르면 빗나가서, 스냅샷의 ref로 누르고 대화상자 이름이 바뀌었는지 확인한다.
- 캡션 단계의 "Threads에 공유" 스위치는 끈다. 켜 두면 스레드에 두 번 올라간다.
- 캡션 단계의 Meta "AI 레이블 추가"는 켜지 않는다. 카드는 실사 사진이 아니고, 법적 표기는 카드와 본문에 이미 있다(ADR 0019). AI 실사 배경을 쓰는 스타일(#34)이 나오면 다시 본다.
- 올린 뒤 글 이미지의 비율이 0.8±0.03이 아니면 오류 로그를 남긴다. 표기 배지가 잘렸을 수 있다.
- 댓글 ID는 글 페이지의 `/c/<댓글ID>/` 링크에서 얻는다. 답글 ID는 웹에서 안정적으로 얻을 수 없어 빈 값으로 둔다.
- JS에서 `new RegExp('\\s…')`처럼 문자열로 정규식을 만들면 실측에서 일치하지 않았다. 정규식 리터럴(`/…/`)을 쓴다.

## 개정 1 (2026-11-10, 배치 C43): 게시 뒤 주소를 못 찾으면 확인 실패로 재시도한다

- **사실**: "게시는 됐지만 글 주소를 찾지 못함"을 성공으로 적은 줄이 스레드 7건·인스타그램 1건이었다. 확인할 수 있었던 스레드 2건은 프로필에 없었다. 그 글은 실제로 안 올라갔는데, 성공으로 적혀 재시도도 알림도 없었다(incidents/0015).
- **결정**
  - 게시 버튼을 누른 뒤 프로필에서 글을 못 찾으면(완료 화면을 못 본 `posted: 'unknown'` 포함) 일시적 실패 "게시를 확인하지 못함(프로필에서 글을 못 찾음)"을 던진다. 스크립트가 탭을 닫기 전에 찍은 화면을 증거(`publish_unverified`)로 남긴다.
  - 엔진의 기존 재시도(15분·1시간·4시간, 그 뒤 포기 + 검토로)를 그대로 탄다.
  - **중복은 게시 전 멱등 확인이 막는다.** 재시도는 게시 단계에 가기 전에 프로필에서 같은 글(고유 문구)을 찾고, 있으면 그 글을 돌려준다. 찾는 범위는 6시간에서 **72시간**으로 넓혔다. 재시도 간격 합은 5시간 15분이지만, 게시 잡은 게시 시간 안에서만 돌아 재시도가 밤을 넘긴다(예: 11:30 실패 → 12:45 재시도가 18:00에, 18:00 실패 → 23:15 재시도가 다음 날 09:00에). 절전·요청 제한 쉬기(최대 8시간)·플랫폼 멈춤도 재시도를 민다. 6시간이면 첫 시도에 올라간 글을 시간 필터로 건너뛰고 다시 올린다(코드 리뷰 지적). 같은 고유 문구(본문 앞 40자)의 다른 글이 사흘 안에 있을 일은 드물다.
  - **고유 문구가 없는 짧은 글(본문 8자 미만)만 예전대로** 주소 없이 성공으로 적는다. 다시 올리면 중복을 막을 수 없기 때문이다. 로그에 "짧은 글이라 확인 생략"을 남긴다.
  - 스레드는 게시 뒤 글을 찾는 시간을 45초에서 90초로 늘렸다(3초 간격). 증거를 찍을 약 8초에, 마감을 회차 앞에서만 보는 대기 한 회차(약 9초)를 더해 17초를 남긴다.
- **과거 줄**: 유지보수 잡이 한 번만(`settings_kv` 표시), C43 코드가 처음 켜진 시각(켤 때 `stamp_unverified_cutoff`) 전에 게시된 줄 중 `external_id`가 빈 published 줄을 abandoned("게시 확인 안 됨(C43 이전: 프로필에 글 없음)")로 바꾼다. 원고 상태는 그대로 둔다(옛 소식을 다시 올리지 않는다). 한 번만 도는 이유는, C43 뒤의 짧은 글은 주소 없이 published인 것이 정상 기록이기 때문이다. 전이 규칙은 published → abandoned를 막으므로 저장소 메서드가 직접 UPDATE 한다.
- **트레이드오프**: 실제로 올라갔는데 재시도 때까지 프로필에 안 보이면(드묾) 재시도가 같은 글을 한 번 더 올릴 수 있다. 인스타그램은 최근 글 2개만 보므로, 재시도 전에 다른 글이 2개 넘게 올라가면 못 찾는다. 72시간이 지나 다시 승인해 올리는 경우도 같다. 예전에는 반대로 안 올라간 글을 성공으로 남겼다. 놓친 게시는 아무도 모르지만 중복 게시는 사람이 보고 지울 수 있어, 이쪽이 낫다고 본다.
