# 0020. 실계정 어댑터는 `aside repl` 고정 스크립트로 돌리고, 이미지는 일회용 로컬 서버로 넘긴다

- 상태: 제안 (배치 G1) · 날짜: 2026-10-13 · 관련: [0017](0017-aside-default-driver-after-day1.md), 이슈 #14, [day1-verification](../day1-verification.md)

## 배경

0017에서 Aside를 기본 드라이버로 정했다. 실제로 만들어 보니 다음이 확인됐다(2026-10-13, Aside CLI 1.26).

- `aside repl "<js>"`는 부를 때마다 새 세션이고 120초 제한이 있다. JS 안에서는 `fs`가 **세션 폴더와 Aside 프로젝트 폴더 밖을 읽지 못한다**. 앱 설정의 Can view에 `~/.nsm`을 넣어도 repl에는 적용되지 않았다.
- repl 안의 `fetch()`는 `http://127.0.0.1`에 닿는다.
- 스레드 웹: 인라인 답글 칸에는 게시 버튼이 없고, 댓글 페이지의 답글 아이콘을 누르면 "답글" 창이 열린다. 아이콘 이름은 `aria-label` 대신 SVG `<title>`에 있는 경우가 많다.

## 선택지

1. 자연어 `aside "...올려줘"`: 구현이 쉽다 / 게시 문구가 에이전트 지시가 되는 프롬프트 인젝션, 매번 다른 동작, 1분 안팎
2. **고정 JS 템플릿 + 값은 base64 JSON 데이터로만 + 이미지는 127.0.0.1 일회용 HTTP 서버**
3. 사용자가 Aside 프로젝트 폴더에 이미지를 복사: 설정이 늘고, Aside가 볼 수 있는 범위가 넓어진다

## 결정

2번.

- **실행:** `subprocess.run([aside.exe, "repl", script])`. 셸을 쓰지 않는다. 결과는 `@@NSM@@{json}` 한 줄로 받는다. 오류 메시지는 ANSI와 쿠키·토큰처럼 보이는 값을 지우고 300자로 자른다.
- **이미지:** 넘길 PNG만 무작위 포트·무작위 경로로 내주는 서버를 호출 동안만 연다. JS가 받아 세션 폴더에 쓴 뒤 업로드한다. 올릴 수 있는 파일은 NSM `media` 폴더 아래 PNG로 제한한다.
- **계정 확인:** 모든 동작 전에 로그인된 핸들을 읽어 `settings.accounts`와 비교한다. 핸들이 비어 있으면 실계정 동작을 하지 않는다.
- **멱등 게시:** 게시 전에 프로필에서 같은 글(본문 고유 문구)을 찾아 있으면 다시 올리지 않는다. 게시 버튼을 누른 뒤에는 주소를 못 찾아도 오류로 돌리지 않는다. 오류가 나면 재시도하고, 재시도는 중복 게시가 된다.
- **댓글 ID:** `작성자:코드`. 대시보드가 `플랫폼:ID`를 URL 경로에 넣으므로 `/`는 쓰지 않는다.

## 결과

- Aside 설정 Can view에 `~/.nsm`을 넣을 필요가 없다(1일차 검증 때 넣었다면 빼도 된다). Aside가 볼 수 있는 범위가 줄어든다.
- 동작마다 Aside 브라우저에 탭이 잠깐 열린다. 스크립트는 끝나면 자기가 연 탭을 닫는다.
- 화면 구조가 바뀌면 `nsm/adapters/platforms/threads.py`의 JS만 고친다. 계약 테스트(`-m contract`)가 실계정에서 바로 알려 준다.
- 한계: 답글은 글 화면 첫 페이지에 보이는 것까지만 읽는다. 답글이 많은 글은 놓칠 수 있다.
- Aside 세션 폴더(`~/.aside/u/0/sessions`)에 업로드용 사본이 남는다. 정리는 Aside가 한다(확인 필요).
