# 0040. 실행 기록 화면은 작업 상태 표 + 변화가 있던 실행만(같은 결과는 묶음), 전체는 버튼으로

- 상태: 제안 (배치 C11. 선웅제: "일단 해 보고 아니다 싶으면 롤백")
- 날짜: 2026-10-16
- 결정한 사람: 선웅제(방향 승인), 배치 C11 기본값
- 관련: [ADR 0039](0039-readable-run-summaries.md)(요약 문장), [ADR 0038](0038-instagram-rate-limit-rest.md)

## 배경

댓글 확인은 5분마다 돈다. 실행 기록 화면이 "새 댓글 없음", "새 댓글 없음 · 인스타그램 요청 제한으로 쉬는 중(…)" 같은 같은 줄로 가득 찼다. 사용자는 "중복이 너무 많고, 성공한 것도 너무 많이 뜬다"고 했다.

실행 기록을 보는 이유는 두 가지다.

1. 잘 돌고 있나?
2. 무슨 일이 있었나?

한 줄씩 다 보여 주는 화면은 둘 다에 답하기 어렵다.

## 선택지

1. **그대로 둠**: 단순하다 / 중요한 줄(실패, 새 댓글)이 묻힌다.
2. **아무 일 없던 실행은 저장하지 않음**: 화면이 짧다 / 작업이 멈춘 건지 할 일이 없던 건지 구분할 수 없다.
3. **저장은 전부, 화면에서 정리(채택)**: 위에 작업 상태 표, 아래는 변화가 있던 실행만 두고 같은 결과는 묶는다. "전체 보기" 버튼으로 모든 줄을 본다.

## 결정

3번. 화면만 바꾸므로 마음에 들지 않으면 이 PR 하나를 되돌리면 된다.

- **작업 상태 표:** 작업마다 마지막 실행 한 줄을 보여 준다.
  - 칸: 언제 도나, 마지막 실행 시각, 상태, 마지막 결과
  - 상태 값
    - 정상
    - 실패: 마지막으로 성공한 시각을 함께 보여 준다.
    - 실행 중
    - 아직 안 돌았음
    - 오래 안 돌았음: PC가 꺼졌거나 프로그램이 멈췄을 수 있다.
      - 자주 도는 작업만 본다. 댓글 확인은 간격×3과 60분 중 긴 쪽, 로그인 점검·게시하기는 90분을 넘으면 이 상태가 된다. 작업은 한 줄로 차례로 돌아, 원고 만들기가 길면 댓글 확인이 밀리기 때문이다.
      - 실패로 끝난 뒤 멈춘 경우도 이 상태다. "실행 중"인 채로 2시간이 넘으면(실행 도중 프로그램이 꺼짐) 역시 이 상태다.
- **변화가 있던 실행(기본)**
  - 아무 일 없던 성공은 숨긴다. "새 댓글 없음", "로그인 정상", "건너뜀: 활동 시간 밖·게시 시간 밖·오늘 생성 목표 달성"이 여기에 든다.
  - "올린 글 없음"은 이유가 모두 평소 일(간격 대기, 오늘 다 올림, 올릴 원고 없음)일 때만 숨긴다. "연결 안 됨", "일시 중지됨", 요청 제한은 보여 준다.
  - 오류가 적힌 줄은 성공으로 끝났어도 숨기지 않는다.
  - 최근 1000번 실행 안에서 고른다(하루 약 400번). 조용한 밤에도 어제 일이 보인다.
  - 숨긴 횟수는 위에 적는다.
  - 같은 작업이 같은 결과로 이어지면 한 줄로 묶고 "N번"을 붙인다. 다른 작업이 사이에 끼어도 묶인다.
  - 실패, "건너뜀: 쓸 자료 없음"처럼 알아야 할 건너뜀, 요청 제한은 늘 보인다.
- **전체 보기:** `/logs?all=1`(또는 `true`)은 지금까지처럼 최근 200줄을 하나씩 보여 준다.
- **오늘 화면의 "최근 실행":** 같은 규칙으로 10줄을 보여 준다.
- **휴대폰 폭:** 상태 표의 "언제 도나" 칸을 숨긴다.

## 결과

- 운영 중 화면이 몇 줄로 줄고, 실패나 새 댓글 같은 줄이 바로 보인다.
- 어려워진 것: 숨긴 줄을 보려면 "전체 보기"를 한 번 더 눌러야 한다. "아무 일 없음"으로 분류하는 문장 목록(`nsm/app/run_view.py`의 `ROUTINE`)은 요약 문장(ADR 0039)이 바뀌면 함께 고쳐야 한다.
- 다시 볼 조건: 써 보고 불편하면 PR을 되돌린다. 숨기는 기준이 지나치거나 모자라면 `ROUTINE`만 고친다.
