# 0003. 분류기는 MotherDuck jev를 기본으로, Claude 분류기를 같은 포트의 동등 구현으로 둔다

- 상태: 대체됨([ADR 0048](0048-gemini-classifier-replaces-jev.md), 2026-10-20: MotherDuck 체험 종료로 jev를 빼고 Gemini 무료 구간을 기본으로) · 날짜: 2026-10-11 · 결정: 선웅제 · 관련: [mvp-review](../mvp-review.md) #10, 이슈 #7

## 배경

분류가 필요한 곳은 세 군데다: 자료 관련성, 주제, 댓글 6분류. jev는 TypeSafe의 분류 전용 모델로 선택지 중 하나를 신뢰도와 함께 돌려준다. MotherDuck에서 SQL `prompt_jev()`로 부르며, 현재 Lite 플랜($0)에서 쓸 수 있다(하루 10 AI Unit 소프트 한도, 입력 토큰만 과금, EU 리전 제외, 프리뷰). TypeSafe 직접 가입은 2026-09-22부터 중단.

## 선택지

1. **jev만**: 싸고 빠름 / 프리뷰라 중단·변경 위험
2. **Claude만**: 이미 쓰는 키 하나로 해결 / 대량 분류 시 느리고 비쌈
3. **포트 `Classifier` 하나에 두 구현, 설정으로 선택**

## 결정

3번. jev가 막혀도 설정 한 줄로 돌아가고, 테스트는 가짜 분류기로 둘 다와 무관하게 돈다.

## 결과

- 신뢰도 값의 의미가 구현마다 다를 수 있어 0.8 기준은 배치 D1에서 픽스처로 보정한다.
- 비용은 `costs` 테이블에 구현별로 기록한다.

## 2026-10-13 보충: jev 신뢰도 읽는 법

`prompt_jev(..., choice := [...])`의 `confidence`는 고른 라벨의 확률이 아니라 1등과 2등 확률의 차이다(예: relevant 0.70 / irrelevant 0.30 → 0.40). 이 값을 확률로 읽어 관련성 기준 0.8과 비교하는 바람에 실계정 첫 실행에서 관련 자료가 0건이었다. 이제 `probabilities`에서 고른 라벨의 확률을 쓴다(`nsm/adapters/classifier/jev.py`). Claude 분류기와 같은 뜻이 된다. jev를 기본 분류기로 쓰는 결정은 그대로다.
