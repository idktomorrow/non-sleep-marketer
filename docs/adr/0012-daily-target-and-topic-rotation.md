# 0012. 하루 콘텐츠 목표는 쿼터 최댓값, n번째 콘텐츠는 쿼터가 남은 플랫폼에만, 주제는 순환한다

- 상태: 채택(2026-10-13, 배치 B 반영 PR에서 선웅제 확정) · 날짜: 2026-10-11 · 관련: [ADR 0008](0008-autopublish-guardrails.md), [ADR 0009](0009-per-platform-publication-state.md), 이슈 #8

## 배경

- 플랫폼 쿼터가 인스타 1, 스레드 2, 블로그 1처럼 다르다. 콘텐츠 하나를 세 곳에 모두 배정하면 스레드 두 번째 글용 콘텐츠가 없고, 콘텐츠를 두 개 만들어 둘 다 세 곳에 배정하면 인스타·블로그에 하루치가 계속 밀려 쌓인다.
- 계약 초안의 "최근 14일 주제 제외"는 주제 단위가 페르소나 관심 주제(보통 3~5개)라서, 몇 번 만들면 모든 주제가 막힌다.

## 결정

- 하루 생성 목표 = 활성 플랫폼 쿼터 중 최댓값.
- 오늘 n번째(0부터) 콘텐츠는 `쿼터 > n`인 플랫폼에만 게시 레코드를 만든다. 예: 첫 콘텐츠는 세 곳, 둘째는 스레드만.
- 주제는 제외가 아니라 순환: 가장 오래 안 쓴 페르소나 주제의 자료부터 쓴다. 같은 자료는 한 번만 쓴다(`used_in_content_id`).
- 템플릿도 순환: 최근에 안 쓴 정보형·리스트형·비교형 순.
- `topic_cooldown_days` 설정은 지금은 쓰지 않는다(배치 H 주간 리포트의 추천 주제와 함께 다시 본다).

## 결과

- 밀린 게시가 쌓이지 않는다. 검토 대기로 간 콘텐츠도 게시 레코드는 미리 만들어 두고, 승인되면 다음 게시 슬롯에 올라간다.
- 콘텐츠마다 `persona_topic`을 저장하도록 DB 스키마를 v2로 올렸다(첫 마이그레이션).
