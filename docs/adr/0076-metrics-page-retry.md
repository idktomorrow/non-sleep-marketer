# 0076. 성과 읽기에서 글 페이지가 안 열린 실패는 5초 쉬고 그 자리에서 한 번만 다시 읽는다

- 상태: 채택
- 날짜: 2026-11-20
- 결정한 사람: 선웅제(배치 C52 요청), 대행 Claude
- 관련: [0054](0054-error-taxonomy-and-evidence.md)(오류 종류 표), [0069](0069-instagram-insights-parse.md)(C44 다시 읽기), devlog [2026-11-20-batch-C52](../devlog/2026-11-20-batch-C52.md)

## 배경

2026-11-16 03:19 metrics 실행 기록에 "instagram 게시물 지표 실패: instagram: 페이지를 열 수 없음(HTTP ERROR 500)"이
남았다. 인스타그램 서버가 순간적으로 500을 돌려준 것이라 몇 초 뒤 다시 열면 보통 열린다. 그런데 지금은 그 글을 건너뛰고
"오류 1건"으로 남긴다. 다음 실행에 다시 읽기(`REREAD_PASSES`, C44)가 있긴 하지만 하루 뒤라, 그날 지표 칸이 하루 빈다.

## 선택지

1. **그대로 둔다(다음 날 다시 읽기만)**: 코드가 그대로다 / 오류 표시와 하루 빈칸이 남는다.
2. **일시적 실패 전부를 몇 번씩 다시 읽는다**: 더 많이 건진다 / 빈 화면·셀렉터 못 찾음처럼 몇 초 뒤에도 같은 실패를
   되풀이하며 새벽에 브라우저 시간을 쓴다. 로그인·요청 제한에 다시 요청하면 계정에 해롭다.
3. **어댑터가 `code='page'`를 붙인 실패만, 5초 쉬고 한 번만 그 자리에서 다시 읽는다**: 순간 서버 오류는 대개 건지고 비용은
   글 하나당 많아야 5초와 한 번의 요청이다 / 5초 안에 회복하지 않는 장애는 여전히 다음 날로 넘어간다.

## 결정

3번. `is_page_failure`(일시적 + `code='page'` + 끄는 중 아님, 댓글 확인 C37과 같은 기준을 `context.py`로 옮겨 같이 씀)이고
재시도 시각(`retry_at`)이 없는 실패만, `RETRY_WAIT_S`(5초) 쉬고 같은 호출을 딱 한 번 더 한다. 가장 큰 이유:
"페이지가 안 열림"만 서버 쪽 순간 오류라는 뜻이고, 나머지(로그인·화면 변경·요청 제한·셀렉터 못 찾음)는 몇 초 뒤에도
그대로라 다시 해 봐야 시간과 요청만 쓴다.

- **왜 1회·5초**: 순간 500은 보통 몇 초 안에 풀린다. 두 번째도 실패하면 순간 오류가 아니라는 신호라 더 두드리지 않는다.
  글이 많아도 늘어나는 시간은 실패한 글 수 × 5초뿐이다.
- **왜 다음 날 다시 읽기와 겹쳐 두나**: 그 자리 재시도는 "순간" 오류용, `REREAD_PASSES`는 "그날 밤 내내" 오류용이다.
  두 번째도 실패한 글은 지금처럼 오류·일시적 실패로 세어 C44 다시 읽기 상태에 그대로 남으므로, 다음 실행이 다시 읽는다.
  하나만 두면 순간 오류에 하루를 잃거나, 긴 장애에 새벽 내내 두드리게 된다.
- 쉬기 전·후에 끄는 중이면 다시 읽지 않고 지금처럼 "중단"으로 끝낸다(C47, 오류 기록 없음). 5초는 0.5초씩 나눠 쉬며 끄기를 확인해, Ctrl+C가 5초를 다 기다리지 않는다.
- 다시 읽기도 page로 실패하면 순간 오류가 아니라 장애라는 신호라, 그 실행에서 그 플랫폼의 남은 글은 다시 읽지 않는다. 인스타가 밤새 500이면 63개 다시 읽기가 글마다 5초·두 번 요청이 되는 것을 막는다(댓글 확인의 연속 실패 쉬기 C37과 같은 생각).
- 다시 읽어 성공한 수는 저장까지 된 뒤에 센다. 실패하면 첫 예외를 두 번째 예외의 원인(`__cause__`)으로 묶는다.
- 두 번째 실패의 종류가 다르면(로그인·요청 제한 등) 그 예외를 기존 분기대로 처리한다.

## 결과

- 순간 서버 오류는 그날 밤에 읽혀 오류 표시와 하루 빈칸이 없다. 실행 기록에 "페이지 오류로 다시 읽음 n개"가 보인다(0이면 문장 그대로).
- 지표 읽기가 실패한 글마다 최대 5초 길어진다.
- 다시 볼 조건: 두 번째도 `page`로 실패하는 일이 잦으면 대기를 늘리거나, 어댑터가 HTTP 상태(500·502·503)를 따로 알려 줄 때 그 값으로 나눈다.
