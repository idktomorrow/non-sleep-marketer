# 0028. 대시보드 설정 화면: 바꿔도 안전한 값만 화면에서

- 상태: 채택 (선웅제 요청, 2026-10-13) · 날짜: 2026-10-13 · 관련: [0006](0006-single-process-duckdb-fastapi.md), [0027](0027-posting-hours.md)

## 배경

실계정으로 처음 켰을 때 브랜드 정보가 마법사에서 임시로 넣은 `y`로 남아 있었다. 그 값이 자료 관련성 판정("브랜드 'y'의 소재로 쓸 수 있나")과 원고 프롬프트에 그대로 들어가 관련 자료가 0건이 됐다. 페르소나·브랜드를 바꾸려면 `nsm init`을 다시 돌리거나 YAML을 고쳐야 했다. 마케터가 매일 쓰는 도구로는 불편하고, 이름도 "루나"로 고정된 것처럼 보였다.

## 결정

- 대시보드에 "설정" 화면(`/settings`)을 둔다. 고칠 수 있는 값:
  - 페르소나: 이름, 인물상, 말투, 관심 주제(1~10개), 금칙어, 금칙 패턴(고급, 접어 둠)
  - 브랜드: 이름, 업종, 제품, 핵심 메시지, 주 색·보조 색
  - 운영: 활동 시간, 게시 시간, 플랫폼별 하루 게시 수(0~10), 하루 비용 상한(0.1~100달러), 게시 간격(0~24시간), 전체 "광고" 표기
- 화면에서 바꾸지 않는 값: 드라이런, 게시 계정(페르소나 계정 핸들 포함), API 키, 보호 모드 건수. 실제 게시 대상과 안전장치를 바꾸는 값이라 `nsm init`에서만 바꾼다. 폼에 이 이름으로 값을 보내도 무시한다(테스트로 고정).
- 저장하면 `config.yaml`에 쓰고 실행 중인 설정을 바로 바꾼다(켜기/끄기 스위치와 같은 경로). 활동 시간이 바뀌면 수집·생성 예약도 다시 건다(`JobScheduler.reschedule`).
- 검사는 `nsm/app/settings_form.py`에 모았다. 하나라도 틀리면 아무것도 저장하지 않고, 넣은 값을 그대로 다시 보여 주며 무엇이 틀렸는지 알린다.

## 결과

- 이미 만든 원고는 만들 때의 브랜드·페르소나 값을 그대로 가진다(카드 덱에 함께 저장). 새 값은 다음 원고부터 쓰인다.
- 페르소나·브랜드 모델(동결 계약)은 바꾸지 않았다. 값만 바꾼다.
- 대시보드는 127.0.0.1에서만 열리고 모든 저장은 CSRF 토큰을 확인한다. 별도 로그인은 없다(로컬 단일 사용자, ADR 0006).

## 개정 1 (2026-10-29, 배치 C35): API 키만 화면으로 — 상태: 제안

"화면에서 바꾸지 않는 값"에서 **API 키만** 빼서 설정 화면 "API 키" 칸으로 옮긴다. 드라이런, 게시 계정(페르소나 핸들 포함), 보호 모드 건수는 그대로 `uv run nsm init`에서만 바꾼다(설정 화면 POST에 넣어도 무시, 기존 테스트 유지).

왜 키만 옮기나:
- **잘못 넣어도 드러나고 되돌릴 수 있다.** 틀린 키는 다음 호출이 실패할 뿐이고 계정에 아무것도 올라가지 않는다. 저장 직후 "확인"(모델 목록 조회, 비용 0)이 바로 "키가 틀렸거나 만료됨"을 보여 주고, 다시 넣거나 지우면 된다.
- **나머지는 잘못 바꾸면 실계정에 영향이 간다.** 드라이런을 끄면 실제로 올라가고, 계정 핸들이 바뀌면 다른 계정에 올릴 수 있고, 보호 모드 건수를 0으로 하면 사람 검토 없이 나간다. 되돌릴 수 없는 게시로 이어지므로 화면의 한 번 클릭이 아니라 PowerShell의 명시적 질문을 거친다.
- **키 바꾸기는 자주 있다.** 무료 크레딧 소진, 만료, 공급자 교체(C27 jev → Gemini) 때마다 PowerShell을 열고 마법사 전체를 다시 도는 것은 운영 부담이 컸다.

지키는 것:
- 키는 keyring(Windows 자격 증명 관리자)에만 저장한다. 응답·로그·설정 파일·DB에 값을 다시 쓰지 않고, 화면에는 "등록됨/없음"만 보인다(끝 몇 자리도 안 보여 줌). 입력 칸은 password, autocomplete off. 기존 CSRF 검사를 그대로 탄다. 공백이 있거나 20자 미만이면 거부한다.
- 환경 변수로 넣은 키는 프로그램이 지울 수 없고, keyring보다 먼저 읽혀 여기 저장해도 쓰이지 않는다. 그래서 "환경 변수 키라 여기서는 못 지움"으로 안내하고 입력 칸과 지우기 버튼을 감춘다(요청이 와도 저장·삭제하지 않고 안내).
- 새 키는 **저장하기 전에** 확인한다. "틀렸거나 만료됨"이면 저장하지 않아 잘 되던 키를 덮어쓰지 않는다. 연결 실패·한도처럼 판단할 수 없으면 저장한다. 지우기는 지운 뒤 다시 읽어, 남아 있으면 "지우지 못했습니다"라고 말한다.
- "확인"은 공급자의 모델 목록 조회(생성 없음, 비용 0, 시간 초과 10초)다. 결과는 네 가지(연결됨 / 키가 틀렸거나 만료됨 / 키는 맞지만 한도·결제 확인 필요 / 연결 실패)와, 404처럼 예상 밖 응답의 "확인하지 못함(HTTP n)"만 보여 주고, 응답 본문은 싣지 않는다. Gemini는 틀린 키에 401이 아니라 400(`API_KEY_INVALID`)을 돌려줘 이것도 "틀림"으로 본다(2026-10-29 가짜 키로 확인).
- 저장·변경·삭제 뒤 재시작 없이 다음 작업부터 새 키를 쓴다. 출발점인 PR #101의 어댑터 묶음 재생성은 비용 장부 구조까지 바꿔 지금 main과 많이 어긋나므로, 키를 쓰는 부품(분류기 묶음, 글·이미지 생성기, 자동 진단, 올린 이미지 읽기)만 다시 만드는 `refresh_secret_parts`를 새로 짰다. 작업 스레드에서 돌려 실행 중인 잡과 겹치지 않는다(돌던 잡은 옛 키로 끝난다). 처음 켤 때와 같은 공장 함수(`make_secret_parts`)를 쓰고, 다 만든 뒤 한꺼번에 끼워 만들다 실패하면 예전 부품이 그대로 남는다. 실패하면 "API 키 반영 실패" 알림으로 다시 켜 달라고 한다.
