# 0028. 대시보드 설정 화면: 바꿔도 안전한 값만 화면에서

- 상태: 채택 (선웅제 요청, 2026-10-13) · 날짜: 2026-10-13 · 관련: [0006](0006-single-process-duckdb-fastapi.md), [0027](0027-posting-hours.md)

## 배경

실계정으로 처음 켰을 때 브랜드 정보가 마법사에서 임시로 넣은 `y`로 남아 있었다. 그 값이 자료 관련성 판정("브랜드 'y'의 소재로 쓸 수 있나")과 원고 프롬프트에 그대로 들어가 관련 자료가 0건이 됐다. 페르소나·브랜드를 바꾸려면 `nsm init`을 다시 돌리거나 YAML을 고쳐야 했다. 마케터가 매일 쓰는 도구로는 불편하고, 이름도 "루나"로 고정된 것처럼 보였다.

## 결정

- 대시보드에 "설정" 화면(`/settings`)을 둔다. 고칠 수 있는 값:
  - 페르소나: 이름, 인물상, 말투, 관심 주제(1~10개), 금칙어, 금칙 패턴(고급, 접어 둠)
  - 브랜드: 이름, 업종, 제품, 핵심 메시지, 주 색·보조 색
  - 운영: 활동 시간, 게시 시간, 플랫폼별 하루 게시 수(0~10), 하루 비용 상한(0.1~100달러), 게시 간격(0~24시간), 전체 "광고" 표기
- 화면에서 바꾸지 않는 값: 드라이런, 게시 계정(페르소나 계정 핸들 포함), API 키, 보호 모드 건수. 실제 게시 대상과 안전장치를 바꾸는 값이라 `nsm init`에서만 바꾼다. 폼에 이 이름으로 값을 보내도 무시한다(테스트로 고정).
- 저장하면 `config.yaml`에 쓰고 실행 중인 설정을 바로 바꾼다(켜기/끄기 스위치와 같은 경로). 활동 시간이 바뀌면 수집·생성 예약도 다시 건다(`JobScheduler.reschedule`).
- 검사는 `nsm/app/settings_form.py`에 모았다. 하나라도 틀리면 아무것도 저장하지 않고, 넣은 값을 그대로 다시 보여 주며 무엇이 틀렸는지 알린다.

## 결과

- 이미 만든 원고는 만들 때의 브랜드·페르소나 값을 그대로 가진다(카드 덱에 함께 저장). 새 값은 다음 원고부터 쓰인다.
- 페르소나·브랜드 모델(동결 계약)은 바꾸지 않았다. 값만 바꾼다.
- 대시보드는 127.0.0.1에서만 열리고 모든 저장은 CSRF 토큰을 확인한다. 별도 로그인은 없다(로컬 단일 사용자, ADR 0006).
