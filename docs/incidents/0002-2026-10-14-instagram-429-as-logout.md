# 0002. 인스타그램 요청 제한(HTTP 429)을 로그인 풀림으로 오인, "로그인 필요" 반복

- 날짜: 2026-10-14 20:24 ~ 2026-10-16 00:47 (KST)
- 종류: `rate_limited`인데 그때는 `auth`(로그인)로 잘못 보고됨
- 고친 것: PR #74(배치 C9), ADR 0038

## 증상 (사용자가 본 것)

대시보드 실행 기록에서 인스타그램 댓글 확인이 5분마다 "instagram 로그인 필요: 로그인돼 있지 않음"으로 실패했다. 같은 시간 로그인 점검과 게시는 성공이라 앞뒤가 맞지 않았다.

## 영향 (기간·건수)

| 항목 | 값 | 근거 |
|---|---|---|
| 기간 | 10-14 20:24 ~ 10-16 00:47, 약 28시간 20분 | `nsm.log` 첫 게시 실패 줄, 마지막 "instagram 로그인 필요" 줄 |
| 실패한 댓글 확인 | 172회 (알림 1건 포함 로그 173줄) | `nsm.log`에서 "instagram 로그인 필요"를 10-14~10-16 범위로 grep |
| 날짜별 | 10-14 39줄, 10-15 128줄, 10-16 8줄 | "로그인돼 있지 않음" 줄 수(어댑터 경고 줄 포함 175) |
| 게시 실패 | 2회(10-14 20:24, 21:24), `net::ERR_HTTP_RESPONSE_CODE_FAILURE` | `nsm.log` |
| 놓친 댓글 | 그 기간 인스타그램 새 댓글을 읽지 못함 | devlog C9 |

## 원인

인스타그램이 글 페이지에 Chrome 오류 화면 "HTTP ERROR 429"(요청이 너무 많음)를 보여 줬다. 홈 화면은 정상이었다. 댓글 스크립트는 오류 화면에서 내 프로필 사진을 찾지 못하자 "로그인 안 됨"으로 보고했다. 오류 문구는 관찰("사진이 없다")을 원인("로그인 풀림")으로 해석한 말이었다.

## 어떻게 발견했나

사용자가 실행 기록을 보고 이유를 물었다. 로그에서 첫 실패를 찾고, 같은 시간 health·게시가 성공인 것을 확인했다. Aside로 글 페이지 8개를 읽기 전용으로 열어 모두 429 화면임을 봤다.

## 고친 것

- 핸들을 읽기 전에 오류 화면인지 먼저 본다. 429면 `RateLimitedError`.
- 2시간 쉬고, 다시 막히면 4·8시간으로 늘린다(최대 8시간). 쉬는 동안은 브라우저를 열지 않는다.
- health는 429로 멈추지 않고, 게시는 재시도 횟수를 쓰지 않는다.
- 인스타그램 댓글 확인 간격 30분, 최근 3일 글만.

## 재발 방지

- 테스트: 429 화면 → 요청 제한(로그인 오류 아님), 2→4→8시간, 쉬는 동안 요청 0건(`tests/unit/test_instagram_adapter.py`, `tests/engine/test_rate_limit.py`).
- C9 머지 뒤 인스타그램 "로그인 필요" 오보는 0건이다(로그의 다음 "instagram 로그인 필요"는 0008의 재시작 중 멈춤 1건뿐).
- 요청 제한 알림은 쉬는 구간마다 한 번(`nsm.log`에 4건).

## 지금 체계였다면

- E1: 429는 `rate_limited`로 분류돼 쉬기만 한다. 증거는 남기지 않는다(쉬는 동안 매번 던지므로).
- E2: 장애 화면 "요청 제한" 줄이 "진행 중 · 인스타그램: 요청 제한으로 HH:MM까지 쉬는 중"으로 보이고, "오늘" 화면 맨 위에도 같은 한 줄이 뜬다. 진단은 하지 않는다(원인이 분명한 종류).
- 당시처럼 오류 화면을 로그인으로 오인하는 새 경우가 생기면 `auth`로 기록돼 health가 멈출 수 있다. 이때 E2 장애 화면에는 "로그인 필요로 멈춤"이 보이지만 health 점검은 성공하는 모순이 드러난다. 사람이 그 모순을 보는 것이 당시 발견 경로와 같다.
