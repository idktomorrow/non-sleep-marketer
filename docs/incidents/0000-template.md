# NNNN. 제목 (한 줄, 사용자가 본 증상 중심)

- 날짜: YYYY-MM-DD (처음 본 시각 ~ 끝난 시각, KST). 파일 이름의 날짜는 시작한 날
- 종류(ADR 0054 오류 종류 표): `transient` / `rate_limited` / `auth` / `ui_changed` / `config_or_bug` / 표 밖(예외 없는 조용한 실패 등)
- 고친 것: PR #, 배치, ADR

## 증상 (사용자가 본 것)

대시보드·알림·계정 화면에서 무엇이 보였나. 사람이 본 그대로 쓴다.

## 영향 (기간·건수)

| 항목 | 값 | 근거 |
|---|---|---|
| 기간 | 시작 ~ 끝 (몇 시간) | `~/.nsm/logs/nsm.log` 첫·마지막 줄 |
| 실패 건수 | N | 로그 grep 문구, DB 조회 |

숫자마다 어디서 어떻게 셌는지 적는다(grep 문구, 읽기 전용 DB 백업 조회). 운영 DB는 고치지 않는다.

## 원인

겉으로 보인 오류 문구와 실제 원인을 나눠 쓴다.

## 어떻게 발견했나

사용자 제보 / 알림 / 감시(ADR 0041) / 로그 / 코드 리뷰.

## 고친 것

PR·배치·ADR과 바뀐 동작.

## 재발 방지

테스트, 감시, 알림, 설정. 아직 남은 위험이 있으면 적는다.

## 지금 체계였다면

E1(오류 종류 표·증거 저장, ADR 0054), E2(장애 화면·자동 진단, ADR 0055), 알림이 그때 어떻게 보였을지.
