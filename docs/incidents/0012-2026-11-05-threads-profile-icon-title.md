# 0012. 스레드 화면 변경(프로필 아이콘 이름이 `<title>`로)을 "로그인 필요"로 오판해 스레드 멈춤

- 날짜: 2026-11-05 (20:56 ~ 22:35까지, 약 1시간 39분, KST)
- 종류(ADR 0054 오류 종류 표): 실제로는 `ui_changed`, 보인 것은 `auth`(로그인 필요, 원인 모름)
- 고친 것: 배치 C38, ADR 0063

## 증상 (사용자가 본 것)

- 20:56 댓글 확인이 "threads 로그인 필요: 로그인돼 있지 않음"으로 실패했고, 스레드가 멈췄다(멈춤 이유 `auth`, 세부 상태 unknown).
- 21:15·21:47 건강 점검도 "로그인 필요(원인 모름)"으로 멈춤을 유지했다.
- 실제로는 로그인돼 있었고 글 페이지도 정상으로 열렸다. 인스타그램은 정상이었다.

## 원인

- **겉으로 보인 문구**: "로그인돼 있지 않음". 실제 로그아웃이 아니었다.
- **실제 원인**: 스레드 왼쪽 메뉴의 프로필 링크 구조가 바뀌었다(2026-11-05 확인).
  - 전: `<a href="/@핸들">` 안에 `<svg aria-label="프로필">`.
  - 후: `<a href="/@nonsleepmarketer" role="link">` 안에 `<svg role="img"><title>프로필</title></svg>`. aria-label이 없다.
- `nsm/adapters/platforms/threads.py`의 `readHandle`은 `svg[aria-label="프로필"|"Profile"]`만 찾았다. 그래서 빈 핸들을 돌려줬고, `nsmAssertHandle`이 `NsmError('login', '로그인돼 있지 않음')`을 냈다. 건강 점검도 같은 `readHandle`을 써서 멈춤이 풀리지 않았다.

### 판정의 한계

- **오류 종류가 틀렸다.** 오류 종류 표(ADR 0054)로는 화면 구조 변경, 즉 `ui_changed`다. 코드는 "핸들을 못 읽음 = 로그인 안 됨"으로 보아 `auth`가 됐다. `auth`는 사람이 다시 로그인하면 풀린다고 보고 그렇게 안내한다. 하지만 이번에는 다시 로그인해도 풀리지 않는다. 코드를 고쳐야 했다.
- **로그인된 화면의 증거를 무시했다.** 증거(`~/.nsm/logs/shots/threads-20261105-205557`)의 화면 글과 사진에는 로그인된 사람만 보는 것들이 있었다.
  - 답글 입력칸 "nonsleepmarketer님에게 답글 남기기..."
  - 왼쪽 메뉴 "새로운 스레드·메시지·활동·프로필·인사이트·저장됨"
  - 오른쪽 "인사이트" 칸
  - 화면의 이름표 목록(labels)에도 "프로필"이 있었다.

  그래도 판정은 핸들 하나에만 기댔다. E5(ADR 0060)의 세부 상태 분류도 로그인 폼·본인 확인 문구만 찾으므로 "원인 모름"으로 끝났다.

## 어떻게 발견했나

사용자가 11-04 제한(incidents/0011) 회복 뒤 첫 댓글 확인 로그를 보던 중 "로그인 필요"를 발견했다. 증거 폴더 화면과 스레드 홈을 직접 열어 로그인이 정상인 것을 확인했다.

## 고친 것

배치 C38(ADR 0063):
- `readHandle`이 svg `aria-label`뿐 아니라 svg 안 `<title>` 글("프로필"/"Profile", 공백 제거)도 본다.
- 둘 다 못 찾으면 마지막 대체로 왼쪽 메뉴의 `a[href="/@설정핸들"]`을 쓴다. 글 카드·가운데 칼럼 안 링크(글 작성자 링크)는 뺀다.
- 테스트는 가짜 탭으로 aria-label 화면, `<title>` 화면, 대체 경로, 그리고 프로필 링크가 없을 때 여전히 로그인 필요인지를 본다.

## 회복

이 배치를 반영하고 `nsm run`을 다시 켜면, 다음 건강 점검(30분 이내)이 로그인을 확인하고 멈춤을 자동으로 푼다("threads 다시 연결됨" 알림). 실제 회복 시각: 2026-11-05 22:35, 재시작 6분 뒤 건강 점검에서 자동으로 풀림.

## 재발 방지

- 이번 배치는 아이콘 이름의 두 방식과 대체 경로만 넣었다. 남은 위험이 있다.
  - 화면이 다시 바뀌어 메뉴 링크마저 못 찾으면 다시 "로그인 필요"로 보인다.
  - 대체 경로로 버티는 중인지는 기록되지 않는다.
- 다음 배치 후보(ADR 0063 "다음 배치 후보"):
  - 답글 입력칸·"새로운 스레드" 메뉴 같은 로그인 표지가 보이면 로그인으로 본다.
  - 핸들을 못 읽으면 `auth`가 아니라 `ui_changed`로 판정한다.
  - 대체 경로 사용을 기록한다.

## 지금 체계였다면

- E1(ADR 0054)은 실패와 증거를 남겼다. 이번에도 증거 폴더에 화면 사진·화면 글·이름표가 남아 원인을 바로 볼 수 있었다.
- E2(장애 화면)는 이것을 "로그인 필요(원인 모름)"으로 보여 줬다. E5 안내는 "Aside 브라우저에서 직접 확인"이었고, 사용자는 그대로 따라 "로그인돼 있음"을 확인했다. 그다음 할 일(코드 수정)은 화면이 알려 주지 못했다.
- 위 다음 배치 후보가 들어가면 "화면이 바뀜(코드 수정 필요)"으로 보인다.
