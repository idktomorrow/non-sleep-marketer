# 장애 기록

운영 시작(2026-10-13)부터 겪은 장애를 한 건당 한 장으로 남긴다. 무엇이 보였고, 얼마나 영향이 있었고, 왜 났고, 무엇을 고쳤는지 적는다. 마지막 절 "지금 체계였다면"은 E1(오류 종류 표·증거, ADR 0054)과 E2(장애 화면·자동 진단, ADR 0055)가 그 장애를 어떻게 보여 줬을지 적는다.

- 새 장애는 [0000-template.md](0000-template.md)를 복사해 `NNNN-YYYY-MM-DD-slug.md`로 만든다. 날짜는 **시작한 날**이다.
- 숫자는 `~/.nsm/logs/nsm.log`, 새벽 DB 백업(`~/.nsm/backups/`)의 읽기 전용 복사본, devlog에서 직접 센다. 기록마다 근거를 적는다.
- DB 시각은 UTC다. 날짜별로 셀 때는 9시간을 더해 KST로 바꾼다.
- 댓글 작성자 핸들 같은 개인 정보는 옮기지 않는다.

## 9건에서 보이는 것

- **플랫폼 어댑터의 예외로 드러난 실패는 5건**(0002·0004·0008·0009·0010)이고, 오류 체계(E1·E2)가 다루는 것은 이 5건이다.
- 예외는 났지만 어댑터 밖이었던 것이 2건이다. 0006은 분류기 예외 30건(분류기 대체 사슬이 맡음), 0003은 대시보드 500(작업 폴더 분리로 막음)이다.
- 나머지 3건(0001·0005·0007)은 예외 없이 "성공, 0건"이거나 결과만 틀렸다. 감시(ADR 0041), 사람 검토, 품질 하한(ADR 0051)이 맡는다.
- **"로그인 필요"는 두 번 거짓이었다**(0002의 429, 0008의 재시작). 오류 문구는 관찰이지 원인이 아니다.
- **"로그인 필요"가 맞아도 할 일은 달랐다**(0010). 로그아웃이 아니라 본인 확인·문자 인증이었다. E5부터 화면 문구로 세부 상태를 나눈다(ADR 0060).
- **외부 화면 변경은 재시도로 풀리지 않는다**(0004). 지금 표대로면 첫 실패에서 검토로 넘어간다. 전에는 원고 하나를 포기하기까지 재시도 대기만 15+60+240 = 315분, 즉 최소 5시간 15분이었다. 게시 잡은 30분마다 플랫폼당 한 건만 시도하므로 실제로는 더 길다. ADR 0054는 이를 "네 시간 반"이라고 적었는데 설정 기본값(`retry_delays_minutes: [15, 60, 240]`)으로 계산하면 5시간 15분이다.
