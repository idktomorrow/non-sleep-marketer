# 0016. 인스타그램 인사이트 숫자를 엉뚱한 칸으로 읽음: 조회 0·좋아요=조회가 "성공"으로 한 달 쌓임

- 날짜: 2026-10-15 무렵 ~ 2026-11-12 (KST). 파일 이름의 날짜는 인스타그램 지표가 처음 쌓이기 시작한 무렵이다
- 종류(ADR 0054 오류 종류 표): 표 밖(조용한 거짓 성공). 고친 뒤에는 `ui_changed`
- 고친 것: 배치 C44, ADR 0069

## 증상 (사용자가 본 것)

- R5 문서 질문의 "성과 요약"이 인스타그램 글을 "조회 3 · 참여율 266.7%"처럼 보였다. 사용자가 인스타그램 앱의 숫자와 대조하다 이상함을 알았다.
- 글 DfjNjZkHST4(11-10 게시)는 11-10 18:15 기록이 조회 0, 조회한 사람 4였다. 사용자가 11-11 밤 앱에서 본 값은 조회 6, 좋아요 0, 댓글 0이었다.
- 로그에 실패가 없다. 틀린 숫자가 매번 "성공"으로 저장됐다.

## 영향 (기간·건수)

| 항목 | 값 | 근거 |
|---|---|---|
| 인스타그램 글 | 63개 중 57개의 최신 지표가 조회·좋아요·댓글 전부 0 | 배치 요청에 적힌 백업 DB(2026-11-11) 분석 |
| 10-28 이후 읽은 행 | 100% 0 | 같은 분석 |
| 0이 아닌 행 | 30건 중 25건이 조회=좋아요(3·3, 5·5 …) | 같은 분석 |
| 스레드 | 57개 중 1개만 0. 이 사고와 무관 | 같은 분석 |
| 주간 리포트·R5 성과 요약 | 인스타그램 참여율이 부풀거나(좋아요=조회) 0으로 보임 | 둘 다 최신 행을 쓴다 |

## 실제 화면 글 (C44 1번, 2026-11-11 23:36 시험 계정)

글 하나의 인사이트를 한 번만 열어 읽었다. 증거 폴더 `instagram-20261111-233612`(화면·`t2.txt`·`main.txt`·`insights.json`).

- "인사이트 보기"를 누르면 대화상자가 아니라 `/insights/media/<id>/` 페이지로 바뀐다. 그래서 `t2`와 `main` innerText가 같다.
- 연 직후 0.5초·1초에는 글이 "0" 한 줄뿐이었다. 1.5초에 아래 전체가 보였다. 로딩 중 0이 먼저 보인다.
- 전체 글(줄바꿈을 " / "로, 계정 정보는 원래 없음):

```
0 / 조회수 / 조회수 / 10 / 팔로워 / 100% / 팔로워가 아닌 사람 / 0% / 홈 / 6 / 프로필 / 4 /
조회한 사람 / 4 / 반응 / 반응 / -- / 게시물 반응 / 0 / 좋아요 / 0 / 댓글 / 0 / 저장 / 0 / 공유 / 0 /
참여한 계정 / -- / 프로필 / 프로필 활동 / 0 / 프로필 방문 / 0 / 외부 링크 누름 / 0 /
비즈니스 주소 누름 / 0 / 팔로우 / 0 / 광고 / 이 게시물 홍보하기
```

- 순서는 **"이름 숫자"**다: "조회수 10", "조회한 사람 4", "좋아요 0", "댓글 0", "저장 0", "공유 0".
- "조회수"는 두 번 나온다(제목과 항목). 맨 앞의 "0"은 제목 앞에 붙은 숫자다.
- 다른 숫자 항목: 팔로워·팔로워가 아닌 사람 비율(%), 조회수가 나온 곳(홈 6, 프로필 4), 게시물 반응 합계, 프로필 활동(방문·외부 링크·주소·팔로우). "--"는 값 없음이다.

## 원인

- `instagram.py` `_POST_METRICS`의 정규식이 "숫자 이름" 순서(`([0-9]…)\s*조회수`)를 가정했다. 화면은 "이름 숫자"다.
- 그래서 각 이름 바로 **앞**의 숫자, 즉 직전 항목의 숫자를 집었다.
  - 조회수 ← 맨 앞 "0"(제목 앞 숫자). 그래서 조회가 거의 늘 0이었다.
  - 좋아요 ← "게시물 반응" 합계.
  - 댓글 ← 좋아요 숫자, 저장 ← 댓글 숫자, 공유 ← 저장 숫자.
- 조회=좋아요 25건은 이 밀림으로 설명된다. 맨 앞 숫자가 화면 상태에 따라 반응 합계와 같은 값으로 보였던 것으로 보인다. 정확한 예전 화면은 남아 있지 않다.
- `reach`만 "조회한 사람 N"(이름 숫자)으로 짜여 있어 맞게 읽혔다. 조회 0·조회한 사람 4 같은 있을 수 없는 조합이 그래서 생겼다.

## 왜 한 달 동안 몰랐나

- 0이 실패가 아니라 성공으로 저장됐다. 정규식이 숫자를 하나라도 집으면 값이 되고, 못 집어도 실패가 아니었다.
- 시험 계정이라 팔로워가 거의 없다. 조회 0·좋아요 0이 이상해 보이지 않았다.
- 대시보드 성과 화면·주간 리포트는 숫자를 보여 주기만 하고 앱과 대조할 기회가 없었다.
- 발견 경로: R5 성과 요약이 "조회 3 · 참여율 266.7%"를 보였고, 사용자가 앱의 숫자와 대조했다.

## 고친 것

C44(ADR 0069).

- **해석은 파이썬에서**: 스크립트는 인사이트 글 원문만 돌려준다. `parse_insights(text)`가 해석한다.
  - 줄마다 이름과 숫자를 나눈다.
  - 항목마다 "이름 바로 뒤 숫자"를 먼저 보고, 없으면 "이름 바로 앞 숫자"를 본다. 한 숫자는 한 항목에만 쓴다.
  - 화면 전체가 예전처럼 "숫자 이름"이면 앞 우선이 더 많이 채우므로 그쪽을 쓴다.
  - 비율(%)은 숫자가 아니다. 천·만·K·M은 예전 규칙 그대로.
- **못 찾으면 None**: 이름이 없는 항목은 0이 아니라 None(대시보드 `-`)으로 둔다. 댓글은 인사이트에 없으면 글 화면의 댓글 수를 쓴다.
- **있을 수 없는 값은 실패**: 아래 두 경우는 `ui_changed` 실패(오류 1건)로 남기고 화면 증거를 저장한다.
  - 조회수를 못 찾음.
  - 조회수 0인데 조회한 사람·좋아요·댓글·저장·공유 중 하나라도 1 이상.
- **로딩 대기**: "조회수" 줄 바로 뒤에 숫자가 보인 뒤에도, 0.5초 간격으로 두 번 연속 같은 글이 나올 때까지(최대 10초) 기다린다.
- **한 번 다시 읽기**: 성과 읽기는 게시 뒤 7일만 읽어 옛 글은 틀린 값에 멈춰 있다.
  - 고친 뒤 첫 성과 읽기가 인스타그램 최근 90일 글 전부를 한 번 읽는다(kv `c44_instagram_reread`).
  - 요청 제한(429)으로 쉬면 다음 실행이 이미 읽은 글은 건너뛰고 이어 간다.
  - 실행 기록에 "인스타그램 지표 다시 읽기 N/63"이 남는다.
  - 예전 틀린 행은 지우지 않는다. 최신 행을 쓰는 곳(주간 리포트, R5 성과)은 다시 읽은 뒤 맞는 값을 쓴다. 이미 만든 주간 리포트 파일은 그대로 둔다.

## 재발 방지

- 값이 있을 수 없는 조합은 실패로 한다. "숫자를 읽었다"와 "맞는 숫자를 읽었다"는 다르다.
- 실제 화면 글을 그대로 픽스처로 둔다(`tests/unit/test_instagram_insights_parse.py`). 화면이 바뀌면 새 글을 픽스처로 더한다.
- 남은 위험: 이름이 같은 다른 항목(예: "프로필"은 두 번 나온다)을 쓰게 되면 첫 번째 것을 집는다. 지금 읽는 여섯 항목은 화면에 한 번씩만 숫자와 붙어 있다.

## 지금 체계였다면

첫 읽기에서 "조회한 사람 4인데 조회수 0"이 `ui_changed` 실패로 실행 기록에 남고, 화면 증거가 저장됐을 것이다. 다음 날에도 같은 오류가 반복되므로 한 달이 아니라 하루 안에 보였다.
