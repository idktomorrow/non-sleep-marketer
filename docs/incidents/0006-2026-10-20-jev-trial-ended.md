# 0006. MotherDuck 체험 종료로 분류 전부 실패, Gemini로 교체

- 날짜: 2026-10-20 00:29 ~ 04:25 (KST)
- 종류: 플랫폼 어댑터 밖(분류기). 성격은 `config_or_bug` — 다시 해도 같고, 사람이 계약·설정을 바꿔야 풀린다
- 고친 것: PR #95(배치 C27), ADR 0048

## 증상 (사용자가 본 것)

00:29 자료 모으기에서 새 자료 31개를 살폈는데 관련 자료가 0개였다. 오류 30건이 "관련성 분류 실패: prompt_jev 호출 실패"였다. 01:00 원고 만들기는 "쓸 자료 없음"으로 건너뛰었다.

## 영향 (기간·건수)

| 항목 | 값 | 근거 |
|---|---|---|
| 분류 실패 | 31건 중 30건 오류, 관련 0개 | `nsm.log` 10-20 00:31 collect 줄 |
| 원고 | 0건(01:00 "쓸 자료 없음") | `nsm.log` 10-20 01:00 generate 줄 |
| 멈춘 시간 | 00:29 ~ 04:25, 약 4시간 | 실패 줄 ~ 교체 후 첫 원고 줄 |
| 교체 후 첫 실행 | 04:21 새 자료 22개 중 관련 4개, 04:25 원고 1개 | `nsm.log` |
| 후보 비교 | 실제 자료 294건 + 댓글 9건, 비용 0원. Gemini 약 97%, 댓글 9/9 | devlog C27 |

## 원인

분류에 쓰던 MotherDuck의 jev 모델 체험이 끝났다("Your MotherDuck trial has ended"). jev는 MotherDuck 안에서만 쓸 수 있고, 계속 쓰려면 호출 과금이 필요했다.

## 어떻게 발견했나

수집 실행 기록의 오류 30건. 원고가 0건이라 사용자가 바로 알았다.

## 고친 것

- 사용자 결정: 돈이 나가지 않는 쪽으로, jev·MotherDuck은 뺀다.
- Gemini 무료 구간 분류기(10건 묶음, JSON 스키마 출력).
- 분류기 사슬: Gemini → Claude → 낱말 규칙. 호출이 실패하면 다음으로 넘어가고 처음 한 번 "분류기 대체" 알림. 30분 뒤 첫 분류기를 다시 시도한다(유료 Claude에 눌러앉지 않게).

## 재발 방지

- 대체 사슬과 되돌아오기(`tests/unit/test_classifiers.py`).
- Gemini 429가 하루 여러 번이면 묶음을 키우거나 Claude로 바꾼다(ADR 0048 다시 볼 조건).

## 지금 체계였다면

분류기 실패는 플랫폼 어댑터의 오류 종류 표가 아니라 분류기 대체 사슬(C27)이 맡는다. ADR 0054 "자동으로 하는 것"에 있는 "분류기가 실패하면 다음 분류기로 대체"가 바로 이 장애에서 나왔다. 지금 같은 일이 나면 Gemini가 실패해도 Claude나 낱말 규칙으로 넘어가 수집이 0건이 되지 않고, "분류기 대체" 알림이 한 번 온다. E2 장애 화면에는 나타나지 않는다(어댑터 실패만 기록).
