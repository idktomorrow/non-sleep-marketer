# 0005. 인스타그램 답글이 초점을 잃고 새 댓글로 달림

- 날짜: 2026-10-16 ~ 2026-10-19 21:05 (KST, 관찰 구간)
- 종류: 표 밖 — 예외 없이 결과만 틀린 실패(답글은 "성공"으로 끝남). 확인 단계가 경고만 남김
- 고친 것: PR #87(배치 C22), PR #88(배치 C23, 확인 못 한 답글은 사람에게), PR #93(배치 C25)

## 증상 (사용자가 본 것)

자동 답글이 댓글 아래(스레드 답글)가 아니라 "@작성자 …"로 시작하는 **새 댓글**로 올라갔다. 사용자가 "답글로 다는 게 낫지 않나"라고 물었다. C22로 고친 뒤에도 같은 날 21:05에 한 번 더 새 댓글로 올라갔다.

## 영향 (기간·건수)

| 항목 | 값 | 근거 |
|---|---|---|
| "답글은 보냈지만 확인하지 못함" 경고 | 4회(10-16, 10-18, 10-19 16:47, 10-19 21:05) | `nsm.log` grep. 댓글 작성자 핸들은 기록에 옮기지 않는다 |
| C22 전 새 댓글로 관찰 | 2회 | devlog C22 |
| C22 뒤 새 댓글 | 1회(10-19 21:05). 같은 코드로 16:48 답글은 정상 | devlog C25 |
| C25 뒤 같은 경고 | 0회 | `nsm.log` |
| 실험으로 단 테스트 답글 | C22 2회, C25 2회. 사용자 테스트 댓글 아래에만 달고 지움 | devlog C22·C25 |

## 원인

두 단계였다.
1. **C22**: "답글 달기"를 누른 뒤 입력창을 마우스로 다시 클릭하면 인스타그램이 답글 대상을 지운다. 입력창의 "@작성자" 글자는 그대로 남아 겉으로는 차이가 없다.
2. **C25**: 클릭을 없앤 뒤에도 "게시" 버튼 마우스 클릭이 mousedown 순간 입력창 초점을 빼앗았다(blur). blur 처리와 click 처리의 순서가 매번 달라 결과가 들쭉날쭉했다(경쟁 조건).

## 어떻게 발견했나

사용자가 계정 화면에서 보고 물었다. 로그의 "확인하지 못함" 경고가 같은 시각에 있었다. 전송 전에는 화면에 차이가 없어 사용자의 테스트 댓글 아래에서 전송 방법을 하나씩 바꿔 실험했다.

## 고친 것

- C22: 입력창을 클릭하지 않고 "@작성자"로 채워질 때까지 기다린 뒤 `focus()`와 `insertText`를 쓴다.
- C23: 보냈지만 확인하지 못한 답글은 다시 보내지 않고 사람 확인으로 넘긴다.
- C25: Enter로 보낸다. 6초 안에 입력창이 비지 않을 때만 "게시"를 누른다.

## 재발 방지

- 답글 스크립트 구조 테스트(클릭·End 없음, Enter 먼저).
- "확인하지 못함"이면 사람에게(중복 답글보다 한 번 빠지는 쪽, C23·C24).

## 지금 체계였다면

- 예외가 나지 않는 실패라 E1 표와 E2 장애 화면에는 잡히지 않는다. "확인하지 못함"은 지금 사람 확인 댓글로 넘어가 댓글 화면과 "댓글 확인 필요" 알림에 보인다.
- 이 장애는 ADR 0054가 "자동 수정"을 하지 않는 이유의 실제 사례다. 화면이 같은데 내부 상태가 달라 결과가 갈렸다. 코드가 추측해서 "비슷한 버튼"을 눌렀다면 새 댓글이 더 늘었을 것이다.
