# 0017. 스레드 게시가 1·2차 "게시를 확인하지 못함"으로 실패하고 3차에 올라감: 게시 직후 탭 이동이 업로드를 끊음

- 날짜: 2026-11-13 08:12 ~ 2026-11-24 08:41 (KST). 파일 이름의 날짜는 처음 본 날
- 종류(ADR 0054 오류 종류 표): `transient`(확인 실패로 재시도). 실제로는 우리 스크립트가 게시를 끊은 것
- 고친 것: PR(C58), 배치 C58, ADR [0078](../adr/0078-threads-publish-stay-on-tab.md)

## 증상 (사용자가 본 것)

- 실행 기록과 장애 화면에 `threads 게시 실패: PlatformError: threads: 게시를 확인하지 못함(프로필에서 글을 못 찾음)`이 떴다.
- 같은 원고가 30분 뒤 재시도에서 또 실패하고, 세 번째에 올라갔다. 글은 늦게 올라갔지만 빠지거나 겹친 글은 없었다.
- 증거 폴더(`~/.nsm/logs/shots/threads-…`)를 열면 `dialogs.json`만 있고 화면(`screenshot.png`)이 없었다.

## 영향 (기간·건수)

| 항목 | 값 | 근거 |
|---|---|---|
| 기간 | 11-13 08:12 ~ 11-24 08:41 | `~/.nsm/logs/nsm.log*` 첫·마지막 줄 |
| 실패 건수 | 11회: 11-13 08:12·12:23·16:31, 11-16 11:36·12:09, 11-17 08:17, 11-18 08:36, 11-20 11:50·12:26, 11-24 08:05·08:41 | `grep "threads 게시 실패: PlatformError: threads: 게시를 확인하지 못함" nsm.log*` |

| 게시 지연 | 원고마다 1·2차 실패 뒤 3차 성공. 재시도 간격만큼 늦었다 | 실행 기록(사용자 확인) |

운영 DB는 열지 않았다. 숫자는 로그와 증거 폴더에서 셌다.

## 원인

- 겉으로 보인 것: "프로필에서 글을 못 찾음". 11-24 08:05의 `dialogs.json`을 보면, 창은 닫혔는데(`closed`=true) 프로필에 새 글이 없었다. 약 90초 동안 프로필을 다시 읽었는데도 없었다.
- 실제 원인: `threads.py` `_PUBLISH`는 미리보기가 생기자마자 '게시'를 누르고, 창이 닫히자마자 같은 탭을 프로필로 옮겼다(`findMine(pg)`의 `pg.goto`). 스레드 웹은 창을 먼저 닫고 업로드·게시를 뒤에서 마치므로, 탭 이동이 진행 중인 요청을 끊었다. 인스타그램은 같은 페이지에서 "공유되었습니다"를 기다린 뒤 옮겨서 괜찮았다.
- 3차에 된 이유는 확인하지 못했다. 업로드가 빨리 끝난 때는 이동 전에 마쳤을 것으로 추정한다.
- 증거 화면이 없던 이유: 글 찾기 예산이 `nsmLeft() - 17000`이었다. 그런데 `nsmUntil`은 마감을 회차 앞에서만 보므로, 마지막 회차가 끝나면 4~6초만 남았다. `nsmEvidence`의 화면 예산(`nsmLeft() - 3000`)이 그만큼 깎여 `pg.screenshot`이 실패했다.

## 어떻게 발견했나

사용자가 운영 로그에서 같은 문구가 반복되는 것을 보고, `dialogs.json`과 호출 시간으로 좁혔다.

## 고친 것

C58, ADR 0078:
- 게시 탭은 '게시'를 누른 뒤 주소를 옮기지 않는다. 창이 닫히면 5초를 기다리고, "게시 중"이 사라지거나 "게시됨"이 보일 때까지 최대 15초를 더 기다린다.
- 확인은 따로 연 탭에서 한다.
- '게시'는 활성일 때만 누른다. `nsmClickText`가 비활성 버튼을 건너뛰고, 답글 두 곳도 `nsmUntil`로 다시 본다.
- 글 찾기 예산은 `nsmLeft() - 25000`으로 바꿨다. 증거는 게시 탭에서 5초 예산으로 찍는다.

## 재발 방지

- 테스트(`tests/unit/test_threads_publish_settle_c58.py`):
  - 순서: 창 닫힘 → 5초·문구 대기 → 확인 탭 글 찾기
  - 게시 뒤 게시 탭에는 `goto`가 없다
  - '게시' 클릭을 `nsmUntil`로 감쌌다
  - node 가짜 실행기로 비활성 버튼 건너뛰기와 증거 탭 지정을 확인한다
  - 바뀐 스크립트의 문법을 검사한다
- 남은 위험:
  - 스레드의 "게시 중/게시됨" 실제 문구는 아직 모른다. 로그의 `게시 뒤 화면 문구`로 확인한다.
  - 업로드가 20초보다 오래 걸려도 게시 탭은 살아 있다. 다만 글 찾기가 그 전에 끝나면 확인 실패로 재시도한다. 멱등 확인이 중복을 막는다.
