# 0010. 인스타그램이 "로그인 필요"로 사흘 반 멈춤, 실제로는 본인 확인·문자 인증 요구

- 날짜: 2026-10-29 (08:56 처음 실패 ~ 11-01 20:54 자동 재개, KST). 첫 게시 재개는 11-01 21:22
- 종류(ADR 0054): `auth`(분류는 맞았다. 세부 원인을 나누지 못했다)
- 고친 것: 배치 E5(로그인 세부 상태), ADR 0060

## 증상 (사용자가 본 것)

- 10-29 09:00 "instagram 로그인 필요" 알림이 왔다. 본문은 "브라우저에서 다시 로그인하세요. (인스타그램 로그인 필요(Aside 브라우저))"였다.
- 오늘 화면과 장애 화면에도 "인스타그램(로그인 필요)"만 보였다.
- 화면과 알림만 봐서는 로그아웃인 줄 알았다. 실제 Aside 브라우저에는 로그인 폼이 아니라 인스타그램의 보안 확인 창이 떠 있었다.
- 스레드는 영향이 없었다(같은 기간 게시 4건, 댓글 확인 정상).

## 원인

- **겉으로 보인 문구**: "로그인돼 있지 않음". 점검 스크립트는 화면 위쪽의 내 프로필 링크만 보고, 없으면 로그인 안 됨이라고 했다.
- **실제 원인**: 로그아웃이 아니라 인스타그램의 보안 확인 요구였다. 증거의 화면 글로 확인했다.
  - 10-29 08:56: "nonsleepmarketer님, 계정을 사용하려면 사람임을 확인하세요 / 계속 / 약 30초 소요"(captcha 단계)
  - 10-30·11-01 03:25: "휴대폰 번호를 입력하세요 / SMS 또는 WhatsApp을 통해 전송된 코드로 … / 코드 보내기"(문자 인증 단계)
  - 세 화면 모두 주소는 `/accounts/suspended/?next=…&__coig_ufac=1`이었다. 인스타그램은 계정 정지가 아닌 보안 확인도 이 주소로 띄운다.
- 문자 인증 단계에서 코드가 바로 오지 않아 그 자리에서 풀지 못했다. 11-01 저녁 다시 시도하니 문자가 와서 인증을 마쳤다. 그 직후 20:54 점검이 "다시 연결됨"으로 자동 재개했다.
- 왜 보안 확인이 떴는지는 모른다. 자동화(브라우저 조작) 감지일 수 있다.

## 어떻게 발견했나

알림("instagram 로그인 필요")을 보고 Aside 브라우저를 열었을 때 로그인 폼이 아니라 보안 확인 창이 떠 있는 것을 사람이 보고 알았다. 앱의 화면과 알림으로는 구분되지 않았다.

## 고친 것

배치 E5, ADR 0060.

- **로그인 세부 상태**: 로그인 안 됨을 볼 때 그 순간 화면의 주소·글·라벨로 나눈다. 상태는 logged_out(로그아웃), challenge(본인 확인·captcha), verify(문자·이메일 코드), two_factor(두 단계 인증), restricted(계정 제한), unknown(원인 모름)이다.
  - 화면 문구를 주소보다 먼저 본다. 이번처럼 `/accounts/suspended/`여도 문구가 "사람임을 확인"이면 challenge, "휴대폰 번호·코드 보내기"면 verify다.
  - 패턴은 `nsm/adapters/platforms/data/auth_states.json` 한 곳에 있다.
- **알림·화면이 상태별로 할 일을 말한다.** 이번 경우라면 "인스타그램이 본인 확인 창을 띄웠습니다. Aside 브라우저에서 직접 확인을 끝내 주세요. 자동으로 풀지 않습니다"였다.
- **멈춘 뒤에도 상태를 따라간다.** 본인 확인에서 문자 인증으로 바뀌면 멈춤 정보를 고치고 바로 다시 알린다. 같은 상태면 24시간마다 한 번 "(계속)" 알림을 보낸다.
- **health가 예외 없이도 증거를 남긴다.** 보안 확인·제한 상태면 점검 화면을 남긴다(한 시간에 한 번).
- **지표 잡이 멈춘 플랫폼을 건너뛴다.** 새벽마다 보안 확인 중인 계정에서 글 페이지 21개씩을 여는 일이 없어진다.

## 재발 방지

- 테스트: 실제 증거 네 건이 분류 고정 입력이다(`tests/fixtures/auth_states/`, `tests/unit/test_auth_state.py`). 알림 억제·재알림·지표 건너뛰기는 `tests/engine/test_login_state.py`가 본다.
- 인스타그램이 문구를 바꾸면 unknown("로그인 필요(원인 모름)")으로 보인다. 그때 증거 폴더의 화면 글을 보고 `auth_states.json`에 문구를 더한다.
- **지켜볼 것**: 자동화 감지가 원인일 수 있다. 풀린 뒤 며칠 안에 같은 보안 확인이 되풀이되는지 지켜본다. 되풀이되면 인스타그램 활동 간격(댓글 확인 5분, 지표 새벽 한 번)을 줄이는 것을 검토한다.
- 자동으로 풀지 않는다. 확인 창을 누르거나 코드를 넣는 것은 사람이 한다(ADR 0060).

## 지금 체계였다면

이 장애는 이미 E1~E4 아래에서 일어났다. 실제로 이렇게 보였다.

- **E1(오류 종류 표·증거)**: 종류는 `auth`로 맞았다. 댓글 확인과 지표 잡처럼 스크립트가 오류를 던진 곳은 증거를 남겼고, 그 덕에 원인을 알아냈다. 하지만 멈춤을 결정한 health는 예외 없이 "로그인 안 됨"을 돌려줘서 사흘 동안 증거를 한 장도 못 남겼다.
- **E2(장애 화면·자동 진단)**: 장애 화면에 "인스타그램: 로그인 필요로 자동 게시·답글 멈춤(다시 로그인하면 풀림)"이 떴다. 다시 로그인하라는 안내가 틀렸다. 사람이 할 일은 로그인이 아니라 보안 확인이었다.
- **E4(멈춤 이유)**: 멈춘 플랫폼은 실패를 다시 쌓지 않아 알림은 한 번뿐이었다. 대신 멈춘 동안 상태가 본인 확인에서 문자 인증으로 바뀐 것을 앱은 몰랐다.
- **부족했던 것**:
  - 화면의 문구를 보고도 나누지 않았다.
  - health가 증거를 남기지 못했다.
  - 지표 잡(`run_metrics`)은 멈춘 플랫폼을 건너뛰지 않았다. 새벽마다 인스타그램 글 페이지를 20·15·11개씩 열어 49건의 실패를 남겼고, 보안 확인 중인 계정을 계속 건드렸다.
