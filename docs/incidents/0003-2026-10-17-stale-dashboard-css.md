# 0003. 대시보드 CSS가 낡은 채 남아 화면이 깨짐

- 날짜: 2026-10-17 (배치 C20 작업 중 사용자 제보)
- 종류: 표 밖 — 대시보드 자체의 배포·캐시 문제(어댑터 실패가 아님). 성격은 `config_or_bug`
- 고친 것: PR #85(배치 C20)

## 증상 (사용자가 본 것)

1. 설정 화면에서 올린 캐릭터 그림이 원래 크기로 크게 보였다. 새 CSS가 줄인 크기가 적용되지 않았다.
2. 같은 날 작업 중 운영 대시보드가 잠깐 500 오류를 냈다.

## 영향 (기간·건수)

| 항목 | 값 | 근거 |
|---|---|---|
| 캐시 지시 없이 바뀐 CSS | 10-13~10-17에 `app.css`를 바꾼 커밋 14개(C20 포함) | `git log -- nsm/app/static/app.css` |
| 500 오류 | 작업 중 잠깐, 바로 되돌려 200 확인 | devlog C20. `nsm.log`에는 대시보드 요청 기록이 없어 횟수는 셀 수 없다 |
| 게시·수집 | 영향 없음 | 잡은 별도로 계속 돎 |

## 원인

1. **브라우저 캐시.** 정적 파일에 캐시 지시가 없어 브라우저가 예전 `app.css`를 저장해 두고 계속 썼다. 서버는 새 파일을 주고 있었다.
2. **운영 폴더에서 브랜치 작업.** 운영 `nsm run`은 파이썬 코드는 켤 때 것을 쓰지만, 템플릿과 정적 파일은 작업 폴더에서 그때그때 읽는다. batch 브랜치의 템플릿이 운영 서버에 없는 함수(`asset`)를 불러 화면을 못 그렸다.

## 어떻게 발견했나

사용자 제보(캐릭터가 크게 보임). 500은 작업 중 직접 확인했다.

## 고친 것

- 정적 파일 주소에 내용 지문을 붙였다(`/static/app.css?v=…`). 파일이 바뀌면 주소가 바뀐다.
- 캐릭터 견본 `img`에 `width`·`height`를 넣어 CSS 없이도 작게 보이게 했다.
- 운영 폴더를 main으로 되돌렸다.

## 재발 방지

- 테스트 `test_static_files_are_versioned_by_content`.
- 규칙: batch 작업은 git worktree에서 한다(C21부터, 메모리·devlog C20). 그 뒤 같은 500은 없었다.

## 지금 체계였다면

E1·E2는 어댑터·잡의 실패만 기록하므로 이 문제는 장애 화면에 나타나지 않는다. 대시보드 자체가 깨지면 장애 화면도 같이 깨진다. 이런 종류는 "작업 폴더 분리"라는 절차로 막는 것이 맞다.
