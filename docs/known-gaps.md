## 2. 운영 중 조용히 멈출 수 있는 것 (높음)

| 빈틈 | 왜 문제인가 | 지금 할 수 있는 것 |
|---|---|---|
| **화면 구조 변경에 약함** | 수집(네이버)과 게시·댓글(인스타·스레드, Aside)은 웹 화면을 읽고 누르는 방식이다. 사이트가 바뀌면 오류 없이 "0건"이 될 수 있다. 실제로 2026-10-13에 네이버 뉴스 탭 구조가 바뀌어 뉴스를 하나도 못 가져왔다(C2에서 고침) | 매일 "실행 기록"에서 `relevant=0`, `published=0`이 이어지는지 본다 |
| **"계속 0건" 알림 없음** | 수집 관련 자료·게시가 며칠째 0건이어도 알림이 오지 않는다(실패가 아니라 성공으로 기록됨) | 위와 같음. 연속 0건 알림은 다음 작업 후보 |
| **PC가 꺼지면 멈춤** | 내 PC의 단일 프로세스다. 꺼져 있는 동안 수집·게시·댓글이 모두 멈추고, 켜면 이어서 한다 | 절전 해제, `nsm install-autostart` |
| **Aside 로그인 유지** | 로그인이 풀리면 그 플랫폼을 멈추고 알림을 보낸다(30분마다 점검). 다시 로그인하기 전까지는 게시·답글이 없다 | 알림이 오면 Aside 브라우저에서 다시 로그인 |
| **장기 무인 운영 미검증** | 실계정은 2026-10-13부터 운영했다. 며칠 연속 켜 두었을 때 브라우저 세션·메모리·로그 크기는 아직 지켜보지 않았다 | 첫 주는 매일 확인 |

## 3. 품질·기능 (중간)

| 빈틈 | 설명 |
|---|---|
| 구글 트렌드 쓸모 적음 | 전체 인기 검색어(스포츠·연예 등)라 틈새 주제(예: 치이카와)와 거의 맞지 않는다. 비용은 거의 없지만 관련 자료로 남는 일이 드물다 |
| 네이버 블로그 결과는 후기가 많음 | 블로그 검색 결과는 방문·구매 후기가 많아 대부분 걸러진다. 실제 자료는 주로 뉴스에서 나온다 |
| 자료 작성일을 모름 | 네이버 검색 결과에 작성일이 늘 보이지 않아 자료마다 작성일을 기록하지 못한다. 대신 검색을 최신순·최근 1주로 걸고(ADR 0032), 원고에 수집일을 알려 준다 |
| 원고는 하루 한 번 | 첫 활동 시간 시작 50분 뒤에 한 번 만든다. 낮에 더 만들려면 대시보드에서 "원고 만들기"를 누른다 |
| 설정 변경은 새 원고부터 | 페르소나·브랜드를 바꿔도 이미 만든 원고(검토 대기 포함)는 그대로다. 필요하면 폐기하고 다시 만든다 |
| 이미지 생성 꺼둠 | 이 PC 설정은 `image_generation: off`. 카드 배경은 브랜드 색이고, 사진은 검토 화면에서 직접 올린다 |
| 인스타 댓글 숨기기 없음 | 인스타그램 웹에 숨기기 메뉴가 없어 스팸은 사람 검토로 넘어간다(스레드는 자동 숨김) |
| 댓글은 첫 화면까지만 | 게시물 화면 첫 페이지에 보이는 댓글까지 읽는다. 댓글이 아주 많은 글은 일부를 놓칠 수 있다 |
| 게시 시간 최적화 없음 | 게시 시간은 사람이 정한다. 시간대별 성과로 자동 조정하지 않는다 |
| 설정 화면에 없는 값 | 수집 건수(`collect.per_source_limit`), 관련성 기준(`relevance_threshold`), 재시도 간격 등은 `config.yaml`에서만 바꾼다. 드라이런·계정·키·보호 모드는 일부러 뺐다(ADR 0028) |

## 4. 알고 쓰면 되는 것 (낮음)

| 항목 | 설명 |
|---|---|
| 네이버 블로그 게시 안 함 | MVP 범위에서 뺐다(ADR 0016). 네이버는 자료 수집에만 쓴다 |
| Windows 전용 | 자동 시작·알림·키 보관이 Windows 기준이다 |
| 대시보드 로그인 없음 | 127.0.0.1(내 PC)에서만 열리고 저장마다 CSRF 토큰을 확인한다. 같은 PC를 쓰는 다른 사람은 열 수 있다 |
| 데이터 백업 없음 | `%USERPROFILE%\.nsm\data.duckdb`를 자동으로 백업하지 않는다. 필요하면 프로그램을 끈 뒤 복사한다 |
| 실계정 계약 테스트 | `-m contract` 테스트는 운영 계정(@nonsleepmarketer)에 실제로 올렸다가 지운다. 그 사이 팔로워에게 보일 수 있어 실행 전에 알린다 |
| `nsm run` 중 설정 파일 직접 수정 | 켜진 상태에서 `config.yaml`을 고치면, 설정 화면에서 저장할 때 실행 중인 값으로 덮어쓴다. 파일은 끈 뒤에 고친다 |
