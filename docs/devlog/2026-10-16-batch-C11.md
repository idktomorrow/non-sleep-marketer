# 2026-10-16 배치 C11: 실행 기록 화면 정리 (작업 상태 표, 변화가 있던 실행만)

## 목표

C10으로 요약은 문장이 됐다. 그런데 실행 기록이 5분마다 같은 줄("새 댓글 없음 · 인스타그램 요청 제한으로 쉬는 중")로 가득 찼다. 사용자가 두 가지를 물었다. "중복으로 너무 뜨는 거 아닐까요", "성공한 것도 너무 많이 뜨는데 이대로 두는 게 맞을까요". 작업 상태 표와 "변화가 있던 실행만" 보기를 제안했고, 사용자가 "일단 해 보고 아니다 싶으면 롤백"하기로 했다.

## 한 일

- **`nsm/app/run_view.py`(새 파일)**
  - `build_rows(runs, show_all)`
    - 아무 일 없던 성공은 숨긴다(`ROUTINE`).
    - 같은 작업이 같은 결과로 이어지면 묶는다. 묶은 줄에는 시작은 가장 이른 시각, 끝은 가장 늦은 시각, `count`가 들어간다.
    - 숨긴 실행 수도 돌려준다.
  - `job_statuses(...)`: 작업 상태 표. 언제 도나, 마지막 실행, 상태(정상·실패·실행 중·오래 안 돌았음·아직 안 돌았음), 마지막 결과를 만든다. 실패면 마지막 성공 시각도 붙인다.
- **저장소:** `latest_runs()`(작업별 마지막 실행, DuckDB `QUALIFY`), `last_success_at()`
- **화면**
  - 실행 기록: 위에 작업 상태 표를 두었다.
  - 아래 목록은 기본이 "변화가 있던 실행"이다. 숨긴 횟수를 보여 주고, "전체 보기"(`/logs?all=1`)를 두었다.
  - 요약을 고정폭 상자 대신 보통 글자로 바꿨다(`.run-text`).
  - 휴대폰 폭에서는 "언제 도나" 칸을 숨긴다.
  - 오늘 화면의 "최근 실행"도 같은 규칙으로 10줄을 보여 준다.
- **데모 스크립트:** 운영처럼 반복되는 줄(요청 제한 6번, 새 댓글 없음 5번 등)을 더했다.
- **문서:** ADR 0040(제안), 사용설명서 4절, architecture, CHANGELOG

## 막힌 것과 해결

- **무엇을 "아무 일 없음"으로 볼까.** "건너뜀"을 모두 숨기면 "건너뜀: 쓸 자료 없음(관련 자료 수집 필요)"처럼 사람이 알아야 할 줄까지 숨는다. 그래서 정해진 시간 밖이라 건너뛴 것만 숨겼다(활동 시간 밖, 게시 시간 밖, 오늘 생성 목표 달성).
- **묶음이 다른 작업에 끊김.** 댓글 확인 사이에 로그인 점검·게시하기가 끼면 "바로 앞 줄과 같음"으로는 묶이지 않는다. 작업별로 "지금 이어지는 묶음"을 따로 들고 있게 해, 다른 작업이 끼어도 같은 작업끼리는 묶이게 했다. 아무 일 없던 실행이 끼면 묶음을 끊는다. 요청 제한이 한 번 풀렸다가 다시 걸린 것은 따로 보여야 하기 때문이다.
- **코드 리뷰(`/code-review`) 반영.**
  - "올린 글 없음 · 이유: …"를 통째로 숨겨, "연결 안 됨"·"일시 중지됨"·요청 제한까지 숨겨졌다. 이제 이유가 모두 평소 일(간격 대기·다 올림·올릴 원고 없음)일 때만 숨긴다.
  - 오류가 적힌 줄은 성공으로 끝났어도 숨기지 않는다.
  - 실패로 끝난 뒤 멈추거나, 실행 도중 꺼져 "실행 중"으로 남은 작업도 "오래 안 돌았음"으로 보인다.
  - 댓글 확인 기준을 간격×3+5분(20분)에서 최소 60분으로 늘렸다. 작업이 한 줄로 돌아, 원고 만들기 중에는 댓글 확인이 밀리기 때문이다.
  - 살펴볼 범위를 최근 200번에서 1000번으로 늘렸다. 조용한 밤 몇 시간에 어제 일이 밀려나지 않게 하려는 것이다.
  - 상태 표 쿼리는 최근 30일로 제한했다(실행 기록은 지우지 않아 계속 쌓인다).
  - `?all=true`도 받는다.
  - "언제 도나"의 분 단위 주기를 스케줄러 설정에서 읽는다.
  - 성공·실패 배지를 공용 매크로(`_run_badge.html`)로 묶었다.
  - 의도대로 둔 것: 묶인 줄은 가장 최근 실행 자리에 놓인다. 시작 칸에는 가장 이른 시각이 들어가 다른 작업 줄과 시작 순서가 어긋나 보일 수 있다. 끝 시각 순서는 맞다.
- **고정폭 글꼴.** 요약이 `<pre>` 상자 안에 있어, 문장인데도 글자 사이가 벌어져 보였다. 보통 글꼴의 상자로 바꿨다.

## 배운 것 (신입 개발자용)

1. **기록과 보기는 따로 생각한다.** 원본 기록은 다 남겨 두고, 화면에서 사람이 봐야 할 것만 고른다. 그러면 나중에 문제를 찾을 때 원본을 그대로 볼 수 있고, 화면을 바꿨다가 되돌리기도 쉽다.
2. **"잘 돌고 있나"와 "무슨 일이 있었나"는 다른 질문이다.** 앞의 질문은 작업마다 마지막 상태 한 줄(상태 표)로 답한다. 뒤의 질문은 변화가 있던 사건 목록으로 답한다. 한 표로 둘 다 하려니 표가 길어졌다.
3. **"멈춤"도 상태다.** 실패만 보면, 프로그램이 아예 안 돌 때(PC 꺼짐) 아무 경고도 없다. 마지막 실행 시각이 주기보다 많이 오래됐으면 "오래 안 돌았음"으로 보여 준다.
