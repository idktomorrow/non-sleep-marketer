# 2026-10-13 배치 C4: 지난 정보와 소문을 원고에 쓰지 않게

## 목표

선웅제가 짚었다: "이미 출시한 팝콘통인데 '가격은 소문 단계'라고 쓴다, 정보를 어디서 가져오나?"

## 원인 찾기

- 대시보드 검토 화면의 "사실 주장과 출처"에서 근거 자료를 확인했다. 네이버 블로그 글 한 편("CGV 먼작귀 팝콘통 3종 출시일 가격 총정리")으로, 9월 30일 개봉 전에 쓴 글이었다.
- 진단 스크립트로 네이버 검색을 직접 열어 비교했다. 기본(정확도순) 블로그 검색은 개봉 전 글이 위에 왔고, 최신순·1주(`nso=so:dd,p:1w`)는 10월 글이 나왔다. 검색 결과 줄에는 작성일이 대부분 보이지 않았다.

## 한 일

- 수집: 블로그·뉴스 검색에 최신순·기간(`RECENT_PARAMS`), 설정 `collect.recent_period`(기본 1w), 설정 화면 "자료 검색 기간"
- 원고: 프롬프트에 오늘 날짜(설정 시간대)와 자료별 수집일·작성일, 지난 예정·소문 금지 규칙
- 검사: `UNCONFIRMED_PHRASES`가 SNS 글에 있으면 규칙 위반 → 한 번 다시 만들고 → 검토
- ADR 0032(채택), 사용설명서·known-gaps·CHANGELOG

## 막힌 것과 해결

- 작성일로 거르려 했지만 검색 결과에 날짜가 대부분 없었다. 그래서 검색 단계에서 기간을 걸었다.
- "출시 예정"을 코드 검사에 넣으면 공식 발표된 앞으로의 일정도 막힌다. 프롬프트 규칙으로만 다뤘다.

## 테스트 결과

- ruff 통과, pytest 초록. 새 테스트 7개: 소문 표현 위반·정상 문장 통과, 검색 URL 최신순·기간(3가지)·전체, 프롬프트의 오늘·자료 날짜, 설정 화면 기간 저장·거절
- 실측: 고친 수집기로 페르소나 주제 6개에서 24건 수집, 모두 10월 글·기사

## 배운 것 (신입 개발자용)

1. **AI에게 "오늘"을 알려 주지 않으면 자료의 시점이 곧 현재가 된다.** 모델은 자료가 언제 쓰였는지 모르면 "개봉 예정"을 그대로 "개봉해요"로 옮긴다. 날짜는 문맥이다.
2. **검색 정렬 기본값도 설계 결정이다.** 정확도순은 오래되고 잘 쓴 글을 올려 준다. 소식형 콘텐츠에는 최신순이 맞다.
3. **문제를 찾을 때는 결과에서 근거로 거슬러 올라간다.** 원고 → 사실 주장 → 근거 자료 ID → 원문 URL로 따라가니 한 번에 원인이 보였다. claim마다 출처를 연결해 둔 설계(ADR 0008) 덕분이다.

## 다음 배치 메모

- 이미 모은 자료에는 예전 방식으로 들어온 오래된 글이 남아 있을 수 있다. 며칠은 검토에서 날짜에 민감한 내용을 한 번 더 본다.
