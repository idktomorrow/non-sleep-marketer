# 2026-11-28 배치 C60: 외부 코드 감사에서 확인된 런타임 버그 4건 수정

## 목표

외부 정적 코드 검토 항목을 실제 코드와 대조해, 운영 중 조건이 맞으면 잘못 동작하는 4건을 고친다. 4건은 게시 확인 문구 공백, 게시 뒤 기록 예외, 낱말 분류기 우선순위, 빈 직접 답글이다. 원본 검토 파일은 저장소에 넣지 않고, 결과는 `docs/known-gaps.md` 2-5절에 표로 남긴다.

## 검토 항목과 "검토가 맞았나"

| 번호 | 검토 내용 | 맞았나 |

| 1-1 | `_probe`가 문장 안 연속 공백·탭·NBSP를 그대로 둬서 브라우저(`innerText.replace(/\s+/g, ' ')`)와 어긋남 | **맞음.** main의 `threads.py`·`instagram.py` `_probe`가 줄 사이만 `" "`로 이었다. 첫 40자 안에 탭이 있으면 Python 쪽 probe에 탭이 남는데, 화면 글은 한 칸이라 `includes`가 실패한다. 그러면 게시 확인이 "못 찾음"이 되고 재시도 전 멱등 확인도 빗나가 중복 게시로 이어질 수 있다 |
| 1-2·1-3 | 게시 성공 뒤 `published` 기록·원고 상태 갱신 예외가 게시 줄을 `publishing`에 가두고, 플랫폼 루프에 `try`가 없어 다른 플랫폼까지 멈춤 | **맞음.** `_publish_one` 끝의 두 호출이 감싸여 있지 않았고, `run_publish`의 `_publish_one` 호출에도 `try`가 없었다 |

보안(CSRF·Host·업로드·셸/프롬프트 주입), 법정 표기, 시간대 지적은 코드와 대조해 이상이 없었다. 설계대로인 항목(하루 목표 집계, 첫 40자 멱등 기준, 답글 일시 오류는 사람 확인, 자정 상한 리셋)은 known-gaps 2-5에 근거와 함께 적었다.

## 한 일

- **1-1** `aside_common.post_probe`
  - 표기 첫 줄과 `#` 줄을 뺀 본문을 `" ".join(body.split())`으로 접고, 8자 이상이면 앞 40자를 돌려준다.
  - 스레드·인스타는 `_probe = post_probe`로 같은 함수를 쓴다. 브라우저 스크립트는 그대로 두었다.
- **1-2·1-3** `engine/publish.py`(ADR 0080)
  - `_record_published`
    - `published` 기록이 실패하면 한 번 더 시도한다.
    - 재시도가 `InvalidTransitionError`이고 이미 `published`면 성공으로 본다.
    - 그래도 실패하면 `record_incident(stage="record")`를 남기고, 알림 "게시 기록 실패"(글 주소, "다시 승인하지 마세요")를 보낸 뒤 `"failed"`를 돌려준다.
    - 삭제·abandoned·검토로 돌리기는 하지 않는다.
  - `mark_content_published_if_complete`는 따로 감싸 `result.errors`에만 적는다.
  - `run_publish`는 플랫폼마다 `_publish_one`을 감싼다.
- **1-8** `KeywordClassifier(priority=)`
  - vocab 앞 n개 범주 중 낱말이 맞는 첫 범주가 이긴다.
  - `COMMENT_PRIORITY = 4`(spam·legal·price_refund·complaint)는 `make_classifiers`의 댓글 분류기에서만 켰다. 관련성·주제는 0이다.
- **1-10** 직접 답글
  - `comments.html` 입력칸에 `required maxlength="500"`을 달았다.
  - `POST /comments/{key}/reply`는 `Form("")`로 받아 `strip()`한다. 빈 값이나 `REPLY_MAX_CHARS`(500)를 넘으면 400을 내고, 상태를 바꾸지 않으며 어댑터도 부르지 않는다. 저장은 strip한 값이다.
- 문서
  - known-gaps: 2-5 표를 새로 두고, 4절에 "끄는 중 Ctrl+C" 줄을 더했다.
  - ADR 0080, architecture 상태 표, CHANGELOG, user-guide 문제 해결 표("게시 기록 실패")를 고쳤다.
  - 버전은 0.4.49다.

## 막힌 것과 해결

- Bash heredoc으로 넘긴 Python·테스트 문자열의 `\n`·`\t`가 실제 줄바꿈·탭으로 들어갔다(C59와 같은 일). 테스트 조각은 Write로 파일을 만든 뒤 `cat >>`로 붙였다.
- 게시 뒤 기록 실패를 재현하려고 `ctx.repo.transition_publication`을 인스턴스에서 감쌌다(플랫폼·상태·n번째 호출 조건). 이렇게 하면 진짜 DB 전이는 그대로 쓰면서 원하는 호출만 실패시킬 수 있다.
- 대시보드 라우트는 `Form(...)`이면 빈 문자열이 FastAPI 검증(422)에서 먼저 걸린다. 그래서 `Form("")`로 받아 직접 400을 낸다.

## 배운 것

1. **같은 비교를 두 언어가 하면 정규화 규칙을 한 곳에 적고 테스트로 묶는다.** 브라우저는 `\s+`를 한 칸으로 접는데 Python은 줄만 합쳤다. 평소 원고에는 탭이 없어 몇 달 동안 드러나지 않았다. 이런 불일치는 운영 로그로는 "가끔 못 찾음"으로만 보인다.
2. **되돌릴 수 없는 일이 끝난 뒤의 실패는 앞 단계 실패와 다르게 다룬다.** 게시 전 실패는 다시 하면 되지만, 게시 뒤 기록 실패에 같은 경로(검토로 돌리기)를 쓰면 사람이 다시 승인해 글이 두 번 올라간다. 이미 일어난 일은 건드리지 않고 사람에게 정확히 알리는 것이 안전하다.
3. **주석이 말하는 규칙과 코드가 다르면 테스트가 진실을 정한다.** "위험 범주가 먼저"라는 주석은 동점일 때만 맞았다. 규칙을 생성자 인자(`priority`)로 드러내고 대표 문장으로 테스트하면, 다음 사람이 주석이 아니라 테스트를 보고 안다.
