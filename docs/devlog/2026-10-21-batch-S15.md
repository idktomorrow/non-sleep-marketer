OpenAI 키 하나로 만화 2컷·보조 스티커를 **같은 캐릭터 모습으로** 그리고, 실패한 컷만 다시 만들며, 사람이 본 미리보기 그대로 승인·게시되게 한다.

- **승인 산출물**: `engine/artifacts.py`(판 지문, 미리보기 manifest, 굳히기, 게시용 PNG·캡션, 마이그레이션), `ApprovalGate`(사람 승인 전 판 확인·굳히기·실패 시 되돌림), 승인 라우트는 판이 다르면 새 미리보기 후 상세 화면으로. `publish.render_images`는 산출물만(정책 승인은 첫 렌더를 굳힘), 캡션도 굳힌 것.
- **화면**: 검토 상세 "그림"(출연진 폼은 지금 값으로 미리 선택·참조가 있으면 접힘, 슬롯마다 썸네일·상태·오류·장면 지시·다시 만들기·직접 올리기·다시 요청·과금 안 됨 확인·이전 그림), 설정 "캐릭터". 비용 원장 `release_unknown_by_ref`.

## 막힌 것과 해결
- DuckDB는 커서마다 별개 연결이라 트랜잭션 안에서 `repo.update_generated`를 부르면 같은 트랜잭션이 아니다 → 결과 반영·재사용·업로드는 커서로 직접 `UPDATE contents … revision+1`.
- 승인 게이트를 넣자 기존 "승인 뒤 템플릿이 바뀌면 다시 그린다" 테스트 2개가 새 규칙과 충돌 → 내부 렌더 캐시(`_render_cached`) 테스트로 옮기고, 굳힌 산출물 불변성 테스트를 더함.
- 출연진 폼이 늘 펼쳐지고 첫 항목을 보여 줘 지금 출연진처럼 보였다(직접 화면을 보고 발견) → 지금 값 미리 선택, 참조가 있으면 접기.

## 배운 것 3개
1. "작업이 유효한가"는 **그 작업이 만들려던 조건**(spec)으로 묻는다. 콘텐츠 전체 판 번호로 물으면 관계없는 수정(대사)이나 형제 작업(1번째 컷)이 서로를 무효로 만든다.
2. 유료 호출은 "보내기 직전" 상태를 남겨야 재시작 뒤에 "안 보냄(다시 보내도 됨)"과 "보냈는데 모름(사람이 판단)"을 가를 수 있다.
3. 승인은 "지금 그려서 승인"이 아니라 "본 것을 승인"이다. 그래서 미리보기에 판 지문을 남기고 승인 때 비교한다.
