# 2026-10-17 배치 C16: 올린 이미지를 읽어 자료로 쓰기

## 목표

자료 올리기가 txt·md·csv·xlsx·pdf만 받아서, 굿즈 공지 이미지는 쓸 수 없었다. 예: CGV "먼작귀 팝콘통 예약판매 OPEN, 네이버에 [CGV 스토어] 검색". 사용자가 정한 것은 이렇다.

- 이미지는 읽어서 정보로 쓴다. "예약판매, 네이버 CGV 스토어" 같은 글을 뽑아 원고를 만든다.
- 사진을 카드에 넣는 쪽은 하지 않는다(캐릭터 저작권, ADR 0036).

## 한 일

- **이미지 읽기**(`nsm/adapters/sources/image_reader.py`)
  - Claude(`models.classifier`, 기본 Haiku)에 이미지를 보내고 `{has_info, text}`로 받는다.
  - 지시: 보이는 글자와 사실(상품명·날짜·장소·가격·구매처·디자인 수)만 짧은 한국어 줄로 쓴다. 추측하지 않고, 캐릭터 생김새는 쓰지 않는다.
  - 형식은 png·jpg·webp이고 5MB 이하다. 파일 앞부분으로 진짜 형식을 확인한다.
  - 비용은 `llm`으로 기록한다.
  - 결과를 `<NSM_HOME>/upload-text/`에 캐시한다. 키는 경로·크기·수정 시각이다.
- **올린 파일 읽기**(`upload.py`)
  - `SUPPORTED`에 이미지 확장자를 더했다.
  - `extract_text(path, read_image)`와 `UploadSource(read_image=)`를 추가했다. 키가 없으면 이미지는 조용히 건너뛴다.
- **대시보드**(`materials.save_material(read_image=)`, `/materials/upload`)
  - 올리는 순간 읽고, 옮긴 글 앞 200자를 안내에 보여 준다.
  - 정보 없음, 키 없음, 가짜 확장자, 5MB 초과는 저장하지 않고 이유를 보여 준다.
  - 읽기는 스레드에서 돈다(`run_in_threadpool`).
- **조립**
  - `runtime.build_context`가 읽기 객체를 만들어 `UploadSource`에 넣는다.
  - `AppState.read_image`에도 같은 객체를 넣는다. 캐시를 같이 써서, 올릴 때 한 번만 읽는다.
- **화면**
  - 파일 선택 `accept`에 이미지를 더했다.
  - "오늘"과 "자료"의 설명 문장을 바꿨다.
  - 데모 대시보드에 가짜 읽기를 넣었다.
- **문서**
  - ADR 0045(제안)
  - 사용설명서: 폴더 표, 자료 화면, 자주 하는 일 3번, 문제 해결 두 줄
  - architecture, CHANGELOG
  - 화면 캡처: `docs/samples/ui/image-materials/`

## 막힌 것과 해결

- **사용자의 실제 이미지 파일은 없었다.**
  - 채팅에 붙인 이미지는 디스크에 없다. 그래서 같은 문구(CGV, 먼작귀, 팝콘통, 예약판매, OPEN, "네이버에 [CGV 스토어]를 검색하세요")로 비슷한 포스터를 Playwright로 그렸다.
  - keyring의 키로 실제 Claude를 불렀다(키는 출력하지 않음).
  - 결과는 "CGV 먼작귀 팝콘통 예약판매 오픈 / POPCORN BUCKET / 구매처: 네이버에서 [CGV 스토어] 검색"이었다. 비용은 $0.00016이었다.
  - 글자 없는 그림은 빈 글로 나왔다($0.00009).
  - DB는 운영 중인 `nsm run`이 잡고 있어, 비용은 DB 대신 화면에 찍었다.
- **"한 장에 1센트 안팎"은 너무 컸다.** 실제로는 1센트의 1/50 정도였다. 그래서 화면 문구를 "1센트 미만"으로 고쳤다.
- **비용 종류.** `CostKind`는 동결 계약(`llm`, `image`, `classifier`)이라 새 종류를 만들지 않았다. Claude 호출이므로 `llm`으로 세고, 메모(`ref`)를 `read_image`로 남겼다.
- **테스트 이름이 너무 길었다.** 5MB짜리 바이트를 `parametrize` 값으로 넣으니, pytest가 그 값을 테스트 이름에 넣었다. Windows 환경 변수 한도(32767자)를 넘겨 실패했다. `ids=`로 짧은 이름을 붙였다.
- **셸이 바이트를 바꿨다.** Git Bash `sed`로 `\x00`을 넣으려다 실제 NUL 바이트가 파일에 들어갔다. 파이썬으로 다시 이스케이프로 바꿨다. 파이썬 문자열 안의 이스케이프는 셸을 거치지 않고 Edit 도구로 고치는 것이 안전하다.
- **코드 리뷰(`/code-review`) 반영(8건)**
  - **키·연결 오류가 "파일이 깨짐"처럼 보였다.** 이제 "Claude 호출 실패(…). API 키와 인터넷 연결을 확인하세요"로 보인다.
  - **업로드가 오래 멈출 수 있었다.** SDK 기본 시간 제한은 10분이다. 사람이 기다리는 경로라 60초, 재시도 2번으로 줄였다.
  - **못 읽은 폴더 이미지를 매번 다시 보냈다.** Claude가 거절했거나 응답을 못 쓴 파일은 `.err`로 남겨 다시 보내지 않는다. 키·연결 문제는 고치면 될 수 있어 남기지 않는다.
  - **키를 새로 넣으면 다시 켜야 한다.** 이 점을 사용설명서 문제 해결과 ADR에 적었다.
  - **같은 이름 파일을 동시에 올리면 덮어쓸 수 있었다.** 읽기를 스레드로 옮기면서 생긴 문제다. 이름 고르기와 쓰기를 잠금으로 묶었다.
  - **미리보기용 두 번째 읽기를 없앴다.** `save_material`이 읽은 글을 돌려준다. 그래서 다시 부를 일도, 거기서 실패할 일도 없다.
  - **"…" 표시가 실제로 자른 것과 어긋났다.** 서버가 자를 때만 붙인다.
  - **캐시가 자료로 읽힐 수 있었다.** 자료 폴더를 `NSM_HOME`으로 잡으면 그랬다. 자료 모으기가 `upload-text` 폴더를 건너뛴다.
  - 테스트를 더했다: 올림→자료 모으기에서 Claude는 한 번만, 읽기 실패 문구, 이름·미리보기 이스케이프, 긴 미리보기 자르기, 거절 기억, SDK 오류.

## 배운 것 (신입 개발자용)

1. **비싼 일은 한 번만, 결과는 남긴다.** 올릴 때 읽은 결과를 파일로 남겨 두면, 나중에 자료 모으기가 같은 이미지를 다시 보내지 않는다. 캐시 키에 "수정 시각"을 넣으면 파일을 바꿨을 때만 다시 읽는다.
2. **확장자를 믿지 말고 내용을 본다.** `.png`라고 붙어 있어도 실제는 다른 파일일 수 있다. PNG는 `\x89PNG`, JPEG는 `\xff\xd8\xff`로 시작한다. 이런 앞부분("매직 넘버")을 보고 거르면 API에 헛돈을 쓰지 않는다.
3. **AI가 읽은 결과는 사람이 바로 볼 수 있게.** 이미지 읽기는 틀릴 수 있다. 올리자마자 옮긴 글을 보여 주면, 사용자가 그 자리에서 맞는지 확인하고 다시 올릴 수 있다.

## 다음 배치 메모

- 머지 후 `nsm run`을 다시 켠다. "오늘"의 자료 올리기로 실제 CGV 팝콘통 공지 이미지를 올려 미리보기를 확인한다(1센트 미만).
- 그다음 "자료 모으기" → "원고 만들기"로 원고를 만들어 본다. 키워드 원고는 네이버 검색 결과만 쓰므로, 올린 이미지는 들어가지 않는다.
- 올린 자료를 키워드 원고에도 섞을지는 쓰임을 보고 정한다.
- 옮긴 글을 사람이 고치고 싶다는 요청이 오면 "옮긴 글 고치기"를 검토한다(ADR 0045).
