# 범위 변경: 네이버 블로그 게시 제외 (2026-10-12)

- 관련: [ADR 0016](../adr/0016-drop-naver-blog-publishing.md), 이슈 #3 #14 #34 · 브랜치: batch/drop-naver-blog · 담당: 메인(Claude)

## 목표

선웅제의 결정("네이버는 빼고")을 코드·계획·문서에 반영한다. 게시 대상은 인스타그램·스레드 두 곳이고, 네이버 검색 수집은 유지한다.

## 한 일

- 설정 기본값(`nsm/config/schema.py`): `enabled_platforms`는 인스타그램·스레드, 쿼터에서 네이버 블로그 삭제.
- 1일차 마법사(`scripts/day1_wizard.sh`): 네이버 블로그 테스트 계정 질문과 에디터 탐색 단계 삭제. 8단계에서 7단계로 줄었다. 네이버 검색 수집용 계정 질문은 남겼다.
- 계획 문서: process.md 배치 G는 PR 2개, issues.md의 M2 5번과 M13 범위, PRD·user-guide·README·architecture·contracts의 플랫폼 목록. ADR 0004는 "대체됨"으로 표시.
- CLAUDE.md의 "네이버 제외"를 "네이버 블로그 게시 제외(수집은 유지)"로 고쳐 수집 소스와 헷갈리지 않게 했다.
- GitHub 이슈 #3(M2)과 #14(M13) 본문도 같은 내용으로 고쳤다.

## 막힌 것과 해결

- **동결 계약을 건드릴지**: `Platform`의 `"naver_blog"`와 블로그 원고 필드는 동결 계약이다. 지우면 두 사람이 합의하는 PR이 필요하다. 그래서 값은 남겨 두고 기본 설정에서만 뺐다. 켜면 여전히 동작하므로 표기 규칙 테스트는 남겼다.

## 테스트 결과

`220 passed`. 고친 테스트: 엔진 테스트(드라이런 E2E, 게시, 생성)가 기본 두 플랫폼 기준으로 바뀌었다. E2E는 네이버 블로그 폴더가 생기지 않는지도 확인한다. 새 테스트: 기본 설정에 네이버 블로그가 없음, 네이버 블로그 게시물을 만들면 제목·본문 표기가 여전히 붙음.

## 배운 것 (신입 개발자용)

1. **범위를 줄일 때는 코드를 지우기 전에 설정부터 바꾼다**: 기능을 끄는 가장 싼 방법은 기본값에서 빼는 것이다. 코드를 지우면 되살릴 때 비싸고, 동결 계약까지 건드리게 된다.
2. **같은 단어가 두 가지를 뜻하면 문서가 어긋난다**: "네이버"는 게시 플랫폼(네이버 블로그)도 되고 수집 소스(네이버 검색)도 된다. 결정을 적을 때는 무엇을 빼는지 정확한 이름으로 쓴다.
3. **결정이 바뀌면 옛 ADR은 지우지 않고 "대체됨"으로 둔다**: 왜 한때 세 플랫폼이었고 왜 바뀌었는지가 기록으로 남아야 나중에 같은 논의를 반복하지 않는다.
