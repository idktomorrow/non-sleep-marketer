# 2026-11-06 배치 C39: 로그인 표지로 "화면 변경"과 "로그인 풀림"을 가르기

## 목표

로그인 판정이 "내 계정 이름(핸들) 읽기" 하나에 걸려 있었다. 그래서 메타가 화면을 조금만 바꿔도, 로그인된 상태를 "로그인 필요"로 오판해 플랫폼을 멈췄다(incidents/0012, ADR 0063 "다음 배치 후보"). 원칙은 셋이다.
1. 로그인 표지가 보이는데 핸들을 못 읽으면 `auth`가 아니라 `ui_changed`다.
2. 게시·답글처럼 계정으로 행동하기 직전에는 핸들로 계정을 확인하지 못하면 하지 않는다. 플랫폼은 멈추지 않고 그 건만 실패한다.
3. 로그인 폼·본인 확인·제한 화면이면 지금처럼 `auth`와 E5 세부 상태를 쓴다.

## 한 일

- **표지 문구**(`data/auth_states.json` `logged_in_markers`)
  - 스레드: 글쓰기 칸 문구만. "님에게 답글 남기기", "새로운 소식을 공유해보세요", 영어 대응 2개.
  - 인스타그램: 줄 전체 "새로운 게시물·New post·만들기·Create·알림·Notifications".
  - 기존 증거 15개와 픽스처 6개에 대 봤다. 로그인된 스레드 화면 2건(0012, 10-30)에서만 맞고, 로그아웃·본인 확인·빈 화면에서는 하나도 안 맞았다. 메뉴 문구로만 맞던 로그인 화면 2건(11-04·11-05)은 이제 맞지 않는다.
- **`auth_state.py`**
  - `looks_logged_in(page, platform)`: 빈 화면 아님 + `classify`가 unknown + 표지 일치.
  - `js_auth_args(platform)`: 같은 정규식 원문을 브라우저에 넘긴다. 함께 가는 것은 표지, 로그인 폼과 화면 글 규칙을 합친 blockers, 로그인·확인 주소다.
- **`aside_common.py`**
  - `_call`이 모든 스크립트에 `ARGS.nsm_auth`를 넘긴다.
  - JS `nsmLoggedInScreen`이 화면 글과 이름표(svg title, aria-label)로 판정한다. `nsmAssertHandle`은 핸들이 비면 오류 화면 확인 다음에 이것을 보고 `ui` 또는 `login`을 던진다.
  - `_health`는 표지가 있으면 `logged_in=True`와 `ui_warning`을 남긴다. 증거는 `ui_changed` 종류로 한 시간에 한 번이고, 스크린샷은 auth나 ui_changed 증거를 남길 수 있을 때 찍는다.
- **health 잡**(`health_metrics.py` `_ui_warning`)
  - 멈추지 않는다(멈춰 있었으면 푼다).
  - 6시간에 한 번 장애 기록(`ui_changed`, 증거 폴더)과 "<플랫폼> 화면 변경" 알림을 낸다.
  - 실행 기록 `counts.ui_changed`를 남긴다.
  - 6시간 시계는 게시의 화면 변경 알림과 같은 키다. 그래서 `publish.py`의 계산을 `ui_changed_notice_due`로 뺐다.
- **게시·댓글 확인**: 코드를 바꾸지 않았다. `ui`가 `ui_changed`로 바뀌는 매핑과, 기존 표대로의 처리(게시는 바로 검토로, 댓글 확인은 그 회차만 실패, 멈춤 없음)를 테스트로 못 박았다.
- **테스트 픽스처**: `tests/fixtures/auth_states/threads-20261105-205557.json`(0012 증거의 text·labels). 우리 테스트 계정 주소와 우리 글 본문뿐이고, 키·다른 사람 핸들은 없다.
- **문서**: ADR 0064, ADR 0063 후보에 "C39에서 구현", 설명서 한 문단, 0012 재발 방지 한 줄, architecture, CHANGELOG. 버전 0.4.24.

## 막힌 것과 해결

- **메뉴 문구가 로그아웃 화면에도 있음**(PR 리뷰에서 사용자가 새 브라우저로 확인): 로그아웃 스레드의 왼쪽 메뉴에도 "새로운 스레드"가 보여 표지가 맞았고, "가입하기"가 로그인 폼 규칙에 걸려서야 로그아웃으로 판정됐다. 메뉴 문구("새로운 스레드"·"Start a thread")를 표지에서 빼고 글쓰기 칸 문구만 남겼다. 로그아웃 메뉴 화면 픽스처를 넣어, "가입하기"·"로그인"을 빼도 로그인으로 보지 않음을 못 박았다.
- **C38 테스트가 새 규칙에 걸림**: C38의 가짜 글 화면(`POST_PAGE`)에는 "me님에게 답글 남기기"가 있다. 그래서 "핸들 없음 → 로그인 필요" 테스트가 이제 화면 변경을 냈다. 규칙대로 둘로 나눴다.
  - 표지 있는 화면: `ui_changed`.
  - 표지 없는 공개 화면(`PLAIN_PAGE`): `auth`.
- **스크린샷 쿨다운 테스트**: 전에는 auth 증거를 남기면 한 시간 동안 찍지 않았다. 이제 ui_changed 증거를 아직 남길 수 있으면 찍는다. 기존 테스트는 두 종류 모두 쿨다운일 때만 안 찍는 것으로 고쳤다.
- **health 잡 기록이 30분마다 쌓일 문제**: 핸들을 못 읽는 상태는 고칠 때까지 계속된다. 매 점검 기록하면 하루 48건이 쌓인다. 그래서 알림을 보낼 차례(6시간에 한 번)일 때만 장애 기록을 남긴다. 실행 기록에는 매번 남긴다.
- **정규식 이스케이프**: Python 문자열, heredoc, JSON, JS의 네 겹 이스케이프가 섞여 `\n`이 실제 줄바꿈이 되는 일이 두 번 있었다. JSON은 `json.dumps`로 만들고, 결과를 다시 읽어 확인했다.

## 배운 것

1. **실패 판정에는 "아니라는 증거"도 함께 본다.** 핸들을 못 읽은 것은 "로그인 안 됨"의 증거가 아니라 "모름"이다. 이번에는 로그인한 사람만 보는 것(답글 입력칸, 글쓰기 칸 문구)이 있으면 로그아웃이 아니라고 본다. 반대로 로그인 폼이 함께 있으면 표지보다 그것을 믿는다. 증거가 서로 부딪힐 때 어느 쪽을 이기게 할지 정하는 것이 판정 규칙의 핵심이다.
2. **판정과 행동의 기준은 달라도 된다.** "로그인돼 있다"고 판정하는 데는 표지로 충분하다. 하지만 "이 계정으로 글을 올린다"는 행동에는 더 강한 증거(핸들 일치)가 필요하다. 틀렸을 때의 피해가 다르기 때문이다. 멈춤(하나의 판정)과 게시(하나의 행동)를 나눠 생각하면 둘 다 안전하게 할 수 있다.
3. **규칙은 한 곳에 두고 여러 언어가 같이 읽게 한다.** 같은 문구를 Python과 JS에 따로 적으면 언젠가 어긋난다. JSON에 정규식 원문을 두고, Python은 컴파일하고, JS에는 ARGS로 넘겼다. 다만 두 언어 정규식 문법의 공통부분만 써야 한다(인라인 플래그 `(?i)`나 lookbehind는 피했다).

## 다음 배치 메모

- 로그인된 인스타그램 화면 증거가 생기면 인스타그램 표지를 실제 문구로 확인하고 픽스처로 넣는다.
- ADR 0063의 "대체 경로 사용 기록"은 남았다.
- 화면 변경 동안 게시는 원고를 검토로 되돌린다. 오래 이어지면 승인된 원고가 계속 검토로 돌아가니, 게시 잡이 ui_warning을 보고 미리 건너뛸지 검토한다.
