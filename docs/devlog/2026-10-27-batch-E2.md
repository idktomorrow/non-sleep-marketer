# 2026-10-27 배치 E2: 장애 화면과 자동 진단

## 목표

E1의 오류 종류 표와 증거를 사람이 대시보드에서 바로 보게 하고, 화면 변경 실패는 Claude가 증거를 읽고 원인 추정을 알림에 붙이게. 진단은 자동, 수정은 사람(ADR 0054 경계 그대로).

## 한 일

- `failures` 표(스키마 v5)와 `Repository` 조회들. `run_logs`는 잡 한 번 = 한 줄이라 재활용하지 않음(ADR 0055).
- `nsm/engine/incidents.record_incident`: 게시·렌더·댓글 조회·답글·health·지표 실패에서 부른다. 취한 조치(예: "15분 뒤 다시(1/4회째)", "14:00까지 쉬기", "다시 하지 않고 원고를 검토로")를 함께 적는다.
- `nsm/adapters/diagnosis.ClaudeDiagnoser`: 스크린샷 + dialogs.json 요약 + 메시지 → "원인 추정 / 확인할 것". 데이터 경계(`<screen>`·`<error>`, 이스케이프), 6시간·하루 5회·비용 상한, 60초 시간 초과, 비용을 `costs`(llm/diagnose)에.
- 알림: 게시 화면 변경·게시 포기·댓글 사람 확인 알림 끝에 진단.
- 대시보드 `/incidents`(고급): 종류별 요약·지금 상태·최근 실패, `/incidents/<id>` 상세, 스크린샷(127.0.0.1 + shots 폴더 안만). "오늘" 화면 진행 중 한 줄.
- 정리 잡이 실패 기록도 `run_log_keep_days`로 정리.
- ADR 0055, architecture 6-2절·구현 상태, 설명서(장애 화면 행, 문제 해결 2행), CHANGELOG. 버전 0.4.11.

## 막힌 것과 해결

- **실제 호출이 버그를 잡았다.** 생성 모델(`claude-sonnet-5-5`)에 분류기처럼 `thinking: disabled`를 보냈더니 400("이 모델은 끄기 대신 between_tools"). 같은 모델을 쓰는 원고 생성기는 `thinking`을 아예 보내지 않는다 → 똑같이 맞추고 테스트에 박았다. 가짜 클라이언트 테스트만으로는 못 잡았을 것이다.
- **E1 테스트가 실제 홈에 증거 폴더 9개를 남겼었다.** E1에서 격리 픽스처를 넣기 전 첫 전체 테스트가 `~/.nsm/logs/shots`에 `*-20261011-100000*`(테스트 시계 시각) 폴더를 만들었다. 내용이 모두 테스트 문구("x")임을 확인하고 그 이름만 지웠다. 지금은 autouse 픽스처로 막혀 있다.
- **패치가 shots 경로를 못 따라감.** 장애 화면 모듈이 `shots_dir`을 이름으로 가져와 테스트 격리 패치가 닿지 않았다 → 모듈 속성으로 읽게.
- **재시도 대기의 종류.** 게시 레코드에는 실패 종류가 없다. 그 플랫폼의 마지막 게시 실패 기록의 종류로 어림한다(ADR에 한계로 적음).

- **코드 리뷰 10건 반영.** 실패한 진단 시도가 상한에 안 잡혀 매번 다시 부르던 것(시도 시각을 먼저 찍음), health 멈춤이 전부 "로그인"으로 보이던 것, 멈춘 동안 같은 실패가 30분마다 쌓이던 것, 끄는 중 끊긴 실패 기록, 지표 조치 문구, 댓글 조회 진단이 알림 없이 묻히던 것, `dialogs=0`이 빈칸 되던 것, 스크린샷 허용 주소에 테스트 전용 이름이 섞였던 것, 짧은 이름 중복.

## 배운 것 (신입 개발자용)

1. **가짜로 통과한 외부 호출은 한 번은 진짜로 불러 본다.** 같은 SDK라도 모델마다 받는 인자가 다르다. 테스트의 가짜는 우리가 상상한 API를 흉내 낼 뿐이다.
2. **"지금 상태"는 저장하지 말고 계산한다.** 쉬는 중·멈춤·재시도 대기는 이미 어댑터·설정·게시 표에 사실로 있다. 따로 저장하면 둘이 어긋난다.
3. **진단과 행동 사이에 사람을 둔다.** 모델이 화면 글을 읽는 순간 그 글은 입력이 된다. 출력을 글로만 두면 화면 속 지시가 행동으로 이어질 길이 없다.
