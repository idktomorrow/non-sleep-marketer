# 2026-10-22 배치 C30: 구글 뉴스 RSS 소스

## 목표

관련 자료 비율(네이버 19%, 트렌드 0%)을 올릴 소스를 더한다. 사용자 결정: 트렌드는 두고(큰 주제 프리셋에서 쓸모), 구글 뉴스 RSS를 더해 며칠 써 보고 아니면 끈다.

## 한 일

- 실험(`$TEMP/nsm-c20/gnews_probe.py`): "치이카와" RSS 92건, 매체 다양, 발행 시각 있음. 리다이렉트 주소는 base64로는 안 풀리고(2024년 암호화) `batchexecute` 호출로 풀림(4/4).
- `GoogleNewsSource`: 주제별 RSS, 한도를 주제 수로 분배, 제목 낱말 겹침(≥0.6) 중복 제거(주제 건너서도), `pubDate` → `published_at`, 해시는 구글 기사 id. `fetch_body`는 관련 자료만 주소를 풀어(요청 2번) 브라우저 추출기(있으면) 또는 HTTP로 읽음.
- 런타임: 브라우저 수집이 켜져 있으면 네이버의 `fetch_article`을 공유, 아니면 HTTP만으로도 동작. 설정 `collect.google_news`(기본 켬 = 끄면 롤백).
- 자료 화면에 "구글 뉴스" 라벨·필터. ADR 0050, 설명서 설정표, known-gaps, architecture, README 그림. 버전 0.4.5.

## 막힌 것과 해결

- **RSS에 요약이 없다.** description은 제목 링크뿐. 요약을 얻으려면 원문을 읽어야 하는데 모든 링크를 푸는 건 구글 요청 2번 × 수십 건 → 제한 위험. ADR 0022대로 관련 자료만 지연 읽기로 하고, 판정은 제목·매체로 한다(한국 기사 제목은 내용을 담는다).
- **리다이렉트 주소 풀기.** base64 풀기는 옛 형식만. 기사 페이지의 `data-n-a-sg`·`data-n-a-ts`를 읽어 `batchexecute`에 보내는 방식으로 성공. 구글이 바꾸면 실패하도록(예외 삼키고 None) 두고 로그 경고.
- **Git Bash에서 한글 인코딩.** 실험 출력이 깨져 보였지만 데이터는 정상(cp949 콘솔). `PYTHONIOENCODING=utf-8`로 해결.

## 배운 것 (신입 개발자용)

1. **소스는 "내 주제로 좁혀 최신 것을 주는가"로 고른다.** 양이 많은 소스(트렌드)보다 좁은 소스(주제 검색 RSS)가 관련 비율을 올린다. 비율이 낮으면 분류 비용이 아니라 "쓸 자료 없음"이 문제가 된다.
2. **공짜 API의 비용은 요청 수다.** 링크를 전부 풀면 돈은 안 들어도 제한에 걸린다. "필요한 것만 나중에" 원칙(지연 읽기)이 여기서도 통한다.
3. **외부 내부 호출은 깨질 것을 전제로 감싼다.** `batchexecute`는 공식 API가 아니다. 실패해도 수집이 멈추지 않게(None → 제목만) 하고, 로그로 알아차리게 한다.
