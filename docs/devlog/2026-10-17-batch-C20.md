# 2026-10-17 배치 C20: 예시 캐릭터 빼고 기본 "없음", 캐릭터 작게

## 목표

선웅제가 정한 것:
- 앵무새·햄스터는 예시였으니 프로그램에 넣지 않는다.
- 기본은 캐릭터 없음(빈칸)이고, 쓰고 싶으면 직접 올린다.
- 일러스트형 캐릭터 칸이 너무 크니 조금 줄인다.

## 한 일

- `nsm/templates/characters/`(앵무새·햄스터 PNG)를 지웠다.
- 설정 화면의 견본 그림 주소 `/settings/character/{name}.png`도 없앴다.
- `brand.character`
  - 선택지는 `none`(기본)·`custom`·`drawn`이다.
  - 예전 설정 파일의 `parrot`·`hamster`는 `none`으로 읽는다(설정 파일이 깨지지 않게).
  - 올린 캐릭터를 다 지우면 `none`으로 돌아간다.
- 크기
  - 카드 캐릭터 상자: 340px → 260px
  - 설정 화면 캐릭터 고르기
    - 칸은 3개다.
    - 칸 높이를 내용만큼만 잡고 안쪽 여백을 줄였다.
    - 견본 그림은 96px → 64px로 줄였다.
- AI 표기 체크 칸 안내: "기본 캐릭터" 대신 "AI로 만든 그림이라도 만화 캐릭터면 꺼 두셔도 됩니다"로 바꿨다.
- 문서: ADR 0046, 사용설명서, architecture, CHANGELOG를 고쳤다. 샘플도 바꿨다.
  - 예전 샘플(앵무새·햄스터 카드와 설정 화면)은 지웠다.
  - 새 샘플: 캐릭터 없는 표지, 올린 그림 예시가 들어간 표지·마지막 장, 새 고르기 칸

## 막힌 것과 해결

- **예전 설정 파일.** 설정 스키마는 모르는 값을 받지 않는다. 이미 저장된 `character: parrot`이 있으면 `nsm run`이 켜지지 않을 수 있었다. 그래서 읽을 때 `none`으로 바꾸는 검사를 넣었다.
- **"일러스트 칸"이 무엇인지.** 카드 안 캐릭터 크기로도, 설정 화면의 고르기 칸으로도 읽혔다. 둘 다 줄였다.
- **데모 화면 상태.** 앞선 확인에서 올린 그림이 데모에 남아, "기본은 없음" 확인이 실패했다. 데모를 새로 켜서 다시 확인했다.
- **올린 캐릭터가 설정 화면에서 원래 크기로 크게 보였다(사용자 제보).**
  - 서버는 새 `app.css`를 보내고 있었다. 하지만 브라우저가 예전 `app.css`를 저장해 두고 썼다. 정적 파일에 캐시 지시가 없어 브라우저가 마음대로 오래 쓴다.
  - 정적 파일 주소에 내용 지문을 붙였다(`asset('app.css')` → `/static/app.css?v=…`). 파일이 바뀌면 주소가 바뀐다.
  - 캐릭터 견본 `img`에 `width`·`height`를 넣어, CSS가 없어도 작게 보이게 했다.
- **작업 중 운영 대시보드가 잠깐 500을 냈다.**
  - 운영 중인 `nsm run`은 파이썬 코드는 켤 때 것을 쓰지만, 템플릿과 정적 파일은 이 작업 폴더에서 그때그때 읽는다.
  - batch 브랜치에서 템플릿을 새 함수(`asset`)에 맞게 바꾸자, 그 함수가 없는 운영 서버가 화면을 못 그렸다.
  - 바로 main으로 되돌려 200을 확인했다. 앞으로 batch 작업은 별도 작업 폴더(git worktree)에서 한다.

## 배운 것 (신입 개발자용)

1. **값을 없앨 때는 예전 데이터를 생각한다.** 선택지에서 값을 빼면, 그 값이 이미 저장된 파일을 읽다가 프로그램이 멈출 수 있다. 읽을 때 새 값으로 바꿔 주는 검사(`mode="before"` 검증기)를 두면 사용자가 아무것도 안 해도 넘어간다.
2. **예시 데이터는 제품에 넣지 않는다.** 시험용 그림을 기본값으로 넣으면, 사용자 계정에 그대로 실려 나간다. 테스트는 테스트가 직접 만든 그림을 쓰게 하면 제품과 테스트가 서로 묶이지 않는다.
3. **애매한 요청은 둘 다 작게 고칠 수 있으면 둘 다.** 어느 쪽을 말했는지 모를 때, 둘 다 되돌리기 쉬운 작은 변경이면 함께 하고 보고서에 어떻게 읽었는지 적는다.
