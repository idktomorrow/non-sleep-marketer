# 2026-11-28 배치 C61: 외부 코드 검토 후속 다듬기(CLI 오류, 대시보드 오류 화면, 설정 검증, doctor 판정, 답글 확인 문구, 문서)

## 목표

C60에서는 외부 정적 코드 검토(2026-11-27)의 동작 버그 4건을 고쳤다. 이번에는 "틀리진 않지만 불친절하거나 서로 안 맞는 것"을 고친다. 대상은 사용자 눈에 보이는 문구·화면·문서·점검이다. 엔진 동작·스케줄·분류기·게시 로직은 바꾸지 않는다.

## 한 일

- **CLI(1-15·1-16)**

## 막힌 것과 해결

- **워크트리의 pydantic import 실패**: 처음 `import nsm.engine.runner`가 `cannot import name 'AfterValidator' from 'pydantic' (unknown location)`으로 죽었다. 워크트리 `.venv`의 `pydantic/__init__.py`가 없어 이름공간 패키지로 읽힌 것이다(`%TEMP%` 아래라 정리 도구가 지운 것으로 보임). `uv sync --reinstall`로 다시 깔고 해결했다.
- **도움말을 `JOBS`에서 바로 만들면 모든 명령이 2초 느려짐**: 도움말 문자열은 모듈을 불러올 때 정해진다. 그래서 `runner`를 import하면 `nsm doctor`·`nsm --help`도 잡 전부를 불러온다. 가벼운 이름 목록을 두고 `runner`가 import될 때 대조하게 했다. 원본은 여전히 `JOBS`이고, 어긋나면 첫 테스트부터 깨진다.
- **브라우저가 아닌 요청까지 HTML로 바꾸면 기존 테스트 67곳이 깨짐**: 테스트 클라이언트와 `fetch` 기본 Accept는 `*/*`다. 판단 순서를 HTMX → JSON → HTML로 하고 `*/*`는 JSON으로 두었다. 편집 폼을 다시 그리는 것도 `text/html` 요청일 때만 한다.
- **60분 하한은 경계에 걸림**: 원고 시각은 창 시작 +50분이고 APScheduler 지터는 0~600초를 더한다(`BaseTrigger._apply_jitter`). 창 끝은 포함하지 않는다(`policy._in_window`의 `t < end`). 그래서 딱 60분인 창은 작업 스레드가 다른 잡에 밀리면 창 밖이 될 수 있다. 하한은 배치 지시대로 60분으로 두고, ADR 0081과 known-gaps에 적었다. 오프셋 보정은 지시대로 하지 않았다.

## 배운 것 3개

1. **"같은 오류를 누가 받나"에 따라 모양을 바꿀 수 있다.** HTTP의 `Accept` 헤더는 "나는 이런 형식을 원한다"는 요청자의 말이다. 브라우저 폼은 `text/html`, 스크립트는 `application/json`이나 `*/*`를 보낸다. 서버는 상태 코드(400·409)를 그대로 두고 몸통만 바꾸면 된다. 그러면 사람은 읽을 화면을, 프로그램은 다루기 쉬운 JSON을 받는다. 다만 판단 순서를 문서로 남겨야 다음 사람이 헷갈리지 않는다.
2. **검증은 "들어오는 모든 길"이 지나는 한 곳에 둔다.** 활동 시간은 설정 화면, 마법사, config.yaml, 프리셋 네 길로 들어온다. 화면에만 검사를 달면 파일을 손으로 고친 사람이 빠져나간다. 그래서 문자열 파서(`parse_windows`)와 모델 검사(`field_validator`)가 같은 함수(`check_windows`)를 부르게 했다. 프리셋처럼 `model_copy`로 검사를 건너뛰는 길은 따로 찾아 막아야 한다.
3. **점검 도구의 등급은 "이게 없으면 무엇이 안 되나"로 정한다.** WARN과 FAIL의 차이는 기분이 아니라 결과다. Claude 키가 없으면 원고가 0건이니 FAIL이다. 드라이런에서 Aside가 없어도 아무 일도 안 막히니 WARN이다. 같은 항목이라도 설정(`dry_run`)에 따라 등급이 바뀔 수 있다. 문서의 약속("FAIL이 없으면 준비 끝")이 참이 되도록 도구를 맞추는 편이, 문서에 예외를 늘어놓는 것보다 낫다.
