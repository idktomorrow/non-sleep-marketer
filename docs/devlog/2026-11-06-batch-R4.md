# 2026-11-06 배치 R4: 문서 질문에 수집 자료와 우리가 올린 글을 출처로 더하기

## 목표

문서 질문(RAG)은 docs 폴더만 색인했다(R1~R3, ADR 0056~0059). 운영하며 궁금한 것들의 답은 DB에 있다. "그 기사에 뭐라고 나왔지", "우리가 그 얘기를 언제 올렸고 댓글에 뭐라고 답했지" 같은 것이다.

R1에서 출처를 포트(`DocumentSource`: `kind`, `documents()`)로 분리해 둔 것이 이 확장을 위해서였다. 그래서 색인·검색·답변 코드는 최소로만 건드리고 출처 어댑터를 더한다(ADR 0065).

## 막힌 것과 해결

- **DB 출처가 0건이 되면 지워지지 않음**: `index_documents`에는 "문서를 하나도 못 찾았는데 저장된 조각이 있으면 지우지 않고 멈춤" 보호가 있다(docs 경로 실수 대비). 수집 자료가 전부 기간 밖으로 밀리면 이 보호에 걸려 오래된 조각이 영원히 남는다. 출처에 `allow_empty` 표시를 두어 DB 출처는 0건도 정상으로 본다. docs 보호는 그대로다.
- **같은 날 막힌 시도도 한도에 세어짐**: 앞 출처에서 429가 나면 뒤 출처가 또 보내 볼 이유가 없다. 남은 상한을 0으로 해 조각만 저장한다. 테스트는 보내 본 횟수(한 번)까지 센다.
- **기존 화면 테스트가 배지 위치에 걸림**: 근거 줄 "[1] 제목 경로" 사이에 배지를 넣었더니 기존 테스트의 문구가 깨졌다. 사람이 읽는 순서도 "번호 → 제목 → 출처 → 점수"가 자연스러워 배지를 제목 뒤로 옮겼다.
- **코드 리뷰 지적 반영**
  - **댓글 글·답글에 남의 이름이 남음**: 작성자 이름 칸만 뺐는데, 답글이 "OO님 고마워요"처럼 이름을 부르거나 댓글이 `@핸들`을 언급할 수 있었다(답글 프롬프트가 작성자 이름을 받음). `scrub_people`이 `@핸들`을 `@…`로, 그 댓글 작성자 이름을 `…`로 바꾼다.
  - **`nsm index --dry-run`이 DB를 씀**: 기본 출처가 all이 되면서 dry-run이 `Database()`로 열어 스키마·마이그레이션을 적용했다. `nsm run`이 켜져 있으면 잠금 오류로 끝나기도 했다. dry-run은 읽기 전용 연결로 열고, 잠겨 있으면 DB 출처만 건너뛴다고 알린다.
  - **닫히지 않은 코드 울타리**: 수집 원문의 울타리(```` ``` ````) 하나가 뒤 절(카드 문구·댓글)을 한 조각으로 삼켜 임베딩 입력 한도를 넘을 수 있었다. 울타리 줄도 제목 줄처럼 글자로 바꾼다.
  - **종료 코드**: 출처를 못 읽으면(문서 폴더가 빔) 예전처럼 2로 끝낸다. 오류로 멈춘 뒤 미룬 조각을 "오늘 상한으로 내일"이라고 적지 않는다.
- **heredoc 안의 `\n`**: 패치 스크립트를 셸 heredoc으로 넘기면 `\\n`이 실제 줄바꿈이 되는 일이 다시 있었다. 파일로 쓴 스크립트로 바꿨다.

## 배운 것

1. **포트는 "나중에 붙일 것"을 위한 약속이다.** R1에서 출처를 `kind`와 `documents()` 두 개로만 정의해 두었다. 그래서 이번에는 "DB를 읽어 마크다운 문서를 돌려주는 클래스"만 쓰면 됐다. 증분·삭제·벡터 재사용·상한 같은 어려운 부분은 이미 출처마다 따로 동작했다. 새 기능의 코드가 거의 다 어댑터 안에 있고, 핵심 로직은 그대로라 기존 테스트가 보증을 계속 서 준다.
2. **안전장치는 출처마다 뜻이 다르다.** "문서가 0개면 지우지 말고 멈춤"은 폴더 경로를 잘못 준 사고를 막는 장치다. 그런데 DB 출처에서 0건은 사고가 아니라 정상이다(예: 기간이 지나 다 빠짐). 같은 규칙을 모든 출처에 걸면 오래된 자료가 영원히 남는 버그가 된다. 규칙을 지우지 말고, 출처가 자기 성격을 밝히게(`allow_empty`) 하는 것이 안전하다.
3. **검색에 무엇을 넣지 않을지가 넣을 것만큼 중요하다.** 관련 없는 기사와 올리지 않은 원고를 빼고, 댓글 작성자 이름도 뺐다. 검색은 넣은 것을 그대로 보여 주는 기계다. 넣는 순간 화면·프롬프트·90일 보관 기록까지 퍼진다. 쓸모(그 댓글에 뭐라고 답했나)에 필요 없는 개인 정보는 처음부터 넣지 않는 것이 가장 싸다.
