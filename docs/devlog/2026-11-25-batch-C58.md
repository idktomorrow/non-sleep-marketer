# 2026-11-25 배치 C58: 스레드 게시 직후 탭 이동으로 업로드가 끊기는 문제 + 실패 증거 화면 시간 확보

## 목표

스레드 게시가 1·2차 "게시를 확인하지 못함"으로 실패하고 3차에 올라가는 일이 11번 있었다. 게시 탭을 떠나지 않게 해서 이 일을 없앤다. 또 실패하면 증거 폴더에 화면(`screenshot.png`)이 남게 한다.

## 한 일

- `threads.py` `_PUBLISH`(ADR 0078)
  - 게시 탭 `pg`는 '게시'를 누른 뒤 주소를 옮기지 않는다. 게시 전 멱등 확인(`before = findMine(pg)`)은 그대로다.
  - 창이 닫히면 `sleep(5000)`을 둔다. 그 뒤 `게시 중|Posting`이 보이면 사라질 때까지, `게시됨|게시되었|Posted`가 보이면 바로 넘어간다. 최대 15초이고, 문구가 없어도 실패가 아니다. 본 문구는 결과 `settle`로 돌려주고, Python이 `스레드: 게시 뒤 화면 문구 …`로 로그에 남긴다.
  - 확인 탭은 한 번만 연다(`makeChecker`). 첫 회차는 방금 연 화면을 읽고(`findMine(chk, true)`), 다음부터 `goto`로 다시 읽는다. 탭 열기를 포함한 오류는 모두 '못 찾음'으로 본다(게시 뒤에는 던지지 않음). `findMine`의 `goto`는 마감 10초 전까지만 기다린다.
  - 문구는 글 카드·대화상자 밖에서만 찾는다(`postStatusText`). 끝까지 못 찾았는데 아직 "게시 중"이면 증거 시간만 남기고 더 기다린 뒤 한 번 더 찾는다.
  - 이미지가 있으면 미리보기 개수가 찬 뒤 `sleep(1500)`을 두고, `nsmUntil(() => nsmClickText(dlg, '게시'), 15000, 500)`으로 누른다.
  - 글 찾기 예산은 `nsmLeft() - 17000`에서 `nsmLeft() - 25000`으로 바꿨다. 증거는 `nsmEvidence({ page: pg })`로 게시 탭에서 찍는다.
- `aside_common.py` `nsmClickText`: `aria-disabled="true"`·`disabled` 버튼을 건너뛴다.
- 답글 두 곳의 '게시'를 `nsmUntil(…, 5000, 300)`으로 감쌌다: 스레드 `_REPLY`, 인스타 `_REPLY`(Enter가 안 먹었을 때). 인스타는 그사이 입력창이 비면 보낸 것으로 본다. 버튼이 있는데 계속 비활성이어도 던지지 않는다(Enter로 이미 보냈을 수 있어서, 던지면 중복 답글). '삭제'·'숨기기'·'4:5'는 그대로 두었다.
- `drivers/aside.py` `nsmEvidence(opts)`: `opts.page`로 찍을 탭을 받는다. 없으면 예전처럼 마지막에 연 탭이다.
- ADR 0078, 장애 0017, user-guide 문제 해결 표, architecture 상태 표, 버전 0.4.47.

## 막힌 것과 해결

- 테스트에서 "게시 뒤 `pg.goto`가 없다"를 문자열로 검사했더니 내 주석의 "(pg.goto 금지)"에 걸렸다. 주석을 "그 주소에 그대로 두고"로 바꿨다.
- `nsmClickText`·`nsmEvidence`는 node 가짜 실행기로 동작을 본다. 가짜 시계를 먼저 세우고 그 시계로 마감을 정해야 `nsmUntil`의 회차가 예측대로 돈다.
- 코드 리뷰 지적 6건 모두 반영
  1. 인스타 답글 회귀: Enter로 보낸 뒤 '게시'가 비활성(전송 중)이면, 바뀐 `nsmClickText`가 건너뛰어 "답글 게시 버튼 없음"을 던지고 중복 답글로 이어질 수 있었다 → 입력창이 비면 보낸 것, 버튼이 있으면 던지지 않음
  2. 게시 뒤 예외: `.catch`가 `findMine`에만 있고 확인 탭 열기는 보호되지 않았다 → `makeChecker`가 전체를 감쌈. 창 닫힘 대기의 `count()`에도 `.catch`
  3. 글 찾기를 건너뛰고 바로 끝나면 업로드 중인 탭이 닫힐 수 있었다 → 못 찾았는데 "게시 중"이면 더 기다림. `sleep(5000)`은 남은 시간 안에서만
  4. 확인 탭 첫 회차가 같은 주소를 두 번 읽고, `goto`에 상한이 없었다 → 첫 회차는 이동 없이, `goto`는 마감 10초 전까지
  5. 문구 정규식이 내 글 본문까지 봤다 → 글 카드·대화상자 밖의 글만
  6. ADR의 "글 찾기 8초 줄어든다"는 틀렸다(13~28초) → 고침. 아무것도 검증하지 않던 assert는 지우고, 문구 대기 5가지와 확인 탭(열기 실패·goto 오류에도 던지지 않음, 탭 한 번만)을 node 가짜 실행기로 실제로 돌리는 테스트를 넣음
- node 출력에 한글이 있으면 Windows 기본 인코딩(cp949)으로 읽다가 깨졌다 → `subprocess.run(..., encoding="utf-8")`

## 배운 것

1. **버튼을 누른 뒤 창이 닫혔다고 해서 일이 끝난 건 아니다.** 웹앱은 화면을 먼저 정리하고 요청을 뒤에서 마치는 일이 많다. 그 탭을 바로 다른 주소로 옮기면 브라우저가 진행 중인 요청을 끊는다. 확인은 다른 탭에서 하면 시간 추측 없이 안전하다.
2. **"마감을 회차 앞에서만 본다"는 대기 함수는 마지막 회차만큼 예산을 넘긴다.** `nsmUntil(fn, wait, 3000)`은 마감 직전에 시작한 회차를 끝까지 돌리므로, 뒤에 할 일(증거 화면 5초)의 여유는 회차 길이까지 더해 잡아야 한다(17초 → 25초).
3. **공통 도우미를 바꾸면 쓰는 곳을 다 찾아본다.** `nsmClickText`가 비활성 버튼을 건너뛰게 되자, 예전에는 눌러지던(효과는 없던) 순간에 이제 '버튼 없음'이 된다. 그래서 호출부를 grep해 '게시'를 누르는 세 곳은 다시 보기(`nsmUntil`)로 감쌌다.
