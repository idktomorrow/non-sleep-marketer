# 2026-11-03 배치 E5: 로그인 안 됨의 세부 상태

## 목표

"로그인 필요(Aside 브라우저)" 한 가지로만 알리던 것을, 실제로 무엇이 막고 있는지 나눠 알린다. 상태는 로그아웃·본인 확인·문자 인증·두 단계 인증·계정 제한·원인 모름이다. 사람이 해야 할 일이 상태마다 다르기 때문이다.

계기는 두 건이다.
- 10-29~11-01 인스타그램이 본인 확인·문자 인증에 걸려 사흘 반 멈췄는데, 앱은 로그아웃처럼 보여 줬다(incidents/0010).
- 11-02 스레드는 하얀 빈 화면을 로그인 풀림으로 잘못 보고했다.

## 한 일

- **분류**
  - `nsm/adapters/platforms/auth_state.py`와 `data/auth_states.json`을 만들었다. 화면 글·라벨, 주소, 로그인 폼 순서로 판정한다.
  - 빈 화면 판정(`is_blank`)은 세 조건을 모두 만족할 때만이다: 로그인·확인 주소가 아니고, 글이 없고, 라벨도 없다.
- **health**
  - 스크립트는 로그인이 안 보이면 `nsmEvidence()`로 그 화면 정보를 함께 돌려준다.
  - `AsideAdapterBase._health`가 상태를 `auth_state` 속성에 둔다. 보안 확인·두 단계 인증·제한이면 예외가 없어도 증거를 남긴다(1시간 쿨다운).
  - 빈 화면은 `transient`로 던진다.
- **댓글 확인·게시 전 확인**: `nsmAssertHandle`의 login 오류에 이미 붙어 오던 증거로 같은 분류를 한다. `LoginRequiredError.auth_state`에 상태를 두고, 빈 화면은 `transient`로 본다.
- **엔진**
  - 멈춤 정보에 `auth_state`와 `notified_at`을 더했다.
  - 멈춘 플랫폼도 점검 결과를 본다. 상태가 바뀌면 고치고 바로 알린다. 같으면 24시간마다 "(계속)"을 보낸다. 실패 횟수와 실패 기록은 다시 쌓지 않는다.
  - `run_metrics`는 멈춘 플랫폼을 건너뛴다.
- **문구**
  - `pause.py`에 상태별 짧은 이름, 할 일, 알림 본문을 두었다.
  - 오늘 화면에는 플랫폼별 할 일을, 장애 화면에는 상태별 이유를 보인다.
  - "로/으로"와 "이/가·을/를"은 받침에 맞게 붙인다.
- **문서**: 장애 기록 0010(부록: 11-02 스레드), ADR 0060, 설명서 상태별 할 일 표, architecture, CHANGELOG. 버전은 0.4.20.

## 막힌 것과 해결

- **health가 증거를 못 남기던 이유**: 증거는 스크립트가 예외를 던질 때만 `_WRAP`이 모은다. health는 "로그인 안 됨"을 값으로 돌려주므로 사흘 동안 한 장도 없었다. 그래서 health 스크립트가 직접 `nsmEvidence()`를 돌려주게 했다.
- **주소의 함정**: 증거 세 건 모두 `/accounts/suspended/`였는데, 하나는 captcha였고 둘은 문자 인증이었다. 주소를 먼저 보면 "계정 정지"라고 거짓말을 한다. 그래서 글을 먼저 본다.
- **화면 정보가 없는 로그인 오류**
  - 처음에는 이런 오류도 unknown으로 두었다. 그러자 기존 테스트가 예전 제목("로그인 필요") 대신 "로그인 필요(원인 모름)"를 받았다.
  - 화면을 못 봤을 때는 상태를 모르는 것(None)이 맞다. 그래서 예전 문구를 그대로 쓰고, unknown은 화면을 봤는데 못 알아본 경우에만 쓴다.
- **E4 전 멈춤(이유 없음)**: 새 로직이 이유를 지어내지 않게 했다. 화면으로 알아낸 상태가 있을 때만 적는다.
- **조사**: "본인 확인 창로"처럼 어색하게 붙었다. 받침을 보고 고르는 작은 함수를 두었다(괄호 설명은 빼고 판단).
- **영향 세기**
  - 운영 DB는 잠겨 있어 11-02 새벽 백업을 복사해 읽었다.
  - 지표 잡 오류 21·16·12건은 run_logs 메시지에 첫 오류만 있다. 그래서 7일 안 인스타그램 게시물 수(20·15·11)에 계정 지표 1을 더한 값과 맞춰 보고 "모두 인스타그램"이라고 적었다.

- **코드 리뷰 10건 모두 반영.**
  - ① 화면 글 읽기가 시간 초과하면(글 정보 없음) 빈 화면으로 오판할 수 있었다 → 글 정보가 있을 때만 빈 화면으로 판단.
  - ② 문자로 받는 두 단계 인증이 문자 인증으로 분류됐다 → 두 단계 인증 주소를 먼저 본다.
  - ③ 로그인 폼 문구가 "로그인"·"password" 낱말이라 Meta 안내문에도 맞았다(문자 인증 증거에도 "로그인을 돕고"가 있다) → 폼에만 있는 문구로.
  - ④ E5 전에 멈춘 플랫폼은 올리자마자 "(계속)" 알림이 갔고, 일시적·화면 변경 멈춤에도 재알림이 생겼다 → 재알림은 세부 상태가 있는 auth만, 시각이 없으면 그때부터 센다.
  - ⑤ 본인 확인 → 계정 불일치로 바뀌어도 모르던 것 → 바뀐 것으로 본다.
  - ⑥ 증거를 안 남길 때도 30분마다 스크린샷을 찍어 버렸다 → 쿨다운 중엔 글만.
  - ⑦ 플랫폼 한국어 이름 표가 셋째로 생겼다 → `rate_limit.NAMES` 하나를 쓴다.
  - ⑧ 빈 화면 오류를 두 곳에서 만들었다 → `_blank_error()` 하나.
  - ⑨ dict가 아닌 증거가 오면 분류기가 터졌다 → 방어.
  - ⑩ 오늘 화면이 상태를 두 번 말했다 → 플랫폼마다 괄호 안에 "이유: 할 일".

## 배운 것 (신입 개발자용)

1. **오류 문구는 관찰이지 원인이 아니다.** "로그인돼 있지 않음"은 "내 프로필 링크가 안 보였다"는 뜻일 뿐이다. 그 순간 화면에 무엇이 있었는지 같이 남겨야 원인을 나눌 수 있다. 이번에 원인을 알아낸 것도 다른 잡이 우연히 남긴 증거 덕분이었다.
2. **판정 순서는 거짓말이 가장 적은 신호부터.** 주소는 플랫폼이 마음대로 재사용한다(보안 확인도 `/suspended/`). 화면 문구가 사람에게 하는 말이라 더 정직하다. 그래서 문구 → 주소 → 기본값 순으로 본다.
3. **알림은 "처음, 바뀔 때, 가끔"만.** 30분마다 같은 알림을 보내면 사람이 무시하게 된다. 아예 안 보내면 사흘 동안 바뀐 사정(본인 확인 → 문자 인증)을 놓친다. 상태와 마지막 알림 시각을 같이 저장하면 둘 다 피할 수 있다.
