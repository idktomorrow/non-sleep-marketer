# 2026-10-13 배치 N1: 알림과 "지금 실행" 피드백

## 목표

선웅제 지적 세 가지: 알림이 안 뜬다, 지금 실행이 끝났는지 모른다, 원고를 더 만들 수 없다. 작업 중에 알림 켜기/끄기 요청이 더해졌다.

## 한 일

- 알림: 앱 ID `NonSleepMarketer` 등록(HKCU), 알림 XML 이스케이프 → PowerShell 작은따옴표 → `-EncodedCommand`, 실패 로그, 별도 스레드. winotify 의존성 제거.
- 설정 `desktop_notifications`와 설정 화면의 "Windows 알림 받기", "테스트 알림 보내기".
- 지금 실행: `ManualRun` 기록, 누른 화면으로 돌아가기(같은 대시보드에서 온 경우만), 오른쪽 아래 진행 표시(`_jobstatus.html`, HTMX 2초 갱신, 다 끝나면 갱신 멈춤), 완료 알림, 한국어 결과 요약(`ko.result_text`).
- 원고 만들기 지금 실행: `run_job(..., manual=True)` → `run_generate(manual=True)`는 1건 더, 쿼터를 넘긴 원고는 모든 플랫폼에 배정.
- 데모 대시보드의 지금 실행은 3초 뒤 그럴듯한 결과를 돌려준다(진행 표시 확인용).
- ADR 0030(채택), 사용설명서·architecture·CHANGELOG.

## 막힌 것과 해결

- 알림이 "보냈다"고 로그에 남았는데 안 보였다: winotify가 PowerShell 출력을 버려서 Windows가 알림을 버린 걸 알 수 없었다. 등록된 앱 ID로 직접 보내니 떴다.
- 진행 표시의 상태 클래스를 `ok`/`bad`로 붙였더니 기존 전역 `.ok { color: 초록 }`과 겹쳐 글자 전체가 초록이 됐다. `is-ok`처럼 이름을 바꿨다.
- `uv remove winotify`가 실행 중인 `nsm.exe`를 지우지 못해 중간에 멈췄다(Windows는 쓰는 중인 exe를 못 지움). `--no-sync`로 의존성 목록만 바꿨다. 다음에 `nsm run`을 껐다 켤 때 환경이 맞춰진다.
- 원고 1건 더 테스트가 "쓸 자료 없음"으로 실패: 픽스처 자료를 하루 목표 2건이 다 썼다. 테스트에서 새 자료를 넣고 확인했다.

## 테스트 결과

- ruff 통과, pytest 초록. 새 테스트: 알림 3개(문구 이스케이프, 인코딩 왕복, 켜기/끄기·중복 억제), 지금 실행 5개(진행 → 완료·알림·3분 뒤 사라짐, 실패, 외부 referer, 결과 요약, 알림 스위치·테스트 버튼), 원고 1건 더 1개.
- 실측: 등록된 앱 ID로 테스트 알림을 보냈다(종료 코드 0). 데모 대시보드 1280·390px에서 진행 표시 → 완료 표시, 가로 넘침 없음.

## 배운 것 (신입 개발자용)

1. **"보냈다"와 "보였다"는 다르다.** 외부 시스템에 일을 시키고 결과를 버리면 실패를 영영 모른다. 하위 프로세스의 종료 코드와 오류 출력은 꼭 받아서 로그에 남긴다.
2. **문자열을 다른 언어의 코드 안에 끼워 넣을 때는 그 언어의 "해석되지 않는" 자리에만 넣는다.** PowerShell 큰따옴표 here-string은 `$()`를 실행한다. 작은따옴표 문자열은 실행하지 않는다. 거기에 넣고, 작은따옴표 자체는 두 번 써서 끝나지 않게 한다.
3. **사람이 누른 버튼은 반드시 결과로 답한다.** 자동 작업은 기록만 남겨도 되지만, 사람이 직접 누른 작업은 "하고 있다 → 끝났다 → 무엇이 바뀌었다"를 그 자리에서 보여 줘야 "하염없이 기다리는" 일이 없다.
