# 2026-10-24 배치 C32: 사람이 답할 댓글 줄이기

## 목표

사람 칸에 "돈·약속이 걸린 댓글"만 남긴다. 사용자 결정: 스팸과 소식에 대한 불만·감정은 자동, 브랜드·거래·환불·법적 불만만 사람에게.

## 한 일

- `policy.decide_comment`에 `complaint_scope`: 소식 반응이면 자동 답글, 브랜드 불만·불확실은 사람에게. 숨기기 없는 플랫폼의 스팸은 escalate → ignore(사유 기록).
- `reply._complaint_scope`: 댓글 분류기(Gemini)에게 브랜드 이름과 함께 2차 판정. 라벨 이상·신뢰도 < 0.6·실패는 None(사람에게).
- 소식 반응 답글은 지시 맨 앞에 "공감만, 사과·보상·약속 금지" 안내. 답글 시스템 프롬프트에도 한 줄.
- 댓글 픽스처 `ctx`를 `tests/engine/conftest.py`로 옮김(새 테스트 파일과 공유). ADR 0052, contracts 4절, 설명서, CHANGELOG. 버전 0.4.7.

## 막힌 것과 해결

- **같은 댓글 글로 두 번 묻는다.** 가짜 분류기가 글 기준(`by_text`)으로 답해서 2차 판정도 "complaint"를 돌려줬다 → 테스트에서 지시문으로 가르는 분류기를 둠. 실제 Gemini는 지시가 다르니 문제없다.
- **어느 쪽으로 기울이나.** 오판의 비용이 비대칭이다(브랜드 불만에 공감만 → 손해, 소식 반응을 사람에게 → 버튼 한 번). 지시에 "애매하면 brand_complaint", 코드에 신뢰도 하한, 실패는 None. 세 겹 모두 사람 쪽.
- **인스타그램 2차 실행 간격.** 테스트에서 같은 시각 두 번째 `run_reply`가 30분 간격 규칙에 걸려 아무것도 안 함 → `manual=True`.

## 테스트 결과

- ruff, pytest 805 passed(contract 제외)
- `tests/engine/test_comment_triage.py`: 소식 반응 → 자동 답글 + 지시 앞머리, 브랜드 불만·낮은 신뢰도 → 사람, 판정 실패 → 사람. `test_reply_job`: 스팸(숨기기 없음) → 넘김·답글 없음. 정책 단위 테스트: 범위별 결정, 하루 한도 유지, 환불은 범위와 무관.

## 배운 것 (신입 개발자용)

1. **"사람에게 넘긴다"도 비용이다.** 안전해 보이지만 사람이 매번 눌러야 하면 자동화가 아니다. 넘길 기준은 "사람만 할 수 있는 판단인가"(돈·약속)로 좁힌다.
2. **오판 비용이 비대칭이면 기울인다.** 두 오류의 손해가 다르면 지시·신뢰도·실패 처리 모두를 싼 쪽으로 기울여 둔다.
3. **같은 입력으로 다른 질문을 할 땐 가짜도 질문을 봐야 한다.** 테스트 가짜가 입력만 보고 답하면 2단계 판정을 검증할 수 없다.
