# 2026-10-16 배치 C13: 대시보드 간단 모드와 고급 모드

## 목표

지금 대시보드는 개발하며 쓰던 화면 그대로라 일반 사용자에게는 복잡하다. 사용자가 "일반 사용자용은 최대한 간단하게, 개발자는 고도화된 화면"을 원했다. 화면을 두 벌 만드는 대신 한 앱 안의 스위치로 보이는 것만 줄이기로 했다.

사용자가 정한 것은 셋이다.

- 기본은 간단 모드
- 간단 "오늘"은 할 일, 요약, 지금 실행 몇 개
- 숨길 메뉴는 자료와 실행 기록. 성과와 주간 리포트는 남긴다. 자료 올리기는 "오늘"의 칸으로 옮긴다.

## 한 일

- **스위치:** 모든 화면 오른쪽 위에 "간단 | 고급"을 두었다. `POST /ui-mode`(CSRF 검사)로 DB 설정 `ui_mode`에 저장한다. 처음 값과 알 수 없는 값은 간단이다.
- **간단 모드에서 숨기는 것**
  - 메뉴: 자료, 실행 기록. 주소로는 열리고, 그 화면에 있는 동안은 탭이 보인다.
  - "오늘": 쓸 수 있는 자료 수, 지금 실행 8개 중 5개(게시하기, 성과 읽기, 로그인 점검, 주간 리포트, 백업·정리), 최근 실행 표
  - 설정: 활동 시간, 게시 간격, 자료 검색 기간, 댓글 확인 간격 둘, 금칙 패턴
- **간단 모드에 더한 것:** "오늘"의 자료 올리기 칸. 올리면 "오늘"로 돌아와 "올렸습니다, 글자 N자"를 보여 준다. 처음 시작 안내 문구도 모드에 맞게 바꿨다.
- **설정 화면 줄 바꿈:** 숨기는 칸끼리 한 줄로 모아(활동 시간 + 게시 간격), 간단 모드에서 빈 반쪽 줄이 생기지 않게 했다(게시 시간 + 비용 상한, 하루 게시 수 둘).
- **문서:** ADR 0042(제안), 사용설명서 4절 "간단 모드와 고급 모드", architecture, CHANGELOG, known-gaps 다음 후보에서 간단 모드 뺌. 화면 캡처는 `docs/samples/ui/modes/`

## 막힌 것과 해결

- **숨긴 칸이 그대로 보였다.** `hidden` 속성을 붙였는데 `.field-row { display: grid }`가 브라우저 기본 `[hidden] { display: none }`보다 우선했다. `[hidden] { display: none !important; }`를 한 줄 넣었다.
- **숨긴 설정을 어떻게 저장하나.** 폼에서 칸을 빼면 저장 함수가 "값이 없음"으로 실패하거나 기본값으로 덮을 수 있다. 칸을 폼에 그대로 두고 숨기기만 해서, 지금 값이 같이 저장되게 했다. 브라우저에서 간단 모드로 저장해 숨은 값이 그대로인 것을 확인했다.
- **자료 올리기 뒤 어디로 돌아가나.** 업로드는 원래 자료 화면으로 돌아간다. `next` 값을 받되 `/`일 때만 따르게 했다. 아무 주소나 따르면 다른 사이트로 보내는 데 쓰일 수 있다(열린 리다이렉트).
- **기존 테스트 하나가 깨졌다.** "오늘"의 최근 실행 표를 보던 테스트였다. 표가 고급 모드에만 있으니, 그 테스트에서 고급 모드로 바꾸고 보게 했다.

## 배운 것 (신입 개발자용)

1. **"숨기기"와 "없애기"는 다르다.** 간단 모드는 기능을 지우지 않고 보이는 것만 줄였다. 그래서 라우트와 테스트가 그대로고, 숨긴 화면도 주소로 열린다. 화면을 두 벌 만들었다면 고칠 때마다 두 번 고쳐야 했다.
2. **CSS가 HTML 속성을 이길 수 있다.** `hidden`은 브라우저 기본 스타일 `display: none`일 뿐이라, 내가 쓴 `display: grid`가 더 우선한다. "속성을 붙였는데 왜 보이지?"는 이 경우가 많다.
3. **사용자 입력으로 이동할 주소를 정하면 안 된다.** "끝나면 여기로 돌아가라"는 값을 그대로 따르면, 다른 사이트로 보내는 링크를 만들 수 있다(열린 리다이렉트). 허용할 값(`/`)을 정해 두고 나머지는 무시했다.
