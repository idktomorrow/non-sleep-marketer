# 2026-10-13 배치 M17: 대시보드 설정 화면

## 목표

페르소나(이름 포함)와 브랜드 정보, 운영 값을 대시보드에서 고칠 수 있게 한다. 계기는 실계정 첫 실행에서 브랜드가 `y`로 남아 관련 자료가 0건이 된 일이다.

## 한 일

- `nsm/app/settings_form.py`: 폼 → 새 `AppConfig`(`apply_settings_form`), 현재 값 → 폼(`form_values`). 줄 목록은 빈 줄·중복 제거, 숫자 범위, 시간 형식, 색, 금칙 패턴 정규식을 검사한다.
- `GET/POST /settings`: 틀리면 400과 함께 넣은 값을 그대로 다시 보여 준다. 맞으면 저장 후 "저장했습니다".
- 메뉴에 "설정"을 추가했다. 색 고르개와 글자 칸을 서로 맞추고, 저장하지 않고 떠나면 경고한다. 휴대폰 폭에서는 한 줄씩 보인다.
- `JobScheduler.reschedule`: 활동 시간이 바뀌면 수집·생성 예약을 다시 건다. 창 개수가 줄면 남는 수집 예약은 지운다.
- ADR 0028(채택)을 썼다. 사용설명서 4절, architecture, CHANGELOG도 고쳤다.

## 막힌 것과 해결

- APScheduler는 시작 전에 넣은 작업을 "임시"로만 들고 있어서, 시작 전에는 `replace_existing`이 적용되지 않았다. 테스트에서는 스케줄러를 멈춘 상태로 시작(`start(paused=True)`)한 뒤 다시 걸었다. 실제 실행 중인 스케줄러와 같은 상황이다.
- 브라우저 화면 점검 중 잘못된 색 값이 서버까지 가지 않았다. 입력 칸의 `pattern` 검사가 먼저 막았기 때문이다. 서버 검사는 금칙 패턴처럼 브라우저가 모르는 값으로 따로 확인했다.
- 모델 전체 검사 오류는 위치가 `persona`로만 나와 "persona: …"처럼 보였다. 위치를 모르면 메시지만 보여 주게 고쳤다.

## 테스트 결과

- ruff 통과, pytest 초록. 새 테스트: 설정 화면 18개(현재 값 표시, 저장, 보호 값 무시, 게시 시간 비우기, 잘못된 값 11가지, 넣은 값 유지, CSRF, 순수 함수)와 예약 다시 걸기 1개.
- 데모 대시보드에서 1280·390px로 화면을 찍어 가로 넘침이 없는 것, 오류 표시, 저장 후 머리줄 브랜드 이름이 바뀌는 것을 확인했다.

## 배운 것 (신입 개발자용)

1. **설정 화면은 "무엇을 못 바꾸게 할지"부터 정한다.** 드라이런·게시 계정·키는 잘못 바꾸면 실제 계정에 사고가 난다. 화면에 칸을 안 두는 것만으로는 부족하고, 서버가 그 이름의 값을 받아도 무시해야 한다(폼은 누구나 조작할 수 있다).
2. **검사와 저장을 나누면 "전부 아니면 전무"가 쉽다.** 새 설정을 다 만들어 검사한 다음에만 저장하므로, 중간에 틀린 값이 있어도 반쯤 바뀐 설정이 남지 않는다.
3. **설정을 바꿨을 때 그 값을 미리 계산해 둔 곳을 찾는다.** 활동 시간은 매번 읽히지만, 수집·생성 시각은 시작할 때 한 번 계산해 예약해 둔다. 그래서 값만 바꾸면 예약은 옛 시간 그대로다. 이런 "캐시된 계산"은 바뀔 때 다시 계산해 줘야 한다.

## 다음 배치 메모

- 실행 중인 `nsm run`은 옛 코드라 설정 화면이 없다. 머지 뒤 껐다 켜야 한다.

## 이어서 M17b: 댓글 확인 간격

- 선웅제 결정(A): 10분 고정 → 설정값(기본 5분, 3~60분). ADR 0029.
- 확인 주기는 돈이 아니라 계정 위험과 작업 줄 서기의 문제라 최소값을 뒀다. 저장하면 `reschedule`이 reply 예약도 새 간격으로 다시 건다.
- 테스트 3개(트리거 간격, 설정 화면 저장·최소값, 스키마 최소값).
- 배운 것: **"얼마나 자주"를 정할 때는 비용 말고 상대 시스템이 어떻게 보는지도 따진다.** 우리 쪽 비용이 0이어도 플랫폼 입장에서는 같은 계정의 반복 접속이다.
