# 2026-11-21 배치 C54: API 키 저장 때 만료일 처리를 눈에 보이게

## 목표

C53은 새 키를 저장할 때 날짜 칸 값이 옛 메모와 같으면 "미리 채워진 옛 날짜"로 보고 조용히 버렸다. 결과 문구는
"키를 저장했습니다. 다음 작업부터 씁니다"뿐이라 사용자는 만료 알림이 이어지는 줄 안다. 라벨 "만료일(선택)"만으로는
만료 없는 키는 비워 두면 된다는 것도 알 수 없었다.

## 한 일

1. `nsm/app/keys.py` `_saved_msg`: 새 키 저장 문구를 세 갈래로(새 날짜 적음 / 날짜 칸 비움 / 옛 날짜가 그대로 와서 지움).
2. `settings.html`: 날짜 칸 라벨 "만료일(없으면 비움)", 표 아래 안내문에 "만료가 없는 키는 비워 두면 됩니다. 새 키를 저장할 때는
   옛 만료일을 지우니 새 날짜를 같이 적으세요". 환경 변수 키 줄의 날짜 폼은 그대로.
3. 문서: ADR 0077 한 줄, architecture 갱신 줄·상태 표, CHANGELOG, user-guide "만료일 적기" 한 문장. 버전 0.4.46.

## 막힌 것과 해결

- C53 테스트가 라벨 "만료일(선택)"을 확인하고 있어 새 라벨로 바꿨다. 환경 변수 키 줄은 라벨을 그대로 두어 C54 테스트로 지켰다.

- `/code-review` 지적 8건 중 2건 반영(devlog 테스트 결과 채움, `_saved_msg` 직접 테스트). 그대로 둔 6건:
  같은 날짜를 일부러 다시 적은 경우도 버림(C53 동작, 문구가 날짜만 따로 저장하라고 안내), 칸을 비웠을 때 옛 날짜 언급 없음·
  다른 날짜로 바꿀 때 옛 날짜 언급 없음·"를" 조사(요청 문구 그대로), 환경 변수 키 라벨(요청대로 그대로), 테스트 헬퍼 import(C53과 같은 방식).

## 배운 것 3개

1. **조용한 보정은 버그처럼 보인다.** 옳은 판단(옛 날짜 버림)이라도 화면이 말해 주지 않으면 사용자는 반대로 믿는다. 고친 것은 고쳤다고 말한다.
2. **"선택"보다 "언제 비우나"를 적는다.** 선택이라는 말은 비워도 된다는 것만 알려 주고, 비워야 할 때는 알려 주지 않는다.
3. **문구 분기는 함수 하나로 빼면 테스트가 쉽다.** 라우트 안에서 문자열을 조립하면 갈래마다 화면을 다 그려야 하지만, 판단은 작은 함수에 둔다.
