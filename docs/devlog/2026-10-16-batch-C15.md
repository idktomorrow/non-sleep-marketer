# 2026-10-16 배치 C15: 키워드로 원고 만들기, 수집 제외어

## 목표

사용자는 "치이카와 굿즈"가 궁금한데, 원고는 극장판 이야기뿐이었다. 원하는 이야기를 직접 고를 방법이 없어 자동 수집에 기대야 했다.

사용자가 정한 것은 셋이다.

- 키워드 원고와 수집 제외어를 둘 다 만든다.
- 키워드 원고도 평소 자동 게시 규칙을 따른다.
- 쓸 만한 자료가 없으면 만들지 않고 알린다.

## 한 일

- **원인 확인**(대시보드 자료 화면 읽기)
  - 관련 자료 20건 중 굿즈 기사도 있었다. 예: "용산점 10/22 입고 굿즈 리스트", "롯데시네마 먼작귀 굿즈 2종"
  - 원인
    - 한 번에 30건을 주제 6개 × 블로그·뉴스로 나눠 주제마다 2건 남짓만 모은다.
    - "치이카와 굿즈"로 찾아도 극장판 특전 기사가 많다.
    - 원고 주제는 돌아가며 고른다.
- **키워드 원고**(`nsm/engine/keyword.py`)
  - 키워드로 검색 소스(네이버·커뮤니티)만 바로 찾는다. 소스마다 12건이다.
  - 판정할 때 키워드도 관심 주제로 더해 지시한다.
  - 이번에 찾은 안 쓴 관련 자료 중 관련성 높은 3건을 고르고 원문을 읽는다.
  - 평소 원고 함수(`_make_one`)로 만든다. 게시 규칙도 평소와 같다.
  - 자료가 없으면 "찾은 최근 글 N개 중 쓸 만한 자료가 없어 만들지 않음"으로 끝낸다. 생성 비용은 0이다.
- **값을 받는 잡**
  - `runner.ARG_JOBS`, `run_job(..., arg=)`
  - `JobScheduler.run_now(name, arg)`
  - CLI `nsm run --once --job keyword --keyword "…"`
- **대시보드**
  - "오늘"에 "키워드로 원고 만들기" 칸을 두었다(간단·고급 모두).
  - `POST /keyword-draft`: 키워드 2~40자, CSRF를 검사한다.
  - 진행 표시에 "키워드 원고 '치이카와 굿즈'"가 나온다.
  - 잘못된 키워드는 "오늘" 위에 이유를 보여 준다.
- **수집 제외어**(`settings.collect.exclude_words`, 설정 화면 페르소나 칸)
  - 수집할 때 저장하지 않는다(분류 비용 없음). 이미 모은 자료도 원고에 쓰지 않는다(`_pick_material`).
  - 키워드 원고에서는 키워드 안에 든 제외어만 풀린다.
  - 요약 문장에 "제외어가 든 글 N개 뺌"이 붙는다.
- **데모 대시보드:** 키워드 원고 흉내를 더했다(검색·API 없음).
- **문서**
  - ADR 0044(제안)
  - 사용설명서: 설정값 표, 자주 하는 일 2번, 문제 해결 두 줄
  - architecture, CHANGELOG
  - 화면 캡처: `docs/samples/ui/keyword/`

## 막힌 것과 해결

- **이미 모아 둔 글은 ID가 다르다.** 같은 글을 다시 찾으면 새 ID로 들어오고, 저장은 URL 해시 중복으로 막힌다. 그래서 "이번에 찾은 글"을 ID가 아니라 URL 해시로 모으고, 저장소에 `items_by_url_hashes`를 더했다. 이미 모아 둔 글이 다시 나오면 그것도 후보가 된다.
- **원문 읽기 순서.** 평소 원문 읽기는 "관련 자료 중 최근 6건"이라, 키워드로 고른 글이 빠질 수 있었다. `_fetch_bodies(only=…)`로 고른 글만 읽게 했다.
- **"지금 실행" 버튼 목록에 끼면 안 된다.** 잡 이름표(`ko.JOBS`)가 버튼 목록이기도 해서, 키워드 잡은 따로(`ko.ARG_JOBS`) 두고 이름 찾기에만 합쳤다(`ALL_JOBS`).
- **실제 검색은 하지 않았다.** 운영 중인 `nsm run`이 DB와 브라우저를 쓰고 있다. 같은 브라우저를 두 프로세스가 움직이면 서로 방해할 수 있어, 실제 네이버 검색과 Claude 호출은 머지 후 대시보드에서 사용자가 처음 눌러 보는 것으로 남겼다. 엔진은 가짜 소스로, 화면은 데모 대시보드와 Playwright로 확인했다.

## 배운 것 (신입 개발자용)

1. **"같은 것"을 무엇으로 알아보나.** 같은 기사도 모을 때마다 새 ID가 붙는다. 중복은 URL 해시로 막고 있었으므로, "이번에 찾은 글"도 URL 해시로 묶어야 이미 있던 글까지 제대로 찾는다.
2. **새 기능은 기존 길을 다시 쓴다.** 키워드 원고는 원고 만들기 함수, 판정, 원문 읽기를 그대로 쓰고 "무엇을 고를지"만 바꿨다. 그래서 비용 상한, 출처 검증, 보호 모드 같은 안전장치가 저절로 따라온다.
3. **돈이 드는 일은 확인한 뒤에.** 쓸 만한 자료가 있는지 먼저 보고, 없으면 Claude를 부르지 않는다. 사람이 누르는 버튼일수록 "헛돈"이 나가지 않게 순서를 짠다.
