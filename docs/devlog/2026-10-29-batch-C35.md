# 2026-10-29 배치 C35: 설정 화면에서 API 키 넣고 바꾸기

## 목표

대시보드 설정 화면에서 API 키(Claude, Gemini, OpenAI)를 등록·변경·확인·삭제한다. 출발점은 PR #101(S13, 머지 안 함)의 키 화면이다. 값은 keyring에만 두고 어디에도 다시 쓰지 않는다. 저장 뒤 재시작 없이 다음 작업부터 새 키를 쓴다.

## 한 일

- `nsm/app/keys.py`(PR #101 `keys_routes.py`에서 가져와 고침)
  - 순서와 문구를 우리 구조대로: Claude(원고·답글, 필수) → Gemini(분류, 무료 구간) → OpenAI(배경 이미지, 선택·기본 꺼짐). "OpenAI 키 하나면 전부" 문구는 뺐다.
  - 저장(덮어쓰기)·삭제·확인 라우트. 기존 CSRF 검사, 공백 포함·20자 미만 거부, 모르는 키 이름 400.
  - 키 확인 `check_key`: 공급자 모델 목록 GET(생성 없음, 비용 0, 10초). 결과는 연결됨 / 키가 틀렸거나 만료됨 / 한도·결제 확인 필요 / 연결 실패 네 가지만 보여 주고 응답 본문은 싣지 않는다. 저장 직후 자동으로 한 번 확인한다.
- `nsm/config/secrets.py`: `is_env(key)`. 환경 변수 키는 "환경 변수 키라 여기서는 못 지움"으로 보이고 지우기 버튼이 없다. 그래도 지우기를 보내면 지웠다고 하지 않고 안내한다.
- `nsm/runtime.refresh_secret_parts`: 키를 쓰는 부품만(분류기 묶음, 글·이미지 생성기, 자동 진단, 올린 이미지 읽기) 다시 만든다. 대시보드는 저장 뒤 작업 스레드에 이 일을 넣는다.
- 설정 화면 "API 키" 절, "여기서 바꾸지 않는 것"에서 키를 빼고 이유 한 줄.
- ADR 0028 개정 1(제안), 설명서 2절 "API 키 넣고 바꾸기"·화면 표·문제 해결 3행, architecture, CHANGELOG, 스크린샷 `docs/samples/ui/after/14-settings-api-keys.png`. 버전 0.4.13.

## 막힌 것과 해결

- **PR #101의 재생성 방식은 그대로 못 가져왔다.** #101은 어댑터 묶음을 만드는 함수를 새로 짜면서 비용 장부(`CostLedger`)와 공급자 선택까지 바꿨다. 지금 main에는 그 구조가 없다. 지시대로 최소한의 방법을 골랐다. 키를 쓰는 부품 다섯 가지만 같은 공장 함수로 다시 만들고 `ctx`의 칸을 바꿔 끼운다. 플랫폼 어댑터와 수집기는 키를 안 쓰므로 그대로 둔다.
- **언제 바꿔 끼우나.** 대시보드 요청 스레드에서 바꾸면 돌던 잡이 중간에 다른 분류기를 볼 수 있다. 작업 스레드(`scheduler.submit`)에 넣어, 돌던 잡은 옛 부품으로 끝나고 다음 작업부터 새 키를 쓰게 했다.
- **Gemini는 틀린 키에 401이 아니다.** 가짜 키로 세 공급자의 모델 목록을 직접 불러 봤다. Claude·OpenAI는 401이었고 Gemini는 400이었다. 본문에 `API_KEY_INVALID`가 있을 때만 "틀림"으로 보고, 다른 400은 "한도·결제 확인 필요"로 둔다. 본문은 판정에만 쓰고 화면에는 싣지 않는다.
- **환경 변수 키.** `KeyringSecretStore.delete`는 keyring만 지우므로, 환경 변수 키는 지운 뒤에도 그대로 보인다. #101은 지운 뒤 다시 읽어 확인했는데, 그러면 keyring 값은 이미 지워진 뒤다. 지우기 전에 `is_env`로 먼저 확인하고 안내만 한다.
- **셸 heredoc 깨짐.** 테스트 파일에 따옴표가 섞여 bash heredoc이 닫히지 않았다. 파일 쓰기 도구로 바꿨다.

## 배운 것 (신입 개발자용)

1. **비밀 값은 "들어오는 길"만 만든다.** 화면은 키를 받아 저장소에 넣을 뿐, 다시 꺼내 보여 주는 길이 없다. 끝 몇 자리를 보여 주는 것도 길이다. 확인은 "되나 안 되나"로만 답한다.
2. **오류 코드는 공급자마다 다르다.** 같은 "틀린 키"가 어디선 401, 어디선 400이다. 문서보다 가짜 값으로 한 번 불러 보는 것이 빠르고 확실하다. 진짜 키 없이도 할 수 있다.
3. **실행 중에 부품을 바꿀 때는 "언제"가 중요하다.** 같은 값을 바꿔도 작업 중간에 바꾸면 한 작업이 두 부품을 섞어 쓴다. 작업과 같은 줄(작업 스레드)에 바꾸는 일을 넣으면 경계가 깔끔하다.
