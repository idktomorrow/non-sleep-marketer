# 2026-10-19 배치 C25: 인스타그램 답글 전송은 Enter로

## 목표

C22(입력창 재클릭 제거)를 머지하고 다시 켠 뒤에도(17:03 재시작) 21:05 답글이 또 "@작성자 …" 새 댓글로 올라갔다. 같은 코드로 16:48 답글은 댓글 아래에 달렸다. 같은 코드가 다른 결과를 내는 원인을 찾는다.

## 한 일

- **입력창 관찰(전송 없음)**: "답글 달기"를 누르는 순간(0ms) 인스타그램이 입력창 요소를 새것으로 갈아 끼우고 "@작성자 "를 채우며 초점을 준다. 그 뒤 2.5초 동안 DOM·속성·초점에 변화가 없다. 즉 "답글 대상"은 화면에 흔적이 없는 내부 상태다.
- **남은 변수 = 전송 방법.** 지금은 "게시" 버튼을 마우스로 누른다. 마우스 클릭은 mousedown 순간 입력창의 초점을 빼앗는다(blur). 인스타그램이 blur에서 답글 대상을 지우는 처리와 click 처리의 순서가 매번 달라, 어떤 때는 답글(16:48)·어떤 때는 새 댓글(21:05)이 된 것으로 봤다. C22 실험(A·D)은 둘 다 우연히 답글 쪽이었다.
- **고침**: `insertText` 뒤 **Enter**로 보낸다. Enter는 입력창 안에서 처리돼 초점이 움직이지 않는다. 6초 안에 입력창이 비지 않으면(Enter가 안 먹음) 그때만 "게시"를 누른다.
- **실험**: 사용자가 개인 계정으로 단 테스트 댓글 아래에 실제 어댑터(`InstagramAdapter.reply`)로 2회 보냈다. 둘 다 댓글 아래 "답글 N개"로 달렸고 새 댓글로는 보이지 않았으며, 어댑터도 `seen:` 표지(확인됨)를 돌려줬다. 테스트 답글은 지웠다.
- **테스트**: 답글 스크립트가 Enter를 먼저 쓰고, 입력창이 비워졌는지 확인한 뒤에만 "게시"로 가는지 구조 검사.

## 막힌 것과 해결

- **C22가 틀린 건 아니었지만 충분하지 않았다.** 재클릭은 확실히 답글 대상을 지웠고(실험으로 확인), 그걸 없앤 뒤에도 "게시" 클릭의 blur가 같은 일을 가끔 일으켰다. 같은 코드가 다른 결과를 내면 "경쟁(race)"을 의심해야 한다는 걸 늦게 떠올렸다.
- **실험 대상.** 남은 댓글이 모두 실제 팔로워 것이라 거기에 실험하지 않았다. 사용자에게 테스트 댓글을 다시 부탁했고, 운영 프로그램이 30분 안에 그 댓글에 먼저 답할 수 있어 바로 진행했다.

## 배운 것 (신입 개발자용)

1. **같은 코드, 다른 결과 = 경쟁 조건.** 재현이 들쭉날쭉하면 "무엇이 동시에 일어나는가"를 본다. 여기서는 마우스 클릭의 blur 처리와 click 처리가 경쟁했다.
2. **마우스 클릭은 공짜가 아니다.** 버튼을 누르는 건 "focus 이동 + mousedown + mouseup + click"이다. 입력 상태가 초점에 묶여 있으면 키보드 전송(Enter)이 더 안전하다.
3. **고친 뒤에도 운영 데이터를 본다.** C22 뒤 "고쳐졌다"고 믿을 수 있었지만, 로그의 "확인하지 못함" 경고와 사용자 화면이 아니라고 말해 줬다. 고침의 증거는 테스트 통과가 아니라 운영 결과다.
