# 2026-10-13 배치 #43: 블로그 원고 생성 생략

## 목표

네이버 블로그를 게시하지 않는데 원고마다 만들던 블로그 글(1,500~2,500자)을 그만 만들어 Claude 비용을 줄인다. 함께 선웅제의 운영 결정(아래)을 문서에 반영한다.

## 한 일

- `ClaudeTextGenerator(include_blog=...)`: 꺼져 있으면 구조화 출력 스키마(`llm_schema`)와 시스템 프롬프트에서 블로그 칸을 뺀다. 결과의 `blog_title`·`blog_markdown`은 빈 문자열.
- `make_text_generator`가 `enabled_platforms`에 `naver_blog`가 있는지로 정한다.
- 검토 상세: 블로그 원고가 비어 있으면 그 칸을 숨긴다.
- 운영 결정 기록
  - @nonsleepmarketer는 테스트 계정이자 실제 운영 계정이다(`docs/day1-verification.md`).
  - OpenAI 키를 넣지 않고 배경 이미지 자동 생성도 끈다. 이 PC의 설정(`~/.nsm/config.yaml`)에서 `image_generation: off`로 바꿨다(저장소 밖).
  - 팀원 작업(S-β·S-γ·S8)은 이번 범위에서 뺀다.
- ADR 0026(채택).

## 막힌 것과 해결

- 동결 계약: 필드를 지우면 두 사람 합의가 필요하다. 필드는 두고 빈 값을 채우는 쪽으로 계약을 건드리지 않았다.

## 테스트 결과

- `uv run ruff check .`·`ruff format --check .` 통과, `uv run pytest` 초록. 새 테스트 2개(블로그 칸을 요청하지 않음, 설정에 따라 켜고 끔).

## 배운 것 (신입 개발자용)

1. **구조화 출력 스키마는 비용이다.** 모델은 스키마의 필수 칸을 모두 채워야 하므로, 쓰지 않는 칸도 출력 토큰으로 돈이 든다. 필요 없는 칸은 요청 단계에서 빼야 한다.
2. **동결 계약을 피해 가는 방법.** 데이터 모델을 바꾸지 않고도 "값을 비워 두는" 방식으로 동작을 바꿀 수 있다. 계약 변경은 비용이 큰 일이라, 작은 개선은 계약 안에서 해결하는 게 먼저다.
3. **설정에서 동작을 끌어낸다.** "블로그를 쓸지"를 새 설정으로 만들지 않고 이미 있는 `enabled_platforms`에서 끌어냈다. 같은 사실을 두 곳에 적으면 언젠가 서로 어긋난다.
