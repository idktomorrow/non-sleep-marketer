## 목표
설정의 '관심 주제'에 적은 주제(예: 치이카와, 한국 아이돌)가 수집 → 후보 → 원고·대본 → 그림 계획까지 그대로 이어지게 한다. 커피 예시 페르소나나 견본 캐릭터가 다른 분야 콘텐츠에 새지 않게 한다.

## 한 일

- **밈 사례 탐색**: `adapters/sources/meme_discovery.py`(네이버 블로그·카페·커뮤니티 공개 검색, X 미수집), `domain/meme_discovery.py`(A 최근 확산/B 지속 형식/C 근거 부족/D 창작, 작성자 수·게시·관측 시각, 반응 수치 null). 같은 실행에서 같은 주제는 한 번만 탐색.
- **밈 경로**: 주인공은 고른 캐릭터만. 없으면 대본까지 만들고 후보만 제안(`suggested_character`) → "캐릭터·참조 필요"로 대기. 의미상 같은 농담은 모델 표시(`same_as_recent`)로 제외, 실존 인물 행동 지어내기 금지 문구.

- **실검증에서 찾아 고친 것**: OpenAI 분류기(`adapters/classifier/openai.py`), 같은 사건 모델 확인(`_same_event_as_made`), 네이버 결과 항목 날짜(`drivers/base.LINK_CONTEXT_JS`).

## 막힌 것과 해결
- **밈이 커피 "루나" 이야기였던 원인**: `meme_request`가 페르소나 이름·인물상을 주인공으로, 관심 주제 전체를 소재로 넘겼고(검증 스크립트가 커피 픽스처 페르소나를 씀), 그림은 견본 흰 스티커를 참조로 썼다. 프롬프트 예시도 커피였다 → 주제 하나·고른 캐릭터만·중립 예시.
- **OpenAI 키만 있으면 정보 추천 0건**: 낱말 규칙 분류기가 관련성을 최대 0.7(치이카와)·0.5(한국 아이돌)로 줘 문턱 0.8을 못 넘었다. 넓은 주제는 글에 글자 그대로 나오지 않는다 → OpenAI 분류기. 처음엔 추론 강도 `none`을 넣었다가 모델이 거절(HTTP 400)해 글 생성 설정을 따르게 했다.
- **모든 자료가 "날짜 확인 필요"**: 네이버 새 결과 화면은 "2시간 전"이 링크 블록 두 단계 위에 있다. 실제 페이지 DOM을 찍어 확인하고 항목 칸까지만 올라가 날짜를 붙였다(목록 경계 안). 고친 뒤 23건 모두 날짜를 읽음.
- **같은 사건 두 번**: "200만 눈앞 4DX"와 "200만 육박 흥행"이 제목 낱말 겹침이 낮아 둘 다 추천됐다 → 모델에 같은 사건인지 물어 건너뜀(재실행에서 1건 제외).

## 배운 것
1. **입력이 둘이면 사람은 어느 쪽이 진짜인지 모른다.** 관심 주제 칸과 분야 묶음 버튼이 같은 일을 하면 헷갈림만 남는다. 기능을 더하기 전에 이미 있는 입력이 끝까지 이어지는지부터 본다.
2. **가짜 분류기로 통과한 테스트는 실제 모델 선택을 검증하지 않는다.** 테스트는 모두 초록이었지만, 키 조합이 "OpenAI만"일 때 분류기가 낱말 규칙으로 떨어지는 경로는 실제로 돌려 보고서야 보였다.
3. **긁어 오는 화면은 바뀐다.** 날짜를 못 읽는 것은 코드가 아니라 상대 화면이 바뀐 탓이었다. 추측하지 말고 실제 페이지의 DOM을 찍어 위치를 확인한 뒤 고친다.
