## 막힌 것과 해결

- **repl은 내 파일을 못 읽음**: Aside 앱의 Can view 설정은 repl에 적용되지 않았다("Path escapes Project and session roots"). 대신 repl 안의 `fetch()`가 127.0.0.1에 닿는 것을 확인했다. 그래서 이미지를 일회용 로컬 서버로 넘긴다(ADR 0020). 덕분에 Aside에 `~/.nsm` 읽기 권한을 줄 필요가 없어졌다.
- **아이콘 이름이 aria-label이 아님**: 좋아요·답글·더 보기 아이콘은 SVG `<title>`에 이름이 있었다. 왼쪽 메뉴에도 같은 이름 아이콘이 있다. 그래서 가운데 칼럼(`칼럼 본문`) 안에서만, `<title>` 또는 `aria-label`로 찾는 도우미를 만들었다.
- **답글 칸에 게시 버튼이 없음**: 인라인 입력칸에는 게시 버튼이 보이지 않았다. 댓글 페이지의 답글 아이콘을 누르면 열리는 "답글" 창을 쓴다. 그 창에 인용된 작성자가 맞는지 확인한 뒤 쓴다.
- **내 답글 지우기가 실패**: 답글 페이지에는 원글 맥락의 메뉴가 먼저 나온다. 메뉴를 차례로 열어 "삭제"가 있는 것(내 글)을 고른다.
- **중복 게시 위험**: 게시 버튼을 누른 뒤 시간 초과나 주소 찾기 실패가 오류로 돌아가면 엔진이 재시도해 두 번 올라간다. 게시 전에 같은 글이 이미 있는지 보고, 게시 후에는 주소를 못 찾아도 성공으로 기록하게 했다.
- **댓글 ID의 `/`**: 대시보드는 `플랫폼:ID`를 URL 경로에 넣는다. 처음 정한 `작성자/코드`는 답글 보내기 경로를 깨뜨린다. `작성자:코드`로 바꿨다.
- 막 올린 글의 인사이트는 "—"(아직 없음)라서 조회수가 비어 있을 수 있다. 계약 테스트에서 허용했다.

## 배운 것 (신입 개발자용)

1. **외부 값은 코드가 아니라 데이터로 넘긴다**: 게시 문구를 JS 소스에 이어 붙이면 따옴표 하나로 스크립트가 깨지고, 악의적인 문구면 코드가 실행된다. SQL 인젝션과 같은 원리다. 고정 스크립트에 base64 JSON 한 덩어리만 넣으면 문구가 무엇이든 데이터로만 읽힌다.
2. **재시도가 있으면 멱등성을 먼저 생각한다**: "실패하면 다시"는 안전해 보이지만, 실제로는 성공했는데 응답만 못 받은 경우가 있다. 그러면 재시도가 중복 게시가 된다. 다시 하기 전에 이미 됐는지 확인하는 단계(멱등 키: 여기서는 본문 고유 문구)를 두는 것이 외부 시스템을 다룰 때의 기본이다.
3. **화면 자동화는 실제 화면에서 검증한다**: 문서도 API도 없는 웹 화면은 추측한 선택자가 거의 다 틀렸다(aria-label, 게시 버튼 위치, 메뉴 순서). 읽기 전용 탐색 → 시험 글 하나 → 계약 테스트 순서로 실제 화면에서 확인하고, 그 결과를 테스트로 남겨야 화면이 바뀌었을 때 바로 알 수 있다.
