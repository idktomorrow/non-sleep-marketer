# 2026-10-30 배치 R3: 문서 질문 화면

## 목표

대시보드에서 질문하면 찾은 문서 조각만 근거로 Claude가 답하는 화면(R1 색인 → R2 검색 → R3 묻고 답하기). 운영 DB는 벡터가 채워지는 중이라(모레 저녁 완료) 측정은 화면에서 다시 할 수 있게 한다.

## 막힌 것과 해결

- **첫 질문의 답이 비었다.** 실제 화면에서 "보호 모드가 뭐야"를 물으니 근거는 찾았는데 "답변이 비어 있음"이었다. 빈 답이면 한 번 다시 부르게 해도 또 비었다.
  - 같은 근거로 직접 불러 응답을 보니 `stop_reason=max_tokens`, 블록은 `thinking` 하나였다. haiku가 생각에 출력 한도 700토큰을 다 썼다.
  - "429가 나면 어떻게 돼"의 답이 "플랫폼 멈춤이"에서 끊긴 것도 같은 원인이었다.
  - 분류기처럼 생각을 끄고 부르게 했다(`thinking: disabled`). 생각 끄기를 받지 않는 모델(E2에서 본 생성 모델)로 바꾸면 끄지 않고 출력 한도 4,000으로 다시 부른다. 한도에서 잘린 답에는 "…(답이 길어 잘렸습니다)"를 붙인다.
  - 처음 직접 불렀을 때는 생각 없이 바로 답해서 재현되지 않았다. 같은 입력이라도 생각을 할지는 그때그때 다르다.
- **오늘 Gemini 한도가 거의 없었다.** R2 측정에서 하루 한도를 거의 다 써(996건) 이번엔 질문 4건만 쓸 수 있었다. 그래서 다음처럼 했다.
  - 실제 질문 3개(+ 고친 뒤 1개 다시)는 화면에서 던졌다.
  - 측정 버튼은 "오늘 남은 한도가 1건이라 20개를 다 잴 수 없습니다"로 거절하는지 확인했다(장부에 오늘 실제 사용량을 반영해서).
  - 지금 상태의 표는 R2에서 **같은 DB로** 잰 점수를 측정 기록으로 옮겨 화면에 보였다.
  - 고친 뒤의 답은 화면이 아니라, 저장된 근거 조각으로 Claude를 직접 불러 확인했다(Gemini 없이).
- **`similar`는 DuckDB 예약어**라 표 정의가 깨졌다. 열 이름을 `similar_titles`로.
- **같은 시각에 저장된 질문의 순서가 들쭉날쭉했다**(고정 시계 테스트). `rowid DESC`로 순서를 고정.

- **코드 리뷰 10건 중 9건 반영.**
  - ① 하나의 답변기를 여러 요청이 같이 써서 실패 비용이 섞일 수 있었다 → 비용을 오류와 함께 넘김.
  - ② 질문 임베딩이 실패하면 장부에 안 셌다(막힌 시도도 한도를 씀) → 셈.
  - ③ 측정이 중간에 멈추면 일부 질문으로 만든 표를 저장했다 → 저장하지 않고 안내, 시도는 셈.
  - ④ 조각의 따옴표까지 `&quot;`로 바꿔 Claude가 그대로 옮길 수 있었다 → 본문은 <, >, &만 바꿈.
  - ⑤ 키를 바꿀 때 옛 Claude 연결을 안 닫았다 → 닫음.
  - ⑥ 생각 끄기를 거절하는 모델이면 매번 한 번씩 헛호출했다 → 한 번 알면 기억.
  - ⑦ 동시에 들어온 질문이 하루 상한을 넘을 수 있었다 → 한 줄로 처리.
  - ⑧ Claude가 "문서에 그 내용이 없습니다"라고 해도 근거 있음으로 기록됐다 → 근거 없음으로.
  - ⑩ 화면과 `nsm ask`가 검색·장부를 따로 했다 → `budgeted_search` 하나로.
  - 남긴 것 ⑨(측정 질문 파일을 패키지 안으로): 이 프로그램은 저장소를 받아 `uv run`으로만 돌리고, 파일 위치는 R2에서 정한 `tests/fixtures/rag/questions.yaml`이라 그대로 둔다.

## 배운 것 (신입 개발자용)

1. **"모른다"는 싸게, 먼저.** 근거가 없으면 모델을 부르지도 않는다. 가장 싼 거절은 부르지 않는 것이고, 지어낼 기회도 같이 없앤다. 모델의 규칙("없으면 없다고 하라")은 그 뒤의 두 번째 문이다.
2. **모델 출력에 "생각"이 섞일 수 있다.** 같은 모델·같은 입력인데 어떤 때는 바로 답하고 어떤 때는 생각에 한도를 다 쓴다. 출력 한도를 작게 둘 때는 생각을 끄거나, 한도에서 멈춘 답(`stop_reason=max_tokens`)을 잘렸다고 표시해야 한다.
3. **모델의 답도 HTML이 아니다.** 화면에 바로 넣으면 `<script>`가 그대로 실행될 수 있다. 템플릿의 자동 이스케이프에 맡기고, 테스트로 한 번 확인해 둔다.
