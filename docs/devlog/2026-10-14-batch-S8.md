# 2026-10-14 배치 S8: 카드 디자인 스타일 (clean · photo · illust)

## 목표

이슈 #34(S8)를 끝낸다. 소유권은 ADR 0034대로 메인이다. 배치 지시로 정해진 것은 다음과 같다.

- AI 배경 이미지(OpenAI Images)는 유료라 이번 범위에서 뺀다. 세 스타일 모두 코드로 그린 배경만 쓴다.
- 기존 이미지 어댑터와 `image_generation` 설정은 지우지 않고 기본값만 off로 바꾼다.
- 원고별 스타일(덱 JSON `style`)은 계약 동결이라 ADR 초안만 남긴다.

  - `photo`: 주 색을 아주 어둡게 깐 꽉 찬 배경, 고리·사선 띠·점 무늬, 아래쪽 어둡게, 줄마다 형광펜 상자 제목, 흰 말풍선(부제·본문 문단·마무리 문구). 배경 사진이 있는 장은 `.has-bg`(사진 + 어두운 그라디언트)가 뼈대다.

  - 구조: `<body class="style-…">` + `photo.css`·`illust.css` + 장식 매크로(`deco`, `mascot`). 글자·표기 슬롯 HTML은 세 스타일이 같다.

  - 대시보드 설정 화면 → 브랜드 → "카드 스타일" 선택. 칸이 없는 옛 폼은 지금 값을 지킨다(라우트 테스트 그대로 통과).

## 막힌 것과 해결

- **동결된 `Brand`에 `card_style`을 어디 둘까.** `brand.card_style`은 설정 YAML 경로라 `AppConfig.brand`에 있어야 한다. 그런데 `Brand`는 동결 모델이고 생성기 포트도 쓴다. 그래서 설정 쪽에 `BrandSettings(Brand)` 하위 클래스를 만들었다.
  - 마법사·테스트가 도메인 `Brand`를 넘겨도 받도록 `AppConfig`에 변환 검사기를 두었다.
  - 마법사는 기존 스타일을 지키도록 고쳤다.
- **렌더 포트에 스타일 인자가 없음.** `render(deck, out_dir)`는 동결이다. 렌더러 생성자에 스타일 "함수"를 넘겨 렌더 때마다 읽게 했다. 설정 저장이 `ctx.config`를 바꾸므로 그대로 따라온다.
- **노란 브랜드 색에서 photo 배경이 밝아짐.**
  - 처음에는 HLS 밝기를 고정(0.12·0.26)했다. 그런데 노랑은 같은 밝기에서도 훨씬 밝게 보여 흰 글자 대비가 떨어졌다.
  - 흰 글자 대비가 기준(14·8·5)에 닿을 때까지 어둡게 내리는 함수를 만들었다. 두 방법 중 더 어두운 쪽을 쓴다.
  - 테스트: 노랑·주황·초록·남색·흰색에서 대비를 검사한다.
- **형광펜 상자 여백 때문에 "5"가 혼자 줄바꿈.** 상자 여백 0.16em → 0.1em, photo 표지 제목 자간을 조금 좁혀 한 줄에 들어가게 했다(글자 크기는 그대로).
- **코드 리뷰(서브 에이전트)와 실제 사진 렌더에서 나온 것.**
  - illust에서 배경 사진이 있는 장에도 언덕·캐릭터를 그려, 흰 페이지 번호가 밝은 언덕에 묻혔다. 배경 사진이 있는 장은 장식을 그리지 않게 고쳤다(photo와 같은 규칙).
  - 같은 경우 번호 카드가 흰 바탕에 흰 글자였다. 사진 장에서도 스티커 카드는 진한 글자로 고정했다.
  - 회귀 테스트를 더했다. 실제 렌더에서 "칠한 상자 안 글자 ↔ 상자 바탕" 대비를 세 스타일 × 코드 배경·사진 배경으로 잰다. 수정을 빼면 실패하는 것을 확인했다.
  - 스타일을 바꾸면 게시 대기 중인 원고도 올릴 때 새 스타일로 다시 그린다(캐시 지문에 스타일 포함). 넘치면 기존 규칙대로 검토로 돌아가고 알림이 뜬다. 설정 화면 안내와 사용설명서에 적었다.
- **레퍼런스 확인.** 검색 결과만으로는 디자인을 알 수 없었다. 그래서 Aside 브라우저로 각 계정의 최근 게시물을 열어 이미지를 직접 봤다(읽기 전용). 이미지는 scratchpad에만 두었다. Dribbble은 자동 조회가 막혀 작가 설명 기준이라고 적었다.

## 배운 것 (신입 개발자용)

1. **동결된 계약을 안 깨고 기능 더하기.** 공유 모델(`Brand`)과 포트(`render`)를 바꾸면 모든 호출부와 상대 팀원 코드가 흔들린다. 대신 경계 바깥에 붙인다.
   - 설정 쪽 하위 클래스(`BrandSettings`)를 만든다.
   - 생성자 인자(스타일 함수)로 받는다.
   - 계약을 바꿔야 하는 부분(원고별 스타일)은 ADR 초안으로 미뤄 합의를 받는다.
2. **"값" 대신 "값을 읽는 함수"를 넘기면 설정 변경이 바로 반영된다.** 렌더러가 시작할 때 스타일 문자열을 받으면, 대시보드에서 바꿔도 재시작 전까지 옛 값이다. `lambda: ctx.config.brand.card_style`을 받으면 렌더할 때마다 지금 값을 읽는다. 캐시 지문에도 같은 값을 넣어야 옛 그림이 재사용되지 않는다.
3. **색의 "밝기"는 눈이 느끼는 밝기와 다르다.** HLS 밝기가 같아도 노랑은 남색보다 훨씬 밝게 보인다. 글자가 읽히는지는 WCAG 대비(상대 휘도)로 재야 한다. 그래서 "대비 기준을 넘을 때까지 어둡게"처럼 결과로 조건을 건다.
