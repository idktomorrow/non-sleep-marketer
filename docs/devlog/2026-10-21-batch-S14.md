## 목표
레퍼런스의 생성 요소 둘(메모 옆 보조 캐릭터, 2컷 만화)을 덱 계약과 렌더러로 표현하고, 밈을 정보 원고와 **다른 경로**로 만들며, 하루 "정보 N + 밈 M"을 슬롯 상태 기계로 계획·추적한다. 실제 그림 제작은 S15.

## 막힌 것과 해결
- 스티커가 메모 상자 테두리에서 잘림 → `.content`가 overflow:hidden이라 스티커가 있는 상자만 `overflow: visible`(넘침 판정은 scrollHeight라 영향 없음) + 상자 위 여백.
- 긴 라벨·말풍선이 겹침 → 라벨 폭 52%·말풍선 38%, 왼쪽 말풍선은 아래로. 실측 테스트(컷 안·서로 안 겹침·라벨 ≥40px).
- 밈 중복 판정에서 "월급과"·"월급"이 다른 토큰 → 밈 비교에만 조사 제거(`meme_tokens`), 정보 클러스터링은 그대로.
- 슬롯 2개에 아이디어가 다르면 둘 다 채우는 게 맞다 → "전부 중복이면 빈 슬롯" 테스트는 아이디어 하나로.

## 배운 것 3개
1. "빈 값"과 "없음"은 계약에도 들어간다: `ai_slides: None`(레거시)과 `[]`(AI 없음)을 구분해야 실제 사진 장에 AI 표기가 붙지 않는다.
2. 상태 기계는 **실패에서 어디로 돌아가는지**까지 적어야 완결이다(원고 실패 → planned, 그림 실패 → images_pending·원고 유지).
3. 제목·말풍선 같은 절대 배치 글자는 `scrollHeight` 넘침 판정에 안 잡히므로, 길이 제한(계약)과 실측 테스트(컷 안·겹침 없음)로 막는다.
