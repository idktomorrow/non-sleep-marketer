# 2026-11-26 배치 C59: 분류기 폴백을 묶음(10건) 단위로 + Claude 분류기 묶음 호출

## 목표

분류기 폴백이 앞 묶음의 성공한 판정을 버리지 않게 한다. Claude로 넘어갔을 때 건마다 한 번씩 부르던 것을 10건 묶음 한 번으로 줄인다. 목적은 시간 단축이 아니라 호출 수·비용 정리와 폴백의 정확성이다.

## 한 일

- `nsm/adapters/classifier/__init__.py`(ADR 0079)
  - `CHUNK = 10`을 두었다. 값은 `gemini.BATCH`와 같고, 같은지는 테스트로 고정한다.
  - `FallbackClassifier.classify_many`가 `texts`를 10건씩 잘라 묶음마다 `_call`을 부르고 이어 붙인다. 빈 목록이면 호출하지 않는다.
- `nsm/adapters/classifier/claude.py`
  - `classify_many`: 0·1건은 기존 단건 경로다. 2건 이상은 `BATCH = 10`건씩 `_batch`로 보낸다.
  - `_batch`
    - 번호를 매긴 나열로 보내고 건당 `TEXT_LIMIT = 1500`자다.
    - 스키마 `_batch_schema`는 `items[{i,label,confidence}]`이고, 모든 object에 `additionalProperties: false`를 건다.
    - `max_tokens=2048`, thinking 끔, effort low다. 비용은 묶음마다 `classify_many`로 기록한다.
    - refusal·max_tokens는 단건과 같이 `AdapterError`를 낸다.
  - `_parse_batch`: 번호가 다 있고 라벨이 허용 목록 안일 때만 순서대로 매핑한다. 신뢰도는 0~1로 자른다.
  - 묶음 응답이 깨지면(JSON 파싱 실패·번호 누락·비허용 라벨·텍스트 블록 없음) 경고 한 줄을 남기고 그 묶음만 단건 `classify`로 다시 판정한다. 단건이 내는 예외(API 장애·refusal)는 그대로 올린다.
- 테스트(`tests/unit/test_classifiers.py`)
  - 15건(10+5)에서 뒤 묶음만 실패: 앞 10건은 첫 분류기 판정이고, 둘째 분류기는 5건으로 한 번만 불리며 `state.index == 1`이다.
  - 빈 목록이면 호출이 없다. `CHUNK == gemini.BATCH == claude.BATCH`이다.
  - Claude 13건(10+3)
    - `create`가 2번 불리고, 번호가 뒤섞여 와도 `i`로 맞춘다.
    - 신뢰도 1.3은 1.0으로, -0.2는 0.0으로 자른다. `record_cost`가 2번 불린다.
    - 스키마 모양과 1500자 자르기를 확인한다.
  - 깨진 응답 다섯 가지(번호 누락·비허용 라벨·깨진 JSON·텍스트 없음·배열): 예외 없이 `create`가 1 + 4번 불리고, 결과 길이와 순서가 맞는다.
  - 묶음 refusal은 예외다. 0건과 1건은 단건 스키마로 부른다.

## 막힌 것과 해결

- Python 수정 스크립트를 bash heredoc으로 넘겼더니 문자열 안의 `\\n`이 실제 줄바꿈으로 들어가 `SyntaxError`가 났다. 그 몇 줄만 `chr(92)`로 만든 스크립트로 다시 썼다.
- 기록되는 분류기 이름 섞임은 이번에 고치지 않았다. `collect.py`가 `classify_many` 뒤 `FallbackClassifier.name`을 읽어서, 뒤 묶음에서 넘어가면 앞 묶음까지 `claude`로 적힌다. ADR 0079에 알려진 한계로 적었다.

- 코드 리뷰 지적 반영
  - 번호가 겹치거나 정수가 아닌(`true`·`1.0`) 묶음 응답도 깨진 것으로 보고 단건으로 다시 판정한다(테스트 2개 추가).
  - `CHUNK` 주석의 이유를 실제 이유로 고쳤다. 순환 import가 아니라, gemini(httpx)를 키가 있을 때만 늦게 가져오기 때문이다.
  - ADR에 더 적은 것
    - 뒤 묶음이 낱말 규칙으로 갈 때의 한계
    - 배치 지시대로 둔 것: 묶음 max_tokens는 예외, 단건 재시도 중 예외는 그대로, 마지막 1건은 단건 경로
    - ADR 상태는 `채택`으로 두었다. 결정이 전부 배치 지시에서 왔기 때문이다.
  - 그대로 둔 것(배치 지시와 충돌)
    - 건당 1500자 제한
    - 묶음 코드가 Gemini와 비슷하게 겹치는 것(공통 모듈은 다음에)

## 배운 것

1. **폴백의 단위는 실패의 단위와 맞춰야 한다.** Gemini는 10건씩 따로 요청을 보내는데, 폴백은 "전체"를 한 덩어리로 다뤘다. 그래서 일부만 실패해도 전부를 다시 했다. 감싸는 쪽이 안쪽과 같은 크기로 자르면 성공한 만큼은 남는다.
2. **"응답이 이상하다"와 "서비스가 안 된다"는 다르게 다뤄야 한다.** 폴백 사슬은 예외를 "이 분류기는 지금 못 쓴다"로 읽고 30분 동안 다음 것으로 넘어간다. 묶음 JSON 한 번 깨진 것을 예외로 올리면 그 신호가 과장된다. 그 자리에서 단건으로 고쳐 끝내고, 진짜 장애만 위로 올린다.
3. **느린 원인을 먼저 재고 고친다.** "Claude로 넘어가서 느렸다"는 짐작은 로그 시각으로 보면 틀렸다. Claude 23번은 30초였고 Gemini 재시도 대기가 6분이었다. 그래서 이번 변경의 이득은 시간이 아니라 호출 수·비용·정확성이라고 문서에 적었다.
