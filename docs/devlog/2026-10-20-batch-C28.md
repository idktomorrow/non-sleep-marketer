# 2026-10-20 배치 C28: "오늘" 화면 레이아웃 다듬기

## 목표

사용자 화면 캡처: 왼쪽 "오늘 해야 할 일" 칸이 너무 넓고, 오른쪽 "게시 대기(승인됨)" 칸의 "다음 게시 인스타그램 08:00 · 스레드 08:00"이 "스레 / 드"로 끊겨 보였다.

## 한 일

- `.today` 두 칸 비율 1.6:1 → 1.25:1. 오른쪽 숫자 칸들이 넓어진다.
- 화면 전체 `word-break: keep-all`(어절 단위 줄바꿈). 근본 원인은 한국어 기본 줄바꿈이 음절 단위라는 것이라, 한 칸만 고치지 않고 전체에 적용했다. "다음 게시"의 플랫폼+시각은 `inline-block; nowrap`으로 한 덩어리(한 줄에 맞으면 한 줄, 안 맞으면 플랫폼 사이에서만 줄바꿈).
- `.stats` 칸을 `minmax(0, 1fr)`로. 그리드 칸은 기본 최소 폭이 내용 폭이라 `nowrap` 글이 길면 칸이 밖으로 삐져나온다.
- 버전 0.4.3.

## 막힌 것과 해결

- 처음엔 플랫폼마다 `display:block`으로 세 줄을 만들었다. 리뷰: 넓은 화면에서도 세 줄이 되고 옆 칸과 높이가 안 맞으며, `nowrap`이 그리드 칸을 밀어낼 수 있다. 어절 단위 줄바꿈(`keep-all`)을 화면 전체에 두고, 묶음은 `inline-block`으로 바꿨다.

## 테스트 결과

- ruff, pytest(대시보드 테스트 포함) 통과. "다음 게시" 문구 테스트는 그대로 만족.
- 실제 화면은 머지 뒤 사용자가 확인(`nsm run` 재시작 필요, 정적 파일은 내용 해시 URL이라 캐시 문제 없음).

## 배운 것 (신입 개발자용)

1. **한국어 줄바꿈의 기본값은 음절 단위다.** 브라우저는 "스레드"를 "스레/드"로 끊어도 된다고 본다. `word-break: keep-all` 한 줄이면 어절 단위가 되고, 이건 한 칸이 아니라 화면 전체에 두는 게 맞다. "인스타그램 08:00"처럼 띄어쓰기가 있어도 한 덩어리여야 하는 것만 `nowrap`으로 묶는다.
2. **그리드 칸의 최소 폭은 내용 폭이다.** `1fr`은 "남는 폭을 나눠 갖되 내용보다 작아지지는 않는다"라서, 안 끊기는 글이 길면 칸이 밖으로 삐져나온다. `minmax(0, 1fr)`로 바닥을 0으로 내려야 진짜로 나눠 갖는다.
3. **작은 UI 수정도 버전을 올린다.** 바닥글 번호로 "다시 켰는지"를 알 수 있어야 사용자가 캡처를 보내 줄 때 어느 코드인지 바로 안다.

## 다음 배치 메모
