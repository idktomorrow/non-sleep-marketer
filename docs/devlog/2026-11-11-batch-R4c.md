# 2026-11-11 배치 R4c: "우리 글"의 카드 문구를 원고당 한 번만 색인

## 목표

R4b 재측정([devlog](2026-11-11-batch-R4b.md), ADR 0065 개정 1)에서 문제가 하나 드러났다. `PostsSource`는 같은 원고의 `## 카드 문구` 절을 인스타·스레드 두 문서에 똑같이 넣는다. 그래서 카드 문구 140조각이 70쌍 모두 같은 글이었다. 질문 5개의 상위 25자리 중 15자리를 같은 원고의 두 벌이 차지했다.

이 배치는 카드 문구를 원고당 문서 하나(`posts/<content_id>/cards`)로 옮긴다. 효과는 같은 질문 5개로 다시 잰다. 검색 결과를 원고당 묶는 정리(본문 두 벌 문제)는 이 배치 범위가 아니다(`search.py`는 그대로).

## 한 일

- **`nsm/rag/sources_db.py`**
  - `PostsSource.documents()`: 플랫폼 문서 `posts/<cid>/<platform>`에서 `## 카드 문구` 절을 뺐다. 제목·플랫폼·게시·주소·주제·본문·댓글은 그대로다.
  - 원고를 처음 만날 때 카드 문서 `posts/<cid>/cards`를 하나 낸다. 게시된(published) 플랫폼이 하나라도 있는 원고만이고, 카드 줄이 비면 내지 않는다. 한 플랫폼에만 올린 원고도 카드 문서는 하나다.
  - `_cards_markdown(gen)`: 카드 문서는 `# <제목>`, 빈 줄, `## 카드 문구`, `- 카드 줄`들만 둔다.
    - 메타 줄(플랫폼·게시·주소·주제)을 넣지 않는 이유: chunker가 제목 절을 따로 조각내 본문 없는 메타 조각이 원고마다 생긴다. 카드 조각의 글도 달라진다.
    - 지금 구조면 조각은 "우리 글 > <제목> > 카드 문구" 절 하나에서만 나온다. 예전 플랫폼 문서의 카드 조각과 글자까지 같다.
  - 카드 문서 제목은 `post_title(gen, "")`로 본문 없이 구한다. 블로그 제목 → 카드 표지 순이고, 둘 다 없으면 "제목 없음"이다. 플랫폼마다 본문 첫 문장으로 제목이 갈리지 않게 하려는 것이다.
  - `label`은 `POSTS_LABEL` 그대로라 화면 배지는 "우리 글"이다. 경로 끝 `cards`는 상수 `CARDS`로 둔다.
  - 생성 JSON 파싱을 `_parse`로 뺐다. 객체가 아니면 `{}`로 본다.
- **경로를 읽는 곳**
  - 화면(`nsm/app/ask.py`·`ask_format.py`·`ask.html`)은 제목 경로와 배지만 보이고 `posts/<cid>/<platform>`을 쪼개 플랫폼을 보여 주는 곳이 없다. 그래서 고칠 것이 없었다(`answer.py`는 `doc_qa`에 경로를 그대로 저장만 한다).
  - 측정 스크립트 `duplicate_cards`는 `cards`를 플랫폼으로 세지 않는다. 카드 문서는 원고당 하나라 중복이 될 수 없다. 자리 수에는 그 원고의 카드 조각도 넣는다(같은 원고가 차지한 자리).
- 테스트, 문서(ADR 0065 개정 2, architecture 6-3·갱신 줄, 설명서 9절 한 줄, CHANGELOG), 버전 0.4.31.

## 막힌 것과 해결

- **새 백업이 없고, 새 복사본은 200개를 넘음**
  - 측정 시각(11-11 03:50)에 가장 최신 백업은 R4b와 같은 `data-2026-11-10.duckdb`였다. 새로 복사해 색인하면 새 임베딩이 약 232개였다(문서 80, 수집 82, 카드 70). 오프라인으로 조각 해시를 비교해 셌고, 200개 기준을 넘는다.
  - 그래서 R4b가 같은 백업에 색인을 채워 둔 복사본(`%TEMP%\nsm-r4b-measure`)을 다시 복사해 썼다. 그 복사본에서는 새 임베딩이 104개(문서 34, 카드 70)라 기준 안이다.
  - 덕분에 R4b와 수집·문서 조각이 같은 상태에서 이번 변경의 효과만 비교된다. 문서 34조각은 R4b 머지로 바뀐 docs(devlog·ADR 등)다.
- **해시만 보면 카드는 "새로 임베딩 0"으로 나옴**
  - 오프라인 추정 스크립트는 DB 전체의 같은 해시를 찾아서, 카드 조각을 재사용할 수 있다고 셌다.
  - 실제 `index_documents`는 **같은 경로** 안에서만 벡터를 재사용한다. `posts/<cid>/cards`는 새 경로라 70조각이 새로 임베딩된다.
  - 실제 색인 결과로 이를 확인했다. 숫자는 아래 표의 실측을 쓴다.
- **셸 heredoc의 역슬래시**
  - 패치 스크립트를 heredoc으로 넘겼더니 `"\n"`이 진짜 줄바꿈이 돼 문자열이 깨졌다. 테스트의 `"\\~~~"`도 `\~`로 줄었다.
  - 패치 스크립트를 파일 쓰기 도구로 만들어 해결했다. (기존 `test_rag_sources_db.py` 348줄의 `SyntaxWarning`은 이 배치 전부터 있던 것이라 그대로 두었다.)

## 배운 것

1. **조각 글이 같아야 측정이 "변경의 효과만" 보여 준다.** 카드 문서를 메타 줄 없이 "# 제목 / ## 카드 문구"로만 만든 덕분에 조각 글이 예전과 글자까지 같았다. 그래서 벡터와 점수가 같고, 표에서 바뀐 것은 자리뿐이다. 메타 줄을 넣었다면 점수도 조금씩 바뀌어 "중복이 줄어서 좋아졌나, 글이 바뀌어서 달라졌나"를 가를 수 없었다.
2. **증분 색인의 재사용 범위를 정확히 알아야 비용을 맞게 센다.** 해시만 보면 카드 70조각은 이미 있는 글이라 공짜 같았다. 하지만 색인기는 같은 경로 안에서만 벡터를 재사용하므로, 경로를 옮기면 같은 글도 다시 임베딩한다. 추정은 실제 코드의 규칙대로 해야 하고, 의심스러우면 복사본에서 실제로 돌려 확인한다.
3. **지표의 정의가 기대값보다 넓을 수 있다.** "중복 카드" 칸은 이름과 달리 같은 원고의 두 플랫폼 조각을 모두 센다. 기대값("0")을 적을 때는 카드만 떠올렸다. 측정 칸을 만들 때 이름이 실제 계산과 맞는지, 기대값이 그 정의로 적혔는지 같이 확인해야 한다.
