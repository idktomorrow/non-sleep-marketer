# 2026-11-19 배치 C51: 폴더 선택 창을 브라우저 앞에 + 설정 바로가기 "백업" 칩 + 쉬운 문구

## 목표

1. 설정 바로가기 칩에 빠진 "백업"을 넣는다(고급 모드만).
2. "폴더 고르기…"를 누르면 선택 창이 브라우저 뒤에 떠 Alt+Tab으로 찾아야 하던 것을, 바로 앞에 뜨게 한다.
3. 백업 복사 칸과 선택 창의 문구를 쉽게 바꾼다("한 부 더" 표현 빼기).

## 한 일

1. **칩**: `settings.html` 바로가기 목록의 `('ops','운영',true)` 다음에 `('backup','백업', not simple)`. 간단 모드에서는
   `#backup` 절이 숨어 있으니 칩도 만들지 않는다.
2. **선택 창 앞으로**(`nsm/app/folder_picker.py`의 `picker_script`만, ADR 0075 "포그라운드 잠금 우회" 절)
   - 주인 폼을 실제로 띄운다: `FormBorderStyle None`·`ShowInTaskbar $false`·`TopMost`·`Opacity 0`·1×1·`CenterScreen`, `Show()`. `System.Drawing` 추가.
   - `ShowDialog` 직전에 최소화 → 복원 → `Activate()` → `DoEvents()`.
   - `finally`에서 대화 상자와 주인 폼을 닫는다. 종료 코드는 `$code`(0·1·3)에 담아 `finally` 뒤에 `exit $code` 한 번.
   - `-STA`·`-EncodedCommand`·UTF-8(BOM 없음) 출력·`ps_literal`은 그대로.
   - `settings.js`의 "보이지 않으면 작업 표시줄을 확인하세요"는 안전망으로 그대로.
3. **문구**: 선택 창 제목 "백업 파일을 복사해 둘 폴더를 선택하세요". 칸 안내를 요청 문구로 바꿨고, user-guide 7절 줄도
   같은 말투로 고쳤다("한 부 더" 제거, 바로가기 **백업**·**폴더 고르기…** 먼저 안내).
4. **데모**: `scripts/dashboard_demo.py --real-picker`면 가짜 대신 진짜 Windows 선택 창을 쓴다(화면 확인용, 기본은 그대로 가짜).
5. 문서: ADR 0075에 절 덧붙임, architecture 갱신 줄·상태 표, CHANGELOG. 버전 0.4.43.

## 실제 확인 (필수 항목)

예시 데이터 데모 서버만 썼다(운영 대시보드 아님). 비교를 위해 같은 서버를 C50 스크립트로 바꿔 끼운 것(전, 8796)과
C51(후, 8795) 두 개를 띄웠다. 보이는 Chromium을 띄워 설정 → 고급 → 백업으로 간 뒤, 브라우저가 포그라운드인 것을
확인하고 버튼을 눌렀다. 1초 뒤 `GetForegroundWindow`와 `EnumWindows`(z-순서)로 재고 화면을 캡처했다.

| 누르는 방법 | 전(C50) | 후(C51) |
|---|---|---|
| Playwright 클릭(OS 입력 아님) | 선택 창이 앞 | 선택 창이 앞 |
| OS 마우스 클릭(SendInput, 사용자와 같음) | **포그라운드는 브라우저, z-순서도 브라우저가 위**(재현) | **포그라운드가 선택 창, 브라우저 위·화면 중앙**(767,327)–(1152,710) |

- 화면 캡처로도 같았다. 전에는 선택 창이 보이지 않았고, 후에는 "폴더 찾아보기" 창이 브라우저 위 가운데에 떴다.
- 선택 창은 `WM_CLOSE`로 닫았고 화면 안내는 원래대로(취소) 돌아왔다. 남은 `powershell.exe` 창은 없었다.
- 2번(최소화·복원)으로 포커스까지 와서, 4번(Alt 키 보내기 `SendKeys`)은 넣지 않았다.

## 막힌 것과 해결

- **처음 측정에서 재현이 안 됐다**: Playwright 클릭으로 누르면 전(C50)도 선택 창이 앞에 떴다. 포그라운드 잠금은
  "마지막 입력을 받은 프로세스"와 "마지막 입력 뒤 지난 시간"(기본 200초)을 보는데, Playwright 클릭은 OS 입력이 아니고
  그동안 사람의 입력이 없어 잠금이 풀린 상태였다. 실제처럼 `SendInput`으로 마우스를 눌러 브라우저가 마지막 입력을
  받게 하자 C50에서 바로 재현됐다.
- **`exit`가 `finally`를 건너뛸까**: `try` 안에서 `exit 3`을 하던 것을 `$code`에 담아 `finally` 뒤에 한 번만 끝내도록
  바꿨다. 주인 폼이 열린 채 프로세스가 끝나는 경우를 생각하지 않아도 된다.

## `/code-review` 반영

고친 것:
- 선택 창이 열린 동안 모든 창 위에 머문다(주인 폼이 진짜 TopMost라서): "포커스를 못 가져와도 브라우저 위에 보이게"가 요청한 최소 목표라 유지하고, ADR 0075에 함께 생기는 것으로 적었다.
- 주인 폼이 작업 표시줄에 없어 선택 창도 작업 표시줄 단추가 없을 수 있다: "이미 떠 있습니다" 안내가 작업 표시줄 대신 "화면 가운데의 그 창"을 가리키게 바꿨다. `settings.js`의 "작업 표시줄을 확인하세요"는 요청대로 안전망으로 둔다.
- architecture 상태 표의 C50·C51 줄이 3칸뿐이었다(표는 5칸): 배치·비고 칸을 채웠다.

그대로 둔 것:
- 최소화·복원이 다른 PC(다중 모니터·배율)에서도 통하는지: 이 PC에서만 확인했고 ADR·다음 배치 메모에 적었다. 못 통해도 TopMost라 창은 보인다.
- ADR 0075에 덧붙인 결정의 상태 "채택": 요청이 0075에 절을 덧붙이라고 정했다.
- 종료 코드 3·따옴표 테스트가 C50과 겹침: 요청이 "기존 동작이 그대로인지" C51 테스트로 확인하라고 했다.
- `System.Drawing.Size` 대신 Width/Height: 요청이 `Size`와 `Add-Type`을 정했다.
- 스크립트 글자를 확인하는 테스트의 한계: 진짜 창 동작은 테스트에서 띄우지 않는 규칙이라, 위 "실제 확인"이 받친다.

## 배운 것 3개

1. **Windows는 아무 프로그램이나 창을 앞으로 끌어올리지 못하게 막는다(포그라운드 잠금)**: 사용자가 글을 쓰는데 다른
   프로그램이 창을 띄워 입력을 빼앗으면 안 되기 때문이다. 방금 사용자 입력을 받은 프로세스(여기서는 브라우저)만
   앞의 창을 바꿀 수 있다. 우리 선택 창은 `nsm run`이 낳은 백그라운드 PowerShell이라, 막히면 작업 표시줄만 깜빡인다.
2. **"TopMost"는 창이 실제로 떠 있어야 효과가 있다**: C50은 맨 위 속성을 켠 폼을 주인으로 넘겼지만 그 폼을 `Show()`하지
   않아 아무 일도 없었다. 보이지 않게(투명·1px) 띄우되 진짜로 띄우고, 대화 상자가 그 폼 위치를 기준으로 뜨니 화면
   가운데에 둔다. 최소화했다 복원하는 것은 잠금에 걸리지 않고 창을 앞으로 가져오는 알려진 방법이다.
3. **재현 조건을 사용자와 똑같이 맞춰야 고쳤는지 안다**: 자동화 도구의 클릭은 OS 입력이 아니어서, 고치기 전 코드도
   "잘 된다"고 나왔다. 사용자가 겪는 조건(브라우저가 방금 진짜 클릭을 받음)을 SendInput으로 만들자 비로소 전·후가
   갈렸다. "고쳤다"는 말은 고치기 전에 실패를 재현한 뒤에만 할 수 있다.

## 다음 배치 메모
