# 2026-10-13 배치 N2: 알림함과 게시 대기 화면

## 목표

선웅제 요청이 세 가지였다.
- 끝난 진행 표시가 계속 남는다 → 닫기
- 알림을 다시 볼 곳(종 모양)
- 승인한 원고를 볼 수 없다 → 게시 대기 탭과 수정·삭제

## 한 일

- 스키마 v3 `notifications`, 저장소 메서드(추가·목록·안 읽은 수·읽음·전체 읽음·정리)
- `RecordingNotifier`: 모든 알림을 기록하고 데스크톱으로 넘김. `link_for`로 이동 화면을 정함. `nsm run`에서 감싼다
- 머리줄 종 모양(`<details>`, 바깥 클릭·Esc로 닫힘, 안 읽은 수 30초 갱신), `/notifications` 화면
- 진행 표시 × 닫기(`/jobs/status/{id}/dismiss`, HTMX)
- `/queue` 게시 대기, `/queue/{id}/unapprove` 검토로 되돌리기, 폐기 뒤 게시 대기로 돌아오기, 올리는 중이면 409. 검토 상세에서 승인된 원고에 되돌리기·폐기 막대
- 데모 대시보드에 예시 알림 추가, ADR 0031(채택), 사용설명서·README·architecture·CHANGELOG

## 막힌 것과 해결

- Notifier 포트는 동결이라 "이동할 화면"을 넘길 수 없었다. 포트를 바꾸지 않고, 기록하는 쪽에서 알림 제목으로 화면을 정했다.
- 되돌리기·폐기가 게시와 부딪히는지 확인했다. 게시 대상 조회가 `contents.status = 'approved'`를 조건으로 하므로, 상태만 바꾸면 그 즉시 멈춘다. 이미 올리는 중인 순간만 막았다.
- 휴대폰 폭에서는 머리줄이 두 줄이라 알림 창을 화면 너비에 맞춰 고정 위치로 띄웠다.

## 배운 것 (신입 개발자용)

1. **알림은 "보내기"와 "보관"이 따로다.** 데스크톱 알림은 한 번 놓치면 끝이다. 중요한 일은 DB에 남겨 두고 사람이 원할 때 다시 보게 해야 한다.
2. **상태 기계가 있으면 "멈추기"가 쉽다.** 게시 작업이 "승인됨"인 원고만 고르게 만들어 두었기 때문에, 되돌리기는 상태 하나만 바꾸면 됐다. 처음에 상태 전이를 엄격하게 정해 둔 덕이다.
3. **동결된 인터페이스를 넓히지 않고 기능을 더하는 법.** 포트에 인자를 더하는 대신, 포트를 감싸는 어댑터(`RecordingNotifier`)를 만들어 필요한 정보를 그 안에서 만들었다.
