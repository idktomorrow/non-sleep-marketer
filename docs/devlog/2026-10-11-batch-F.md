# 배치 F: 대시보드·대댓글·스케줄러 → 드라이런 MVP (2026-10-11)

- 이슈: #11 #12 #13 #22 · 브랜치: batch/F-dashboard-reply-scheduler

## 목표

`nsm run` 하나로 스케줄러와 로컬 대시보드가 함께 떠서, 드라이런으로 하루치 흐름(수집 → 생성 → 검토/게시 → 댓글 → 지표)이 돌아가는 상태. 드라이런 MVP.

## 한 일

- `reply` 잡: 내 게시물의 새 댓글 → 6분류 → 자동 답글(페르소나 말투, 금칙어 검사) / 숨김 / 사람에게. 작성자별 하루 3회, 분류 불확실(신뢰도 < 0.6)은 사람에게, 한 댓글 실패가 나머지를 막지 않음.
- `health` 잡: 로그인 풀린 플랫폼을 일시 중지하고 알림, 다시 로그인되면 재개. `metrics` 잡: 최근 7일 게시물·계정 지표 스냅샷.
- 데스크톱 알림(winotify): 같은 제목은 60초 안에 한 번만.
- 스케줄러: 모든 잡을 **작업 스레드 하나**에서 차례로. 활동 시간 창 시작 시각 기준으로 수집·생성 시각을 잡고 지터를 섞음.
- 대시보드(FastAPI + Jinja2 + HTMX): 개요(스위치·지금 실행·최근 실행), 검토 대기열·상세(승인·폐기·수정), 댓글(직접 답글·처리 완료), 성과, 실행 로그. 모든 POST에 CSRF 토큰. 카드 이미지 경로 조작 차단.
- `nsm run`: DB 하나, 재시작 복구, 스케줄러 시작, 대시보드 실행, 종료 시 스케줄러 → 브라우저 → DB 순으로 정리. 로그는 파일로도(5MB × 3개 회전).
- `nsm install-autostart`: 시작프로그램 폴더에 실행 스크립트(ADR 0013).
- 사용설명서 3·4·7절.

## 막힌 것과 해결

- **Playwright 동기 API는 만든 스레드에서만 써야 한다**: 스케줄러가 여러 스레드로 잡을 돌리면 브라우저 호출이 깨진다. 작업 스레드를 하나로 고정하고, 대시보드의 "직접 답글"도 `submit()`으로 그 스레드에 넣었다. 실서버 스모크에서 수집 잡이 작업 스레드의 실제 Chromium으로 문제없이 돌았다.
- **셸 heredoc이 따옴표 많은 템플릿에서 깨짐**: 템플릿은 파일 쓰기 도구로 작성.

## 배운 것 (신입 개발자용)

1. **스레드 친화성(thread affinity)**: 어떤 라이브러리 객체는 만든 스레드에서만 써야 한다(Playwright 동기 API, 많은 GUI 라이브러리). 이럴 때는 "그 일만 하는 스레드 하나"를 두고 다른 곳에서는 일을 그 스레드에 넘긴다(`submit` → `Future`로 결과 받기).
2. **CSRF**: 대시보드가 내 PC(127.0.0.1)에서만 열려도 안전하지 않다. 내가 다른 웹사이트를 보는 중에 그 사이트가 내 브라우저를 시켜 `http://127.0.0.1:8765/review/x/approve`로 POST를 보낼 수 있다. 서버가 화면에 심어 둔 비밀 토큰을 요청에 같이 보내게 하면, 다른 사이트는 토큰을 모르므로 막힌다.
3. **동작을 테스트하고 모양은 테스트하지 않는다**: 대시보드 테스트는 "승인을 누르면 상태가 approved가 되고 포기했던 게시가 다시 대기열에 들어간다"를 검사하고, HTML 모양은 검사하지 않는다. 그래서 배치 I에서 디자인을 통째로 바꿔도 테스트가 기능을 지켜 준다.
