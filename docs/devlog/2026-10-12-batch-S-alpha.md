# 배치 S-α: 카드뉴스 템플릿·렌더러 (2026-10-12)

- 이슈: #18 #19 · 브랜치: batch/S-alpha-templates-renderer · 담당: 메인(원래 서브, [ADR 0015](../adr/0015-main-takes-s-alpha.md))

## 목표

카드 덱 JSON(contracts.md 5절)이 실제 카드뉴스 PNG(1080×1350)로 그려지고, 법적 표기 슬롯이 모든 장에 들어가며, 긴 문구에서도 깨지지 않는 상태. 지금까지 드라이런은 단색 PNG(`PlaceholderRenderer`)였다.

## 한 일

- 템플릿 `nsm/templates/cards/`: `info.html`·`list.html`·`compare.html`(종류별 가운데 장), `_layout.html`(페이지 뼈대·색 변수·글자 맞춤 스크립트), `_parts.html`(표지·본문·목록·비교·마무리 조각 매크로), `base.css`.
- 표기 슬롯(계약 그대로): 모든 장에 `data-label="virtual-person"` "가상인물" 배지와 `data-page` "n / N", 협찬이면 표지에 `data-label="ad"` "광고" 배지, AI 배경이 있는 장에 `data-label="ai-generated"` "AI 생성 이미지", 마무리 장에 `data-sources` 출처 목록.
- 색: 브랜드 주색·강조색에서 대비를 계산해 글자색을 정한다(WCAG 대비 비율). 밝은 브랜드 색은 밝은 면 위에서 읽히도록 어둡게 바꾼다. 배경 이미지가 없거나 파일이 사라졌으면 브랜드 색 그라디언트.
- 폰트: Pretendard(Regular·SemiBold·Bold·ExtraBold, SIL OFL, `nsm/templates/fonts/LICENSE.txt`) 동봉.
- 렌더러 `nsm/render/html_renderer.py` `HtmlCardRenderer`: 덱을 한 HTML 페이지로 그리고 슬라이드마다 스크린샷. 글이 넘치면 `data-fit` 글자를 최소 크기까지 6%씩 줄이고, 그래도 넘친 장은 `last_overflow`에 남긴다. `get_renderer()`가 자동으로 고르고, Playwright가 없을 때만 단색 대체.
- 미리보기 하네스: `uv run nsm render-preview 덱.json --out 폴더`(배치 A의 명령에 실제 렌더러가 연결됨).
- CI: `playwright install chromium` 단계 추가.

## 막힌 것과 해결

- **장식 원이 회색 덩어리로 보임**: 강조색(주황)을 남색 위에 24%로 겹치면 수학적으로 회색이 된다. 실제로 그려 보고 알았다. 글자색을 7%로 겹친 은은한 원으로 바꿈.
- **"광고"·"가상인물" 배지 높이가 어긋남**: 배지 줄을 세로 가운데 정렬.
- **Playwright를 한 스레드에서 두 번 띄울 수 없음**: 수집용 브라우저 드라이버가 같은 작업 스레드에 떠 있으면 렌더러의 Playwright가 충돌한다. 렌더는 매번 전용 스레드에서 하고, 이 상황을 그대로 재현하는 테스트를 넣었다.
- 폰트 CDN 경로가 GitHub 저장소 구조와 달라 404 → npm 패키지 경로로 받음.

## 배운 것 (신입 개발자용)

1. **HTML로 이미지를 만드는 이유**: AI 이미지 생성은 한글을 정확히 못 그린다. 글자는 HTML·CSS로 그리고 브라우저(Playwright)로 사진을 찍으면, 폰트·줄바꿈·색을 코드로 정확히 다룰 수 있고 같은 입력이면 같은 그림이 나온다. 배경만 AI에 맡긴다(ADR 0007).
2. **테스트로 "그림"을 검사하는 방법**: 픽셀을 비교하면 작은 변화에도 깨진다. 대신 "크기가 1080×1350인가", "표기 슬롯 요소가 HTML에 있는가", "넘친 장이 없는가"처럼 꼭 지켜야 하는 성질을 검사하고, 보기 좋은지는 사람이 PNG를 보고 판단한다.
3. **색 대비는 계산할 수 있다**: "흰 글자가 잘 보이나"는 감이 아니라 공식(WCAG 상대 휘도·대비 비율)으로 정한다. 브랜드 색이 무엇이든 표기 배지와 본문이 읽혀야 법적 표기 의무도 지킬 수 있다.

## 코드 리뷰 반영 (/code-review medium, 8건)

- **대체 경로가 작동하지 않음**: playwright는 필수 의존성이라 "playwright가 없으면 단색" 조건은 절대 참이 안 된다. 실제로 생기는 문제는 크로미움 미설치였다. 크로미움 실행 파일을 확인해 없으면 단색으로 대체하도록 바꿈. 이전 코드라면 크로미움이 없는 PC에서 모든 게시가 4번 재시도 후 포기했다.
- **넘친 카드가 그대로 게시됨**: 최소 글자 크기에서도 넘친 덱은 게시하지 않고 검토 대기열로 보낸다(재시도해도 결과가 같으므로 바로). 렌더 캐시에도 넘침 여부를 함께 기억한다.
- **출처가 말줄임표로 잘림**: 출처 줄은 접히게 하고 글자 맞춤 대상에 넣었다.
- **법적 표기 대비**: 강조색이 브랜드 색과 비슷하면 "광고" 배지를 반전 색으로. 그라디언트 양 끝 모두에서 대비가 나는 글자색을 고른다.
- 렌더 전용 스레드와 크로미움을 한 번 띄워 재사용(테스트 34초 → 26초), 로컬 경로가 담긴 HTML을 결과 폴더에 남기지 않음, `last_overflow`를 렌더마다 초기화.
