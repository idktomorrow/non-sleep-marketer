## 막힌 것과 해결

- **실측 자료가 중복으로 걸러짐**: 원래 DB로는 같은 자료가 "이미 수집됨"이라 새 코드를 통과하지 않았다. DB를 임시 폴더로 복사해 분류 기록만 지우고 돌렸다. 원래 DB와 설정은 건드리지 않았고, 임시로 바꾼 하루 목표도 되돌렸다.
- **본문에 보이지 않는 글자**: 네이버 블로그 본문에 `​`(폭 없는 공백)가 많았다. `split()`은 이것을 공백으로 보지 않는다. 정리 단계에 추가하고 테스트로 고정했다.
- **doctor 테스트가 실제 DB에 쓸 뻔함**: 처음에는 `run_live_checks`가 기본으로 DB를 열게 했는데, 그러면 기존 테스트가 사용자 PC의 `~/.nsm` DB에 가짜 비용을 기록한다. CLI만 DB를 열어 넘기도록 바꿨다.

## 배운 것 (신입 개발자용)

1. **"프롬프트에 적었다"는 "지켜진다"가 아니다**: LLM은 지시를 확률적으로 따른다. 개수·금지어·형식처럼 기계가 셀 수 있는 규칙은 생성 뒤에 코드로 검사하고, 어기면 다시 만들거나 사람에게 넘긴다. 프롬프트는 확률을 높이고, 코드는 보장한다.
2. **같은 입력으로 전후를 비교한다**: 개선 효과를 보려면 다른 날 다른 자료로 돌린 결과를 비교하면 안 된다. 같은 자료를 새 코드에 다시 통과시켜야 차이가 코드 때문인지 알 수 있다. 원래 데이터를 망치지 않게 복사본에서 했다.
3. **테스트가 실제 환경을 건드리지 않게 한다**: 기본값으로 "설정된 DB를 연다"를 넣으면, 그 함수를 부르는 모든 테스트가 개발자 PC의 실제 데이터에 쓰게 된다. 외부 자원(DB, 파일, 네트워크)은 호출하는 쪽이 열어서 넘기게 하면, 테스트는 가짜를 넘기면 된다(의존성 주입).

## 다음 배치 메모

- 원문 본문은 관련 글만 가져오므로 관련성 판정이 앞에서 정확해야 한다. 판정이 빗나가면 엉뚱한 글을 연다(현재 상한 6개).
- 다시 만들면 비용이 최대 두 배다. 주간 리포트의 비용 항목으로 다시 만드는 빈도를 지켜본다(`regenerated` 카운트).

## 코드 리뷰 반영

- **[높음] 카드 목록 번호를 떼다가 소수를 바꿈**: "3.5도 차이"가 "5도 차이"가 됐다(사실이 바뀌어 게시될 수 있음). 번호 뒤에 공백이나 끝이 와야 번호로 본다. "*주의*" 같은 강조도 지키게 했다. 반례를 테스트로 고정했다.
- **[중간] 제외 장르 오탐**: "매일기록하는", "일기예보", "월요일기분", "산지 다녀온 바리스타의 원두 고르는 법", "웨이팅 시간"이 걸렸다. 분류기를 거치지 않아 되돌릴 수 없는 판정이라 `일기`·`다녀온`·`웨이팅`을 구체적인 말로 좁혔다. 대신 "카페 리뷰", "방문 리뷰"를 추가했다.
- **[중간] 이모지 과대 계산**: 👍🏻(피부색), 🇰🇷(국기), 👨‍👩‍👧(ZWJ)이 2~3개로 세어졌다. 화면에 보이는 대로 1개로 센다. 1️⃣ 같은 키캡도 센다.
- **[낮음]**
  - "이모지는 최대 한 개", "1~2개(큰 쪽)", "한 개 정도"를 읽게 했고, 못 읽으면 로그를 남긴다.
  - 본문 가져오기에서 일시 실패는 3번까지 다시 시도한다. 브라우저가 없는 실행에서는 기록하지 않고 다음으로 미룬다.
  - `doctor --live`는 `nsm init` 전에 DB를 만들지 않는다.
  - 출처 줄은 인스타·스레드에만 붙인다(블로그는 본문에 참고 자료가 있다).
- 의도대로 둔 것: 출처 줄의 "브랜드 제공 자료"(업로드 자료가 출처일 때 그대로 표시), ★·♥ 같은 기호는 이모지로 센다(프롬프트에도 그렇게 알림).
