# 2026-10-25 배치 C33: 자잘한 수정 묶음 (중단 표시·자료 정리·해시태그 상한·짧은 표기)

## 목표

운영하며 쌓인 작은 것 네 가지. 사용자 결정: 실행당 원고 상한·프리셋 자동 저장은 빼고, 표기는 35자에서 더 줄이기.

## 한 일

- **끄는 중 중단 표시**: `JobContext.shutting_down`(런타임이 종료 이벤트로 연결). 끄는 중 난 잡 오류는 실행 기록에 `중단(프로그램 종료 중): …`으로 적고 알림을 보내지 않는다. 배지는 회색 "중단". Aside CLI가 결과 줄 없이 끝나면 오류에 종료 코드·stderr를 붙인다.
- **자료 정리**(새벽 백업·정리 잡): 관련 없음(또는 판정 없음)으로 남은 자료는 `source_body_keep_days`(7) 뒤 본문을 비우고(제목·지문·판정 유지), `source_keep_days`(60) 뒤 판정 기록과 함께 지운다. 원고에 쓰인 자료와 관련 자료는 건드리지 않는다.
- **해시태그 상한**: 캡션 해시태그 > 5(협찬이면 4)면 규칙 위반 → 재생성 → 검토. 생성 지시는 "3~4개".
- **짧은 표기 + 첫 문장 훅**: `AI 가상인물 포함 게시물`(13자, ADR 0053). 예전 긴 문구는 붙여 넣어도 걷어낸다. 캡션 첫 문장은 핵심 사실 110자 안에.
- 설명서(표기·설정표·품질 규칙·문제 해결), contracts 5절 문구, ADR 0019 상태 줄, CHANGELOG. 버전 0.4.8.

## 막힌 것과 해결

- **"중단"을 어디에 둘까.** `run_logs.ok`는 참/거짓/비어 있음(실행 중)뿐이라 열을 더하지 않고 메시지 접두어로 표시하고 배지가 접두어를 읽는다. 스키마 변경 없이 끝.
- **종료 신호를 잡에게 어떻게 알리나.** `run_forever`의 `finally` 맨 앞에서 `threading.Event`를 켜고 `ctx.shutting_down`으로 연결. Ctrl+C로 uvicorn이 멈추는 순간 켜지고, 작업 스레드에서 돌던 잡은 끝날 때 이 플래그를 본다.
- **표기 단축의 근거.** 지침이 긴 문구와 짧은 문구("가상인물 포함")를 모두 예시로 든다는 보도 2건을 확인하고 ADR에 링크. 피드 125자 제한은 인스타그램 화면 규격이라 못 늘린다.
- **협찬 해시태그 수.** `#광고`는 게시할 때 앞에 붙으므로 캡션 상한을 1 줄여야 5개 안에 든다.

## 배운 것 (신입 개발자용)

1. **"실패"와 "중단"을 구분하면 알림이 조용해진다.** 같은 오류 문구라도 끄는 중이면 사람이 볼 일이 아니다. 상태 하나를 더 두는 것보다 "언제 났나"를 기록하는 게 싸다.
2. **법정 문구도 예시인지 의무인지 읽는다.** 예시라면 소비자 인식이 기준이고, 짧고 분명한 쪽을 골라도 된다. 근거는 ADR에 링크로.
3. **지우기는 두 단계로.** 용량을 차지하는 본문부터 비우고, "봤다"는 지문은 오래 남긴다. 그래야 같은 글을 다시 모으는 낭비가 없다.
