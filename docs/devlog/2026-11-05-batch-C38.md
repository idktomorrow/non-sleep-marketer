# 2026-11-05 배치 C38: 스레드 프로필 아이콘 변경을 "로그인 필요"로 오판하던 것

## 목표

11-05 20:56부터 스레드가 "threads 로그인 필요: 로그인돼 있지 않음"으로 멈췄다(incidents/0012). 실제로는 로그인돼 있었다. 스레드가 왼쪽 메뉴 프로필 아이콘의 이름을 svg `aria-label`에서 svg 안 `<title>`로 바꿨고, `readHandle`이 내 핸들을 못 읽었다. 고칠 것은 다음과 같다.
- 두 방식을 다 읽는다.
- 대체 경로를 넣을지 판단해 ADR로 남긴다.
- 장애 기록을 쓴다.

## 한 일

- **`nsm/adapters/platforms/threads.py` `readHandle`**
  - `a[href^="/@"]` 안의 svg마다 `aria-label` 또는 `<title>` 글을 앞뒤 공백을 떼고 "프로필"/"Profile"과 비교한다. 맞으면 그 링크의 핸들을 돌려준다.
  - 둘 다 없으면 마지막 대체로 넘어간다. `a[href="/@설정핸들"]` 중 글 카드(`data-pressable-container`)와 가운데 칼럼(`칼럼 본문`) 밖에 있고, `nav` 안이거나 아이콘을 가진 링크면 설정 핸들을 돌려준다. 설정 핸들이 비어 있으면 대체하지 않는다.
- **테스트**(`tests/unit/test_page_errors.py`)
  - C37의 가짜 탭(node) 화면에 `links`를 추가했다. 각 링크는 href, aria, title, 이름 없는 svg, nav, 글 카드 여부를 정한다.
  - 핸들을 읽는 4가지: aria-label, `<title>`, 영문 `<title>`, 메뉴 대체(글 카드 안 작성자 링크가 앞에 있어도).
  - `<title>`로 다른 계정이 보이면 계정 불일치로 나온다.
  - 로그인 필요가 유지되는 3가지: 링크 없음, 작성자 링크·하위 주소뿐, 맨 링크.
  - 건강 점검이 `<title>` 화면을 로그인으로 본다.
  - `test_aside_scripts.py`는 JS 문자열 구조 검사라 실제로 돌려 보는 가짜 탭 쪽이 맞았다.
- **문서**
  - 장애 기록 0012와 README 한 줄.
  - ADR 0063(제안): 대체 경로의 근거와 다음 배치 후보. 후보는 로그인 표지가 보이는데 핸들을 못 읽으면 `ui_changed`로 보기, 대체 사용 기록이다.
  - 0011의 되돌린 설정 문장을 "30분·5일"로 바로잡았다. architecture, CHANGELOG, 설명서도 고쳤다. 버전 0.4.23.

## 막힌 것과 해결

- **대체 경로의 범위**: 처음에는 "글 카드 밖 + 아이콘 있는 `/@me` 링크"면 다 받게 했다. 그런데 테스트에 "검색" 아이콘을 단 `/@me` 링크를 넣자 그것도 내 계정으로 받았다. 실제 화면에 그런 링크는 없으므로 테스트 쪽을 현실적인 경우(맨 링크)로 바꿨다. 판정은 일부러 넓게 뒀다(메뉴가 `<nav>`인지 확인하지 못해서). 그 대가로 대체 경로로는 계정 불일치를 잡지 못한다. ADR 0063에 적었다.
- **작업 폴더**: 운영 `nsm run`이 켜져 있어 worktree(`%TEMP%\nsm-wt-c38`)에서 작업했다. worktree는 자기 `.venv`를 따로 만들어 `uv sync`가 운영 실행 파일 잠금과 부딪히지 않았다.
- **줄바꿈**: 테스트 파일을 Python `write_text`로 쓰니 Windows에서 줄 끝이 CRLF로 바뀌었다. LF로 되돌렸다.

## 배운 것

1. **"못 찾음"과 "없음"은 다르다.** `readHandle`이 빈 값을 돌려준 것은 "로그인 안 됨"이 아니라 "내가 아는 모양의 프로필 링크를 못 찾음"이었다. 화면에서 무언가를 못 찾았을 때 그것을 곧바로 사실(로그아웃)로 바꾸면, 화면이 바뀔 때마다 엉뚱한 진단이 나온다. C37의 "기다렸는데 비었음 ≠ 댓글 0개"와 같은 교훈이다.
2. **접근성 이름은 여러 방법으로 붙는다.** svg의 이름은 `aria-label` 속성으로도, 안쪽 `<title>` 요소로도 붙는다. 화면 읽기 프로그램에는 둘 다 "프로필"로 들린다. 그래서 사이트는 바꿔도 된다고 생각하고 바꾼다. 선택자를 짤 때는 "보이는 이름"을 기준으로, 이름이 붙는 방법을 여러 개 받아 두면 덜 깨진다.
3. **대체 경로는 무엇을 잃는지 같이 적는다.** 설정 핸들로 메뉴 링크를 찾는 대체는 멈춤을 막는다. 대신 "다른 계정으로 로그인됨"을 잡는 힘이 없다. 그래서 1순위 경로(실제 핸들 읽기)를 먼저 시도하고 대체는 마지막에만 쓴다. 범위는 글 카드 밖으로 좁혀 작성자 링크로 착각하지 않게 했다.

## 다음 배치 메모

- ADR 0063의 다음 배치 후보를 구현한다.
  - 핸들을 못 읽어도 답글 입력칸·"새로운 스레드" 메뉴 같은 로그인 표지가 보이면 `ui_changed`(화면 변경)로 판정해 "다시 로그인"이 아니라 "코드 수정 필요"로 안내한다.
  - 대체 경로를 탔으면 기록한다.
- 인스타그램 `readHandle`도 이름 하나에 기대는지 점검한다.
- 장애 기록 0012의 회복 시각과 실패 건수는 반영 후 사용자가 채운다.
