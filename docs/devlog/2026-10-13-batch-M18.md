# 2026-10-13 배치 M18: 자료 화면

## 목표

선웅제 요청: 직접 올리는 파일을 대시보드에서 올리고, 제대로 읽었는지, 자료로 쓰였는지 확인한다.

## 한 일

- `nsm/app/materials.py`: `save_material`(형식·크기·바로 읽기 확인, 못 읽으면 저장 안 함, 안전한 이름, 같은 이름은 번호), `list_files`(파일 ↔ 자료 연결, 고친 뒤 안 읽음 표시), `delete_file`(폴더 안만), `verdict`(판정을 사람 말로), `source_label`
- 저장소: `list_source_items_view`(자료 + 최근 관련성 판정·방법, 주제, 쓰인 원고), `source_counts`
- `/materials` 화면, `/materials/upload`, `/materials/files/delete`, 메뉴 "자료", 데모 대시보드 uploads 폴더
- ADR 0033(채택), 사용설명서·README·architecture·CHANGELOG

## 막힌 것과 해결

- 올린 파일과 자료를 잇는 열쇠: 자료의 주소는 파일 경로(`file://`)다. 같은 파일을 고치면 해시가 바뀌어 새 자료가 생긴다. 그래서 같은 주소의 가장 최근 자료를 그 파일의 상태로 보고, 파일 수정 시각이 더 늦으면 "고친 뒤 아직 안 읽음"으로 표시한다.
- 판정 방법을 보이려면 마지막 판정이 필요했다. `classifications`에서 `arg_max(label, created_at)`로 가장 최근 판정만 붙였다.

## 테스트 결과

- ruff 통과, pytest 초록. 새 테스트 10개(`tests/app/test_materials.py`): 올리기·읽은 글자 수·안 읽음 표시, 자료로 들어간 뒤 판정 표시와 거르기, 쓸 수 없는 파일 3가지 거절, 이름 경로 탈출·덮어쓰기 방지, 크기 제한, 폴더 밖 지우기 거절, 목록·잘못된 필터, 판정 문구
- 데모 1280·390px: 올리기 → "글자 32자를 읽었습니다", 가로 넘침 없음

## 배운 것 (신입 개발자용)

1. **올리기는 "저장"이 아니라 "검사 후 저장"이다.** 읽을 수 없는 파일을 받아 두면 사람은 올렸다고 믿는데 시스템은 조용히 건너뛴다. 받는 순간 읽어 보고 결과를 바로 알려 준다.
2. **사용자가 준 파일 이름은 경로로 쓰지 않는다.** `../../밖으로.txt` 같은 이름으로 폴더 밖에 쓰는 공격을 막으려면 마지막 이름 부분만 남기고 금지 문자를 지운다. 지울 때도 실제 경로가 폴더 안인지 확인한다.
3. **"무엇이 일어났나"를 보여 주는 화면이 디버깅 시간을 줄인다.** 오늘 "관련 자료 0건" 원인을 찾느라 진단 스크립트를 몇 번 돌렸다. 이 화면이 있었으면 판정 점수를 바로 볼 수 있었다.

## 이어서 C5: 인터넷이 잠깐 끊겼을 때

- 20:59 원고 만들기가 "Request timed out or interrupted"로 실패했다. 로그를 보니 Claude API 요청 3번(처음 + SDK 재시도 2번)이 각각 약 5초 만에 끊겼다. 같은 시각 네이버 검색도 시간 초과가 났다. 인터넷 연결이 잠깐 불안정했던 것이다(`nsm doctor --live`로 직후 정상 확인).
- SDK 기본 재시도(2번, 약 10초)로는 수십 초 끊김을 못 버틴다. 생성기·분류기 클라이언트를 `max_retries=5`로 올렸다(지수 대기, 약 30초).
- 오류 문구는 `network_error_text`로 연결 끊김·과부하·키 오류를 한국어로 바꿨다. 자료는 그대로 남아 다음에 다시 만든다(기존 동작, 테스트로 고정).
- 배운 것: **외부 API는 "가끔 실패한다"를 기본으로 설계한다.** 재시도 횟수와 대기는 실제로 겪는 끊김 길이에 맞춰야 하고, 실패해도 일감(자료)을 잃지 않아야 한다.

## 이어서 Q2: 카드 마무리 문구

- 마무리 장 문구 "링크는 저장부터 해요"가 어색하다는 지적을 받았다. 프롬프트에는 "cta: 20자 이내"뿐이라 모델이 SNS 관용구(링크·저장)를 끌어왔다.
- 프롬프트에 목적(주제와 이어지는 질문·말 걸기)과 좋은 예를 넣었고, 카드에서 할 수 없는 말은 코드 검사로 막았다. 새 테스트 6개.
- 배운 것: **길이 제한만 주면 모델은 가장 흔한 관용구를 쓴다.** 칸의 "목적"과 좋은 예를 함께 줘야 그 칸에 맞는 말을 쓴다.

## 이어서 Q3: 카드 출처를 사이트 이름으로

- 선웅제 결정: 카드 출처의 긴 주소를 사이트 이름으로. 데이터(원문 주소)는 그대로 두고 렌더 직전에만 바꿨다. 그래서 이미 만든 원고에도 바로 적용되고, 검증 기록은 남는다.
- 언론사 이름표 40여 곳과 하위 도메인 처리. 새 테스트 8개, 실제 렌더로 확인("출처 / 연합뉴스 / 아이즈").
- 배운 것: **보여 주는 모양과 저장하는 값을 나누면 되돌리기 쉽다.** 저장 값을 바꿨다면 옛 원고를 고치는 이전 작업이 필요했을 것이다.
