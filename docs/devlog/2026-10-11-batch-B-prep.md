## 목표

배치 B는 가입·로그인·원문 확인처럼 사람이 직접 하는 검증이다. 사람이 헤매지 않고 한 번에 끝낼 수 있게 단계별 안내 마법사를 만들고, 키가 진짜 동작하는지 확인하는 명령을 추가한다.

## 한 일

- `nsm doctor --live`: Claude·MotherDuck을 한 번씩 실제로 호출. `--with-image`면 OpenAI 이미지 1장도. `--live-only`면 오프라인 점검을 건너뜀. 모델은 사용자 설정을 따르고, 키를 환경 변수에서 읽었는지 keyring에서 읽었는지 표시. 선택 기능(MotherDuck, OpenAI) 실패는 WARN(앱이 대체 경로로 돎), Claude 실패만 FAIL.
- `scripts/day1_wizard.sh`(8단계): API 키(keyring에만 저장) → MotherDuck → 실제 호출 확인 → 테스트 계정 → Aside 무인 게시 → 댓글 숨기기·인스타 프로 계정 → 네이버 에디터 → 법규 원문 대조. 결과를 `docs/day1-verification.md`로 기록. 비밀이 아닌 답은 `.day1-wizard.env`(깃 제외)에 저장해 중간에 멈췄다 다시 실행해도 이어진다.
- Aside 단계는 공식 개발자 문서의 CLI 명령(`aside "작업"`, 설치 스크립트)을 그대로 안내한다. CLI 실행 시 승인을 기다리는지는 문서에 없어서, 그게 바로 사람이 확인할 항목이다.

## 막힌 것과 해결

- **Windows에서 파이썬 출력을 파이프로 받으면 cp949**: 마법사가 한글("실호출")로 결과 줄을 골라내는데 인코딩이 달라 항상 빈 결과가 기록될 뻔했다(리뷰에서 발견). `PYTHONUTF8=1`을 켜고, 그래도 비면 "읽지 못함"을 기록하도록.

## 배운 것 (신입 개발자용)

1. **사람이 하는 일도 자동화할 수 있는 부분이 있다**: 가입·로그인은 사람이 해야 하지만, "어디를 열고 무엇을 누르고 무엇을 복사해 어디에 넣는지"는 스크립트가 안내하고 기록할 수 있다. 다음 사람(팀원)이 같은 일을 할 때 AI에게 다시 설명할 필요가 없다.
2. **인코딩은 경계에서 깨진다**: 같은 문자열도 프로그램 사이(파이썬 → 파이프 → grep)를 지날 때 인코딩이 다르면 사라진다. Windows 한국어 환경의 기본값(cp949)과 UTF-8의 차이는 자주 만나는 함정이다.
3. **실패의 무게를 구분한다**: 필수 기능이 안 되면 FAIL로 멈추고, 대체 경로가 있는 선택 기능은 WARN으로 알리기만 한다. 모든 실패를 똑같이 다루면 사소한 문제로 전체가 멈춘다.
