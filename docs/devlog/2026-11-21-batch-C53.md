# 2026-11-21 배치 C53: API 키 만료일 메모·미리 알림 + 하루 한 번 자동 키 확인 + 키 오류 즉시 알림

## 목표

2026-11-12 00:56 운영 Claude 키(30일 만료)가 만료되자 generate가 401로 조용히 실패했고(로그 한 줄, 알림 없음) 그날 게시가 0건이었다.
프로그램은 만료일을 API로 알 수 없으니 ① 사람이 적은 만료일 메모로 미리 알리고 ② 설정 화면 "확인"과 같은 조회(비용 0)를
하루 한 번 자동으로 돌리고 ③ 실행 중 401/403은 바로 알린다. Claude·Gemini·OpenAI 세 키 모두 같은 규칙.

## 한 일

1. **`nsm/engine/key_watch.py`(새 파일)**: 설정 저장소 세 칸을 다룬다(키 값이 아니라 날짜·상태라 keyring 아님).
   - `key_expiry` = {키: "YYYY-MM-DD"}: `set_expiry`·`expiry_dates`·`parse_date`(형식 틀리면 None).
   - `key_expiry_notified` = {키: {date, stage, on}}: `notify_expiry`가 남은 날 7·3·1·0일에 한 번씩(7·3·1은 warn, 0 이후 error),
     지난 뒤 하루 한 번. 메모 날짜가 바뀌면 처음부터. 그날 꺼져 있었으면 다음 단계 전까지 놓친 단계로 한 번(`stage_of`).
   - `key_check` = {키: {at, code, alerted}}: `auto_check`가 키마다 24시간에 한 번 `ctx.check_key`. invalid는 하루 한 번 error,
     limit은 같은 상태 동안 한 번 warn, network·unknown은 알리지 않음, ok면 `alerted`를 지움. 끄는 중이면 건너뜀.
   - `key_error`: 실행 중 키 거절. `key_check`를 invalid로 적고 알림은 하루 한 번. `looks_like_key_error`: 401/403·`API_KEY_INVALID`.
   - `forget_key`(키 삭제)·`clear_check`(판단 못 한 저장)·`record_check`, 화면용 `key_view`·`key_banner`.
2. **health**: `run_health` 끝에서 `check_keys(ctx)`를 별도 try로. 보낸 알림은 `counts.key_alerts` → 실행 기록 "API 키 알림: …".
   `JobContext.secrets`·`check_key`(없으면 건너뜀). `build_context`가 keyring 저장소와 `nsm.app.keys.check_key`를 끼운다.
3. **즉시 알림**: `generate._make_one`이 `status_code` 401/403이면 `key_error(ctx, "anthropic_api_key", "Claude API 키 오류")`.
   분류기 대체 콜백을 `runtime._on_classifier_switch`로 빼고, Gemini·Claude 분류기가 키 거절로 넘어가면 같은 `key_error`.
4. **설정 → API 키**: "저장·바꾸기" 칸에 `만료일(선택)` 날짜 칸과 숨은 `with_date=1`.
   - 키 칸을 비우고 저장 = 날짜만(키 확인 안 함), 둘 다 비우면 메모 삭제, 키 없이 날짜만은 거절, 형식이 틀리면 아무것도 저장 안 함.

   - 상태 칸: "만료 12-12 (21일 남음)"(7일 이하 warn 배지, 지나면 bad "만료됨"), "자동 확인 11-21 07:30 연결됨".
   - 환경 변수 키도 날짜 칸만 있는 폼으로 메모를 적을 수 있다(키 값은 못 바꿈).
5. **첫 화면**: 맨 위에 만료 7일 이하·만료됨·자동 확인 invalid인 키를 한 줄씩(`notice warn`/`bad`) + "설정 → API 키" 링크. 간단 모드에서도.

## 막힌 것과 해결

- **빈 날짜 칸이 "칸 없음"과 구별되지 않음**: `expires: str | None = Form(None)`으로 "날짜 칸이 있는 폼"을 알아보려 했는데,
  FastAPI는 빈 문자열 폼 값을 기본값으로 읽어 `None`이 됐다. 그래서 "날짜 칸 비우고 저장(메모 삭제)"이 예전 "키 형식이
  아닙니다"로 갔다. 폼에 숨은 `with_date=1`을 넣어 구별했다. 예전 폼(날짜 칸 없음)의 빈 키 저장은 그대로 형식 오류다.
- **엔진이 app을 import하지 않게**: 자동 확인은 `nsm/app/keys.py`의 `check_key`를 쓰지만, 엔진은 함수를 `ctx.check_key`로 받기만
  하고 조립(`build_context`)에서 끼운다. 화면 문구도 key_watch에 짧게 따로 두었다.
- **테스트 픽스처 이름 겹침**: 처음에 generate 테스트의 `ctx` 픽스처를 import했다가 같은 파일의 `ctx` 픽스처를 덮을 뻔해 뺐다.

## 배운 것 3개

1. **모르는 건 사람에게 받아 적되, 그 메모만 믿지 않는다.** 만료일은 발급한 사람만 안다. 그래서 메모로 미리 알리고, 메모를 잊거나
   틀렸을 때를 위해 하루 한 번 실제로 확인하고, 그 사이 실패는 즉시 알린다. 한 겹이 놓친 것을 다음 겹이 잡는다.
2. **알림은 "언제 다시 보내지 않을지"가 절반이다.** 30분마다 도는 점검에 알림을 붙이면 같은 말이 하루 48번 온다. 단계(7·3·1·0)와
   "보낸 날"을 저장해 두고 그날 이미 보냈으면 건너뛴다. 생성 중 401과 자동 확인이 같은 상태(`key_check`)를 써야 서로 겹치지 않는다.
3. **HTML 폼의 "비어 있음"과 "없음"은 서버에서 다르게 보일 수도, 같게 보일 수도 있다.** 브라우저는 빈 칸도 `expires=`로 보내지만,
   FastAPI는 빈 값을 기본값으로 바꿨다. 의미가 중요한 구별은 숨은 칸처럼 명시적인 신호로 받는 편이 안전하다.
