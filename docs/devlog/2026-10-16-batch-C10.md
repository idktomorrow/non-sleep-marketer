# 2026-10-16 배치 C10: 작업 요약을 사람이 읽는 문장으로

## 목표

실행 기록의 요약이 `reply: new=0, auto_replied=0, hidden=0, escalated=0, ignored=0, rate_limited=['…']`처럼 내부 값 그대로였다. 사용자가 이 줄의 뜻을 이해하지 못해 물었고, "요약 줄을 전체적으로 사람이 읽기 쉬운 문장으로" 바꾸기로 했다.

## 한 일

- **`nsm/engine/summary.py`(새 파일):** 잡마다 결과를 문장으로 바꾼다. 문장은 " · "로 잇는다.

  | 잡 | 예 |
  |---|---|
  | 자료 모으기 | 새 자료 31개(이미 본 자료 8개 뺌) · 31개를 살펴 관련 자료 5개 · 후기·일기 3개 제외 · 원문 2개 읽음 |
  | 원고 만들기 | 원고 2개 만듦(검토 대기 2개) · 형식: 리스트형, 비교형 |
  | 게시하기 | 1건 올림 · 안 올린 곳: 스레드 3시간 간격 대기(14:00 이후) |
  | 댓글 확인 | 새 댓글 없음 · 인스타그램 요청 제한으로 쉬는 중(02:56 이후 다시) |
  | 로그인 점검 | 로그인 정상 / 로그인이 필요해 멈춘 곳: 인스타그램 |
  | 성과 읽기 | 게시물 지표 5개, 계정 지표 2개 읽음 |
  | 주간 리포트 | 지난 7일 게시물 9개 정리 · 파일 weekly-….md |

  - 건너뛰면 "건너뜀: 게시 시간 밖", 오류가 있으면 끝에 "오류 N건: 첫 오류"가 붙는다.
- **같은 문장을 모든 곳에서 쓴다.**
  - `JobResult.summary()`: 실행 기록 DB, 로그 파일. 로그 파일에는 앞에 잡 이름을 붙인다.
  - `ko.result_text()`: "지금 실행" 결과 알림. 예전에는 따로 만든 짧은 문장이었다.
- **예전 줄도 문장으로.** DB에 이미 저장된 `reply: new=0, …` 줄은 화면 필터 `run_text`가 읽어 같은 문장으로 바꾼다(실행 기록·개요). 모르는 모양은 그대로 둔다.
- **문서:** 사용설명서 4절 실행 기록 줄, 문제 해결 표("관련 자료 0개"), known-gaps, architecture, CHANGELOG
- **데모 스크립트:** `scripts/dashboard_demo.py`의 예시 실행 기록을 새 문장과 예전 형식 한 줄로 바꿨다.

## 막힌 것과 해결

- **DB의 예전 줄.** 요약은 실행이 끝날 때 문자열로 저장된다. 새 코드만 바꾸면 실행 기록 화면에 예전 줄과 새 줄이 섞여 보인다.
  - 저장된 값을 마이그레이션하지 않고, 보여 줄 때 바꾸기로 했다. DB를 고치지 않으니 되돌리기 쉽다.
  - 예전 형식은 `잡: 키=값, 키=값 / 오류 N건: …`이다. 값에 쉼표가 든 목록(`['a', 'b']`)이 있어 단순히 쉼표로 자를 수 없다. 다음 `, 키=` 앞까지를 값으로 읽고 `ast.literal_eval`로 해석했다.
- **실제 기록으로 확인.** 앱이 DB를 잡고 있어 DB는 읽지 못했다. 같은 요약이 남는 로그 파일의 531줄(collect 12, generate 15, publish 65, reply 375, health 64)을 모두 바꿔 봤다. 바뀌지 않은 줄은 0이었다.
  - 이 과정에서 "0건 올림, 1건 실패"와 "이유:"/"안 올린 곳:" 표기가 어색한 것을 찾아 고쳤다.
- **코드 리뷰(`/code-review`) 반영.**
  - 따옴표 없는 값(`file=weekly-….md`)이 있는 예전 줄이 통째로 안 바뀌었다(실제 로그엔 주간 리포트 줄이 없어 못 잡았다). 글자 그대로 읽게 고쳤다.
  - 목록 글자 안에 `, x=`가 있으면 잘려 실패했다. 잘린 조각을 다음 조각과 이어 다시 읽는다.
  - 지난번 남은 댓글만 처리한 실행이 "새 댓글 없음 · 자동 답글 2개"로 헷갈렸다. "새 댓글 없음, 지난번 남은 댓글 처리 · 자동 답글 2개"로 바꿨다.
  - 문장 함수가 없는 잡은 목록 표기(`[…]`)를 풀어 쓰게 했다. 모든 잡에 문장이 있는지 테스트로 본다.
  - 함수 안 import를 맨 위로 옮겼다.
  - 예전 줄을 보여 줄 때 바꾸는 선택을 ADR 0039(제안)로 남겼다. 리뷰는 DB를 한 번 고치는 쪽을 권했지만, 사용자 데이터를 되돌릴 수 없게 바꾸지 않는 쪽을 골랐다.

## 배운 것 (신입 개발자용)

1. **로그는 개발자용, 화면은 사용자용.** `new=0`은 코드를 아는 사람에게는 정확하지만, 마케터에게는 암호다. 같은 데이터를 두 독자에게 보여 줄 때는 "무엇이 일어났나"를 문장으로 바꾸는 층을 따로 둔다.
2. **한 곳에서 만들고 여러 곳에서 쓴다.** 실행 기록과 "지금 실행" 알림이 각자 문장을 만들면 같은 결과가 다르게 보인다. 문장을 만드는 함수 하나(`describe`)를 모두가 부르게 했다.
3. **저장된 옛 데이터는 읽을 때 바꿀 수도 있다.** DB 값을 고치는 마이그레이션 대신, 보여 줄 때 옛 형식을 알아보고 바꿨다. 데이터를 건드리지 않아 안전하다. 모르는 모양은 손대지 않는 것이 핵심이다.
