# 2026-11-13 배치 R6: 문서 질문 화면을 "질문하러 오는 화면"으로 정리

## 목표

R3~R5에서 기능이 하나씩 붙으며 쌓인 문서 질문 화면을 질문하러 온 사람의 순서로 다시 짠다. 검색·답변·기록 로직과 DB는 그대로 두고 화면만 고친다.
- 순서: 질문 칸 → 답 → 최근 질문 → 검색 측정(개발용, 접힘).
- 근거 접힌 줄은 경로 전체 대신 짧은 제목만 보인다.
- 최근 질문을 표에서 카드로 바꾼다.
- 설명을 한 줄로 줄인다.
- 예시 칩과 출처 칩을 넣는다.

## 한 일

- **전 화면 기록**: 운영 대시보드 `/ask`(최근 기록 하나를 연 화면)를 GET으로만 1280px·400px 전체 길이로 찍었다. 근거 하나를 펼친 400px 화면도 찍었다. 파일은 `docs/samples/ui/before/24-ask-desktop.png`, `24-ask-mobile.png`, `25-ask-source-open-mobile.png`이고 번호는 after 폴더의 다음 번호다. POST는 보내지 않았다.
- **`ask_format.source_title(heading, kind)`**: 제목 경로를 " > "로 나눠 (짧은 제목, 보조 제목)을 돌려주는 순수 함수다(ADR 0070 표).
  - 문서는 (마지막 절, 문서 제목)이다. kind가 없는 예전 기록도 문서로 본다.
  - 수집 자료는 (기사 제목, "")이다.
  - 우리 글은 (글 제목, 카드 문구·댓글)이다.
  - 글자는 자르지 않는다. CSS `.src-title`이 60ch에서 말줄임하고, `title` 속성에 전체 글을 둔다.
  - 펼치면 첫 줄(`src-path`)에 파일 이름을 포함한 전체 경로가 있다.
- **`ask.py` 템플릿 전달값**
  - `present`가 근거마다 `title`·`subtitle`을 더한다.
  - `SOURCE_CHOICES`를 (값, 칩 글자, 전체 이름)으로 바꿨다. 칩 글자는 `KIND_BADGE`, 전체 이름은 `title` 속성에 둔다.
  - `summary_ids`는 최근 20개 중 근거에 `"posts/_summary"`가 든 기록 id를 SQL `contains`로만 찾는 읽기 질의다. 최근 질문 카드의 "요약" 배지에 쓴다.
  - `no_ground`(빈 답일 때 미리보기 문구)를 넘긴다.
  - 라우트·리다이렉트·CSRF는 바꾸지 않았다.
- **`ask.html`**
  - 맨 위 설명은 한 줄이다. 조각 수·출처별 개수·기준값·밤 색인·200자·Gemini 1건·비용 어림은 "자세히" `<details>` 안으로 옮겼다.
  - 질문 칸 `#ask-q` 아래에 출처 라디오 칩 넷(`#ask-source-all|docs|collected|posts`, `name="source"`)과 예시 질문 칩 넷(`<button type="button" class="chip">`)을 두었다. 예시는 템플릿 상수이고, 측정 질문 원문은 쓰지 않았다.
  - 답 카드의 모델 이름은 `title`에만 두고 비용·시간만 보인다.
  - 근거 접힌 줄은 [n] → 출처 배지 → 짧은 제목·보조 제목 → 점수 배지 순서다. 글 보기 링크·성과 줄 위치는 그대로다.
  - 최근 질문은 카드다. 질문 한 줄, 답 두 줄, 날짜·근거 배지(N개·근거 없음·요약)·비용·지우기가 들어간다. "전부 지우기"는 제목 옆 그대로다.
  - 검색 측정은 맨 아래 `<details id="eval">`이다. 측정 결과 안내가 있으면 서버가 `open`을 붙인다.
- **`ask.js`**
  - 예시 칩을 누르면 `#ask-q`에 값을 넣고 `focus()`만 한다.
  - 주소가 `#eval`이면(`hashchange` 포함) 측정 절을 펼친다.
  - 근거로 스크롤할 때 `prefers-reduced-motion`이면 부드러운 스크롤을 쓰지 않는다.
- **`app.css`**
  - 칩·카드·근거 제목·측정 절 규칙을 더했다. 기존 토큰(`--accent`, `--accent-soft`, `--line`, `--muted` 등)만 쓰고 새 색은 없다.
  - `.chunk-text`에 `overflow-wrap: anywhere`를 더했다(`word-break: break-all`은 쓰지 않음).
  - 포커스 표시는 `:focus-visible` 외곽선이다. 쓰지 않게 된 `.ask-source`·`.ask-recent` 규칙은 지웠다.
- **후 화면**: 임시 메모리 DB에 예시 기록 넷(근거 여섯 개: 요약·카드 문구·긴 devlog 제목·ADR·긴 기사 제목·댓글)을 넣은 서버로 같은 두 폭을 찍었다. 운영 DB는 열지 않았다.
  - 파일: `docs/samples/ui/after/24-ask-desktop.png`, `24-ask-mobile.png`, `25-ask-source-open-mobile.png`.
  - 400px에서 근거 [3](공백 없는 긴 주소가 든 본문)을 펼친 상태로 Playwright `document.documentElement.scrollWidth`를 쟀더니 **400**이었다(≤ 400). 1280px은 1280이다.
- **문서**: ADR 0070(제안), architecture 갱신 줄·구현 상태 표·6-4절, user-guide "문서 질문" 절(화면 순서·예시 칩·근거 제목·출처 칩·최근 질문 카드·측정은 맨 아래 접힘), CHANGELOG Changed 한 줄. 버전 0.4.35.

## 막힌 것과 해결

- **예시 문구가 측정 질문과 겹쳤다**
  - 요청서의 예시 넷 중 하나는 `tests/fixtures/rag/questions.yaml`의 측정 질문 1번 원문과 같았다.
  - 지금 질문 칸의 `placeholder`도 같은 문장이었다.
  - 예시는 "보호 모드는 언제 풀려"로 바꾸고, placeholder는 "무엇이든 짧게 물어보세요"로 바꿨다.
  - 새 테스트가 템플릿 원문을 두 질문 파일(`questions*.yaml`)과 비교한다.
  - "자세히" 안의 `HINT`(nsm/rag/answer.py, 이번 범위 밖)에는 아직 같은 예시가 있다. 화면 글자일 뿐 색인되는 문서가 아니라 그대로 두었다.
- **근거 접힌 줄을 flex로 바꾸자 펼침 표시(▶)가 사라졌다**
  - Chrome은 `display: flex`인 `<summary>`에 기본 마커를 그리지 않는다.
  - `::before`로 ▸/▾를 직접 그리고 `::-webkit-details-marker`를 숨겼다. 측정 절도 같다.
- **"요약" 배지에 필요한 값이 목록 질의에 없었다**
  - `recent_qa`는 근거 개수만 읽는다(R3c 리뷰: 목록에서 근거 본문을 읽지 않기). 이번 범위는 `nsm/rag`을 고치지 않는다.
  - 그래서 `ask.py`에 최근 20개 id만 대상으로 하는 읽기 질의를 두었다. 근거의 `path` 칸만 본다(`list_contains(json_extract_string(sources, '$[*].path'), ?)`). 파이썬으로는 id만 돌아온다.
- **스크린샷의 버전 번호**: `uv run --no-sync`로 띄운 서버는 설치된 패키지 메타데이터(0.4.34)를 읽었다. `uv sync` 뒤 다시 찍어 바닥에 0.4.35가 보이게 했다.

- **코드 리뷰(서브 에이전트) 지적 반영**
  - 전역 `.nowrap`이 설정 화면 API 키 표의 `<td class="nowrap">`에도 걸려 좁은 화면에서 버튼이 안 접혔다. `.recent-meta .nowrap`으로 좁혔다.
  - 요약 배지 질의가 JSON 전체에서 `"posts/_summary"` 글자를 찾아, 본문·제목에 같은 글이 있으면 잘못 붙을 수 있었다. `path` 칸만 보게 바꾸고 테스트를 더했다.
  - "자세히"의 `display: inline-block`이 펼침 표시를 지웠다. `width: fit-content`로 바꿔 ▶가 다시 보인다.
  - `<summary>` 안 `<h2>`는 화면 읽기 프로그램의 제목 이동에서 빠진다. `role="heading" aria-level="2"`인 span으로 바꿨다.
  - 테스트의 `doc_qa` 넣기를 열 이름을 적는 방식으로 바꿨다. `source_title`에 접두어 없는 경로·모르는 출처 경우를 더했다.
  - JS 테스트가 글자 검사뿐이라는 지적이 있었다. 그래서 Playwright로 직접 확인했다.
    - 예시 칩을 누르면 `#ask-q` 값이 들어가고 포커스가 가며, 주소는 그대로다(제출 안 됨).
    - 출처 칩을 누르면 라디오가 바뀐다.
    - `/ask`에서는 측정 절이 닫혀 있고, `/ask#eval`에서는 열린다.
  - 반영하지 않은 것
    - 비용 어림이 "자세히" 안으로 들어가 묻기 전에 안 보인다는 지적이 있었다. 요청서가 비용 어림을 "자세히"로 옮기라고 했고, 답 카드와 최근 질문 카드에는 실제 비용이 보이므로 그대로 두었다(ADR 0070 결과에 적음).
    - Safari 16 전의 flex `<summary>` 문제는 그대로다(배치가 아닌 흐름으로 보일 뿐 동작함).

## 배운 것

1. **"보이는 글"과 "데이터"를 나누면 화면을 바꿔도 서버가 안 바뀐다.** 출처 고르기를 `<select>`에서 라디오 칩으로 바꿨지만, `name="source"`와 값("", docs, collected, posts)을 그대로 두어 서버는 아무것도 몰라도 된다. 칩에 보이는 글("수집")과 전체 이름("수집 자료")은 바뀌어도 폼이 보내는 값은 같다. 화면을 다시 짤 때는 먼저 "폼이 서버로 무엇을 보내는가"를 고정하고 시작하면 안전하다.
2. **글자를 자르는 일은 서버보다 CSS에 맡기는 게 낫다.** 파이썬에서 앞 40자로 자르면 한국어가 낱말 중간에서 끊기고, 화면 폭이 넓어도 잘린 채로 보인다. `text-overflow: ellipsis` + `max-width`는 화면이 좁을 때만 줄이고, 원래 글은 HTML에 그대로 남아 `title`이나 복사로 볼 수 있다. 순수 함수는 "무엇을 보여 줄지"(어느 칸이 제목인가)만 정하고, "얼마나 보여 줄지"는 CSS가 정한다.
3. **`<details>`는 JS 없이도 접기·펼치기가 되고, 서버가 `open`을 붙일 수 있다.** 측정 직후에는 서버가 결과 안내가 있다는 걸 알기 때문에 `open`을 붙여 JS 없이도 펼쳐진다. 주소의 `#eval`은 서버로 오지 않는다(해시는 브라우저에만 있음). 그래서 이 경우만 JS가 처리한다. 누가 무엇을 아는지(서버: 쿼리 문자열, 브라우저: 해시)에 따라 일을 나누면 둘 다 단순해진다.

## 다음 배치 메모

- `HINT`(nsm/rag/answer.py)의 예시 문장이 측정 질문 1번 원문이다. 로직 배치에서 예시를 바꾸면 "자세히"와 400 오류 안내가 함께 바뀐다.
- 측정 종류가 늘거나 자주 보게 되면 측정을 별도 화면으로 옮긴다(ADR 0070 다시 볼 조건).
- 최근 질문 카드를 질문 칸 위 "최근에 물은 것" 칩으로도 보여 줄지는 실제로 쓰면서 본다.
