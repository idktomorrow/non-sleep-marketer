# 2026-10-18 배치 C21: 인스타그램 "자르기 단계가 나오지 않음" 고침

## 목표

2026-10-18 08:35부터 인스타그램 게시가 모두 `AdapterError: instagram: 자르기 단계가 나오지 않음`으로 실패했다(스레드는 정상). 10-16까지는 올라갔다. 원인을 찾아 고친다.

## 한 일

- **진단**: 운영 계정 브라우저(Aside)로 업로드 창을 열고 파일을 넣은 뒤, 공유하지 않고 화면 구조만 읽는 진단 스크립트를 돌렸다.
  - `[role="dialog"]`가 **둘**이었다. 첫 번째는 "알림 설정 — 회원님을 팔로우하거나 … 설정 / 나중에 하기" 안내 창, 두 번째가 업로드 창이었다.
  - 게시 스크립트는 `document.querySelector('[role="dialog"]')`로 **첫 번째** 대화상자 안에서만 "자르기 선택" 아이콘을 찾았다. 안내 창에는 그 아이콘이 없으니 30초 뒤 실패했다.
  - 파일 넣기는 Playwright `locator(...).first()`라 두 번째 창의 input을 찾아 성공했다. 그래서 "파일은 넣었는데 자르기만 안 나오는" 모양이 됐다.
- **고침**(`nsm/adapters/platforms/aside_common.py`, `instagram.py`)
  - `nsmDismissPrompts(pg)`: 제목에 "알림/Notification"이 든 대화상자의 "나중에 하기·Not Now" 버튼을 누른다(최대 3번). 업로드 창의 "취소" 같은 버튼은 건드리지 않게 제목으로 거른다.
  - 업로드 흐름에서 세 곳에 넣었다: 파일 넣기 전, 자르기 아이콘을 기다리는 동안, 다음 단계로 넘어가는 반복 안.
  - `nsmMarkIcon`: scope 선택자에 맞는 요소가 여럿이면 전부 본다(`querySelectorAll`). 안내 창이 또 떠도 업로드 창의 아이콘을 찾는다.
- **확인**: 고친 도우미로 다시 진단했다. 안내 창 1개를 닫았고, 자르기 아이콘을 **19ms**에 찾았으며, 대화상자 이름은 "자르기"였다. 끝나면 Escape → "삭제"로 지워 계정에 아무것도 남기지 않았다.
- **문서**: CHANGELOG Fixed, 사용설명서 문제 해결 한 줄, architecture 행, known-gaps "화면 구조 변경" 사례 추가.

## 막힌 것과 해결

- **운영 중인 프로그램과 같은 브라우저를 써야 했다.** 게시 잡은 30분마다 1~2분 돈다. 그 사이를 피해 진단을 돌렸고, 진단은 공유 단계 전에 멈추고 지웠다.
- **메인 작업 폴더를 건드리면 운영 대시보드가 깨진다(C20에서 배움).** 이번 배치는 처음부터 `git worktree`(별도 폴더)에서 했고, 거기에 `uv sync`로 따로 환경을 만들었다. 운영 `nsm run`은 영향이 없었다.
- **브라우저 없이 돌릴 수 있는 테스트가 없다.** JS는 문자열 템플릿이라 pytest로는 "닫기 도우미가 있고, 업로드 흐름이 그것을 부른다"는 구조만 검사한다(`tests/unit/test_aside_scripts.py`). 실제 화면은 진단 스크립트로 확인했다. 실계정 계약 테스트(`-m contract`)는 운영 계정에 실제로 올리므로 사용자 허락 뒤에만 돌린다.

## 테스트 결과

- 실계정 진단(공유 없음): 안내 창 닫힘 1, 자르기 아이콘 발견, 대화상자 "자르기", 정리 후 대화상자 0

## 배운 것 (신입 개발자용)

1. **"첫 번째 것"은 가정이다.** `querySelector`는 첫 요소 하나만 준다. 화면에 같은 역할의 요소가 하나뿐일 때만 맞는 가정이고, 사이트가 안내 창 하나를 더 띄우는 순간 깨진다. 여럿을 보고 고르거나(`querySelectorAll`), 가정이 깨졌을 때 알 수 있게 오류 문구에 "대화상자 2개"처럼 상황을 담는 것이 좋다.
2. **진단은 부작용 없는 길로.** 실패를 재현하려고 실제 게시를 다시 누르면 중복 게시가 날 수 있다. 공유 직전에 멈추고 화면 구조만 읽은 뒤 지우는 진단 스크립트를 따로 두면, 운영 계정에 흔적 없이 원인을 볼 수 있다.
3. **외부 화면은 바뀐다는 전제로 기록한다.** 네이버(10-13), 인스타그램(10-18) 모두 코드 변경 없이 사이트 쪽이 바뀌어 실패했다. known-gaps에 사례를 쌓아 두면, 다음에 "0건·실패"가 나왔을 때 사람이 먼저 의심할 곳을 안다.
