# 2026-11-18 배치 C49: 백업 파일을 다른 폴더에 한 부 더 복사

## 목표

하루 한 번 만드는 DB 백업이 같은 PC 안(`<NSM_HOME>/backups/`)에만 있던 것을, 사용자가 고른 폴더(구글 드라이브·OneDrive
동기화 폴더 등)에도 한 부 더 두게 한다. 선택 설정이고 기본은 끔.

## 한 일

1. **설정** `Settings.backup_copy_dir: str = ""`(빈값이면 끔). config.yaml 주석·마법사는 그대로(설정 화면에서 넣는 값).
2. **`nsm/engine/backup_copy.py`(새 파일)**
   - `check_copy_dir(raw, backups_dir, probe)`: 문제 코드(`relative`·`inside_backups`·`missing`·`not_dir`·`not_writable`) 또는 None.
     probe면 `.nsm-write-test-…` 파일을 만들었다 지워 쓰기를 확인한다.
   - `copy_backup(src, raw_dir, backups_dir)`: 검사 뒤 `.<이름>.<임의>.tmp`로 `shutil.copy2` → `os.replace`로 바꿔 넣는다.
     실패하면 임시 파일을 지우고 `CopyError(이유)`.
   - `prune_copies(folder, prefix, keep, newest)`: 본 백업의 정리 규칙을 함수로 뺀 것. 본 백업과 복사 폴더가 같이 쓴다.
   - `clean_path`: 탐색기 "경로로 복사"가 붙이는 앞뒤 따옴표를 뗀다. 켜짐 판단도 이 값으로 한다(`""`만 있으면 끔).
   - 끊긴 복사가 남긴 같은 접두어의 임시 파일은 다음 복사 때 지운다.
3. **maintenance**: 본 백업과 정리가 끝난 뒤 `backup_copy_dir`이 있으면 `_copy`. 성공이면 `counts.copy_ok=True`·`copy_dir`·
   `copies_removed`, 실패면 `copy_ok=False`·`copy_error`, WARNING 한 줄, 알림 "백업 복사 실패"(제목이 같아 Windows 알림의
   같은 제목 간격 규칙이 그대로 적용). 잡 결과는 성공. 옛 복사본 정리가 실패해도 복사는 성공으로 둔다.
4. **실행 기록 문장**: 설정이 켜져 있을 때만 "복사: <폴더>" 또는 "복사 실패: <이유>".
5. **설정 화면(고급)** "백업" 칸. 저장 때 `check_copy_dir(probe=True)`로 검사하고, 문제가 있어도 값은 저장한 뒤
   `/settings?saved=1&copy_warn=<코드>#backup`으로 돌아가 칸 아래에 안내(`ko.BACKUP_COPY_PROBLEMS`). 다시 열 때는 쓰기
   확인 없이 가벼운 검사만 한다(화면을 열 때마다 동기화 폴더에 임시 파일을 만들지 않게). 모르는 코드는 무시.
   `AppState.backups_dir`(runtime이 넘김)로 "백업 폴더 안" 검사.
6. **지금 실행 → 백업·정리**: `JOBS["maintenance"]`가 같은 `run_maintenance`라 따로 고칠 곳이 없다(테스트로 고정).
7. 문서: ADR 0074(채택), architecture 갱신 줄·잡 표·상태 표, known-gaps 4절, user-guide 7절 "다른 곳에도 백업을 두고
   싶음"(구글 드라이브 데스크톱·OneDrive 예시 경로), CHANGELOG. 버전 0.4.41.

## 막힌 것과 해결

- **Windows에서 "쓰기 불가" 폴더 만들기**: `chmod`로는 Windows 폴더를 읽기 전용으로 만들 수 없다. 테스트는
  `shutil.copy2`(반쯤 쓰고 PermissionError)와 확인용 파일 쓰기(`Path.write_bytes`)를 바꿔 끼워 실패를 만들었다.
- **셸 문자열 안의 역슬래시**: 예시 경로(`C:\Users\…`)를 파이썬 문자열에 넣다가 `\U` 이스케이프 오류가 났다. 템플릿은
  raw 문자열로, ko.py 문구는 역슬래시 없는 "드라이브 이름(예: C:)부터"로 바꿨다.

## 테스트 결과

- `uv run ruff check .`, `uv run ruff format --check .` 통과
- `uv run pytest`: 1521 passed, 13 deselected (C48 뒤 1494개에 새 27개: `tests/engine/test_backup_copy_c49.py` 15개, `tests/app/test_settings_backup_copy_c49.py` 12개)
- 파일은 전부 `tmp_path` 아래. 운영 DB·운영 backups 폴더는 열거나 쓰지 않았다.

## `/code-review` 반영

고친 것:
- 들어갈 수 없는 폴더(권한)에서 Python 3.12의 `Path.exists()`가 `PermissionError`를 올려 maintenance 전체가 멈추고
  설정 화면이 500이 될 수 있었다. 검사가 `OSError`·`ValueError`(NUL 경로)를 "쓸 수 없음"으로 돌려주고, 잡의 복사 단계는
  어떤 예외든 경고로만 받는다.
- 끊긴 복사가 남긴 `.data-….tmp`가 정리 패턴에 안 걸려 동기화 폴더에 쌓일 수 있었다: 다음 복사 때 지운다.
- 켜짐 판단(`strip`)과 경로(`clean_path`)가 달라 `""`만 넣으면 매일 실패 알림이 갈 수 있었다: `clean_path`로 통일.
- 주소의 `copy_warn` 코드를 그대로 믿어, 폴더를 만든 뒤 새로고침해도 "폴더가 없습니다"가 남았다: 늘 가벼운 검사를 다시
  하고, 저장 때 결과는 "쓸 수 없음"만 쓴다.
- 쓰기 확인 임시 파일을 모든 설정 저장마다 만들었다: 값이 바뀐 때만.
- 간단 모드에서는 칸이 숨어 안내가 안 보였다: 간단 모드면 화면 맨 위에 한 줄.
- 실패 때 WARNING이 두 줄(잡 + 알림 어댑터): 잡의 줄을 빼고 알림이 남기는 한 줄만.
- 같은 동기화 폴더를 두 PC가 쓰면 서로의 백업을 지울 수 있다: 칸 설명과 사용설명서에 "PC마다 다른 폴더"를 적었다.

그대로 둔 것:
- ADR 상태 "채택": 요청이 상태를 정했다.

## 배운 것 3개

1. **반쯤 쓴 파일을 남기지 않는 법**: 최종 이름으로 바로 복사하다 끊기면, 이름은 멀쩡한데 내용이 잘린 백업이 남는다.
   같은 폴더에 임시 이름으로 다 쓴 뒤 `os.replace`로 바꿔 넣으면, 바꿔 넣기는 한 번에 일어나서 최종 이름에는 늘
   완전한 파일만 있다. 임시 이름은 정리 패턴(`data-????-??-??.duckdb`)에 걸리지 않게 점으로 시작한다.
2. **부가 기능의 실패가 본 기능을 실패로 만들면 안 된다**: 복사가 실패했다고 maintenance가 실패로 끝나면, 실행 기록과
   알림은 "백업 실패"처럼 보이고 사람은 데이터가 위험하다고 오해한다. 본 백업은 성공, 복사만 경고로 나눠 적는다.
3. **검사와 저장을 나누기**: 사용자는 폴더를 나중에 만들 수도 있다. 검사 실패로 저장을 막으면 순서를 강요하게 된다.
   값은 저장하고 무엇이 문제인지 칸 바로 아래에 보여 주면, 폴더를 만든 뒤 화면을 다시 열기만 해도 안내가 사라진다.
